Flutter Project Structure & Core Widgets

Flutter lets you build apps for several platforms with one Dart codebase. Before building screens, learn where each part of a Flutter project lives and how widgets create the user interface.

By the end: You can create a Flutter app, find the important files, add packages and images in pubspec.yaml, use Stateless and Stateful widgets, build a basic app with MaterialApp and Scaffold, and run it on a device or emulator.

Why Project Structure Matters

A Flutter project has a standard set of folders and files. Once you know what each one does, it is much easier to find your code, images, settings, and packages.

Your Dart code

Put screens, widgets, and app logic in the lib/ folder.

Packages

Add outside libraries and set project details in pubspec.yaml.

Images and files

Keep images, fonts, and data files in an assets/ folder.

Widget tree

Build the screen by putting small widgets inside larger widgets.

Before you start

You should know basic variables, functions, and classes, and have Flutter installed.

A helpful idea

In Flutter, everything you see is a widget. Your screen is a tree of widgets inside other widgets.

CORE IDEA

Flutter builds the screen from the current state: UI = f(state). When the state changes, Flutter updates the parts of the screen that need to change.

BEGINNER NOTE

Do not worry about android/ or ios/ yet. Most of your early work happens in lib/ and pubspec.yaml.

STEP 2 · CREATION

Creating Your First Flutter Project

Flutter can create a ready-to-use project for you, including a small sample app.

Command Line Project Generation

Open a terminal, go to the folder where you keep projects, and run this command to create an app named my_first_app:

flutter create my_first_app
cd my_first_app
Terminal Output
Creating project my_first_app...
Wrote 129 files.
All done! Created my_first_app.

Project Naming Rules

Use snake_case

Use lowercase letters and underscores, such as my_first_app. Do not use capital letters or hyphens.

App identifier

Flutter gives the app an identifier such as com.example.my_first_app. You can change its first part with --org.

flutter create --org com.mycompany my_first_app
In plain language: flutter create makes the starter files your app needs for Android, iOS, web, desktop, and Dart.

Quick check

Which of the following is a valid project name for a Flutter app?

Correct. Flutter project identifiers must be valid Dart identifiers using lowercase snake_case syntax.
STEP 3 · DIRECTORY STRUCTURE

Understanding Key Project Components

A new Flutter project has a few main files and folders. Each one has a job.

The Project File Tree

my_first_app/
├── android/ → Native Android platform wrapper & Gradle scripts
├── ios/ → Native iOS platform wrapper & Xcode setup
├── web/ → Web platform entry point & index.html
├── lib/ → Main Dart source code folder (main.dart)
├── assets/ → User-created folder for images, fonts, and data files
├── test/ → Unit and widget testing scripts
├── pubspec.yaml → Package dependencies, metadata & asset declarations
└── pubspec.lock → Auto-generated lockfile recording exact dependency versions

Component Breakdown

Directory / FilePurposeDeveloper Activity
lib/Your Dart code lives here. The app normally starts in lib/main.dart.Often
pubspec.yamlLists packages, Flutter settings, images, fonts, and project information.When adding packages or assets
android/ & ios/Platform-specific files that let the Flutter app run on Android and iOS.Occasionally
assets/Put images, SVG files, and local data here.When adding assets
COMMON MISTAKE

Never edit files inside pubspec.lock manually. It is managed automatically by the flutter pub get tooling command.

STEP 4 · CONFIGURATION

Mastering pubspec.yaml & Assets

pubspec.yaml is the settings file for your Flutter app. It uses YAML, so the spaces at the start of a line matter.

Anatomy of pubspec.yaml

name: my_first_app
description: A new Flutter project.
publish_to: 'none'
version: 1.0.0+1

environment:
  sdk: '>=3.0.0 <4.0.0'

dependencies:
  flutter:
    sdk: flutter
  cupertino_icons: ^1.0.6

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^3.0.0

flutter:
  uses-material-design: true
  assets:
    - assets/images/logo.png
    - assets/data/config.json
Key YAML Sections Explained:
  1. dependencies: Packages your app needs when it runs.
  2. dev_dependencies: Tools used only while building and testing the app.
  3. flutter: Flutter-specific settings, including Material icons, fonts, and assets.

Adding Static Assets

To show an image from your project, do these two things:

Step 1: Make an assets/images/ folder in your project and put an image there, for example logo.png.

Step 2: Add the image path under flutter: in pubspec.yaml. Keep the indentation exactly as shown.

Quick check

Why might Flutter fail to load an asset even though the image file exists on disk?

Correct. Flutter requires all local static assets to be explicitly declared inside pubspec.yaml.
STEP 5 · CORE CONCEPTS

What is a Widget?

A widget is a small piece of your app's screen or behavior. Text, buttons, spacing, and entire pages are all widgets.

Layout widgets

Put other widgets in the right place, such as Row, Column, Container, and Stack.

Visible widgets

Show something on screen, such as Text, Image, and Icon.

Interactive widgets

React when the user taps or gestures, such as ElevatedButton and GestureDetector.

Helper widgets

Control things like theme and spacing, such as Theme, Padding, and MediaQuery.

The Immutable Widget Concept

Widgets are descriptions, not objects that Flutter edits in place. When something changes, Flutter runs build() again to describe the updated part of the screen.

Widget build(BuildContext context) { ... }
REMEMBER

A widget's build() method returns the widgets that should appear on screen.

STEP 6 · STATELESS WIDGETS

StatelessWidget: Static UI Components

Use a StatelessWidget when the widget does not need to change by itself. It shows the information it receives.

A Small First Example

Start with one simple job: show some text. This widget never changes, so it can be a StatelessWidget.

class HelloMessage extends StatelessWidget {
  const HelloMessage({super.key});

  @override
  Widget build(BuildContext context) {
    return const Text('Hello, Flutter!');
  }
}
What this means:
  • extends StatelessWidget: This widget does not keep changing data.
  • build(): This tells Flutter what to show.
  • Text: This is another widget. Here, it displays “Hello, Flutter!”.

Quick check

When should you use a StatelessWidget?

Correct. Use a StatelessWidget for a part of the screen that does not need its own changing data.
STEP 7 · STATEFUL WIDGETS

StatefulWidget: Dynamic UI & State

Use a StatefulWidget when something on the screen can change, such as a counter, form, or switch. Call setState() after changing its data so Flutter redraws it.

A Small First Example

This example keeps one piece of state: a number named count. Each tap adds one and then asks Flutter to rebuild the screen.

import 'package:flutter/material.dart';

class TapCounter extends StatefulWidget {
  const TapCounter({super.key});

  @override
  State<TapCounter> createState() => _TapCounterState();
}

class _TapCounterState extends State<TapCounter> {
  int count = 0;

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: () {
        setState(() {
          count++;
        });
      },
      child: Text('Taps: $count'),
    );
  }
}
What changes here:
  • count starts at 0. This is the widget's state.
  • When you tap the button, count++ adds one.
  • setState() tells Flutter to show the new number.
Widget TypeState StorageRebuild TriggerTypical Use Case
StatelessWidgetNo changing value of its ownIts parent gives it new informationA label or a simple message
StatefulWidgetKeeps a value that can changeYou call setState()A counter, checkbox, or form
IMPORTANT

Change state inside setState(() { ... }). If you change the value outside setState, Flutter may not update the screen.

STEP 8 · APPLICATION SHELL

MaterialApp & Scaffold Essentials

Most Flutter apps start with two useful widgets: MaterialApp and Scaffold.

MaterialApp

The outer widget for your app. It sets things such as the theme and the first screen.

Scaffold

A ready-made page layout. It can hold an app bar, page body, drawer, floating button, and snack bars.

MaterialApp and Scaffold Integration

import 'package:flutter/material.dart';

Widget buildAppShell() {
  return MaterialApp(
    title: 'Flutter Demo',
    debugShowCheckedModeBanner: false,
    theme: ThemeData(
      primarySwatch: Colors.blue,
      useMaterial3: true,
    ),
    home: Scaffold(
      appBar: AppBar(
        title: const Text('Home Screen'),
      ),
      body: const Center(
        child: Text('Hello, Flutter!'),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {},
        child: const Icon(Icons.add),
      ),
    ),
  );
}
Read it step by step:
  1. MaterialApp sets up the overall app and its theme.
  2. Scaffold gives one screen an app bar, body, and floating button.
  3. Center puts its child in the middle of the available space.

Hot Reload (press r)

Shows many code changes quickly and keeps the current screen state.

Hot Restart (press R)

Starts the app again and resets its state.

TIP

Use Hot Reload for small UI changes such as colors and layout. Use Hot Restart after changing app startup code, global values, or initState().

STEP 10 · COMPLETE CODE

Putting It All Together: Complete App Code

Here is a complete beginner-friendly app in one file. Replace the contents of lib/main.dart with this code to try it.

import 'package:flutter/material.dart';

void main() {
  runApp(const MyFlutterApp());
}

/// The root application widget configuring themes and initial screens.
class MyFlutterApp extends StatelessWidget {
  const MyFlutterApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Flutter Essentials',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
        useMaterial3: true,
      ),
      home: const DashboardScreen(),
    );
  }
}

/// Main dashboard widget providing Scaffold shell and state interaction.
class DashboardScreen extends StatefulWidget {
  const DashboardScreen({super.key});

  @override
  State<DashboardScreen> createState() => _DashboardScreenState();
}

class _DashboardScreenState extends State<DashboardScreen> {
  int _counter = 0;

  void _incrementCounter() {
    setState(() {
      _counter++;
    });
  }

  void _resetCounter() {
    setState(() {
      _counter = 0;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Flutter Structure Demo'),
        backgroundColor: Theme.of(context).colorScheme.inversePrimary,
        actions: [
          IconButton(
            icon: const Icon(Icons.refresh),
            onPressed: _resetCounter,
            tooltip: 'Reset Counter',
          )
        ],
      ),
      body: Padding(
        padding: const EdgeInsets.all(16.0),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            const ProfileCard(
              title: 'Developer Portal',
              subtitle: 'Flutter Basics Codelab',
            ),
            const SizedBox(height: 32),
            Center(
              child: Text(
                'Button Taps Count:',
                style: Theme.of(context).textTheme.titleMedium,
              ),
            ),
            Center(
              child: Text(
                '$_counter',
                style: Theme.of(context).textTheme.headlineLarge,
              ),
            ),
          ],
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _incrementCounter,
        tooltip: 'Increment',
        child: const Icon(Icons.add),
      ),
    );
  }
}

/// Reusable StatelessWidget displaying static information card UI.
class ProfileCard extends StatelessWidget {
  final String title;
  final String subtitle;

  const ProfileCard({
    super.key,
    required this.title,
    required this.subtitle,
  });

  @override
  Widget build(BuildContext context) {
    return Card(
      elevation: 4,
      shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(12)),
      child: Padding(
        padding: const EdgeInsets.all(16.0),
        child: Column(
          children: [
            const Icon(Icons.flutter_dash, size: 48, color: Colors.deepPurple),
            const SizedBox(height: 8),
            Text(
              title,
              style: const TextStyle(fontSize: 18, fontWeight: FontWeight.bold),
            ),
            Text(
              subtitle,
              style: TextStyle(fontSize: 14, color: Colors.grey.shade600),
            ),
          ],
        ),
      ),
    );
  }
}
What you should see
A purple app with a profile card and a counter. Tap the floating plus button to increase the count. Tap refresh in the app bar to set it back to 0.

STEP 12 · FINAL TASK

Build an Interactive Profile Card

Use what you learned to build a profile page with a button that changes.

BUILD IT · Interactive Profile Screen

  1. Make a StatefulWidget named UserProfileApp, using MaterialApp and Scaffold.
  2. Add a StatelessWidget header that shows an avatar and user details.
  3. Create a true-or-false variable named _isFollowing.
  4. Add an ElevatedButton. Inside setState(), use it to switch _isFollowing between true and false.
  5. Show “Following” in green or “Follow User” in blue based on the value.

Done when: Tapping the button changes its text by using setState().

Suggested order: Build the static parts first. Then add the changing follow button with a StatefulWidget.
Reveal one possible solution 
import 'package:flutter/material.dart';

void main() => runApp(const UserProfileApp());

class UserProfileApp extends StatelessWidget {
  const UserProfileApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: ProfileScreen(),
    );
  }
}

class ProfileScreen extends StatefulWidget {
  const ProfileScreen({super.key});

  @override
  State<ProfileScreen> createState() => _ProfileScreenState();
}

class _ProfileScreenState extends State<ProfileScreen> {
  bool _isFollowing = false;

  void _toggleFollow() {
    setState(() {
      _isFollowing = !_isFollowing;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('User Profile')),
      body: Center(
        child: Padding(
          padding: const EdgeInsets.all(24.0),
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              const CircleAvatar(
                radius: 40,
                child: Icon(Icons.person, size: 40),
              ),
              const SizedBox(height: 16),
              const Text(
                'Jane Doe',
                style: TextStyle(fontSize: 22, fontWeight: FontWeight.bold),
              ),
              const Text('Flutter Developer'),
              const SizedBox(height: 24),
              ElevatedButton(
                onPressed: _toggleFollow,
                style: ElevatedButton.styleFrom(
                  backgroundColor: _isFollowing ? Colors.green : Colors.blue,
                  foregroundColor: Colors.white,
                ),
                child: Text(_isFollowing ? 'Following' : 'Follow User'),
              ),
            ],
          ),
        ),
      ),
    );
  }
}
