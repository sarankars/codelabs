STEP 1 · START HERE

Object-Oriented Programming in Dart

OOP is a way to organize programs around objects: things that combine state (data) and behavior (what they can do). Dart uses classes, inheritance, interfaces, and mixins to model that behavior.

By the end: You will be able to model app data with classes, initialize valid objects, protect state, and choose between inheritance, interfaces, mixins, factories, static members, and extensions.

Why OOP matters

Imagine a bank account. It has state such as an account holder and balance, and behavior such as depositing or withdrawing money. Instead of keeping all those pieces unrelated, an object can keep the data and the operations that work on that data together.

Model

Represent real or conceptual things as objects.

Organize

Keep related data and behavior together.

Reuse

Share behavior through inheritance, interfaces, or mixins when appropriate.

Maintain

Give each type a clear responsibility so larger programs are easier to change.

Prerequisites

Basic Dart syntax, variables, types, conditionals, loops, and functions.

Mindset

OOP is a toolbox, not a rule that every problem must be solved with inheritance.

CORE IDEA

A class describes a kind of object. An object is an instance of that class.

STEP 2 · FOUNDATIONS

Classes & objects

A class is a blueprint for a type. An object is a concrete instance created from that type.

The basic shape

class ClassName {
  // fields and methods
}

final object = ClassName();
class Student {
  String name = 'Asha';
  int age = 20;

  void introduce() {
    print('I am $name and I am $age.');
  }
}

void main() {
  final student = Student();
  student.introduce();
}
Expected Output
I am Asha and I am 20.
Class

Student defines what a student object can contain and do.

Object

student refers to one concrete Student instance.

COMMON MISTAKE

Declaring class Student does not create a student object. You create an instance with Student().

Quick check

Which line creates an object?

Correct. The constructor call creates a Student instance.
STEP 3 · STATE & BEHAVIOR

Fields, methods & this

Fields store object state. Methods describe behavior that can read or change that state.

class BankAccount {
  double balance = 0;

  void deposit(double amount) {
    balance += amount;
  }

  void showBalance() {
    print('Balance: $balance');
  }
}

void main() {
  final account = BankAccount();
  account.deposit(500);
  account.showBalance();
}
Expected Output
Balance: 500.0

Using this

Inside an instance member, this refers to the current object. It is especially useful when a parameter and a field have the same name.

class Student {
  String name;

  Student(this.name);

  void rename(String name) {
    this.name = name;
  }
}

Read it

  • name on the left of this.name = name is the field.
  • name on the right is the method parameter.
  • this.name explicitly means “the current object's field.”
DESIGN TIP

Keep methods focused on behavior that naturally belongs to the object. A BankAccount should know how to deposit or withdraw rather than exposing every internal detail to callers.

STEP 4 · INITIALIZING OBJECTS

Constructors

Constructors run when an object is created. They are commonly used to put an object into a valid initial state.

Generative & initializing constructors

class Student {
  final String name;
  final int age;

  Student(this.name, this.age);
}

void main() {
  final student = Student('Asha', 20);
  print('${student.name}, ${student.age}');
}
Expected Output
Asha, 20

Named constructors and initializer lists

A class can provide additional named construction paths when different ways of creating an object are useful.

class Point {
  final double x;
  final double y;

  Point(this.x, this.y);

  Point.origin()
      : x = 0,
        y = 0;

  // ...
}
Initializer list: the part after : runs before the constructor body. It initializes final fields when a constructor cannot use this.field directly.
Default constructor

If you declare no constructor, Dart can provide an unnamed generative constructor with no parameters. Once you declare a constructor, Dart does not also provide that implicit constructor.

Named constructor

Point.origin() gives callers a readable alternative construction path.

Named parameters in constructors

class Product {
  final String name;
  final double price;

  Product({
    required this.name,
    required this.price,
  });
}

final product = Product(name: 'Keyboard', price: 2500);
COMMON MISTAKE

A constructor is not an ordinary method. It has special syntax and is invoked as part of object creation.

STEP 5 · ENCAPSULATION

Encapsulation & privacy

Encapsulation means controlling how an object's internal state is accessed or changed. Dart's privacy model is library-based: an identifier beginning with _ is private to its library.

class BankAccount {
  double _balance = 0;

  double get balance => _balance;

  void deposit(double amount) {
    if (amount <= 0) return;
    _balance += amount;
  }

  bool withdraw(double amount) {
    if (amount <= 0 || amount > _balance) return false;
    _balance -= amount;
    return true;
  }
}

void main() {
  final account = BankAccount();
  account.deposit(1000);
  account.withdraw(250);
  print(account.balance);
}
Expected Output
750.0

Getters & setters

A getter exposes a value through property-like syntax. A setter can validate or transform a value before storing it.

class Person {
  String _name = '';

  String get name => _name;

  set name(String value) {
    if (value.trim().isNotEmpty) {
      _name = value.trim();
    }
  }
}
Important Dart nuance: “Private” does not mean “private to the class.” A leading underscore makes the declaration private to the library. Separate Dart libraries cannot directly access that private identifier.
WHY IT MATTERS

Encapsulation lets a class protect invariants. Instead of allowing arbitrary code to set a balance to an invalid value, the class can expose controlled operations.

STEP 6 · REUSE

Inheritance with extends

Inheritance creates a subtype that extends another class. The child class can reuse accessible behavior and add or replace behavior of its own.

class Animal {
  void eat() {
    print('Eating');
  }
}

class Dog extends Animal {
  void bark() {
    print('Woof!');
  }
}

void main() {
  final dog = Dog();
  dog.eat();
  dog.bark();
}
Expected Output
Eating
Woof!

Calling parent behavior with super

class Vehicle {
  void start() {
    print('Vehicle started');
  }
}

class Car extends Vehicle {
  @override
  void start() {
    super.start();
    print('Car is ready to drive');
  }
}
When inheritance fits: use it when the subtype really represents a specialized form of the parent type and the relationship is meaningful. Do not use inheritance only because it happens to save a few lines of code.
COMMON MISTAKE

extends is not a generic “reuse anything” keyword. For unrelated capabilities, a mixin, interface, or composition may be a better design.

STEP 7 · POLYMORPHISM

Overriding & polymorphism

A subclass can override inherited behavior. Polymorphism lets code work with a common type while the actual object's implementation determines what happens.

class Animal {
  void makeSound() {
    print('Some sound');
  }
}

class Dog extends Animal {
  @override
  void makeSound() {
    print('Woof!');
  }
}

class Cat extends Animal {
  @override
  void makeSound() {
    print('Meow!');
  }
}

void playSound(Animal animal) {
  animal.makeSound();
}

void main() {
  playSound(Dog());
  playSound(Cat());
}
Expected Output
Woof!
Meow!

playSound only needs to know that it received an Animal. The runtime object can be a Dog or Cat, and its overridden method runs.

Quick check

Why does playSound(Dog()) call the dog's implementation?

Correct. The variable can use the parent type while the object's overridden implementation is selected.
REMEMBER

Overriding is the mechanism; polymorphism is the broader idea of using a common abstraction/type with different concrete behavior.

STEP 8 · ABSTRACTION

Abstract classes

An abstract class defines a common contract or shared behavior but is not itself meant to be instantiated directly.

abstract class Shape {
  double area();

  void describe() {
    print('I am a shape.');
  }
}

class Circle extends Shape {
  final double radius;

  Circle(this.radius);

  @override
  double area() => 3.14159 * radius * radius;
}

void main() {
  final shape = Circle(2);
  shape.describe();
  print(shape.area());
}
Expected Output
I am a shape.
12.56636

What is abstract here?

  • Shape cannot be instantiated directly.
  • area() declares behavior without providing an implementation.
  • A concrete subclass such as Circle must provide the missing implementation.
Abstraction vs encapsulation: abstraction focuses on what an object exposes as a useful contract; encapsulation focuses on controlling and protecting its internal state and implementation.
COMMON MISTAKE

An abstract class is not simply a class with “private fields.” Abstraction is about modeling a contract or essential behavior while hiding unnecessary implementation details.

STEP 9 · INTERFACES

extends vs implements

In Dart, every class implicitly defines an interface containing its instance members. Another class can implement that interface with implements.

abstract class PaymentMethod {
  void pay(double amount);
}

class UpiPayment implements PaymentMethod {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using UPI');
  }
}

class CardPayment implements PaymentMethod {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using card');
  }
}

void processPayment(PaymentMethod method) {
  method.pay(500);
}
KeywordMain ideaWhat the child gets
extendsCreates a subtype of a class.Inherits implementation and can override behavior.
implementsPromises to satisfy an interface.Must provide implementations for the interface's members; it does not inherit the class's implementation in the same way.
withAdds mixin behavior.Reusable implementation supplied by one or more mixins.
Useful mental model: extends is primarily about an inheritance relationship, implements is about satisfying a contract, and with is about composing reusable behavior.

Quick check

What must UpiPayment do when it implements PaymentMethod?

Correct. implements makes the class satisfy the interface contract.
STEP 10 · COMPOSITION

Mixins with with

A mixin is a reusable set of members that can be composed into a class. Mixins are useful when behavior can be shared across types without requiring an inheritance relationship.

mixin Logger {
  void log(String message) {
    print('[LOG] $message');
  }
}

mixin JsonSupport {
  Map<String, dynamic> toJson() =>
      {'type': runtimeType.toString()};
}

class User with Logger, JsonSupport {
  final String name;

  User(this.name);

  void save() {
    log('Saving $name');
  }
}

void main() {
  final user = User('Asha');
  user.save();
  print(user.toJson());
}
Expected Output
[LOG] Saving Asha
{type: User}

The User class receives both log and toJson without extending either mixin as a superclass.

Inheritance

Models a subtype relationship such as Dog extends Animal.

Mixin composition

Adds reusable behavior such as logging, serialization helpers, or another capability.

GOOD PRACTICE

Use a mixin for cohesive reusable behavior. Avoid creating huge “utility mixins” that make a class's capabilities difficult to understand.

STEP 11 · DART TOOLBOX

static, factory & extensions

These features make types easier to create and use. They solve different problems: class-level utilities, controlled creation, and focused helper behaviour.

Static members

A static member belongs to the class rather than to a particular instance.

class MathTools {
  static const double pi = 3.14159;

  static double square(double value) => value * value;
}

void main() {
  print(MathTools.square(4));
  print(MathTools.pi);
}
Expected Output
16.0
3.14159

Factory constructors

A factory constructor can validate input or decide which object to return. Unlike a generative constructor, it does not have to create a new instance every time.

class UserId {
  final String value;

  UserId._(this.value);

  factory UserId.fromInput(String input) {
    final cleaned = input.trim();
    if (cleaned.isEmpty) {
      throw ArgumentError('A user ID is required.');
    }
    return UserId._(cleaned.toLowerCase());
  }
}

void main() {
  final userId = UserId.fromInput('  ASHA_42 ');
  print(userId.value);
}
Expected Output
asha_42

Extension methods

An extension adds focused helper behaviour to an existing type without changing that type or creating a subclass. Keep extensions small and easy to discover.

extension PriceLabel on double {
  String asRupees() => '₹${toStringAsFixed(2)}';
}

void main() {
  final price = 2499.0;
  print(price.asRupees());
}
Expected Output
₹2499.00
CHOOSE DELIBERATELY

Use a static member for behaviour with no instance state, a factory to control object creation, and an extension for a focused convenience on an existing type.

STEP 12 · PUT IT TOGETHER

A small OOP system

Now combine constructors, encapsulation, inheritance, overriding, abstraction, interfaces, polymorphism, and a mixin in one focused example.

mixin Auditable {
  void audit(String message) {
    print('[AUDIT] $message');
  }
}

abstract class Employee {
  final String name;
  double _salary;

  Employee({
    required this.name,
    required double salary,
  }) : _salary = salary;

  double get salary => _salary;

  void work();

  void giveRaise(double amount) {
    if (amount > 0) _salary += amount;
  }
}

class Developer extends Employee with Auditable {
  Developer({
    required super.name,
    required super.salary,
  });

  @override
  void work() {
    audit('$name is writing Dart code');
  }
}

class Teacher extends Employee {
  Teacher({
    required super.name,
    required super.salary,
  });

  @override
  void work() {
    print('$name is teaching a class');
  }
}

void runWorkday(List<Employee> employees) {
  for (final employee in employees) {
    employee.work();
  }
}

void main() {
  final employees = <Employee>[
    Developer(name: 'Asha', salary: 60000),
    Teacher(name: 'Rahul', salary: 55000),
  ];

  runWorkday(employees);
  employees[0].giveRaise(5000);
  print(employees[0].salary);
}
Expected Output
[AUDIT] Asha is writing Dart code
Rahul is teaching a class
65000.0
Abstraction

Employee defines the common contract with abstract work().

Encapsulation

_salary is controlled through a getter and giveRaise().

Inheritance

Developer and Teacher extend Employee.

Polymorphism

runWorkday accepts List<Employee> and invokes each concrete work().

Mixin

Developer composes Auditable with with.

Constructors

Named parameters initialize each object's required state.

DESIGN LESSON

The power of OOP is not the number of classes you create. It is the clarity of the relationships, responsibilities, and contracts between them.

STEP 13 · PRACTICE

Final OOP challenge

Design a small library system. Do not copy the solution immediately—first sketch the classes and relationships yourself.

TRY IT · Library management model

  1. Create an abstract class LibraryItem with a required title and an abstract method describe().
  2. Create Book and Magazine classes that extend LibraryItem.
  3. Give each subclass its own implementation of describe().
  4. Create a Library class that stores a collection of LibraryItem objects.
  5. Use a loop to demonstrate polymorphism by calling describe() on every item.
  6. Add a private field and a getter/setter or controlled method where encapsulation makes sense.
  7. Add a small mixin such as Loggable and use it on one appropriate class.

Success condition: your program should contain at least two concrete item types and the library should work with them through the common LibraryItem type.

Planning hint: Start with the relationship: LibraryItem → Book/Magazine. Then decide which state belongs in the base class and which behavior belongs in each concrete class.
Reveal one possible solution 
mixin Loggable {
  void log(String message) => print('[LOG] $message');
}

abstract class LibraryItem {
  final String title;

  LibraryItem(this.title);

  void describe();
}

class Book extends LibraryItem with Loggable {
  final String author;

  Book(super.title, this.author);

  @override
  void describe() {
    log('Book: $title by $author');
  }
}

class Magazine extends LibraryItem {
  final int issue;

  Magazine(super.title, this.issue);

  @override
  void describe() {
    print('Magazine: $title, issue $issue');
  }
}

class Library {
  final List<LibraryItem> items = [];

  void add(LibraryItem item) => items.add(item);

  void describeAll() {
    for (final item in items) {
      item.describe();
    }
  }
}

void main() {
  final library = Library();
  library.add(Book('Dart Basics', 'Asha'));
  library.add(Magazine('Tech Monthly', 42));
  library.describeAll();
}
