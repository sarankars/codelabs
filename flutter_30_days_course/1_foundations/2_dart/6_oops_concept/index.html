Object-Oriented Programming in Dart

OOP is a way to group related data and actions. For example, a bank account has data such as its balance and actions such as depositing money. In Dart, we group these things with classes and objects.

By the end: You will be able to create classes for app data, keep that data safe, and understand the main ways classes can share code.

Why OOP matters

Imagine a bank account. It has state such as an account holder and balance, and behavior such as depositing or withdrawing money. Instead of keeping all those pieces unrelated, an object can keep the data and the operations that work on that data together.

Model

Describe a thing in your app, such as a user, product, or bank account.

Organize

Keep a thing's data and its actions in one place.

Reuse

Share useful code between classes when it makes sense.

Maintain

Give each class one clear job so it is easier to change later.

Prerequisites

Basic Dart syntax, variables, types, conditionals, loops, and functions.

Mindset

These are tools, not rules. Start simple and only use a more advanced tool when it solves a real problem.

CORE IDEA

A class is a description. An object is one real item made from that description. Student is a class; Asha's student record is an object.

STEP 2 · FOUNDATIONS

Classes & objects

Think of a class as a form or recipe. An object is one completed form made from it.

The basic shape

class ClassName {
  // fields and methods
}

final object = ClassName();
class Student {
  String name = 'Asha';
  int age = 20;

  void introduce() {
    print('I am $name and I am $age.');
  }
}

void main() {
  final student = Student();
  student.introduce();
}
Expected Output
I am Asha and I am 20.
Class

Student defines what a student object can contain and do.

Object

student is one Student made from that class.

COMMON MISTAKE

Declaring class Student does not create a student object. You create an instance with Student().

Quick check

Which line creates an object?

Correct. Student() makes one Student object.
STEP 3 · STATE & BEHAVIOR

Fields, methods & this

Fields store information. Methods are actions the object can perform using that information.

class BankAccount {
  double balance = 0;

  void deposit(double amount) {
    balance += amount;
  }

  void showBalance() {
    print('Balance: $balance');
  }
}

void main() {
  final account = BankAccount();
  account.deposit(500);
  account.showBalance();
}
Expected Output
Balance: 500.0

Using this

Inside a class, this means “this object.” It helps when a field and a parameter have the same name.

class Student {
  String name;

  Student(this.name);

  void rename(String name) {
    this.name = name;
  }
}

Read it

  • name on the left of this.name = name is the field.
  • name on the right is the method parameter.
  • this.name explicitly means “the current object's field.”
DESIGN TIP

Keep an action close to the data it works with. A BankAccount should handle deposits and withdrawals instead of letting other code directly change its balance.

STEP 4 · INITIALIZING OBJECTS

Constructors

A constructor runs when you make an object. It gives the object the starting values it needs.

A regular constructor

class Student {
  final String name;
  final int age;

  Student(this.name, this.age);
}

void main() {
  final student = Student('Asha', 20);
  print('${student.name}, ${student.age}');
}
Expected Output
Asha, 20

Named constructors and setup before the body

A class can offer named ways to create an object. For example, Point.origin() clearly says that the point starts at zero.

class Point {
  final double x;
  final double y;

  Point(this.x, this.y);

  Point.origin()
      : x = 0,
        y = 0;

  // ...
}
The part after :: it sets up values before the constructor body runs. Here it gives x and y their starting values.
Default constructor

If you write no constructor, Dart gives the class a simple no-argument constructor. Once you add your own constructor, you choose the available ways to create the object.

Named constructor

Point.origin() is a clearly named extra way to create a Point.

Named parameters in constructors

class Product {
  final String name;
  final double price;

  Product({
    required this.name,
    required this.price,
  });
}

final product = Product(name: 'Keyboard', price: 2500);
COMMON MISTAKE

A constructor looks a little like a method, but its job is only to create and set up an object.

STEP 5 · ENCAPSULATION

Encapsulation & privacy

Sometimes a class should protect its own data. In Dart, a name starting with _ can only be used from the same Dart file library.

class BankAccount {
  double _balance = 0;

  double get balance => _balance;

  void deposit(double amount) {
    if (amount <= 0) return;
    _balance += amount;
  }

  bool withdraw(double amount) {
    if (amount <= 0 || amount > _balance) return false;
    _balance -= amount;
    return true;
  }
}

void main() {
  final account = BankAccount();
  account.deposit(1000);
  account.withdraw(250);
  print(account.balance);
}
Expected Output
750.0

Getters & setters

A getter lets outside code read a value. A setter lets the class check or clean a value before saving it.

class Person {
  String _name = '';

  String get name => _name;

  set name(String value) {
    if (value.trim().isNotEmpty) {
      _name = value.trim();
    }
  }
}
Important: in Dart, “private” means private to the file library, not only to one class. Code in another library cannot use a name that starts with _.
WHY IT MATTERS

This prevents bad data. For example, other code cannot set a bank balance to an invalid amount; it must use the account's deposit or withdrawal methods.

STEP 6 · REUSE

Inheritance with extends

extends lets one class start with another class's features. A Dog is an Animal, so it can use Animal's actions and add its own.

class Animal {
  void eat() {
    print('Eating');
  }
}

class Dog extends Animal {
  void bark() {
    print('Woof!');
  }
}

void main() {
  final dog = Dog();
  dog.eat();
  dog.bark();
}
Expected Output
Eating
Woof!

Calling parent behavior with super

class Vehicle {
  void start() {
    print('Vehicle started');
  }
}

class Car extends Vehicle {
  @override
  void start() {
    super.start();
    print('Car is ready to drive');
  }
}
When to use it: use extends when you can honestly say “a dog is an animal” or “a car is a vehicle.” Do not use it just to avoid writing a few lines twice.
COMMON MISTAKE

extends does not mean “reuse any code.” If two classes only share one small action, a mixin may be a better fit.

STEP 7 · POLYMORPHISM

Overriding & polymorphism

A child class can replace an action it inherited. This lets one function work with different kinds of Animal; each animal still makes its own sound.

class Animal {
  void makeSound() {
    print('Some sound');
  }
}

class Dog extends Animal {
  @override
  void makeSound() {
    print('Woof!');
  }
}

class Cat extends Animal {
  @override
  void makeSound() {
    print('Meow!');
  }
}

void playSound(Animal animal) {
  animal.makeSound();
}

void main() {
  playSound(Dog());
  playSound(Cat());
}
Expected Output
Woof!
Meow!

playSound only needs to know that it got an Animal. It can receive a Dog or a Cat, and Dart runs that object's own makeSound method.

Quick check

Why does playSound(Dog()) call the dog's implementation?

Correct. The function accepts an Animal, but the real object is a Dog, so the dog's version runs.
REMEMBER

Overriding means replacing an inherited method. Polymorphism is the longer name for letting one function work with different related objects.

STEP 8 · ABSTRACTION

Abstract classes

An abstract class is a starting template. You cannot make one directly, but other classes can build on it.

abstract class Shape {
  double area();

  void describe() {
    print('I am a shape.');
  }
}

class Circle extends Shape {
  final double radius;

  Circle(this.radius);

  @override
  double area() => 3.14159 * radius * radius;
}

void main() {
  final shape = Circle(2);
  shape.describe();
  print(shape.area());
}
Expected Output
I am a shape.
12.56636

What is abstract here?

  • You cannot write Shape() directly.
  • area() says every shape needs an area, but it does not say how to calculate it.
  • Circle fills in that missing calculation.
Two similar words: abstraction means showing the useful actions, such as area(). Encapsulation means protecting data, such as a bank balance.
COMMON MISTAKE

An abstract class is not about private fields. It is a way to say, “every class of this kind must provide these actions.”

STEP 9 · INTERFACES

extends vs implements

implements is a promise: “my class will provide these methods.” Unlike extends, it does not copy the other class's method code.

abstract class PaymentMethod {
  void pay(double amount);
}

class UpiPayment implements PaymentMethod {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using UPI');
  }
}

class CardPayment implements PaymentMethod {
  @override
  void pay(double amount) {
    print('Paid ₹$amount using card');
  }
}

void processPayment(PaymentMethod method) {
  method.pay(500);
}
KeywordMain ideaWhat the child gets
extends“This is a kind of that.”It gets the parent class's code and can change parts of it.
implements“I promise to provide these methods.”It writes the promised methods itself.
with“Add this small extra ability.”It gets the mixin's ready-made methods.
Easy way to remember: extends reuses a parent class, implements makes a promise you must write yourself, and with adds a small ready-made ability.

Quick check

What must UpiPayment do when it implements PaymentMethod?

Correct. implements means UpiPayment must write the methods it promised to provide.
STEP 10 · COMPOSITION

Mixins with with

A mixin is a small bundle of ready-made methods. Use with to add that bundle to a class without making it a child of another class.

mixin Logger {
  void log(String message) {
    print('[LOG] $message');
  }
}

mixin JsonSupport {
  Map<String, dynamic> toJson() =>
      {'type': runtimeType.toString()};
}

class User with Logger, JsonSupport {
  final String name;

  User(this.name);

  void save() {
    log('Saving $name');
  }
}

void main() {
  final user = User('Asha');
  user.save();
  print(user.toJson());
}
Expected Output
[LOG] Saving Asha
{type: User}

The User class gets both log and toJson from the mixins. It is not a kind of logger or JSON helper; it simply gains those useful methods.

Inheritance

Use it for a real “is a” relationship, such as Dog extends Animal.

Mixin

Use it to add one small ability, such as logging.

GOOD PRACTICE

Keep a mixin small and focused. A Logger mixin is easy to understand; one giant mixin with dozens of unrelated methods is not.

STEP 11 · DART TOOLBOX

static, factory & extensions

These are three useful extras. They help you put a helper on a class, choose how an object is made, or add a small helper to an existing type.

Static members

A static member belongs to the class itself. You use it with the class name, so you do not need to make an object first.

class MathTools {
  static const double pi = 3.14159;

  static double square(double value) => value * value;
}

void main() {
  print(MathTools.square(4));
  print(MathTools.pi);
}
Expected Output
16.0
3.14159

Factory constructors

A factory constructor can check input and decide what object to return. It can return a new object, or reuse one that already exists.

class UserId {
  final String value;

  UserId._(this.value);

  factory UserId.fromInput(String input) {
    final cleaned = input.trim();
    if (cleaned.isEmpty) {
      throw ArgumentError('A user ID is required.');
    }
    return UserId._(cleaned.toLowerCase());
  }
}

void main() {
  final userId = UserId.fromInput('  ASHA_42 ');
  print(userId.value);
}
Expected Output
asha_42

Extension methods

An extension adds a small helper to a type you already use. Here it lets any double format itself as rupees. Keep extensions small and clearly named.

extension PriceLabel on double {
  String asRupees() => '₹${toStringAsFixed(2)}';
}

void main() {
  final price = 2499.0;
  print(price.asRupees());
}
Expected Output
₹2499.00
WHICH ONE?

Use static for a helper that needs no object, factory when creation needs a decision or check, and an extension for a small extra helper on an existing type.

STEP 12 · PUT IT TOGETHER

A small OOP system

This example brings the ideas together. Read it slowly: notice what each class stores, what it can do, and which code it shares.

mixin Auditable {
  void audit(String message) {
    print('[AUDIT] $message');
  }
}

abstract class Employee {
  final String name;
  double _salary;

  Employee({
    required this.name,
    required double salary,
  }) : _salary = salary;

  double get salary => _salary;

  void work();

  void giveRaise(double amount) {
    if (amount > 0) _salary += amount;
  }
}

class Developer extends Employee with Auditable {
  Developer({
    required super.name,
    required super.salary,
  });

  @override
  void work() {
    audit('$name is writing Dart code');
  }
}

class Teacher extends Employee {
  Teacher({
    required super.name,
    required super.salary,
  });

  @override
  void work() {
    print('$name is teaching a class');
  }
}

void runWorkday(List<Employee> employees) {
  for (final employee in employees) {
    employee.work();
  }
}

void main() {
  final employees = <Employee>[
    Developer(name: 'Asha', salary: 60000),
    Teacher(name: 'Rahul', salary: 55000),
  ];

  runWorkday(employees);
  employees[0].giveRaise(5000);
  print(employees[0].salary);
}
Expected Output
[AUDIT] Asha is writing Dart code
Rahul is teaching a class
65000.0
Shared starting point

Employee says that every employee must have a work() action.

Protected salary

_salary is read through a getter and changed through giveRaise().

Different employees

Developer and Teacher both build on Employee.

One loop, different results

runWorkday can call work() for every employee, and each one does its own job.

Extra ability

Developer gets the audit method from Auditable.

Starting values

Named parameters give each new employee the values it needs.

DESIGN LESSON

Good OOP is not about making many classes. It is about giving each class a clear, useful job.

STEP 13 · PRACTICE

Final OOP challenge

Build a small library system. First try the steps yourself, then use the sample solution if you need it.

TRY IT · Library management model

  1. Create an abstract LibraryItem class with a required title and a describe() method that every item must provide.
  2. Create Book and Magazine classes that extend LibraryItem.
  3. Let each class print its own description in describe().
  4. Create a Library class that stores a collection of LibraryItem objects.
  5. Use a loop to call describe() for every item, even though the items are different types.
  6. Add one private field and a safe way to read or change it.
  7. Add a small mixin such as Loggable to one class.

Success condition: your program has at least a book and a magazine, and the library can store and describe both.

Planning hint: start with LibraryItem → Book/Magazine. Put shared information, such as the title, in LibraryItem. Put book-only or magazine-only information in its own class.
Reveal one possible solution 
mixin Loggable {
  void log(String message) => print('[LOG] $message');
}

abstract class LibraryItem {
  final String title;

  LibraryItem(this.title);

  void describe();
}

class Book extends LibraryItem with Loggable {
  final String author;

  Book(super.title, this.author);

  @override
  void describe() {
    log('Book: $title by $author');
  }
}

class Magazine extends LibraryItem {
  final int issue;

  Magazine(super.title, this.issue);

  @override
  void describe() {
    print('Magazine: $title, issue $issue');
  }
}

class Library {
  final List<LibraryItem> items = [];

  void add(LibraryItem item) => items.add(item);

  void describeAll() {
    for (final item in items) {
      item.describe();
    }
  }
}

void main() {
  final library = Library();
  library.add(Book('Dart Basics', 'Asha'));
  library.add(Magazine('Tech Monthly', 42));
  library.describeAll();
}

OOP recap & knowledge check

You now have the essential Dart OOP toolkit. The next step is repetition: design small models, read class hierarchies, and practice choosing the simplest useful relationship.

The OOP checklist

1. What is an object?

Correct. A class describes a type; an object is a concrete instance of that type.

2. What does encapsulation help you do?

Correct. Encapsulation controls how an object's state and implementation are exposed.

3. Which keyword composes a mixin into a class?

Correct. A class uses with to compose mixin behavior.

4. What is polymorphism in the example with Animal?

Correct. A common type can represent different concrete implementations.

5. Which statement about implements is correct?

Correct. implements expresses a contract that the class must fulfill.

6. What is the main purpose of a class?

Correct. A class describes the fields and methods that its objects can have.

7. When does Dart provide an implicit unnamed, no-argument constructor?

Correct. Declaring any constructor means you define the available construction paths yourself.

8. In this.name = name, what does this.name mean?

Correct. this refers to the current instance.

9. Why might a constructor use an initializer list after :?

Correct. Initializer lists are especially useful for initializing final fields.

10. What does super.start() do inside an overriding method?

Correct. super accesses the parent class's accessible member implementation.

11. What does the @override annotation communicate?

Correct. It documents your intent and helps the analyzer catch mistakes.

12. Which statement about an abstract class is true?

Correct. An abstract class can provide shared implementation, but you create a concrete subtype instead.

13. What is the key difference between extends and implements?

Correct. Use implements to satisfy a contract, not to inherit its implementation.

14. Which situation is a good use for a mixin?

Correct. A mixin composes cohesive reusable behaviour into a class.

15. What can a factory constructor do?

Correct. A factory controls what object is returned to the caller.

16. A static member belongs to:

Correct. Access a static member through the class name, such as PriceRules.taxRate.

17. What does an extension method let you do?

Correct. Extensions add convenient members without modifying or subclassing the original type.

18. In Dart, an identifier beginning with _ is private to:

Correct. Dart privacy is library-based, not class-based.
