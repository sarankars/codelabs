STEP 1 · START HERE

Asynchronous programming in Dart

Apps often start work now and receive the result later. A server responds, a file finishes loading, or a timer fires. Dart uses Future for one eventual result and Stream for a sequence of results over time.

By the end: You will be able to read and write the asynchronous code used in Flutter apps, handle failures, run independent work together, consume streams, and represent loading, error, and success states.

Why async matters

Imagine tapping “Refresh.” The app should start the request, remain responsive while it waits, and update the screen when data or an error arrives. Asynchronous code gives the waiting a clear structure.

Network

Wait for an API without freezing the rest of the app.

Files & databases

Continue useful work while input or output completes.

Timers

Schedule something to happen after a duration.

Live updates

React to many events such as location, messages, or button taps.

Prerequisites

Variables, types, conditionals, loops, functions, collections, and basic classes in Dart.

Mental model

Start the work, keep the handle Dart returns, and decide what should happen when the work completes.

CORE IDEA

await pauses the current async function; it does not freeze the whole program. Other work can continue while that function waits.

IMPORTANT

Async code helps with waiting, especially input and output. It does not automatically move heavy CPU calculations to another thread. Dart isolates are the separate tool for CPU-heavy parallel work.

STEP 2 · THE DIFFERENCE

Synchronous vs asynchronous work

Synchronous code finishes one instruction before starting the next. Asynchronous code can start an operation, let later code run, and report its result when it is ready.

Synchronous: each call finishes first

void prepareOrder() {
  print('1. Take order');
  print('2. Prepare order');
  print('3. Serve order');
}

void main() {
  prepareOrder();
  print('4. Take next order');
}
Expected Output
1. Take order
2. Prepare order
3. Serve order
4. Take next order

Asynchronous: start, continue, complete

Future<void> prepareOrder() async {
  print('1. Start preparing');
  await Future.delayed(const Duration(seconds: 1));
  print('3. Order ready');
}

Future<void> main() async {
  final order = prepareOrder();
  print('2. Take next order');
  await order;
}
Expected Output
1. Start preparing
2. Take next order
3. Order ready
KindWhat the caller receivesTypical use
SynchronousThe result immediately, or an error is thrown immediately.Calculations and in-memory transformations.
AsynchronousA Future or Stream representing later results.Network, file, database, timer, and event work.

Quick check

What happens while prepareOrder() awaits the delay?

Correct. The awaiting function pauses, but the program can continue other work.
STEP 3 · ONE LATER VALUE

Future: a result that arrives later

A Future<T> is a handle to one asynchronous result. It eventually completes with a value of type T or with an error.

Uncompleted

The operation is still running or waiting. Its value is not available yet.

Completed with a value

The operation succeeded and produced its T value.

Completed with an error

The operation failed. The error travels through the future.

Completed once

A future produces one completion. Use a stream when results keep arriving.

Read the return type

Future<String> → one String later
Future<List<Product>> → one list later
Future<void> → completes later without a useful value
Future<String> fetchUsername() {
  return Future.delayed(
    const Duration(seconds: 1),
    () => 'Asha',
  );
}

Future<void> main() async {
  final Future<String> usernameLater = fetchUsername();
  print('Request started');

  final String username = await usernameLater;
  print('Hello, $username!');
}
Expected Output
Request started
Hello, Asha!
COMMON MISTAKE

A Future<String> is not a String. It represents the string that may become available later. Use await or a future callback to access the completed value.

STEP 4 · CREATE & CONSUME

Creating and consuming futures

Most of the time, an API gives you a future. For learning and testing, Dart can also create an already-completed future or one that completes after a delay.

Three common creation patterns

Future<int> cachedScore() => Future.value(95);

Future<String> delayedMessage() {
  return Future.delayed(
    const Duration(milliseconds: 500),
    () => 'Ready',
  );
}

Future<String> failedRequest() {
  return Future.error(Exception('No connection'));
}

Consume with then()

then() registers a callback that runs after the future completes successfully. Returning from one callback passes a value to the next callback.

Future<String> fetchCity() {
  return Future.delayed(
    const Duration(milliseconds: 500),
    () => 'Pune',
  );
}

void main() {
  print('Looking up city...');

  fetchCity()
      .then((city) => city.toUpperCase())
      .then((city) => print('City: $city'));
}
Expected Output
Looking up city...
City: PUNE
Default choice: prefer async/await for multi-step application logic because it is usually easier to read. The Future API remains useful when transforming or forwarding a future directly.
DON'T LOSE THE FUTURE

If completion matters, return or await the future. Starting async work and silently ignoring its future makes errors and completion timing harder to control.

STEP 5 · ASYNC & AWAIT

Write async code in reading order

async marks a function that returns a future. Inside it, await pauses that function until another future completes.

Future<ResultType> functionName() async {
  final value = await someFuture();
  return result;
}
Future<String> fetchUserId() async {
  await Future.delayed(const Duration(milliseconds: 300));
  return 'user-42';
}

Future<String> fetchGreeting(String userId) async {
  await Future.delayed(const Duration(milliseconds: 300));
  return 'Welcome back, $userId';
}

Future<void> main() async {
  print('Loading...');
  final userId = await fetchUserId();
  final greeting = await fetchGreeting(userId);
  print(greeting);
}
Expected Output
Loading...
Welcome back, user-42
async

Changes the function's result into a future and allows await in its body.

await

Waits for one future's completion and gives you its value, or throws its error.

Before the first await

An async function runs synchronously until it reaches its first await.

After completion

The function resumes from the paused point and continues in normal reading order.

Quick check

Why does fetchGreeting run after fetchUserId finishes?

Correct. The second operation depends on the first result, so sequential awaits are appropriate.
COMMON MISTAKE

await can only appear inside an async or async* function. Also give async functions honest return types such as Future<void>, not void, when callers need to track completion.

STEP 6 · FAILURES

Handle asynchronous errors

An awaited future error behaves like a thrown exception at the await expression. Use try, catch, and finally to keep failure and cleanup paths clear.

Future<String> loadProfile() async {
  await Future.delayed(const Duration(milliseconds: 400));
  throw Exception('Server unavailable');
}

Future<void> main() async {
  print('Show loading indicator');

  try {
    final profile = await loadProfile();
    print('Profile: $profile');
  } catch (error, stackTrace) {
    print('Could not load profile: $error');
    print('A stack trace is available for logging.');
  } finally {
    print('Hide loading indicator');
  }
}
Expected Output
Show loading indicator
Could not load profile: Exception: Server unavailable
A stack trace is available for logging.
Hide loading indicator
try

Contains the awaited work that might fail.

catch

Receives the error and optionally its stack trace.

finally

Runs after success or failure, which makes it useful for cleanup.

Rethrow

Use rethrow after logging when a higher layer should still handle the error.

The Future API equivalent

Future<void> main() async {
  final name = await loadProfile()
      .then((profile) => profile.toUpperCase())
      .catchError((Object error) {
        print('Using a fallback: $error');
        return 'Guest';
      });

  print(name);
}
ERROR BOUNDARY

Catch an error where you can make a useful decision: retry, show a message, use a safe fallback, or add context and rethrow. Avoid empty catch blocks that make failures invisible.

STEP 7 · WORK TOGETHER

Run independent futures together

If two operations do not depend on each other, start both before waiting. Future.wait provides one future that completes when every input future completes.

Sequential waits

final user = await fetchUser();
final settings = await fetchSettings();

The second operation starts only after the first completes. That is correct if it depends on the first result, but it adds unnecessary waiting when both are independent.

Start both, then wait for both

Future<String> fetchUser() async {
  await Future.delayed(const Duration(milliseconds: 600));
  return 'Asha';
}

Future<String> fetchSettings() async {
  await Future.delayed(const Duration(milliseconds: 400));
  return 'dark mode';
}

Future<void> main() async {
  final results = await Future.wait([
    fetchUser(),
    fetchSettings(),
  ]);

  print('User: ${results[0]}');
  print('Settings: ${results[1]}');
}
Expected Output
User: Asha
Settings: dark mode
Three facts about Future.wait:
  • The operations run independently after you start them.
  • The result list keeps the same order as the input futures, even if they finish in another order.
  • If an input future fails, the combined future completes with an error; handle it with try/catch.

Quick check

When should two calls usually be awaited sequentially?

Correct. A data dependency requires ordering; independent work can usually start together.
BE PRECISE

“Concurrent” here means the waits can overlap. It does not mean ordinary Dart code is automatically executing CPU instructions in parallel.

STEP 8 · MANY LATER VALUES

Stream: values over time

A Future completes once. A Stream<T> can deliver zero, one, or many values of type T, plus error events, before it closes.

TypeCompletionsExamples
Future<T>One value or one errorOne HTTP response, one file read, one save operation
Stream<T>Many data or error events, then doneChat messages, location changes, download progress, button events

Consume with await for

Stream<int> progressUpdates() {
  return Stream<int>.periodic(
    const Duration(milliseconds: 300),
    (index) => (index + 1) * 25,
  ).take(4);
}

Future<void> main() async {
  await for (final percent in progressUpdates()) {
    print('Downloaded $percent%');
  }
  print('Done');
}
Expected Output
Downloaded 25%
Downloaded 50%
Downloaded 75%
Downloaded 100%
Done
Single-subscription stream

One listener consumes the ordered sequence. File data commonly has this shape.

Broadcast stream

Multiple listeners can receive events emitted while they are listening. UI events commonly have this shape.

CHOOSE WELL

If you need one answer, return a future. If updates keep arriving, expose a stream. Do not use a stream merely because an operation is asynchronous.

STEP 9 · LISTEN & CONTROL

Listen to streams and handle errors

listen() gives callbacks for data, errors, and completion. It also returns a StreamSubscription that can pause, resume, or cancel delivery.

Stream<String> statusUpdates() async* {
  yield 'Connecting';
  await Future.delayed(const Duration(milliseconds: 300));
  yield 'Connected';
  await Future.delayed(const Duration(milliseconds: 300));
  throw Exception('Connection lost');
}

void main() {
  statusUpdates().listen(
    (status) => print('Status: $status'),
    onError: (Object error) => print('Error: $error'),
    onDone: () => print('Stream closed'),
    cancelOnError: false,
  );
}
Expected Output
Status: Connecting
Status: Connected
Error: Exception: Connection lost
Stream closed

Keep the subscription when lifecycle matters

final subscription = statusUpdates().listen(print);

subscription.pause();
subscription.resume();
await subscription.cancel();

In a Flutter object with a lifecycle, store subscriptions that outlive one function and cancel them when that object is disposed.

Errors with await for

Future<void> watchStatuses() async {
  try {
    await for (final status in statusUpdates()) {
      print(status);
    }
  } catch (error) {
    print('Stopped after: $error');
  }
}
LIFECYCLE RULE

Cancel a subscription when its listener should stop receiving updates. This prevents stale work and unwanted callbacks after a screen or controller is gone.

STEP 10 · GENERATORS

Create streams with async*

An asynchronous generator is a function marked async*. It returns a stream and emits values one at a time with yield.

Stream<T> generateValues() async* {
  yield firstValue;
  await somethingLater();
  yield nextValue;
}
Stream<int> countdown(int from) async* {
  for (var value = from; value >= 1; value--) {
    await Future.delayed(const Duration(milliseconds: 300));
    yield value;
  }
}

Future<void> main() async {
  await for (final value in countdown(3)) {
    print(value);
  }
  print('Go!');
}
Expected Output
3
2
1
Go!

yield and yield*

yield value

Emits one data event, then the generator continues when the listener is ready.

yield* stream

Forwards every event from another compatible stream.

Stream<int> twoCountdowns() async* {
  yield* countdown(3);
  yield* countdown(2);
}
Lazy start: an async* generator begins producing events when the returned stream is listened to. When the function returns, its stream closes.
INTRODUCTION, NOT A RULE

Use async* when values naturally come from one sequential asynchronous process. When events arrive from unrelated callbacks or sources, a stream controller or an existing API may be a better source.

STEP 11 · APP STATE

Loading, error & success states

A screen waiting for data should represent its current state explicitly. That prevents old data, spinners, and errors from becoming a pile of unrelated booleans.

enum LoadPhase { idle, loading, success, failure }

class LoadState<T> {
  final LoadPhase phase;
  final T? data;
  final Object? error;

  const LoadState._(this.phase, {this.data, this.error});

  const LoadState.idle() : this._(LoadPhase.idle);
  const LoadState.loading() : this._(LoadPhase.loading);
  const LoadState.success(T value)
      : this._(LoadPhase.success, data: value);
  const LoadState.failure(Object cause)
      : this._(LoadPhase.failure, error: cause);
}

Future<List<String>> fetchProducts() async {
  await Future.delayed(const Duration(milliseconds: 500));
  return ['Keyboard', 'Mouse', 'Monitor'];
}

Move through the states

Future<void> loadProducts() async {
  LoadState<List<String>> state =
      const LoadState.loading();
  print(state.phase);

  try {
    final products = await fetchProducts();
    state = LoadState.success(products);
    print('${state.phase}: ${state.data}');
  } catch (error) {
    state = LoadState.failure(error);
    print('${state.phase}: ${state.error}');
  }
}

Future<void> main() => loadProducts();
Expected Output
LoadPhase.loading
LoadPhase.success: [Keyboard, Mouse, Monitor]
Loading

Show progress and decide whether repeated actions should be disabled.

Success

Render the completed data, including a deliberate empty-data state.

Failure

Show a useful message and, where appropriate, a retry action.

Latest request wins

In real apps, guard against an older request overwriting newer state after it finishes late.

DESIGN TIP

Keep the async operation and state transitions together in one controller, model, or state-management unit. Let the UI render the state rather than owning networking rules.

STEP 12 · PUT IT TOGETHER

Load once, then consume updates

This small task dashboard combines a future for the initial load, a loading/error/success path, and a stream for later count updates.

Future<List<String>> loadTasks({
  bool shouldFail = false,
}) async {
  await Future.delayed(const Duration(milliseconds: 500));
  if (shouldFail) {
    throw Exception('Could not reach the server');
  }
  return ['Read async lesson', 'Build practice app'];
}

Stream<int> pendingCountUpdates() async* {
  for (final count in [2, 1, 0]) {
    await Future.delayed(const Duration(milliseconds: 300));
    yield count;
  }
}

Future<void> main() async {
  print('State: loading');

  try {
    final tasks = await loadTasks();
    print('State: success — $tasks');

    await for (final count in pendingCountUpdates()) {
      print('Pending tasks: $count');
    }
  } catch (error) {
    print('State: error — $error');
  } finally {
    print('Stopped loading and listening');
  }
}
Expected Output
State: loading
State: success — [Read async lesson, Build practice app]
Pending tasks: 2
Pending tasks: 1
Pending tasks: 0
Stopped loading and listening
Initial snapshot

loadTasks() returns one future because the initial list arrives once.

Ongoing changes

pendingCountUpdates() returns a stream because the count changes repeatedly.

Visible states

The program reports loading, then success or error.

One error boundary

The catch handles failures from the future and the await for loop.

TRY IT · Make the failure visible

  1. Call loadTasks(shouldFail: true).
  2. Predict which output lines will appear.
  3. Add a retry function that calls loadTasks() again.
  4. Make the stream throw after the value 1, then confirm the same catch block handles it.
Reveal the expected failure flow

The program prints State: loading, then the error state, then the finally message. It never starts consuming count updates because the awaited initial load did not succeed.

STEP 13 · FINAL CHECK

Async recap & knowledge check

You now have the foundation for the asynchronous code used throughout Flutter. Check the mental model before moving to the final build.

The async checklist

synchronousasynchronousFuture<T> asyncawaitthencatchError trycatchfinallyFuture.wait Stream<T>await forlisten subscriptionasync*yieldyield*

1. What does a Future<String> represent?

Correct. A future has one eventual completion: a value or an error.

2. Where can you use await?

Correct. The containing function must be asynchronous.

3. What does await pause?

Correct. Other work can continue while the current async function waits.

4. What is finally useful for?

Correct. A finally block runs after either path.

5. When is Future.wait a good fit?

Correct. It combines independent future completions into one future.

6. What does a Stream<int> provide?

Correct. A stream is an asynchronous sequence.

7. What does listen() return?

Correct. The subscription controls the active listening relationship.

8. Why cancel a long-lived stream subscription?

Correct. Cancellation keeps updates aligned with the listener's lifecycle.

9. Which return type matches an async* function?

Correct. An asynchronous generator returns a stream.

10. What does yield do?

Correct. The generator emits one data event and can continue later.

11. Which state should be set before awaiting a network request?

Correct. Loading gives the UI an honest state while it waits.

12. Does async/await automatically make CPU-heavy work parallel?

Correct. Async waiting and parallel CPU execution are different concerns.
