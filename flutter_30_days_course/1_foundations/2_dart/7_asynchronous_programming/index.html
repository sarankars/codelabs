STEP 1 · START HERE

Asynchronous programming in Dart

Apps often start work now and receive the result later. A server responds, a file finishes loading, or a timer fires. Dart uses Future for one eventual result and Stream for a sequence of results over time.

By the end: You will be able to read and write the asynchronous code used in Flutter apps, handle failures, run independent work together, consume streams, and represent loading, error, and success states.

Why async matters

Imagine tapping “Refresh.” The app should start the request, remain responsive while it waits, and update the screen when data or an error arrives. Asynchronous code gives the waiting a clear structure.

Network

Wait for an API without freezing the rest of the app.

Files & databases

Continue useful work while input or output completes.

Timers

Schedule something to happen after a duration.

Live updates

React to many events such as location, messages, or button taps.

Prerequisites

Variables, types, conditionals, loops, functions, collections, and basic classes in Dart.

Mental model

Start the work, keep the handle Dart returns, and decide what should happen when the work completes.

CORE IDEA

await pauses the current async function; it does not freeze the whole program. Other work can continue while that function waits.

BEGINNER NOTE

You do not need to learn threads or the event loop yet. Start with this simple idea: some work finishes now, and some work gives you its result later.

STEP 2 · THE DIFFERENCE

Synchronous vs asynchronous work

Synchronous code finishes one instruction before starting the next. Asynchronous code can start an operation, let later code run, and report its result when it is ready.

Synchronous: each call finishes first

void prepareOrder() {
  print('1. Take order');
  print('2. Prepare order');
  print('3. Serve order');
}

void main() {
  prepareOrder();
  print('4. Take next order');
}
Expected Output
1. Take order
2. Prepare order
3. Serve order
4. Take next order

Before the async example: create a delay

The next example uses two Dart tools to represent cooking time. Learn these pieces first, then the complete example will be easier to read.

Duration

Describes an amount of time. It does not pause anything by itself. For example, Duration(seconds: 1) represents one second.

Future.delayed()

Creates a future that completes after the supplied duration. For now, think of a future as a receipt for work that will finish later.

const cookingTime = Duration(seconds: 1);
final waiting = Future<void>.delayed(cookingTime);
Read it in plain language: cookingTime describes a one-second period. Future.delayed(cookingTime) starts that timer and gives us waiting, which completes after one second. In the next example, await pauses that function until this future completes.

Asynchronous: start, continue, complete

Future<void> prepareOrder() async {
  print('1. Start preparing');
  await Future.delayed(const Duration(seconds: 1));
  print('3. Order ready');
}

Future<void> main() async {
  final order = prepareOrder();
  print('2. Take next order');
  await order;
}
Expected Output
1. Start preparing
2. Take next order
3. Order ready
KindWhat the caller receivesTypical use
SynchronousThe result immediately, or an error is thrown immediately.Calculations and in-memory transformations.
AsynchronousA Future or Stream representing later results.Network, file, database, timer, and event work.

Quick check

What happens while prepareOrder() awaits the delay?

Correct. The awaiting function pauses, but the program can continue other work.
STEP 3 · ONE LATER VALUE

Future: a result that arrives later

A Future<T> is a handle to one asynchronous result. It eventually completes with a value of type T or with an error.

Uncompleted

The operation is still running or waiting. Its value is not available yet.

Completed with a value

The operation succeeded and produced its T value.

Completed with an error

The operation failed. The error travels through the future.

Completed once

A future produces one completion. Use a stream when results keep arriving.

Read the return type

Future<int> → one integer later
Future<String> → one string later
Future<void> → finishes later without returning a value
Future<String> fetchUsername() {
  return Future.delayed(
    const Duration(seconds: 1),
    () => 'Asha',
  );
}

Future<void> main() async {
  final Future<String> usernameLater = fetchUsername();
  print('Request started');

  final String username = await usernameLater;
  print('Hello, $username!');
}
Expected Output
Request started
Hello, Asha!
COMMON MISTAKE

A Future<String> is not a String. It is a promise that a string will arrive later. In the next lessons, you will use then() and await to receive it.

STEP 4 · YOUR FIRST FUTURE

Create and receive a future

Let us use one small function throughout this lesson. It waits for one second, then provides a score.

1. Create the future

Future<int> fetchScore() {
  return Future.delayed(
    const Duration(seconds: 1),
    () => 95,
  );
}
Read it one line at a time:
  1. Future<int> says the function will provide one integer later.
  2. Duration(seconds: 1) describes how long to wait.
  3. () => 95 supplies the value when the delay finishes.

2. Receive it with then()

then() means “run this function when the future succeeds.” The parameter named score receives the completed value.

Future<int> fetchScore() {
  return Future.delayed(
    const Duration(seconds: 1),
    () => 95,
  );
}

void main() {
  print('Fetching score...');
  fetchScore().then((score) {
    print('Score: $score');
  });
}
Expected Output
Fetching score...
Score: 95
About Future.value(95): it creates a future whose value is already available. It adds no timer or intentional delay. Beginners can usually return a value from an async function instead, so we will not use Future.value() in the main examples.
NEXT

then() works, but nested callbacks can become hard to read. The next lesson introduces async and await, which make the same idea read from top to bottom.

STEP 5 · ASYNC & AWAIT

Make future code easier to read

async lets a function use await. await pauses that function until a future finishes and gives you its value.

Future<int> fetchScore() async {
  await Future.delayed(const Duration(seconds: 1));
  return 95;
}

Future<void> main() async {
  print('Fetching score...');
  final score = await fetchScore();
  print('Score: $score');
}
Expected Output
Fetching score...
Score: 95
Read it one line at a time:
  1. main() async allows main to use await.
  2. fetchScore() starts the delayed work.
  3. await pauses main until the score arrives.
  4. The completed integer is stored in score.

Quick check

What value is stored in score?

Correct. await unwraps the completed future value, so score is an integer.
REMEMBER

Put async on the function. Put await before the future you want to wait for.

STEP 6 · FAILURES

What if the future fails?

A future can finish with a value or an error. Put an awaited call inside try and use catch to show what should happen when it fails.

Future<int> fetchScore() async {
  await Future.delayed(const Duration(seconds: 1));
  throw Exception('Could not load score');
}

Future<void> main() async {
  print('Loading...');
  try {
    final score = await fetchScore();
    print('Score: $score');
  } catch (error) {
    print('Something went wrong: $error');
  } finally {
    print('Finished');
  }
}
Expected Output
Loading...
Something went wrong: Exception: Could not load score
Finished
Three simple jobs:
  • try: run the code that might fail.
  • catch: respond if it fails.
  • finally: run one last action after success or failure.
TRY IT

Replace the throw line with return 95;. Now the try block succeeds, catch is skipped, and finally still prints Finished.

STEP 7 · TWO TASKS

Wait for two futures together

Sometimes a page needs two separate pieces of data. If neither one needs the other's result, Future.wait can start both and wait until both are ready.

Sequential waits

final user = await fetchUser();
final settings = await fetchSettings();

Here, fetchSettings() starts only after fetchUser() finishes.

Use Future.wait

Future<String> fetchUser() async {
  await Future.delayed(const Duration(seconds: 1));
  return 'Asha';
}

Future<String> fetchSettings() async {
  await Future.delayed(const Duration(seconds: 1));
  return 'dark mode';
}

Future<void> main() async {
  final results = await Future.wait([
    fetchUser(),
    fetchSettings(),
  ]);

  print('User: ${results[0]}');
  print('Settings: ${results[1]}');
}
Expected Output
User: Asha
Settings: dark mode
Read it step by step:
  1. fetchUser() and fetchSettings() both start.
  2. await waits until both futures finish.
  3. results[0] belongs to the first future in the list.
  4. results[1] belongs to the second future.

Quick check

When should two calls usually be awaited sequentially?

Correct. A data dependency requires ordering; independent work can usually start together.
SIMPLE RULE

If task B needs the result from task A, await them one after another. If they are unrelated, you can use Future.wait.

STEP 8 · MANY LATER VALUES

Stream: values over time

A future gives you one result. A stream can give you several results, one after another.

TypeThink of it asExample
Future<int>One package delivered laterOne score: 95
Stream<int>Several packages delivered over timeProgress: 25, 50, 75, 100

Read each value with await for

Stream.fromIterable() turns a list into a simple stream. await for runs once for every value.

Stream<int> progressUpdates() {
  return Stream.fromIterable([25, 50, 75, 100]);
}

Future<void> main() async {
  await for (final percent in progressUpdates()) {
    print('Downloaded $percent%');
  }
  print('Done');
}
Expected Output
Downloaded 25%
Downloaded 50%
Downloaded 75%
Downloaded 100%
Done
Read it step by step:
  1. The stream provides 25.
  2. The loop prints it and waits for the next value.
  3. The same thing happens for 50, 75, and 100.
  4. When there are no more values, the loop ends and prints Done.
REMEMBER

Use a future for one result. Use a stream when several updates can arrive.

STEP 9 · LISTEN

Listen to a stream

listen() is another way to receive stream values. You give it a small function that runs whenever a value arrives.

Stream<String> statusUpdates() {
  return Stream.fromIterable([
    'Preparing',
    'Cooking',
    'Ready',
  ]);
}

void main() {
  statusUpdates().listen(
    (status) => print('Status: $status'),
    onDone: () => print('Stream closed'),
  );
}
Expected Output
Status: Preparing
Status: Cooking
Status: Ready
Stream closed
First function

(status) => ... runs for every value.

onDone

Runs once when the stream has no more values.

Handle a stream error

Add onError when a stream might fail. This example creates an error stream only to demonstrate the callback.

void main() {
  final updates = Stream<int>.error(
    Exception('No connection'),
  );

  updates.listen(
    (value) => print(value),
    onError: (error) => print('Error: $error'),
  );
}
Expected Output
Error: Exception: No connection
FOR NOW

Focus on three ideas: a value arrives, an error happens, or the stream finishes. Subscription pause and cancel controls can wait until you build a real Flutter screen.

STEP 10 · GENERATORS

Your first async* stream

async* marks a function that creates a stream. Inside it, yield sends one value to the listener.

Stream<int> countdown(int from) async* {
  for (var value = from; value >= 1; value--) {
    await Future.delayed(const Duration(seconds: 1));
    yield value;
  }
}

Future<void> main() async {
  await for (final value in countdown(3)) {
    print(value);
  }
  print('Go!');
}
Expected Output
3
2
1
Go!
Only three new pieces:
  1. Stream<int>: this function provides several integers.
  2. async*: this function is an asynchronous stream generator.
  3. yield value: send one value into the stream.
DO NOT OVERTHINK IT

For this course, remember: async creates a future-producing function, while async* creates a stream-producing function.

STEP 11 · APP STATE

Loading, error & success states

While a screen waits for data, the user should know what is happening. Start with three simple states: loading, success, and error.

Future<List<String>> fetchProducts() async {
  await Future.delayed(const Duration(seconds: 1));
  return ['Keyboard', 'Mouse'];
}

Future<void> loadProducts() async {
  print('Loading...');
  try {
    final products = await fetchProducts();
    print('Success: $products');
  } catch (error) {
    print('Error: $error');
  }
}

Future<void> main() => loadProducts();
Expected Output
Loading...
Success: [Keyboard, Mouse]
Loading

Show a spinner or the words “Loading...” while waiting.

Success

Show the data when the future returns successfully.

Error

Show a friendly message if the future throws an error.

FLUTTER CONNECTION

Later, these three print statements can become three UI views: a progress indicator, the product list, or an error message.

STEP 12 · PUT IT TOGETHER

Practice: load data and read updates

This final example combines one future with one small stream. Notice that each part uses syntax you have already learned.

Future<String> loadOrder() async {
  await Future.delayed(const Duration(seconds: 1));
  return 'Veg burger';
}

Stream<String> orderUpdates() async* {
  yield 'Preparing';
  yield 'Cooking';
  yield 'Ready';
}

Future<void> main() async {
  print('Loading order...');
  try {
    final order = await loadOrder();
    print('Order: $order');

    await for (final status in orderUpdates()) {
      print('Status: $status');
    }
  } catch (error) {
    print('Error: $error');
  }
}
Expected Output
Loading order...
Order: Veg burger
Status: Preparing
Status: Cooking
Status: Ready
One order

loadOrder() returns a future because the order name arrives once.

Several statuses

orderUpdates() returns a stream because several status values arrive.

TRY IT · Small changes

  1. Change the order name.
  2. Add a fourth status named Delivered.
  3. Replace return 'Veg burger'; with an exception and observe the error output.

Async recap & knowledge check

The async checklist

synchronousasynchronousFuture<T> asyncawaitthen trycatchfinallyFuture.wait Stream<T>await forlisten async*yield

1. What does a Future<String> represent?

Correct. A future has one eventual completion: a value or an error.

2. Where can you use await?

Correct. The containing function must be asynchronous.

3. What does await pause?

Correct. Other work can continue while the current async function waits.

4. What is finally useful for?

Correct. A finally block runs after either path.

5. When is Future.wait a good fit?

Correct. It combines independent future completions into one future.

6. What does a Stream<int> provide?

Correct. A stream can provide several values, one after another.

7. Which return type matches an async* function?

Correct. An asynchronous generator returns a stream.

8. What does yield do?

Correct. The generator emits one data event and can continue later.

Correct. Loading gives the UI an honest state while it waits.
