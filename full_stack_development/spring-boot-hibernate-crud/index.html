STEP 1 · OVERVIEW

What We Will Build

Build a complete, production-pattern Student CRUD REST API using Spring Boot, Hibernate (via Spring Data JPA), and an embedded in-memory H2 database with zero complex database installation.

Goal: Transform a simple in-memory Student List into a real ORM-backed database application where Hibernate generates tables, executes queries, manages transactions, and handles data persistence automatically.

Why Hibernate Over a Plain In-Memory ArrayList?

Feature Plain ArrayList CRUD Hibernate + JPA CRUD
Data Storage Hardcoded List<Student> in memory. Lost upon restart. Relational database table (STUDENTS) mapped via ORM.
Data Queries Manual Java loops (for (Student s : students)). Automatic SQL generation via JpaRepository and Hibernate.
ID Generation Manual integer counters (nextId++). Database auto-increment identity via @GeneratedValue.
Scalability Cannot scale across multiple server instances or threads safely. Database transactions, connection pooling, and multi-user concurrency.

The REST API Endpoints We Will Build

Method URL Action Hibernate Operation
GET /api/students Return list of all students SELECT * FROM students
GET /api/students/{id} Return single student by ID SELECT * FROM students WHERE id = ?
POST /api/students Create a new student INSERT INTO students ...
PUT /api/students/{id} Update an existing student UPDATE students SET ... WHERE id = ?
DELETE /api/students/{id} Delete student by ID DELETE FROM students WHERE id = ?
GET /h2-console Interactive visual web console View database tables & run SQL live
Architecture Overview:

HTTP Request → StudentController (REST layer) → StudentRepository (Spring Data JPA) → Hibernate ORM (Entity Manager & SQL generation) → H2 Database (In-memory storage).

STEP 6 · ENTITY MAPPING

Create the Student Entity

An entity is a plain Java class annotated with @Entity. Hibernate maps each instance of this class to a row in the database table.

Create a package named entity inside com.example.studentcrudhibernate and create a file named Student.java.

package com.example.studentcrudhibernate.entity;

import jakarta.persistence.*;

@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false)
    private String name;

    @Column(name = "email", nullable = false, unique = true)
    private String email;

    @Column(name = "course")
    private String course;

    // 1. Default No-Argument Constructor (Required by Hibernate for reflection)
    public Student() {
    }

    // 2. Parameterized Constructor (Convenient for creating objects)
    public Student(String name, String email, String course) {
        this.name = name;
        this.email = email;
        this.course = course;
    }

    // 3. Getters and Setters
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getEmail() {
        return email;
    }

    public void setEmail(String email) {
        this.email = email;
    }

    public String getCourse() {
        return course;
    }

    public void setCourse(String course) {
        this.course = course;
    }
}

Essential Hibernate Annotations Explained

Annotation Purpose in Hibernate
@Entity Tells Hibernate that this class represents a database table. Hibernate manages its lifecycle.
@Table(name = "students") Specifies the exact table name in the relational database.
@Id Designates this field as the primary key of the table.
@GeneratedValue(strategy = IDENTITY) Tells the database to automatically generate and increment primary key values (1, 2, 3...).
@Column(nullable = false) Maps field to column and configures constraints like NOT NULL and UNIQUE.
Why is the no-argument constructor mandatory?

When Hibernate loads records from the database, it uses Java Reflection to instantiate the object first using the default Student() constructor, and then sets field values. Without this constructor, Hibernate throws an InstantiationException.

STEP 7 · DATA ACCESS LAYER

Create the StudentRepository

Spring Data JPA provides JpaRepository, which handles all SQL queries and Hibernate session transactions under the hood with zero boilerplate code.

Create a package named repository inside com.example.studentcrudhibernate and create an interface named StudentRepository.java. 

package com.example.studentcrudhibernate.repository;

import com.example.studentcrudhibernate.entity.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;

@Repository
public interface StudentRepository extends JpaRepository<Student, Long> {
    // That's it! No code or SQL needed inside this interface.
}

What JpaRepository Gives You for Free

By extending JpaRepository<Student, Long>, Hibernate dynamically implements this interface with complete CRUD capabilities:

Method Return Type SQL Generated by Hibernate
findAll() List<Student> SELECT * FROM students;
findById(Long id) Optional<Student> SELECT * FROM students WHERE id = ?;
save(Student s) Student INSERT (if new) or UPDATE (if existing).
deleteById(Long id) void DELETE FROM students WHERE id = ?;
existsById(Long id) boolean SELECT count(*) > 0 FROM students WHERE id = ?;
The Magic: You write zero SQL queries. Hibernate inspects the entity, generates the correct dialect-specific SQL, runs it against H2, maps the result set into Student objects, and returns them as a List<Student>!

↓

↓
studentRepository.save(student)
↓
Hibernate executes: INSERT INTO students (name, email, course) VALUES (?, ?, ?)
↓
Database assigns new ID (e.g., 1)
↓
Returns saved Student with ID → 201 CREATED

2. PUT: Update an Existing Student

    // PUT /api/students/{id} - Updates an existing student
    @PutMapping("/{id}")
    public ResponseEntity<Student> updateStudent(@PathVariable Long id, @RequestBody Student studentDetails) {
        return studentRepository.findById(id)
                .map(existingStudent -> {
                    // Update field values
                    existingStudent.setName(studentDetails.getName());
                    existingStudent.setEmail(studentDetails.getEmail());
                    existingStudent.setCourse(studentDetails.getCourse());

                    // Hibernate detects changes and runs SQL UPDATE
                    Student updatedStudent = studentRepository.save(existingStudent);
                    return ResponseEntity.ok(updatedStudent);
                })
                .orElse(ResponseEntity.notFound().build());
    }
Hibernate Dirty Checking: When an entity is loaded from the database into the Session/EntityManager, Hibernate tracks any changes to its fields. Calling save() causes Hibernate to execute an UPDATE statement containing the modified columns.

STEP 12 · COMPLETE CODE

Full StudentController.java

Review the complete controller file. Ensure your file matches this code exactly. 

package com.example.studentcrudhibernate.controller;

import com.example.studentcrudhibernate.entity.Student;
import com.example.studentcrudhibernate.repository.StudentRepository;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/students")
public class StudentController {

    private final StudentRepository studentRepository;

    public StudentController(StudentRepository studentRepository) {
        this.studentRepository = studentRepository;
    }

    // 1. GET ALL
    @GetMapping
    public List<Student> getAllStudents() {
        return studentRepository.findAll();
    }

    // 2. GET BY ID
    @GetMapping("/{id}")
    public ResponseEntity<Student> getStudentById(@PathVariable Long id) {
        return studentRepository.findById(id)
                .map(student -> ResponseEntity.ok(student))
                .orElse(ResponseEntity.notFound().build());
    }

    // 3. POST (CREATE)
    @PostMapping
    public ResponseEntity<Student> createStudent(@RequestBody Student student) {
        Student savedStudent = studentRepository.save(student);
        return new ResponseEntity<>(savedStudent, HttpStatus.CREATED);
    }

    // 4. PUT (UPDATE)
    @PutMapping("/{id}")
    public ResponseEntity<Student> updateStudent(@PathVariable Long id, @RequestBody Student studentDetails) {
        return studentRepository.findById(id)
                .map(existingStudent -> {
                    existingStudent.setName(studentDetails.getName());
                    existingStudent.setEmail(studentDetails.getEmail());
                    existingStudent.setCourse(studentDetails.getCourse());
                    Student updated = studentRepository.save(existingStudent);
                    return ResponseEntity.ok(updated);
                })
                .orElse(ResponseEntity.notFound().build());
    }

    // 5. DELETE
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteStudent(@PathVariable Long id) {
        if (!studentRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }
        studentRepository.deleteById(id);
        return ResponseEntity.noContent().build();
    }
}

STEP 16 · DEEP DIVE

Hibernate Entity Lifecycle in Action

Understand how an entity moves through Hibernate's four states during our CRUD requests.

The 4 Entity States in Our Student CRUD

State When It Happens in Our App Database / Session Status
1. Transient @RequestBody Student student arrives as JSON and is instantiated via new Student(). Has no database ID yet. Not associated with Hibernate Session.
2. Persistent After studentRepository.save(student) or findById() is called. Managed by Hibernate Session. Has an assigned primary key. Any field changes are tracked automatically.
3. Detached When the HTTP request finishes and transaction commits. Object is sent as JSON. Has a database ID, but Session is closed. Hibernate is no longer tracking changes.
4. Removed When studentRepository.deleteById(id) is executed. Marked for deletion. Removed from database upon transaction commit.

Complete Request Flow Architecture

[Client / Postman]
    │ (HTTP JSON Request)
    ▼
[StudentController]
    │ (Entity Object)
    ▼
[StudentRepository (JpaRepository)]
    │ (Method Calls: findAll, save, delete)
    ▼
[Hibernate ORM Engine (Session / EntityManager)]
    │ (Generates & Executes SQL Queries)
    ▼
[H2 In-Memory Relational Database (STUDENTS Table)]

Frequently Asked Questions

How do I switch from H2 to MySQL?
Just swap two things:
  1. In pom.xml, replace the h2 dependency with mysql-connector-j.
  2. In application.properties, set: 
    spring.datasource.url=jdbc:mysql://localhost:3306/student_db
spring.datasource.username=root
spring.datasource.password=yourpassword
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
Zero changes to your Student.java, StudentRepository.java, or StudentController.java code are needed!
What is the difference between save() for new vs. existing entities?
When you pass an entity with id == null, Hibernate recognizes it as new and executes an INSERT INTO statement. When the entity has an existing non-null id that already exists in the database, Hibernate executes an UPDATE statement.
Why use ResponseEntity instead of returning raw Student objects?
ResponseEntity lets you control HTTP status codes (such as returning 201 Created on POST, 204 No Content on DELETE, and 404 Not Found when a student ID does not exist).
