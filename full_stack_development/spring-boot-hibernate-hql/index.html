Why Do We Need Hibernate Query Language?

In our previous CRUD codelab, JpaRepository gave us basic operations out of the box:

  • findAll() — Returns every row in the table.
  • findById(id) — Returns one student by primary key ID.
  • save(student) — Persists or updates one student.
  • deleteById(id) — Removes one student by primary key ID.

However, real-world backend applications need answers to questions like:

  • "Find all students enrolled in 'Computer Science'."
  • "Search students whose name contains 'ali' regardless of uppercase or lowercase."
  • "Get a list of distinct available courses without duplicate names."
  • "Count how many students belong to each department for an analytics chart."
  • "Transfer all students from 'Legacy AI' to 'Generative AI' in one single atomic operation."

Hibernate Query Language (HQL) gives us full power to query Java objects directly without binding our application code to any specific database dialect or SQL vendor.

The Core Architecture

[HTTP Client / Postman] │ ▼ (GET /api/students/search/course?course=Computer Science) [StudentController] │ ▼ calls repository method [StudentRepository: @Query("SELECT s FROM Student s WHERE s.course = :course")] │ ▼ (HQL Object Query: refers to Student entity and s.course field) [Hibernate ORM Engine (AST Query Parser & Dialect Translator)] │ ▼ (Translates HQL into native SQL: SELECT s1_0.id, s1_0.name, ... FROM students s1_0 WHERE s1_0.course = ?) [H2 / MySQL / PostgreSQL Relational Database] │ ▼ (Result rows converted back into List<Student> entities) [Response JSON Payload returned to client]

STEP 3 · CORE CONCEPTS

HQL vs. Native SQL: The Rules

Understand the syntax philosophy of Hibernate Query Language before writing queries. The key concept: HQL talks to Java classes, not relational tables.

The Fundamental Difference

Aspect Native SQL Hibernate Query Language (HQL)
Target Database tables and columns (students, first_name) Java Entity classes and fields (Student, name)
Portability Tied to a specific database dialect (MySQL, Oracle, PostgreSQL) Completely database-independent; Hibernate handles the dialect translation
Result Type Raw database rows / Object[] records Strongly-typed Java Entity objects (List<Student>) or custom DTOs
Case Sensitivity Often case-insensitive depending on database OS and engine Keywords (SELECT, FROM) are case-insensitive; Java Entity & field names (Student, course) ARE case-sensitive!

The Anatomy of an HQL Query

SELECT s FROM Student s WHERE s.course = :courseName ORDER BY s.name ASC
  ▲    ▲      ▲     ▲           ▲             ▲              ▲        ▲
  │    │      │     │           │             │              │        │
  │    │      │     │           │             │              │        └─ Order direction
  │    │      │     │           │             │              └─ Entity property 'name'
  │    │      │     │           │             └─ Named parameter placeholder
  │    │      │     │           └─ Entity property 'course'
  │    │      │     └─ Entity alias (mandatory in HQL when projecting)
  │    │      └─ Java Entity Class Name (NOT database table name 'students'!)
  │    └─ Select target: the alias referring to the Student object
  └─ HQL Keyword (case-insensitive)
✅ Valid HQL

SELECT s FROM Student s WHERE s.email = :email

References the Java class Student and property email.

❌ Invalid HQL (Common Pitfall)

SELECT * FROM students WHERE email = :email

students is a table name, not an entity! And * is not valid in HQL.

How Do We Write HQL in Spring Data JPA?

In Spring Boot, we declare repository interface methods annotated with @Query:

@Query("SELECT s FROM Student s WHERE s.course = :course")
List<Student> findStudentsByCourse(@Param("course") String course);

Notice that we omit nativeQuery = true. Because nativeQuery defaults to false, Spring Data JPA feeds the query directly into the Hibernate HQL engine!

STEP 4 · REQUEST 1

Filter by Course with Named Parameters

Implement our first HQL query to retrieve all students belonging to a specified course using secure named parameter binding.

1. Why Named Parameters Over Positional Parameters?

Hibernate supports two types of query parameters:

  • Positional Parameters: WHERE s.course = ?1 (fragile if parameters are reordered).
  • Named Parameters: WHERE s.course = :course with @Param("course") (clear, robust, and self-documenting).

2. Add Method to StudentRepository.java

Open src/main/java/com/example/studentcrudhibernate/repository/StudentRepository.java and add the following HQL method:

package com.example.studentcrudhibernate.repository;

import com.example.studentcrudhibernate.entity.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;

@Repository
public interface StudentRepository extends JpaRepository<Student, Long> {

    // Request 1: HQL Exact Match Filter
    @Query("SELECT s FROM Student s WHERE s.course = :course")
    List<Student> findByCourseHql(@Param("course") String course);

}

3. Expose the Controller Endpoint

Open src/main/java/com/example/studentcrudhibernate/controller/StudentController.java and add the corresponding GET endpoint:

@GetMapping("/search/course")
public ResponseEntity<List<Student>> getStudentsByCourse(@RequestParam String course) {
    List<Student> students = studentRepository.findByCourseHql(course);
    return ResponseEntity.ok(students);
}

4. What Hibernate Executes Under the Hood

When an HTTP request comes in for /api/students/search/course?course=Computer Science, Hibernate parses your HQL string into an Abstract Syntax Tree (AST), maps Student to the students table, and produces this parameterized native SQL:

Hibernate: 
    select
        s1_0.id,
        s1_0.course,
        s1_0.email,
        s1_0.name 
    from
        students s1_0 
    where
        s1_0.course=?
🛡️ Built-in SQL Injection Protection:

Because Hibernate binds :course as a prepared statement parameter (?), user inputs like ' OR 1=1 -- are treated as literal strings and cannot compromise your database!

STEP 5 · REQUEST 2

Search with LIKE and Case Insensitivity

Build a search bar endpoint that matches substrings in student names using HQL's LIKE operator, CONCAT(), and LOWER() functions.

The Challenge with Case-Sensitive Searches

In standard SQL, comparing strings with LIKE '%john%' might fail to find Alice Johnson if the database engine enforces case sensitivity. In HQL, we achieve universal, cross-database case insensitivity by converting both sides to lowercase:

SELECT s FROM Student s WHERE LOWER(s.name) LIKE LOWER(CONCAT('%', :keyword, '%'))

1. Add Search Method to StudentRepository.java

Add this query method to StudentRepository.java:

// Request 2: HQL Substring Search with Case Insensitivity
@Query("SELECT s FROM Student s WHERE LOWER(s.name) LIKE LOWER(CONCAT('%', :keyword, '%'))")
List<Student> searchByNameKeyword(@Param("keyword") String keyword);

2. Add Endpoint to StudentController.java

In StudentController.java, expose the search endpoint:

@GetMapping("/search/name")
public ResponseEntity<List<Student>> searchStudentsByName(@RequestParam String keyword) {
    List<Student> results = studentRepository.searchByNameKeyword(keyword);
    return ResponseEntity.ok(results);
}

3. How CONCAT() Works in HQL

Instead of manually appending % in Java code (e.g., "%" + keyword + "%"), HQL allows you to use the standard CONCAT('%', :keyword, '%') function directly inside the query string. Hibernate translates this to the appropriate SQL string concatenation syntax for your current database (e.g., CONCAT() in MySQL/H2 or || in Oracle/PostgreSQL).

Multi-Condition Filtering (AND & IN Expressions)

Combine logical operators (AND, OR) and list memberships (IN) to build complex filter criteria.

Scenario A: Course AND Email Domain Filter

Imagine finding all students in a particular course who registered with a specific university or organization email domain (e.g., students in Computer Science with domain university.edu).

Scenario B: Finding Students Across Multiple Selected Courses (IN Clause)

Allow the client to pass a list of courses (e.g. ["Computer Science", "Data Science"]) and return students enrolled in any of them.

1. Add Methods to StudentRepository.java

// Request 3A: HQL Multi-Condition (Course + Email Domain)
@Query("SELECT s FROM Student s WHERE s.course = :course AND LOWER(s.email) LIKE LOWER(CONCAT('%@', :domain))")
List<Student> findByCourseAndEmailDomain(
    @Param("course") String course,
    @Param("domain") String domain
);

// Request 3B: HQL IN Clause with a List parameter
@Query("SELECT s FROM Student s WHERE s.course IN :courses")
List<Student> findByCoursesList(@Param("courses") List<String> courses);
💡 How HQL handles Collections:

When you pass a List<String> to :courses in an HQL IN clause, Hibernate automatically expands the list into the appropriate number of SQL placeholders (e.g., IN (?, ?)). You never need to build strings dynamically!

STEP 8 · REQUEST 5

Projections & Custom DTOs in HQL

Improve performance and tailor payloads by selecting only the specific fields you need instead of loading entire entity records.

The Overhead of Fetching Full Entities

When you execute SELECT s FROM Student s, Hibernate fetches all columns (id, name, email, course) and creates managed entity objects inside the Hibernate Persistence Context. If all you need is a dropdown list of distinct course names, this wastes CPU and memory!

Part A: Distinct Single-Field Projection

To get a list of all distinct course offerings:

// Request 5A: Distinct Course Names
@Query("SELECT DISTINCT s.course FROM Student s ORDER BY s.course ASC")
List<String> findDistinctCourses();

Part B: Constructor Expression DTO Projection

HQL has a powerful feature called Constructor Expressions. You can instantiate lightweight Java Data Transfer Objects (DTOs) directly inside the HQL query!

Create a package named com.example.studentcrudhibernate.dto and create StudentSummaryDTO.java:

package com.example.studentcrudhibernate.dto;

public class StudentSummaryDTO {

    private String name;
    private String course;

    // Hibernate requires this constructor matching the HQL SELECT expression!
    public StudentSummaryDTO(String name, String course) {
        this.name = name;
        this.course = course;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String getCourse() { return course; }
    public void setCourse(String course) { this.course = course; }
}

Add Constructor Expression Query to StudentRepository.java

In HQL, use the new operator with the full package name of your DTO:

// Request 5B: HQL DTO Constructor Expression
@Query("SELECT new com.example.studentcrudhibernate.dto.StudentSummaryDTO(s.name, s.course) FROM Student s ORDER BY s.name ASC")
List<StudentSummaryDTO> findStudentSummaries();

Add Endpoints to StudentController.java

@GetMapping("/courses")
public ResponseEntity<List<String>> getDistinctCourses() {
    return ResponseEntity.ok(studentRepository.findDistinctCourses());
}

@GetMapping("/summaries")
public ResponseEntity<List<StudentSummaryDTO>> getStudentSummaries() {
    return ResponseEntity.ok(studentRepository.findStudentSummaries());
}
🚀 Performance Benefit:

DTO projections created via HQL constructor expressions are read-only POJOs. Hibernate does not track them in its first-level session cache (dirty checking), resulting in faster execution and lower memory usage for read-heavy operations!

STEP 9 · REQUEST 6

Aggregations with COUNT & GROUP BY

HQL supports SQL aggregate functions like COUNT(), AVG(), SUM(), MIN(), and MAX() combined with GROUP BY and HAVING.

Use Case: Course Enrollment Statistics

We want to return a breakdown showing how many students are enrolled in each course, sorted from most popular to least popular.

1. Create CourseStatsDTO.java

Create CourseStatsDTO.java in package com.example.studentcrudhibernate.dto:

package com.example.studentcrudhibernate.dto;

public class CourseStatsDTO {

    private String courseName;
    private Long studentCount;

    // HQL COUNT(s) returns a java.lang.Long
    public CourseStatsDTO(String courseName, Long studentCount) {
        this.courseName = courseName;
        this.studentCount = studentCount;
    }

    public String getCourseName() { return courseName; }
    public void setCourseName(String courseName) { this.courseName = courseName; }

    public Long getStudentCount() { return studentCount; }
    public void setStudentCount(Long studentCount) { this.studentCount = studentCount; }
}

2. Add Aggregate Query to StudentRepository.java

// Request 6A: HQL Aggregation with GROUP BY
@Query("SELECT new com.example.studentcrudhibernate.dto.CourseStatsDTO(s.course, COUNT(s)) " +
       "FROM Student s GROUP BY s.course ORDER BY COUNT(s) DESC")
List<CourseStatsDTO> getEnrollmentStats();

// Request 6B: HQL HAVING Clause (Only courses with at least N students)
@Query("SELECT new com.example.studentcrudhibernate.dto.CourseStatsDTO(s.course, COUNT(s)) " +
       "FROM Student s GROUP BY s.course HAVING COUNT(s) >= :minStudents ORDER BY COUNT(s) DESC")
List<CourseStatsDTO> getPopularCourses(@Param("minStudents") Long minStudents);

3. Add Endpoints to StudentController.java

@GetMapping("/stats/enrollments")
public ResponseEntity<List<CourseStatsDTO>> getEnrollmentStatistics() {
    return ResponseEntity.ok(studentRepository.getEnrollmentStats());
}

@GetMapping("/stats/popular")
public ResponseEntity<List<CourseStatsDTO>> getPopularCourses(@RequestParam(defaultValue = "2") Long min) {
    return ResponseEntity.ok(studentRepository.getPopularCourses(min));
}
⚠️ Notice the return type of COUNT:

In HQL, COUNT(s) always returns a 64-bit java.lang.Long, NOT an Integer. Your DTO constructor must declare Long for the count parameter, otherwise Hibernate will throw a constructor mismatch exception (QueryException)!

STEP 10 · REQUEST 7

Bulk Updates with HQL (@Modifying)

Execute direct database updates across hundreds of records in a single statement without loading them into memory.

The Problem with Standard JPA Updates

To transfer 500 students from "Information Technology" to "Software Engineering" using basic JPA:

  1. JPA executes SELECT and fetches all 500 students into memory.
  2. Your loop calls student.setCourse("Software Engineering") 500 times.
  3. On transaction commit, Hibernate dirty checking triggers 500 individual SQL UPDATE statements!

The HQL Bulk Solution

An HQL bulk update translates into a single SQL UPDATE query executed directly inside the database:

UPDATE Student s SET s.course = :newCourse WHERE s.course = :oldCourse

Required Annotations: @Modifying and @Transactional

  • @Modifying — Informs Spring Data JPA that this query is a DML (Data Manipulation Language) statement (UPDATE or DELETE), not a SELECT query.
  • @Transactional — Required because database modification queries must execute inside a write transaction.
  • clearAutomatically = true — Clears Hibernate's first-level persistence context after the update so subsequent queries don't read outdated cached entities.

1. Add Bulk Update Query to StudentRepository.java

import org.springframework.data.jpa.repository.Modifying;
import org.springframework.transaction.annotation.Transactional;

// Request 7: HQL Bulk Update
@Modifying(clearAutomatically = true)
@Transactional
@Query("UPDATE Student s SET s.course = :newCourse WHERE s.course = :oldCourse")
int transferStudentsCourse(
    @Param("oldCourse") String oldCourse,
    @Param("newCourse") String newCourse
);

2. Add Endpoint to StudentController.java

@PutMapping("/transfer-course")
public ResponseEntity<String> transferCourse(
        @RequestParam String oldCourse,
        @RequestParam String newCourse) {
    int updatedCount = studentRepository.transferStudentsCourse(oldCourse, newCourse);
    return ResponseEntity.ok("Successfully transferred " + updatedCount + " students from " + oldCourse + " to " + newCourse);
}
Return Type:

HQL UPDATE and DELETE repository methods return an int or Integer representing the count of rows modified in the database.

2. StudentController.java (Complete with HQL Endpoints)

package com.example.studentcrudhibernate.controller;

import com.example.studentcrudhibernate.dto.CourseStatsDTO;
import com.example.studentcrudhibernate.dto.StudentSummaryDTO;
import com.example.studentcrudhibernate.entity.Student;
import com.example.studentcrudhibernate.repository.StudentRepository;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/students")
public class StudentController {

    private final StudentRepository studentRepository;

    public StudentController(StudentRepository studentRepository) {
        this.studentRepository = studentRepository;
    }

    // ------------------------------------------------------------------------
    // Standard CRUD Endpoints (from previous codelab)
    // ------------------------------------------------------------------------
    @GetMapping
    public List<Student> getAllStudents() {
        return studentRepository.findAll();
    }

    @GetMapping("/{id}")
    public ResponseEntity<Student> getStudentById(@PathVariable Long id) {
        return studentRepository.findById(id)
                .map(ResponseEntity::ok)
                .orElse(ResponseEntity.notFound().build());
    }

    @PostMapping
    public ResponseEntity<Student> createStudent(@RequestBody Student student) {
        Student saved = studentRepository.save(student);
        return new ResponseEntity<>(saved, HttpStatus.CREATED);
    }

    @PutMapping("/{id}")
    public ResponseEntity<Student> updateStudent(@PathVariable Long id, @RequestBody Student details) {
        return studentRepository.findById(id)
                .map(existing -> {
                    existing.setName(details.getName());
                    existing.setEmail(details.getEmail());
                    existing.setCourse(details.getCourse());
                    return ResponseEntity.ok(studentRepository.save(existing));
                })
                .orElse(ResponseEntity.notFound().build());
    }

    @DeleteMapping("/{id}")

        if (!studentRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }
        studentRepository.deleteById(id);
        return ResponseEntity.noContent().build();
    }

STEP 15 · ARCHITECTURAL GUIDE

HQL vs Native SQL vs Query Methods

When should you use Spring Data derived query methods, when should you write HQL, and when should you drop down to native SQL?

Decision Matrix

Technique Pros Cons Best Used When
Spring Data Derived Methods
findByCourse(String c)		 Zero query strings, auto-generated by method naming convention. Method names become unwieldy with multiple conditions or joins. Simple lookups on 1 or 2 fields (findByName, existsByEmail).
Hibernate Query Language (HQL)
@Query("SELECT s FROM...")		 Full object-oriented query power, database portable, type-safe DTO projections, bulk DML. Requires learning HQL syntax and testing query strings. Recommended standard for all non-trivial searches, filtering, sorting, aggregations, and bulk updates.
Native SQL
@Query(value="...", nativeQuery=true)		 Can use vendor-specific SQL extensions, window functions, and database-specific features. Tied to a specific database; breaks portability; cannot project to arbitrary Java DTOs easily. Only when using proprietary database-specific features not supported by HQL (e.g. JSON columns, specialized spatial indexes).

Top 4 HQL Pitfalls & How to Avoid Them

1. Querying Table Name Instead of Entity

Writing FROM students instead of FROM Student causes org.hibernate.hql.internal.ast.QuerySyntaxException: students is not mapped. Always use the Java class name!

2. Missing @Modifying on DML

Calling an UPDATE or DELETE HQL query without @Modifying throws InvalidDataAccessApiUsageException: Not supported for DDL/DML statements.

3. Forgetting Case Sensitivity of Attributes

If your Java field is private String email;, writing s.Email or s.EMAIL will fail. Java field names in HQL are strictly case-sensitive!

4. Integer vs Long in COUNT() DTOs

HQL COUNT() always produces a 64-bit Long. Declaring int in your DTO constructor causes a reflective constructor lookup failure.
