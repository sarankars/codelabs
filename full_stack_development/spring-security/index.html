STEP 5 · CONCEPTS

Authentication vs Authorization

These two words sound similar, but they answer different questions.

Authentication

“Who are you?”

We verify the username and password and create an authenticated identity.

Authorization

“Are you allowed to do this?”

After authentication, Spring Security decides whether the current request may access an endpoint.

Our API

POST /auth/login is public because a user needs to log in before they have a token. /api/students/** will require authentication.

Which question is authentication answering?

STEP 6 · JWT

Understand the JWT

A JSON Web Token lets the server represent an authenticated identity in a compact signed token that the client can send with later requests.

HEADER
{ algorithm, token type }
.
PAYLOAD
{ subject, issued time, expiration, ... }
.
SIGNATURE
{ proves the token was signed with our secret/private key }
Header

Contains metadata such as the signing algorithm.

Payload

Contains claims such as the username and expiration time.

Signature

Allows the server to detect a token that has been modified or was not signed by the expected key.

Important

A normal signed JWT is not encrypted. Do not put passwords or secrets inside the payload.

Bearer token

The client normally sends the JWT in the HTTP header:

Authorization: Bearer eyJ...

CustomUserDetailsService.java

package com.example.studentapi;

import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;

@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final PasswordEncoder passwordEncoder;

    public CustomUserDetailsService(PasswordEncoder passwordEncoder) {
        this.passwordEncoder = passwordEncoder;
    }

    @Override
    public UserDetails loadUserByUsername(String username)
            throws UsernameNotFoundException {

        if (!username.equals("admin")) {
            throw new UsernameNotFoundException("User not found");
        }

        return User.withUsername("admin")
                .password(passwordEncoder.encode("password123"))
                .roles("USER")
                .build();
    }
}
Demo credentials

Username: admin
Password: password123

This is only for the codelab. In a real application, users and password hashes should normally come from a database or another identity provider.

WHY BCrypt?

We never want to compare or store user passwords as plain text. BCrypt is a password hashing algorithm designed for password storage and verification.

STEP 8 · CONFIGURATION

Create the Security Configuration

The SecurityFilterChain tells Spring Security which requests are public and which require authentication.

SecurityConfig.java

package com.example.studentapi;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration configuration) throws Exception {
        return configuration.getAuthenticationManager();
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http)
            throws Exception {

        http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/login").permitAll()
                .anyRequest().authenticated()
            );

        return http.build();
    }
}
Code Why we need it
BCryptPasswordEncoder Hashes and verifies passwords.
AuthenticationManager Coordinates credential authentication.
csrf.disable() Common for this stateless token-based API example; do not copy this decision blindly to browser/session applications.
STATELESS Spring Security does not use an HTTP session to remember the authenticated API user.
permitAll() Allows login without a JWT.
authenticated() Requires an authenticated user for other requests.
STEP 9 · TOKEN

Create a JwtService

This class has two jobs: create a signed JWT and validate/read a JWT later.

JwtService.java

package com.example.studentapi;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;

@Service
public class JwtService {

    private static final String SECRET =
        "change-this-demo-secret-key-to-a-long-random-value-123456789";

    private static final long EXPIRATION = 1000 * 60 * 60; // 1 hour

    private final SecretKey key = Keys.hmacShaKeyFor(
        SECRET.getBytes(StandardCharsets.UTF_8)
    );

    public String generateToken(String username) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + EXPIRATION);

        return Jwts.builder()
                .subject(username)
                .issuedAt(now)
                .expiration(expiry)
                .signWith(key)
                .compact();
    }

    public String extractUsername(String token) {
        return extractAllClaims(token).getSubject();
    }

    public boolean isTokenValid(String token, String username) {
        try {
            Claims claims = extractAllClaims(token);
            return claims.getSubject().equals(username)
                    && claims.getExpiration().after(new Date());
        } catch (Exception e) {
            return false;
        }
    }

    private Claims extractAllClaims(String token) {
        return Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }
}
Never hard-code a production secret

The secret is hard-coded here only to make the first lesson easy. In a real application, load a strong secret from environment/configuration management and rotate it according to your security requirements.

Why does validation matter?

A client can send any text that looks like a JWT. The server must verify the signature and claims before treating the request as authenticated.

STEP 10 · LOGIN

Create the Login API

The client sends credentials. Spring Security checks them. If they are correct, our application creates a JWT.

AuthController.java

package com.example.studentapi;

import org.springframework.http.ResponseEntity;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/auth")
public class AuthController {

    private final AuthenticationManager authenticationManager;
    private final JwtService jwtService;

    public AuthController(
            AuthenticationManager authenticationManager,
            JwtService jwtService) {
        this.authenticationManager = authenticationManager;
        this.jwtService = jwtService;
    }

    @PostMapping("/login")
    public ResponseEntity<LoginResponse> login(
            @RequestBody LoginRequest request) {

        authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                request.username(),
                request.password()
            )
        );

        String token = jwtService.generateToken(request.username());

        return ResponseEntity.ok(new LoginResponse(token));
    }

    public record LoginRequest(String username, String password) {}

    public record LoginResponse(String token) {}
}

STEP 11 · FILTER

Read the JWT on Every Request

After login, the client does not send the password again. It sends the JWT in the Authorization header.

JwtAuthenticationFilter.java

package com.example.studentapi;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    public JwtAuthenticationFilter(
            JwtService jwtService,
            UserDetailsService userDetailsService) {
        this.jwtService = jwtService;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain)
            throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = authHeader.substring(7);
        String username;

        try {
            username = jwtService.extractUsername(token);
        } catch (Exception e) {
            filterChain.doFilter(request, response);
            return;
        }

        if (username != null
                && SecurityContextHolder.getContext().getAuthentication() == null) {

            UserDetails userDetails =
                    userDetailsService.loadUserByUsername(username);

            if (jwtService.isTokenValid(token, userDetails.getUsername())) {

                UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(
                                userDetails,
                                null,
                                userDetails.getAuthorities()
                        );

                SecurityContextHolder.getContext()
                        .setAuthentication(authentication);
            }
        }

        filterChain.doFilter(request, response);
    }
}
What does the filter actually do?
  1. Read the Authorization header.
  2. Check that it starts with Bearer .
  3. Extract the JWT.
  4. Read the username from the token.
  5. Load the user.
  6. Validate the token.
  7. Put an authenticated object into the SecurityContext.
  8. Continue the request.
STEP 12 · FILTER CHAIN

Connect the JWT Filter to Spring Security

Creating the filter is not enough. Spring Security must execute it before the standard username/password authentication filter.

Update SecurityConfig.java

import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Bean
public SecurityFilterChain securityFilterChain(
        HttpSecurity http,
        JwtAuthenticationFilter jwtAuthenticationFilter)
        throws Exception {

    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(session ->
            session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
        )
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/auth/login").permitAll()
            .anyRequest().authenticated()
        )
        .addFilterBefore(
            jwtAuthenticationFilter,
            UsernamePasswordAuthenticationFilter.class
        );

    return http.build();
}
HTTP request
↓
JwtAuthenticationFilter
↓
JWT valid?
├── YES → put Authentication in SecurityContext
└── NO → continue without authentication
↓
Authorization rules
↓
/auth/login → public
/api/students/** → authenticated only
KEY IDEA

The filter does not decide whether an endpoint is public. It establishes the authenticated user when a valid token is present. The authorization configuration then decides whether the request may continue.

STEP 18 · DEBUG

Common JWT Mistakes

When authentication does not work, check the flow instead of changing random lines.

401 / unauthorized

Check whether the token exists, starts with Bearer , is valid, is not expired, and is signed with the same key used by the server.

Login fails

Check the username, password, UserDetailsService, and BCrypt encoder.

Filter never runs

Make sure the filter is a Spring bean, usually with @Component, and is registered using addFilterBefore().

Everything is public

Check the authorization rules. anyRequest().authenticated() is what protects the remaining endpoints in this lesson.

JWT works after restart unexpectedly

Remember that the demo user is recreated in memory. A real database-backed user system behaves differently.

Secret changed

If you sign tokens with one key and later validate with a different key, old tokens cannot be verified.

STEP 19 · SECURITY

Important Production Differences

The codelab is deliberately small. A real application needs more security decisions.

  • Do not hard-code the JWT secret in source code.
  • Use a strong secret or appropriate asymmetric signing keys.
  • Store password hashes, never plain-text passwords.
  • Use HTTPS so credentials and tokens are protected in transit.
  • Choose a sensible token expiration time.
  • Plan token refresh/revocation if your application needs it.
  • Validate request input and return controlled error responses.
  • Do not put passwords, API keys, or other secrets in JWT claims.
  • Use roles/authorities when different users need different permissions.
  • Do not blindly disable CSRF in applications that use browser cookies/sessions; this lesson uses a stateless Bearer-token API.
JWT is not “security by itself.”

JWT is a token format. Spring Security supplies the authentication and authorization framework around it. Your application still has to protect keys, credentials, transport, endpoints, and user data.

STEP 20 · REVISION

JWT Authentication Revision

Review these questions before moving to database-backed authentication.

Why is /auth/login public?
A user needs a way to authenticate before they have a JWT. After successful authentication, the endpoint returns the token.
What does BCrypt do?
It hashes passwords for storage and can verify a submitted password against the stored hash.
What is the SecurityContext?
Spring Security uses it to hold the authentication information for the current request.
What does JwtAuthenticationFilter do?
It extracts the Bearer token, validates it, loads the user, and places an authenticated object into the SecurityContext when appropriate.
Is a JWT encrypted?
Not by default. A normal signed JWT is readable by whoever possesses it. Its signature protects integrity/authenticity, not secrecy.
Why is the API stateless?
The server does not use an HTTP session to remember the logged-in API user. Each protected request carries its authentication token.
