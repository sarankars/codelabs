Step 2 · 10 minutes

A Java web app is a request-and-response team

The browser, Tomcat, Servlet, and JSP have different jobs. Understanding those jobs makes the code much easier to follow.

Follow one form submission

1. Browser

Collects the name and email, then sends an HTTP POST request.

2. Tomcat

Receives the request and finds the Servlet mapped to /profile.

3. Servlet

Reads parameters, validates them, and adds request attributes.

4. JSP

Turns the attributes into safe HTML.

5. Response

Tomcat returns the generated HTML to the browser.

Controller

The Servlet decides

A Servlet is a Java class managed by Tomcat. It handles requests, validates data, and decides which view should render.

View

The JSP presents

A JSP is a server-side template. Tomcat translates it into Java behind the scenes, then runs it to produce HTML.

POST instead of GET

A GET request normally asks for a page and places parameters in the URL. A POST request sends form data in the request body. We use POST because the user is submitting information to the server.

Explore · Build the requesttype sample values
Keep this picture in mind: the browser never runs the Servlet or JSP. Tomcat runs them on the server and sends only the resulting HTML to the browser.
Step 3 · 10 minutes

Tomcat manages the Servlet lifecycle

You create the Servlet class, but Tomcat creates and manages its object. The lifecycle describes what happens from startup to shutdown.

Explore · Lifecycle stagesselect a stage

How HttpServlet handles requests

Tomcat calls service() for each HTTP request. The inherited HttpServlet.service() method looks at the HTTP method and calls a more specific method such as doGet() or doPost(). In this lab, we override doPost() to process the form.

Important concurrency rule: one Servlet object can serve several requests on different threads. Do not store a student's name or email in instance fields. Keep request-specific values in local variables and request attributes, as this project does.

Where should a submitted email be stored while one request is processed?

Correct. Local variables and request attributes belong to the current request, so simultaneous users do not overwrite one another.

Why is the result JSP inside WEB-INF?

A browser cannot request a file inside WEB-INF directly. Only server-side code can forward to it. This ensures the result page is reached through the Servlet, which supplies the required attributes.

Step 6 · 10 minutes

Build the JSP input form

The first JSP produces the HTML form. It also displays validation errors when the Servlet forwards an invalid submission back to it.

Understand the important lines

  • The page directive chooses UTF-8 so names from many languages display correctly.
  • The JSTL tag library gives us <c:if> and <c:out>.
  • ${pageContext.request.contextPath} keeps links correct even if the WAR context name changes.
  • The fields are named name and email; the Servlet uses those exact parameter names.
src/main/webapp/index.jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Student Profile Form</title>
  <link rel="stylesheet" href="${pageContext.request.contextPath}/css/styles.css">
</head>
<body>
  <main class="form-card">
    <p class="eyebrow">Servlet + JSP Lab</p>
    <h1>Tell us about yourself</h1>
    <p class="intro">Submit the form to send your details to a Java Servlet.</p>

    <c:if test="${not empty errorMessage}">
      <div class="error" role="alert"><c:out value="${errorMessage}" /></div>
    </c:if>

    <form action="${pageContext.request.contextPath}/profile" method="post">
      <label for="name">Name</label>
      <input id="name" name="name" type="text" value="<c:out value='${formName}' />"
             autocomplete="name" required>

      <label for="email">Email</label>
      <input id="email" name="email" type="email" value="<c:out value='${formEmail}' />"
             autocomplete="email" required>

      <button type="submit">Submit profile</button>
    </form>
  </main>
</body>
</html>
Two layers of validation: HTML attributes such as required improve the browser experience, but they can be bypassed. The Servlet must validate the data again on the server.
Step 7 · 20 minutes

Read, validate, and route the request

The Servlet is the controller. It receives the POST request, checks both fields, and forwards to the correct JSP.

ProfileServlet.java
package com.sarankar.codelabs;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

@WebServlet(name = "ProfileServlet", urlPatterns = "/profile", loadOnStartup = 1)
public class ProfileServlet extends HttpServlet {

    @Override
    public void init() throws ServletException {
        super.init();
        getServletContext().log("ProfileServlet initialized");
    }

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws IOException {
        response.sendRedirect(request.getContextPath() + "/");
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        request.setCharacterEncoding("UTF-8");

        String name = valueOrEmpty(request.getParameter("name")).trim();
        String email = valueOrEmpty(request.getParameter("email")).trim();

        request.setAttribute("formName", name);
        request.setAttribute("formEmail", email);

        if (name.isBlank() || email.isBlank()) {
            request.setAttribute("errorMessage", "Please enter both your name and email.");
            request.getRequestDispatcher("/index.jsp").forward(request, response);
            return;
        }

        if (!isValidEmail(email)) {
            request.setAttribute("errorMessage", "Please enter an email address such as student@example.com.");
            request.getRequestDispatcher("/index.jsp").forward(request, response);
            return;
        }

        request.setAttribute("submittedName", name);
        request.setAttribute("submittedEmail", email);
        request.getRequestDispatcher("/WEB-INF/result.jsp").forward(request, response);
    }

    private String valueOrEmpty(String value) {
        return value == null ? "" : value;
    }

    private boolean isValidEmail(String email) {
        int at = email.indexOf('@');
        int dot = email.lastIndexOf('.');
        return at > 0 && dot > at + 1 && dot < email.length() - 1;
    }

    @Override
    public void destroy() {
        getServletContext().log("ProfileServlet destroyed");
        super.destroy();
    }
}

Walk through doPost()

Encoding

Set UTF-8 before reading parameters so the bytes are decoded correctly.

Read

getParameter() reads values whose names match the form fields.

Validate

Reject blank values and a clearly malformed email. The browser's checks are not trusted as the only defence.

Attach

setAttribute() gives the JSP named values for this request only.

Forward

The dispatcher runs a JSP on the server without making the browser send a second request.

Forward versus redirect: a forward keeps the same request and its attributes. A redirect tells the browser to make a new request, so ordinary request attributes do not survive.
Step 8 · 10 minutes

Display the values with a JSP view

The result page reads request attributes and generates HTML. It does not repeat the validation or request-routing logic.

WEB-INF/result.jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Submitted Profile</title>
  <link rel="stylesheet" href="${pageContext.request.contextPath}/css/styles.css">
</head>
<body>
  <main class="form-card result-card">
    <p class="eyebrow">Submission received</p>
    <h1>Hello, <c:out value="${submittedName}" />!</h1>
    <p>Your form travelled through the Servlet and reached this JSP page.</p>

    <dl>
      <div>
        <dt>Name</dt>
        <dd><c:out value="${submittedName}" /></dd>
      </div>
      <div>
        <dt>Email</dt>
        <dd><c:out value="${submittedEmail}" /></dd>
      </div>
    </dl>

    <a class="button-link" href="${pageContext.request.contextPath}/">Submit another profile</a>
  </main>
</body>
</html>

Expression Language and safe output

${submittedName} means “find the attribute named submittedName.” The <c:out> tag writes it as escaped text. If someone submits HTML such as <script>, the browser displays the characters instead of treating them as a script.

Separation of responsibilities: the Servlet contains Java decision-making; the JSP contains presentation markup. This small separation is the foundation of the Model–View–Controller style used by larger frameworks.

Annotation configuration

@WebServlet("/profile") connects one URL pattern to one Servlet class.

Descriptor configuration

Both are valid: mappings can also be written in web.xml. This lab uses an annotation because the mapping is close to the Java class and easy to see.

Step 11 · 5 minutes

Test more than the happy path

A form is not finished when one valid submission works. Try invalid and surprising input too.

Manual test checklist

  • Submit Asha Rao and asha@example.com; both appear on the result page.
  • Try a blank field; the browser blocks it, and the server also rejects a request that bypasses the browser check.
  • Try asha@example; the server returns the email-format message.
  • Try <script>alert(1)</script> as the name; it appears as text and does not run.
  • Open /student-form/profile with GET; it redirects to the form.

Common problems

SymptomLikely causeWhat to check
404 at /student-form/WAR was not deployed or Tomcat is not running.Check webapps, Tomcat logs, port 8080, and the WAR filename.
404 after submittingThe form action and Servlet mapping differ.Both should use /profile.

Read the server log: Tomcat's console and logs folder usually contain the real exception. The browser may only show a short error page.
Step 12 · 5 minutes

Explain the complete journey

You have built Program 6. Check the main ideas, then choose an extension if time remains.

Who creates and manages the Servlet object?

Tomcat loads, initializes, calls, and eventually destroys the Servlet.

Why does the Servlet forward instead of redirecting to result.jsp?

The result JSP needs the name and email stored on the current request.

Why use <c:out> for submitted text?

Escaped output displays user-controlled characters as text instead of executable HTML.

The complete story

  1. The browser renders index.jsp and sends a POST request.
  2. Tomcat maps /profile to ProfileServlet.
  3. doPost() reads, trims, and validates request parameters.
  4. Invalid data is forwarded back with an error; valid data is added as request attributes.
  5. result.jsp safely renders the attributes into HTML.
  6. Tomcat sends that generated HTML response to the browser.

Optional extensions

  • Add a course field using a <select> element.
  • Add a confirmation checkbox and validate it on the server.
  • Display the current request method and context path on the result page.
  • Replace simple email validation with a dedicated validation library in a later lesson.
