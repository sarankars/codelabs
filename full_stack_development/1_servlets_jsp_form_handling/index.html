Step 1 · 5 minutes

Build your first Servlet and JSP form

You will create a small Java web application, run it immediately with Jetty, submit a name and email, and only then package it as a WAR file.

Input

Form JSP

index.jsp collects a name and email.

Java

Servlet

FormServlet receives the submitted values.

Output

Result JSP

result.jsp shows the values in the browser.

The complete request journey

1. Browser

The student fills in the form.

2. POST

The browser sends the form to /submit.

3. Servlet

Java reads the two parameters.

4. Forward

The same request moves to result.jsp.

5. HTML

The result appears in the browser.

Your goal: open http://localhost:8080/student-form/, submit the form, and see both values on the result page.

What you need

  • Java Development Kit (JDK) 17 or newer
  • Visual Studio Code
  • Extension Pack for Java, including Maven for Java
  • About 120 minutes
Step 2 · 15 minutes

Create the Maven webapp in VS Code

Let Maven generate the starting folders. You do not need to create the entire structure by hand.

1. Check the tools

Open a terminal and run these commands. A version number should appear for both.

Terminal
java -version
mvn -version

2. Generate the project

  1. Install Extension Pack for Java from the VS Code Extensions view.
  2. Open the Command Palette with Cmd+Shift+P on macOS or Ctrl+Shift+P on Windows/Linux.
  3. Run Maven: Create Maven Project.
  4. Choose maven-archetype-webapp, then version 1.4.
  5. Enter group ID com.example.studentform.
  6. Enter artifact ID student-form.
  7. Accept version 1.0-SNAPSHOT; we will replace it shortly.
  8. Select a parent folder and open the generated student-form folder in VS Code.

What you should see: pom.xml, src/main/webapp/index.jsp, and src/main/webapp/WEB-INF/web.xml.

student-form/

└── src/main/webapp/
    ├── index.jsp

        └── web.xml

VS Code may display src/main/webapp on one line. That is only the Compact Folders view; the real folders are still nested correctly. A target folder may also appear after Maven runs. It contains generated output and should not be edited.

Step 3 · 20 minutes

Prepare the generated project

Add the Java source folder, then give Maven the exact libraries and plugins needed to compile, run, and package this application.

1. Create the Java package

In the Explorer, create these nested folders under src/main:

java/com/example/studentform

3. Replace WEB-INF/web.xml

This minimal descriptor identifies the application as Jakarta Servlet 6.0. The Servlet URL itself will come from a Java annotation.

src/main/webapp/WEB-INF/web.xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">
</web-app>

Use jakarta.servlet, not javax.servlet. This project targets modern Jakarta Servlet 6 and Tomcat 10.1.

Step 4 · 15 minutes

Create the JSP form

The first JSP produces an HTML form. Its only job is to collect two values and send them to the Servlet.

  1. Open src/main/webapp/index.jsp.
  2. Replace everything in it with the code below.
  3. Save the file.
src/main/webapp/index.jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Student Form</title>
</head>
<body>
  <h1>Student Form</h1>
  <form action="${pageContext.request.contextPath}/submit" method="post">
    <p>
      <label for="name">Name:</label>
      <input id="name" name="name" type="text" required>
    </p>
    <p>
      <label for="email">Email:</label>
      <input id="email" name="email" type="email" required>
    </p>
    <button type="submit">Submit</button>
  </form>
</body>
</html>

Understand the important lines

name="name"

This is the parameter name the Servlet will use. The email input similarly becomes an email parameter.

method="post"

The browser sends the values in a POST request, so our Servlet will implement doPost().

Context path

${pageContext.request.contextPath} becomes /student-form, keeping the URL correct in Jetty and Tomcat.

required

The browser asks the user to fill both fields before submission. This is browser-side checking, not secure server validation.

Checkpoint: the form action should be ${pageContext.request.contextPath}/submit, not only /submit.

Step 5 · 25 minutes

Create the Servlet

The Servlet receives the POST request, reads the fields, attaches them to the request, and forwards that request to the result JSP.

  1. Inside src/main/java/com/example/studentform, create FormServlet.java.
  2. Paste the complete class below.
  3. Save it and wait for VS Code to finish importing Maven dependencies.
src/main/java/com/example/studentform/FormServlet.java
package com.example.studentform;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

@WebServlet("/submit")
public class FormServlet extends HttpServlet {
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String name = request.getParameter("name");
        String email = request.getParameter("email");

        request.setAttribute("name", name);
        request.setAttribute("email", email);

        request.getRequestDispatcher("/result.jsp").forward(request, response);
    }
}
Map
@WebServlet("/submit")

Connects the /submit

Read
getParameter()

Reads the values whose HTML input names are name and email.

Attach
setAttribute()

Stores the two values on this request so the next JSP can use them.

Forward
forward()

Runs result.jsp on the server without starting a new browser request.

Basic lifecycle: the server creates and initializes the Servlet, calls its service logic for requests such as this POST, and destroys it when the application stops. You only override doPost() in this first example.

Step 6 · 15 minutes

Create the result JSP

This page reads the request attributes created by the Servlet and places them into the returned HTML.

  1. In src/main/webapp, create result.jsp next to index.jsp.
  2. Paste the code below and save it.
src/main/webapp/result.jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Submitted Details</title>
</head>
<body>
  <h1>Submitted Details</h1>
  <p>Name: ${name}</p>
  <p>Email: ${email}</p>
  <a href="${pageContext.request.contextPath}/">Back to the form</a>
</body>
</html>

${name} and ${email} are JSP Expression Language expressions. They look for request attributes with those names—the same names passed to setAttribute() in the Servlet.

What you should see in Explorer: two JSP files inside webapp, one Java class inside the package, plus pom.xml and WEB-INF/web.xml.

student-form/
├── pom.xml
└── src/main/
    ├── java/com/example/studentform/
    │   └── FormServlet.java
    └── webapp/
        ├── index.jsp
        ├── result.jsp
        └── WEB-INF/
            └── web.xml
Step 7 · 15 minutes

Run and test before packaging

Yes—you can test first. Jetty reads the project directly from src/main/webapp and compiled classes, so Maven does not need to create the WAR yet.

1. Start the development server

Open VS Code’s terminal in the folder that contains pom.xml, then run:

Terminal
mvn jetty:run

Wait until the terminal reports that Jetty has started. Keep this terminal running.

2. Test the full request

  1. Open http://localhost:8080/student-form/.
  2. Enter a name and email, then select Submit.
  3. Confirm that the result page displays both values.
  4. Select Back to the form, change a value, and submit again.

What you should see: the browser moves to /student-form/submit and shows “Submitted Details” followed by your name and email.

If port 8080 is already in use

Alternative port
mvn jetty:run -Djetty.http.port=8081

Then open http://localhost:8081/student-form/.

Edit and retest

While Jetty is running, change a heading in a JSP and save. Refresh the browser. The plugin scans for changes every second. For Java changes, wait for the restart message before refreshing.

When testing is complete, return to the terminal and press Ctrl+C to stop Jetty.

ProblemCheck
404 Not FoundUse /student-form/ and confirm the Jetty terminal is still running.
Red imports in JavaSave pom.xml, then run Maven: Reload Projects in VS Code.
405 Method Not AllowedOpen the form first. The Servlet implements POST, not a direct GET to /submit.
Port already in useUse the 8081 command above.
Step 8 · 10 minutes

Build the WAR and review

Now that the source application works, package the same files into one archive that a compatible application server can deploy.

1. Package the application

Terminal
mvn clean package

What you should see: BUILD SUCCESS and a new file at target/student-form.war.

2. Optional Tomcat deployment

  1. Install Apache Tomcat 10.1.
  2. Copy target/student-form.war into Tomcat’s webapps folder.
  3. Start Tomcat with bin/startup.sh on macOS/Linux or bin\startup.bat on Windows.
  4. Open http://localhost:8080/student-form/ and repeat the form test.

Quick check: who receives the POST request?

Correct: @WebServlet("/submit") maps the submitted form to FormServlet. It then forwards the request to result.jsp.

Review

  • Maven generated the standard webapp structure.
  • index.jsp sent two form parameters in a POST request.
  • FormServlet read the parameters and created request attributes.
  • result.jsp displayed those request attributes.
  • mvn jetty:run tested the source project before packaging.
  • mvn clean package created target/student-form.war.

Important boundary: this is deliberately minimal teaching code. It has no server-side validation and directly displays user input without output escaping. Do not use this pattern as production-ready code. A real application must validate input and safely encode output.
