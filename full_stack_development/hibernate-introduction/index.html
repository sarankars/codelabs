STEP 1 · INTRODUCTION

What is Hibernate?

Before we look at architecture or configuration, we need to understand the fundamental problem Hibernate solves and why it exists.

By the end: You will understand what an ORM framework is, why JDBC alone is tedious for large applications, and how Hibernate bridges the gap.

The Problem with Raw JDBC

In traditional Java database programming you use JDBC (Java Database Connectivity) to talk to a relational database. While powerful, it forces you to:

  • Write repetitive boilerplate SQL for every table (INSERT, SELECT, UPDATE, DELETE).
  • Manually map every ResultSet column to a Java object field.
  • Handle connection management, transactions, and resource cleanup yourself.
  • Rewrite SQL when you switch databases (MySQL → PostgreSQL → Oracle).
The Impedance Mismatch

There is a fundamental mismatch between the object-oriented world of Java (classes, inheritance, associations) and the relational world of SQL (tables, rows, foreign keys). Bridging this gap manually is repetitive and error-prone.

Enter Hibernate

Hibernate is an open-source Object-Relational Mapping (ORM) framework for Java. It bridges the impedance mismatch by automatically converting Java objects into database rows — and vice versa — so you rarely write raw SQL.

Without Hibernate (JDBC)

You write SQL, iterate over a ResultSet, and copy each column value into a Java object field — every time, for every table.

With Hibernate (ORM)

You work with plain Java objects. Hibernate generates and executes the SQL, caches results, and manages transactions automatically.

Hibernate vs. JDBC at a Glance

AspectRaw JDBCHibernate ORM
SQL WritingManual for every operation.Auto-generated; HQL for custom queries.
Object MappingManual field-by-field copy from ResultSet.Automatic via annotations or XML mappings.
Database PortabilitySQL is often DB-specific.Dialect abstraction makes switching easier.
CachingImplement yourself.First- and second-level cache built-in.
Transaction ManagementManual commit / rollback.Integrated with JTA and Spring transactions.
Learning CurveLow — just SQL and JDBC API.Moderate — new concepts like Session, HQL, mappings.
Key Fact

Hibernate is the most widely used JPA implementation. JPA (Jakarta Persistence API) is a specification; Hibernate is the implementation. When you use Spring Data JPA, Hibernate is running underneath.

STEP 2 · CONCEPTS

Core Hibernate Concepts

Hibernate introduces a small vocabulary of terms you must understand before looking at architecture or configuration.

Entity

An Entity is a plain Java class (a POJO) that is mapped to a database table. Each instance of the class corresponds to one row in that table.

@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private int id;

    @Column(name = "first_name")
    private String firstName;

    @Column(name = "email")
    private String email;

    // getters and setters ...
}
NOTE

@Entity marks the class. @Table names the database table. @Id marks the primary key. @Column maps a field to a specific column name.

Session

A Session is a short-lived, lightweight object that represents a single unit of work with the database. It is the primary interface for performing CRUD operations.

  • Obtained from a SessionFactory.
  • Not thread-safe — create one per request/transaction and close it when done.
  • Maintains a first-level cache (within the session) automatically.

SessionFactory

The SessionFactory is a heavyweight, thread-safe object created once per application lifetime. It reads your configuration, validates your mappings, and acts as a factory for Session objects.

Analogy

Think of SessionFactory as a database connection pool manager. You create it once (expensive), then ask it for a Session every time you need to talk to the database (cheap).

Transaction

A Transaction groups a set of operations that must either all succeed or all fail together (atomicity). You always begin a transaction before writing data and either commit or rollback at the end.

HQL — Hibernate Query Language

HQL is an object-oriented query language similar to SQL, but operates on entity class names and field names instead of tables and columns. Hibernate translates HQL into the correct SQL dialect automatically.

// HQL — works with entity class names, not table names
String hql = "FROM Student WHERE email = :email";

// Equivalent SQL Hibernate might generate for MySQL:
// SELECT * FROM students WHERE email = ?

STEP 3 · ARCHITECTURE

Hibernate Architecture

Hibernate sits between your Java application and the database, acting as a translation layer. Understanding its layered architecture is key to using it effectively.

The Layered View

+------------------------------------------+
| Java Application Layer |
| (Your code: Entity classes, services) |
+------------------+-----------------------+
                  |
                  v
+------------------------------------------+
| Hibernate ORM Layer |
| SessionFactory · Session · Transaction |
| Query (HQL/Criteria) · Cache |
+------------------+-----------------------+
                  |
                  v
+------------------------------------------+
| JDBC / Database Layer |
| Connection Pool · SQL Dialect · DB |
+------------------------------------------+

Key Architectural Components

Configuration

The starting point. Reads hibernate.cfg.xml (or application.properties in Spring Boot), registers entity classes, and builds the SessionFactory.

SessionFactory

Thread-safe, created once. Holds compiled mapping metadata and the database connection pool. The most expensive object to create.

Session

The workhorse. Wraps a JDBC connection, maintains the first-level cache, and provides save(), get(), update(), delete() methods.

Transaction

Wraps database operations in a single atomic unit. Delegates to JDBC transactions or JTA depending on the environment.

Query / Criteria

Interfaces to run HQL or Criteria API queries. Both are translated into dialect-specific SQL at runtime.

Cache

First-level cache lives inside a Session (always on). Second-level cache is shared across sessions (optional; needs a provider like EhCache).

Object States in Hibernate

Every entity object has a lifecycle with four possible states:

StateWhat it meansDatabase Row?
TransientObject just created with new. Hibernate does not know about it.No
PersistentObject is associated with an open Session. Any change is tracked and synced to the DB.Yes (or pending flush)
DetachedSession was closed. Object has a DB identity but is no longer tracked.Yes
RemovedMarked for deletion. Will be deleted on the next flush.Pending deletion
Why States Matter

Understanding object states prevents common bugs like "why didn't my change save?" (object was Detached) or "why did Hibernate fire an unexpected UPDATE?" (object was Persistent and every field change was tracked).

STEP 4 · INSTALLATION

Adding Hibernate to a Java Project

Hibernate is installed by declaring dependencies in your build tool — Maven or Gradle. No separate download or installer is required.

Goal: Understand which dependencies are needed and what role each plays.

Required Dependencies

  1. Hibernate Core — the ORM engine itself.
  2. JDBC Driver — the connector for your specific database (MySQL, PostgreSQL, etc.).
  3. Jakarta Persistence API (JPA) — the standard interface Hibernate implements (bundled inside Hibernate Core from version 6+).

Maven — pom.xml

<dependencies>

    <!-- Hibernate ORM Core (includes JPA API) -->
    <dependency>
        <groupId>org.hibernate.orm</groupId>
        <artifactId>hibernate-core</artifactId>
        <version>6.6.0.Final</version>
    </dependency>

    <!-- MySQL JDBC Driver -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <version>8.4.0</version>
    </dependency>

</dependencies>

Gradle — build.gradle

dependencies {
    // Hibernate ORM Core (includes JPA API)
    implementation 'org.hibernate.orm:hibernate-core:6.6.0.Final'

    // MySQL JDBC Driver
    runtimeOnly 'com.mysql:mysql-connector-j:8.4.0'
}
TIP

If you are using Spring Boot, add the spring-boot-starter-data-jpa starter instead. It automatically pulls in Hibernate Core, the JPA API, and wires everything together — you only need to add the JDBC driver separately.

What Gets Installed

hibernate-core

The main JAR. Contains the Session, SessionFactory, Transaction, HQL engine, mapping processors, and caching infrastructure.

JDBC Driver (e.g., mysql-connector-j)

A thin driver that knows how to speak the MySQL wire protocol. Hibernate delegates all actual SQL execution to this driver.

Jakarta Persistence API

The standard annotations (@Entity, @Id, etc.) that make Hibernate interoperable with JPA-compatible tools like Spring Data.

Byte Buddy / Javassist

Pulled in automatically. Hibernate uses these to create proxy classes for lazy loading without touching your entity source code.

STEP 5 · CONFIGURATION

hibernate.cfg.xml — The Configuration File

The hibernate.cfg.xml file tells Hibernate how to connect to your database, which SQL dialect to use, and which entity classes to map.

A Complete Example

<!DOCTYPE hibernate-configuration PUBLIC
    "-//Hibernate/Hibernate Configuration DTD 3.0//EN"
    "http://www.hibernate.org/dtd/hibernate-configuration-3.0.dtd">

<hibernate-configuration>
    <session-factory>

        <!-- Database Connection -->
        <property name="hibernate.connection.driver_class">
            com.mysql.cj.jdbc.Driver
        </property>
        <property name="hibernate.connection.url">
            jdbc:mysql://localhost:3306/college_db
        </property>
        <property name="hibernate.connection.username">root</property>
        <property name="hibernate.connection.password">secret</property>

        <!-- SQL Dialect -->
        <property name="hibernate.dialect">
            org.hibernate.dialect.MySQLDialect
        </property>

        <!-- Schema Management -->
        <property name="hibernate.hbm2ddl.auto">update</property>

        <!-- Debug: Print Generated SQL -->
        <property name="hibernate.show_sql">true</property>
        <property name="hibernate.format_sql">true</property>

        <!-- Entity Mappings -->
        <mapping class="com.example.entity.Student"/>

    </session-factory>
</hibernate-configuration>

Configuration Properties Explained

PropertyPurpose
connection.driver_classFully-qualified class name of the JDBC driver for your database.
connection.urlThe JDBC URL: protocol, host, port, and database name.
connection.username / passwordDatabase credentials. In production use environment variables, not hard-coded values.
dialectTells Hibernate which SQL flavour to generate (MySQL, PostgreSQL, Oracle, H2, …).
hbm2ddl.autoSchema strategy. See the table below for all options.
show_sqlPrints every generated SQL statement to the console. Useful for debugging.
format_sqlPretty-prints the SQL for easier reading.
<mapping class="…"/>Registers an entity class with Hibernate so it can be managed.

hbm2ddl.auto Options

ValueWhat Hibernate does at startupWhen to use
createDrops existing tables and creates new ones from scratch.Development only — you lose all data on every restart.
create-dropCreates on startup, drops on SessionFactory close.In-memory testing (H2 database).
updateAdds missing columns/tables; never removes existing ones.Development when you want data to persist between restarts.
validateChecks that the schema matches the mappings; throws if not.Production — schema managed by Flyway / Liquibase.
noneDoes nothing. You manage the schema entirely yourself.Production with DBA-managed schemas.
Production Warning

Never use create or create-drop in production — they will delete all your data on each restart. Use validate or none and manage schema changes with a migration tool such as Flyway or Liquibase.

STEP 6 · BOOTSTRAP

Bootstrapping Hibernate — HibernateUtil

The SessionFactory must be created exactly once and shared across the entire application. A utility class is the conventional way to manage this.

Why a Utility Class?

Building a SessionFactory is expensive: Hibernate parses all configuration and mapping metadata, validates the schema, and establishes the connection pool. Creating it more than once wastes resources and may cause bugs.

package com.example.util;

import org.hibernate.SessionFactory;
import org.hibernate.cfg.Configuration;

public class HibernateUtil {

    // Created once when the class is first loaded
    private static final SessionFactory sessionFactory = buildSessionFactory();

    private static SessionFactory buildSessionFactory() {
        try {
            // Reads hibernate.cfg.xml from the classpath
            return new Configuration()
                    .configure("hibernate.cfg.xml")
                    .buildSessionFactory();
        } catch (Throwable ex) {
            System.err.println("SessionFactory creation failed: " + ex);
            throw new ExceptionInInitializerError(ex);
        }
    }

    public static SessionFactory getSessionFactory() {
        return sessionFactory;
    }

    public static void shutdown() {
        getSessionFactory().close();
    }
}

Using the Utility

Session session = HibernateUtil.getSessionFactory().openSession();
Transaction tx = null;

try {
    tx = session.beginTransaction();

    Student s = new Student();
    s.setFirstName("Arjun");
    s.setEmail("arjun@example.com");

    session.save(s);      // generates: INSERT INTO students ...
    tx.commit();          // flush + commit

} catch (Exception e) {
    if (tx != null) tx.rollback();
    e.printStackTrace();
} finally {
    session.close();      // always release the session
}
Application starts
v
HibernateUtil.getSessionFactory() -- reads hibernate.cfg.xml, creates pool
v (called many times)
openSession() -- new Session (wraps one JDBC Connection)
v
beginTransaction() -- Transaction object
v
CRUD operations (save / get / update / delete)
v
commit() -- Hibernate flushes pending SQL, commits JDBC transaction
v
session.close() -- releases JDBC connection back to pool
SPRING BOOT NOTE

In Spring Boot you do not write HibernateUtil yourself. Spring creates and manages the SessionFactory (exposed as EntityManagerFactory) automatically. You inject a JpaRepository or EntityManager wherever you need it.

STEP 7 · SPRING BOOT

Hibernate in Spring Boot

When you use Spring Boot, manual Hibernate bootstrap is replaced by auto-configuration. Understanding what Spring Boot does for you clarifies both approaches.

The Spring Boot Way

Instead of hibernate.cfg.xml, Spring Boot reads from application.properties:

# src/main/resources/application.properties

# DataSource
spring.datasource.url=jdbc:mysql://localhost:3306/college_db
spring.datasource.username=root
spring.datasource.password=secret
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

# Hibernate / JPA
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect

Spring Boot scans all classes annotated with @Entity automatically — no <mapping class="…"/> tags needed.

Dependency Starter

<!-- Maven pom.xml — Spring Boot approach -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

Comparison: Standalone vs. Spring Boot

ConcernStandalone HibernateSpring Boot + JPA
Configuration filehibernate.cfg.xmlapplication.properties
SessionFactoryYou create it in HibernateUtil.Spring creates and manages it automatically.
Entity scanningExplicit <mapping class> tags.Auto-scans classpath for @Entity.
Transaction mgmtManual tx.commit() / tx.rollback().@Transactional annotation handles it.
Data accessDirect Session API.JpaRepository / EntityManager.
Bottom Line

Spring Boot reduces Hibernate configuration to a few lines in application.properties, but every concept — Session, Transaction, Dialect, Entity states — still applies. The plumbing is just hidden.

STEP 8 · RECAP

Theoretical Revision

Review the core concepts before writing your first Hibernate program.

What problem does Hibernate solve?
Hibernate bridges the impedance mismatch between Java's object model and the relational database model. It auto-generates SQL, handles object mapping, connection pooling, caching, and transactions so you don't write boilerplate JDBC code.
What is the difference between JPA and Hibernate?
JPA (Jakarta Persistence API) is a specification — a set of interfaces and annotations. Hibernate is an implementation of that specification. You write against JPA annotations; Hibernate provides the engine that makes them work.
What are the four entity object states?
Transient — not known to Hibernate. Persistent — attached to an open Session; changes tracked. Detached — Session closed; has a DB identity but not tracked. Removed — scheduled for deletion on next flush.
What does hbm2ddl.auto=update do?
It tells Hibernate to add missing tables and columns at startup to match your entity mappings. It never removes existing columns. Safe for development but not for production.
What is HQL and why does it exist?
HQL (Hibernate Query Language) operates on entity class and field names instead of table and column names. It exists so your queries remain database-independent — Hibernate translates HQL into the correct SQL dialect at runtime.
Why is SessionFactory created only once?
Creating a SessionFactory reads and compiles all configuration and mapping metadata, validates the database schema, and initialises the connection pool. This is expensive and should be done exactly once per application lifecycle.
