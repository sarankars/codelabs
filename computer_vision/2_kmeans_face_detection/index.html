Step 2 · Colour Spaces

Why we ditch RGB and use HSV

The colour system we choose has a huge effect on how well skin detection works.

The problem with RGB

RGB mixes the actual colour with brightness. Shadow on a forehead and bright light on a cheek both look like different colours in RGB — even though both are skin.

Skin in bright light

A forehead in sunlight: [220, 170, 140] — bright, warm.

Same skin in shadow

Same spot in shade: [110, 85, 70] — almost half the values. Looks totally different to K-Means.

Enter HSV

H — HueThe actual colour (orange, green…). Skin sits in the orange range: roughly H 0–22 in OpenCV.
S — SaturationHow vivid the colour is. 0 = grey, 255 = very vivid. Skin is moderately saturated.
V — ValueHow bright the pixel is. Skin is bright — not dark like hair or a black shirt.
Think of a paint set. Hue is which colour you pick (orange). Saturation is how much water you add. Value is whether you paint in a dark room or a bright one. HSV lets us describe skin by Hue alone, regardless of lighting.

Step 3 · K-Means

Sorting pixels into colour buckets

K-Means groups similar things together — like sorting a bag of sweets by colour.

Tip a bag of mixed sweets onto a table. You want to sort them into k piles. Start with k piles at random spots. Each sweet goes to the nearest pile. Move each pile’s centre to the average position of its sweets. Repeat until nothing moves. That is K-Means.

How K-Means works

Pick k random centre points

Starting “guesses” for where each colour group lives.

Assign every pixel to the nearest centre

Each pixel gets a label (0, 1, 2…) matching the closest centre colour.

Move each centre to the average of its group

The centre shifts to better represent the pixels in it.

Repeat until centres stop moving

When no centre moves more than a tiny amount, the algorithm is done.

Why k = 4?

Group — Background

The wall or sky. Usually low saturation.

Group — Skin

Face, neck, hands. Orange-ish hue, moderate saturation, bright.

Group — Hair

Usually dark. Low value.

Group — Clothing

The shirt or jacket. Colour varies, usually not orange.

Important: the group numbers (0, 1, 2, 3) are random every run. Never hardcode the cluster number — always detect it from the colour of the cluster centre.

Key takeaway

K-Means gives every pixel a label. We then look at the colour of each label’s centre to decide which label is skin.

Step 4 · OpenCV Code

Running K-Means on an image

OpenCV does the heavy maths. We prepare the data and read the output.

K-Means wants a flat list

An image is a 3-D grid: Height × Width × 3 channels. cv2.kmeans wants one long list where each row is [H, S, V].

Image shape

(1024, 1536, 3)
Height × Width × Channels

→

Flattened shape

(1572864, 3)
All pixels in one list

# flatten the 2D grid into a 1D list; each pixel = [H, S, V]
pixels = hsv.reshape((-1, 3)).astype(np.float32)

The main call

k = 4
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 10, 1.0)
_, labels, centers = cv2.kmeans(
    pixels, k, None, criteria, 10, cv2.KMEANS_RANDOM_CENTERS
)

Reading the outputs

labelsOne number per pixel — its cluster ID (0, 1, 2, or 3).
centersA 4×3 array. Each row is the average [H, S, V] of one cluster.
cv2.KMEANS_RANDOM_CENTERSStarts cluster centres at random positions. Running 10 times and keeping the best reduces the chance of a bad start.
cv2.TERM_CRITERIA_EPSStop early if centres move less than 1.0 between iterations — the result has converged.
TERM_CRITERIA_MAX_ITER, 10Also stop after 10 iterations even if not fully converged.
After cv2.kmeans(), which variable tells you which cluster each pixel belongs to?

✔ Correct — labels is a flat list with one cluster ID per pixel.

Step 5 · Skin Cluster

Which cluster is skin?

The cluster numbers are random every run, so we detect the skin cluster from its colour.

The bug in hardcoding

skin_cluster_id = 1  # WRONG — cluster 1 might be the wall today

K-Means shuffles starting positions randomly. The code above will draw the face box around the white background wall instead of the face.

The fix: check the centre colour

Channel Skin range Why
Hue (H) 0 – 22 Skin is orange-ish. Orange sits at the low end of OpenCV’s hue scale.
Saturation (S) 25 – 130 Not too grey, not super vivid. Wood and some objects have S > 130.
Value (V) 90 – 255 Skin is bright — not dark like hair or a black shirt. 
SKIN_H_MIN, SKIN_H_MAX = 0,   22
SKIN_S_MIN, SKIN_S_MAX = 25, 130
SKIN_V_MIN, SKIN_V_MAX = 90, 255

skin_cluster_id = None
for i, center in enumerate(centers):
    h, s, v = center
    if SKIN_H_MIN <= h <= SKIN_H_MAX and \
       SKIN_S_MIN <= s <= SKIN_S_MAX and \
       SKIN_V_MIN <= v <= SKIN_V_MAX:
        skin_cluster_id = i
        break

# backup: nothing matched? pick the most orange-looking cluster
if skin_cluster_id is None:
    def skin_score(c):
        h, s, v = c
        return s * v / (h + 1)  # high S+V, low H = most skin-like
    skin_cluster_id = int(np.argmax([skin_score(c) for c in centers]))
What about darker skin tones?

Darker skin tones still sit in the orange hue range but have lower Value (V). Lower SKIN_V_MIN from 90 to around 60 to handle them. The Hue range stays roughly the same for all human skin tones.

Why can’t we hardcode skin_cluster_id = 1?

✔ Correct — the cluster numbers are random. You must detect the skin cluster by checking its centre colour.

Step 6 · Binary Mask

Painting skin white, everything else black

Once we know the skin cluster, building the mask is one line of code.

Original photo

Millions of coloured pixels — face, hair, wall, shirt.

→

Skin mask

White where skin was found. Black everywhere else.

# reshape labels back into a 2D image (height x width)
labels_2d = labels.reshape(hsv.shape[:2])

# skin pixel -> 255 (white), everything else -> 0 (black)
mask = np.where(labels_2d == skin_cluster_id, 255, 0).astype(np.uint8)
cv2.imwrite('1_raw_mask.jpg', mask)
hsv.shape[:2]This is (height, width) — just the first two dimensions. That is the shape a mask needs.
np.where(condition, 255, 0)For every pixel: if true put 255, else put 0. Much faster than a Python loop over millions of pixels.
.astype(np.uint8)OpenCV expects unsigned 8-bit integers (0–255). np.where returns floats by default.
The raw mask is noisy. Camera noise means the mask has tiny white dots in the black areas and tiny black holes in the white face. The next step fixes that.

Step 7 · Morphology

Cleaning up the noisy mask

Two operations remove noise and fill the holes left by eyes, beard, and shadows.

ErosionShrinks white areas. Kills isolated white specks.
DilationGrows white areas. Fills small black holes.
OPEN = erode then dilateKills stray white noise dots without changing big white regions.
CLOSE = dilate then erodeFills black holes inside white regions (eye sockets, beard gaps) then returns to the original size.
Imagine a white chalk drawing on a blackboard with chalk dust everywhere. Eroding wipes away tiny specks. Dilating grows every white edge outward. OPEN wipes the dust. CLOSE fills gaps inside the drawing.

Raw K-Means mask — noisy, full of small holes.

The code

# round brush, 15 px -- small enough not to merge nearby objects
small_kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (15, 15))

# OPEN: kills tiny noise dots
mask_clean = cv2.morphologyEx(mask, cv2.MORPH_OPEN, small_kernel, iterations=1)

# CLOSE: fills small holes inside the face
mask_clean = cv2.morphologyEx(mask_clean, cv2.MORPH_CLOSE, small_kernel, iterations=2)

cv2.imwrite('2_clean_mask.jpg', mask_clean)
Keep the kernel small (15 px). A bigger kernel would grow the face blob until it merges with the stick or neck, turning them into one giant region that cannot be separated.

Key takeaway

OPEN first (remove noise), then CLOSE (fill holes). Small kernel = objects stay separate.

Step 8 · Contours & Scoring

Finding and picking the face blob

The mask has several white blobs. We score each one and pick the winner.

Finding contours

contours, _ = cv2.findContours(
    mask_clean,
    cv2.RETR_EXTERNAL,      # only the outermost edge
    cv2.CHAIN_APPROX_SIMPLE # store corners only
)

Why "biggest blob" alone fails

A wooden stick, a patch of wall, or the neck can all be bigger than the face blob. Picking max(contours, key=cv2.contourArea) often draws the box on the wrong object.

The scoring system

Rule Score effect Why
In the top 60% of image ×1.0 (else ×0.3) Faces are upper-body — rarely at the very bottom.
Near the horizontal centre 0.4–1.0 based on distance People usually stand in the middle of the photo.
Width < 45% of image ×1.0 (else ×0.1) A face is not edge-to-edge. Sticks and arms get a huge penalty.
Aspect ratio 0.4–1.8 ×1.0 (else ×0.3) Faces are roughly square-ish — not thin strips or tall columns.

The code

image_height, image_width = image.shape[:2]
min_area = image_height * image_width * 0.005  # skip blobs < 0.5% of image
best_contour, best_score = None, -1

for contour in contours:
    area = cv2.contourArea(contour)
    if area < min_area:
        continue

    x, y, w, h = cv2.boundingRect(contour)
    center_y, center_x = y + h / 2, x + w / 2

    position_bonus = 1.0 if center_y < image_height * 0.6 else 0.3
    h_distance = abs(center_x - image_width / 2) / (image_width / 2)
    center_bonus = 1.0 - 0.6 * h_distance
    width_penalty = 1.0 if w / image_width < 0.45 else 0.1
    aspect = w / h if h > 0 else 0
    shape_bonus = 1.0 if 0.4 < aspect < 1.8 else 0.3

    score = area * position_bonus * center_bonus * width_penalty * shape_bonus
    if score > best_score:
        best_score, best_contour = score, contour

result = image.copy()
if best_contour is not None:
    x, y, w, h = cv2.boundingRect(best_contour)
    cv2.rectangle(result, (x, y), (x + w, y + h), (0, 255, 0), 4)
cv2.imwrite('3_final_detection.jpg', result)
A blob spans 80% of the image width. What does the scoring system do?

✔ Correct — width_penalty drops to 0.1 for any blob wider than 45% of the image.

Step 9 · Full Code & Recap

Putting it all together

The complete, working script — every step in one place.

import cv2, numpy as np, sys

# accept any image via command line, e.g.  python main.py photo.jpg
image_path = sys.argv[1] if len(sys.argv) > 1 else 'image.png'
image = cv2.imread(image_path)
if image is None:
    raise FileNotFoundError(f"{image_path} not found")

# HSV keeps the actual color (Hue) separate from brightness
hsv = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)

# k-means needs a flat list; each pixel = [H, S, V]
pixels = hsv.reshape((-1, 3)).astype(np.float32)

# group pixels into 4 color buckets
k = 4
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 10, 1.0)
_, labels, centers = cv2.kmeans(pixels, k, None, criteria, 10, cv2.KMEANS_RANDOM_CENTERS)

# find which cluster is skin by checking its average HSV
SKIN_H_MIN, SKIN_H_MAX = 0,   22
SKIN_S_MIN, SKIN_S_MAX = 25, 130
SKIN_V_MIN, SKIN_V_MAX = 90, 255

skin_cluster_id = None
for i, center in enumerate(centers):
    h, s, v = center
    if SKIN_H_MIN <= h <= SKIN_H_MAX and SKIN_S_MIN <= s <= SKIN_S_MAX and SKIN_V_MIN <= v <= SKIN_V_MAX:
        skin_cluster_id = i; break

if skin_cluster_id is None:
    def skin_score(c): h, s, v = c; return s * v / (h + 1)
    skin_cluster_id = int(np.argmax([skin_score(c) for c in centers]))

# build mask: skin = white (255), else black (0)
labels_2d = labels.reshape(hsv.shape[:2])
mask = np.where(labels_2d == skin_cluster_id, 255, 0).astype(np.uint8)
cv2.imwrite('1_raw_mask.jpg', mask)

# OPEN: remove noise   CLOSE: fill holes
kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (15, 15))
mask_clean = cv2.morphologyEx(mask, cv2.MORPH_OPEN,  kernel, iterations=1)
mask_clean = cv2.morphologyEx(mask_clean, cv2.MORPH_CLOSE, kernel, iterations=2)
cv2.imwrite('2_clean_mask.jpg', mask_clean)

# find blobs and score them
contours, _ = cv2.findContours(mask_clean, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
image_height, image_width = image.shape[:2]
min_area = image_height * image_width * 0.005
best_contour, best_score = None, -1

for contour in contours:
    area = cv2.contourArea(contour)
    if area < min_area: continue
    x, y, w, h = cv2.boundingRect(contour)
    cy, cx = y + h/2, x + w/2
    pos   = 1.0 if cy < image_height * 0.6 else 0.3
    ctr   = 1.0 - 0.6 * abs(cx - image_width/2) / (image_width/2)
    wp    = 1.0 if w/image_width < 0.45 else 0.1
    asp   = w/h if h > 0 else 0
    shape = 1.0 if 0.4 < asp < 1.8 else 0.3
    score = area * pos * ctr * wp * shape
    if score > best_score: best_score, best_contour = score, contour

result = image.copy()
if best_contour is not None:
    x, y, w, h = cv2.boundingRect(best_contour)
    cv2.rectangle(result, (x, y), (x+w, y+h), (0, 255, 0), 4)
    print(f"face found at x={x}, y={y}, w={w}, h={h}")
else:
    print("no face found")

cv2.imwrite('3_final_detection.jpg', result)
print("done! see 3_final_detection.jpg")

Concept recap

HSV colour space

Separates colour (Hue) from brightness (Value). Skin looks like skin regardless of lighting.

K-Means clustering

Groups all pixels into k colour buckets by minimising distance to cluster centres.

Automatic skin cluster detection

Check each cluster’s average HSV against known skin range. Never hardcode the cluster number.

Binary mask

White = skin, black = everything else.

Morphological OPEN + CLOSE

OPEN removes noise. CLOSE fills holes. Small kernel keeps nearby objects separate.

Contour scoring

Score each white blob by area, position, centre distance, width ratio, and aspect ratio. Highest score = face.

Limitations to discuss: this approach struggles when the background is skin-coloured, when there are multiple faces, or in very dark images. These real problems lead engineers toward deep learning detectors like YOLO or MediaPipe.
