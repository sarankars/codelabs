STEP 1 · FOUNDATIONS

Motion Analysis in Computer Vision

A single photograph freezes time into a flat grid of pixels. A video unfreezes time, revealing how people move, cars navigate, and the world evolves. This codelab explores how computers perceive, quantify, and model motion across space and time.

By the end of this codelab, you will: Understand the difference between 3D scene motion and 2D image flow, build robust background models using adaptive Gaussian Mixture Models, master the Optical Flow constraint equation and solve the aperture problem, track features with the Kanade-Lucas-Tomasi (KLT) tracker, inspect spatio-temporal volumes and Motion History Images (MHI), understand Dynamic Stereo in 3D, and estimate global motion parameters with RANSAC.

What is Motion to a Camera?

In physics, motion is the change of an object's position in 3D space $(X, Y, Z)$ over time $t$. But a camera captures a 2D projection $(x, y)$.

CONCEPT 1 2D Motion Field

The true physical projection of 3D velocities $(V_X, V_Y, V_Z)$ onto the 2D camera sensor. Every real point on a physical surface creates an exact mathematical velocity vector $(u, v)$ on the image plane.

CONCEPT 2 Optical Flow

The apparent motion of brightness patterns across the image. Note: Optical Flow is what the computer actually measures, which might not always equal the true motion field!

CRITICAL DISTINCTION: MOTION FIELD VS OPTICAL FLOW

Consider a completely smooth, featureless white sphere rotating under fixed lighting. The sphere is spinning (real 3D motion exists → non-zero motion field), but every pixel remains identically white over time (apparent motion is zero → zero optical flow!).

Conversely, if a stationary object is illuminated by a moving spotlight, the brightness pattern moves across the surface (optical flow > 0), even though the physical object never moved at all!

Why is Motion Analysis Difficult?

  • Illumination Variations: Passing clouds, camera auto-exposure adjustments, and flickering lights change pixel values without any physical motion.
  • Dynamic Backgrounds: Trees swaying in the wind, rippling water in a pool, and rotating ceiling fans violate the simple assumption that backgrounds never change.
  • Shadows: Moving objects cast moving shadows on the ground. Computers easily confuse a shadow with the object itself!
  • Camera Motion (Ego-Motion): If the camera is mounted on a drone or self-driving car, every single pixel in the entire frame moves simultaneously.

STEP 2 · SEGMENTATION

Background Subtraction & Modeling

When a stationary camera monitors a doorway, parking lot, or factory floor, our first goal is simple: isolate moving objects (foreground) from the stationary environment (background).

1. Simple Frame Differencing

The simplest conceivable method is subtracting the previous frame $I_{t-1}$ from current frame $I_t$:

Foreground Mask: M(x, y) = 1  if  | I(x, y, t) - I(x, y, t - 1) | > τ,  else  0
Why Frame Differencing Fails in Practice:
  • Aperture / Interior Blindness: A uniformly colored moving object (e.g., a white truck) only changes pixels at its leading and trailing edges. The interior pixels remain white, causing the truck to appear hollow like a ghost!
  • Stop-and-Go: If a person pauses to tie their shoe, their frame difference drops to zero and they completely vanish from the detector.

2. Running Average (Adaptive Background)

Instead of comparing only two frames, we maintain a running background estimate $B_t$ that slowly absorbs changes over time:

B(x, y, t) = (1 - α) · B(x, y, t - 1) + α · I(x, y, t)

Where α (the learning rate, e.g., 0.02) determines how quickly new static objects are absorbed into the background.

3. Gaussian Mixture Models (MOG2 / Zivkovic)

What if a pixel contains waving tree branches? Sometimes it sees a green leaf; other times it sees the blue sky behind it. A single average cannot represent both states!

The GMM Solution: Model each pixel $(x, y)$ as a mixture of $K$ (typically 3 to 5) Gaussian probability distributions:
P(I_t) = Σk=1..K  ωk,t · η(I_t; μk,t, Σk,t)
Each Gaussian has a weight $\omega_k$ (how frequently this color appears), a mean $\mu_k$ (the average color), and a variance $\sigma_k^2$ (how much that color fluctuates). Gaussians with high weight and low variance are ranked highest as background components.

4. Shadow Handling

A shadow lowers the brightness (luminance) of a pixel without significantly changing its color tint (chromaticity). Advanced algorithms like OpenCV's MOG2 mark shadows in a separate gray color (value 127) so you can ignore them and keep only true objects (value 255).

Python Practical: Real-Time MOG2 Background Subtraction

import cv2
import numpy as np

# 1. Initialize MOG2 Subtractor
#    history=500: frames used to build model
#    varThreshold=16: Mahalanobis distance threshold
#    detectShadows=True: highlights shadows as gray (127)
bg_subtractor = cv2.createBackgroundSubtractorMOG2(
    history=500, varThreshold=25, detectShadows=True
)

cap = cv2.VideoCapture(0)  # Or provide a video path: 'traffic.mp4'

# Morphological kernel for noise removal
kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (3, 3))

while cap.isOpened():
    ret, frame = cap.read()
    if not ret:
        break

    # Apply background subtraction
    fg_mask = bg_subtractor.apply(frame)

    # Filter out shadows (keep only pixels == 255)
    _, fg_clean = cv2.threshold(fg_mask, 250, 255, cv2.THRESH_BINARY)

    # Morphological Opening (removes speckles) + Closing (fills holes)
    fg_clean = cv2.morphologyEx(fg_clean, cv2.MORPH_OPEN, kernel)
    fg_clean = cv2.morphologyEx(fg_clean, cv2.MORPH_CLOSE, kernel)

    # Find contours of moving objects
    contours, _ = cv2.findContours(fg_clean, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for cnt in contours:
        if cv2.contourArea(cnt) > 800:  # Ignore tiny noise blobs
            x, y, w, h = cv2.boundingRect(cnt)
            cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

    cv2.imshow('Camera Feed with Detections', frame)
    cv2.imshow('Clean Foreground Mask', fg_clean)

    if cv2.waitKey(30) & 0xFF == 27:  # ESC key
        break

cap.release()
cv2.destroyAllWindows()

STEP 3 · MOTION EQUATION

The Optical Flow Constraint Equation

Background subtraction tells us which pixels changed, but not where they went. Optical flow calculates a velocity vector $(u, v)$ for each pixel, describing its direction and speed.

The 3 Core Assumptions

1. Brightness Constancy

The intensity of a physical surface point does not change as it moves across consecutive frames:

I(x, y, t) = I(x + Δx, y + Δy, t + Δt)
2. Small Motion

Displacements between frames are small enough to be approximated by a first-order Taylor series expansion.

3. Spatial Coherence

Adjacent pixels on the same physical object share similar motion velocities.

Derivation of the Constraint Equation

Expanding $I(x + \Delta x, y + \Delta y, t + \Delta t)$ using 1st-order Taylor series:

I(x + Δx, y + Δy, t + Δt) ≈ I(x, y, t) + ∂I/∂x · Δx + ∂I/∂y · Δy + ∂I/∂t · Δt

Since $I(x + \Delta x, y + \Delta y, t + \Delta t) = I(x, y, t)$, the original intensity cancels out:

Ix · u + Iy · v + It = 0

Where Ix = ∂I/∂x, Iy = ∂I/∂y (spatial image gradients), It = ∂I/∂t (frame difference over time), and u = dx/dt, v = dy/dt are the unknown velocity components.

The Aperture Problem Visualized

1 Equation with 2 Unknowns $(u, v)$!

A single pixel gives only one scalar constraint: $I_x u + I_y v = -I_t$. This means we can only determine the motion component perpendicular (normal) to the edge!

Everyday Analogy: Look at a long barber pole or window blind through a tiny peephole (an aperture). If a vertical striped pole moves straight up, or diagonally up-and-right, the view through the hole looks identical! You cannot determine the parallel component of velocity along an edge.

The Lucas-Kanade Solution

Lucas & Kanade (1981) assumed that a small local window (e.g. $5 \times 5 = 25$ neighboring pixels) moves with the exact same velocity $(u, v)$. Now we have 25 equations for just 2 unknowns!

[ Ix1   Iy1 ] [ u ] = [ -It1 ]
[ Ix2   Iy2 ] [ v ] = [ -It2 ]
...
Matrix form: A · v⃗ = b⃗

Using the Least Squares normal equations:

(AT A) · v⃗ = AT b⃗  &implies;  v⃗ = (AT A)-1 AT b⃗
THE SURPRISING CONNECTION

The matrix $A^T A$ is identical to the Structure Tensor used in the Harris Corner Detector:

AT A = [ Σ Ix²    Σ IxIy ]
       [ Σ IxIy   Σ Iy² ]

This means $A^T A$ is invertible only at corner points where both eigenvalues $\lambda_1, \lambda_2$ are large! Tracking is physically impossible on flat regions ($\lambda_1 \approx 0, \lambda_2 \approx 0$) and ambiguous on straight edges ($\lambda_2 \approx 0$).

STEP 4 · DENSE FLOW

Dense Optical Flow with Gunnar Farnebäck

While Lucas-Kanade gives velocity for selected feature points (sparse flow), Gunnar Farnebäck's algorithm computes a motion vector for every single pixel in the frame.

How Farnebäck Flow Works

Farnebäck (2003) approximates the local neighborhood of each pixel as a 2D quadratic polynomial surface:

f1(x) ≈ xT A1 x + b1T x + c1

When the surface shifts by displacement $d$, the new frame polynomial coefficients $A_2, b_2, c_2$ can be compared directly to solve for displacement $d$ analytically. By repeating this across a multi-resolution image pyramid, it handles both subtle movements and fast actions.

Visualizing Flow with the HSV Color Wheel

How to Display a 2D Vector Field as an Image:
  • Hue (Color tint): Encodes the direction (angle $\theta = \text{atan2}(v, u)$). Red = moving right, Cyan = moving left, Green = moving down, Violet = moving up.
  • Value (Brightness): Encodes the magnitude (speed $\sqrt{u^2 + v^2}$). Static pixels appear black; fast-moving pixels glow vibrantly.
  • Saturation: Kept at maximum (255) for crisp, vivid visualization.

Python Practical: Real-Time Dense Optical Flow

import cv2
import numpy as np

cap = cv2.VideoCapture(0)

# Read the first frame and convert to grayscale
ret, prev_frame = cap.read()
prev_gray = cv2.cvtColor(prev_frame, cv2.COLOR_BGR2GRAY)

# Create an HSV canvas to map flow vectors into colors
hsv = np.zeros_like(prev_frame)
hsv[..., 1] = 255  # Full saturation

while cap.isOpened():
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # Compute dense optical flow using Farneback's algorithm
    # pyr_scale=0.5, levels=3, winsize=15, iterations=3, poly_n=5, poly_sigma=1.2
    flow = cv2.calcOpticalFlowFarneback(
        prev_gray, gray, None,
        pyr_scale=0.5, levels=3, winsize=15,
        iterations=3, poly_n=5, poly_sigma=1.2, flags=0
    )

    # Calculate magnitude and angle of 2D flow vectors (u, v)
    u, v = flow[..., 0], flow[..., 1]
    magnitude, angle = cv2.cartToPolar(u, v, angleInDegrees=True)

    # Map angle (0..360 deg) to OpenCV Hue (0..180)
    hsv[..., 0] = angle / 2
    # Map magnitude to brightness (clipped to 255)
    hsv[..., 2] = cv2.normalize(magnitude, None, 0, 255, cv2.NORM_MINMAX)

    # Convert HSV back to BGR for display
    flow_bgr = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)

    cv2.imshow('Live Camera', frame)
    cv2.imshow('Dense Optical Flow (HSV Color Coded)', flow_bgr)

    prev_gray = gray

    if cv2.waitKey(1) & 0xFF == 27:
        break

cap.release()
cv2.destroyAllWindows()
STEP 5 · TRACKING

Kanade-Lucas-Tomasi (KLT) Feature Tracker

KLT is the golden standard of real-time computer vision tracking. It pairs Shi-Tomasi corner detection with iterative Lucas-Kanade tracking and image pyramids.

The 2 Pillars of KLT

Pillar 1: Shi-Tomasi Feature Selection

Jianbo Shi and Carlo Tomasi (1994) showed that instead of the complex Harris formula $R = \det(M) - k \cdot \text{trace}(M)^2$, the most reliable tracking quality metric is simply:

R = min(λ1, λ2)

A point is accepted if $\min(\lambda_1, \lambda_2) > \lambda_{\text{threshold}}$. This directly guarantees numerical stability when inverting $A^T A$.

Pillar 2: Pyramidal Coarse-to-Fine Search

Lucas-Kanade assumes small motions. If a hand swings quickly across 50 pixels, standard LK fails.

The Pyramid Solution: Downsample images into Gaussian pyramid levels (e.g. 1/8, 1/4, 1/2, 1/1 scale). A 50-pixel jump at full resolution is only ~6 pixels at Level 3! LK tracks at the coarse level first, then refines down to sub-pixel accuracy at full scale.

Production Lifecycle Management

In a real video stream, points will inevitably get occluded or move off-screen. A robust tracker must manage the point lifecycle:

1. Detect up to N points with Shi-Tomasi (cv2.goodFeaturesToTrack)
↓
2. Track points to next frame with cv2.calcOpticalFlowPyrLK
↓
3. Filter out lost tracks (where status == 0 or error > threshold)
↓
4. If active points < minimum_count: detect NEW points in empty regions
↓
5. Repeat seamlessly for thousands of frames

Complete Python KLT Tracker with Trajectory Trails

import cv2
import numpy as np

cap = cv2.VideoCapture(0)

# Parameters for Shi-Tomasi corner detection
feature_params = dict(
    maxCorners=150,
    qualityLevel=0.03,
    minDistance=10,
    blockSize=7
)

# Parameters for Lucas-Kanade optical flow
lk_params = dict(
    winSize=(21, 21),
    maxLevel=3,
    criteria=(cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 30, 0.01)
)

ret, first_frame = cap.read()
prev_gray = cv2.cvtColor(first_frame, cv2.COLOR_BGR2GRAY)
p0 = cv2.goodFeaturesToTrack(prev_gray, mask=None, **feature_params)

# Canvas to draw long trajectory trails
mask_canvas = np.zeros_like(first_frame)
colors = np.random.randint(0, 255, (200, 3))

while cap.isOpened():
    ret, frame = cap.read()
    if not ret:
        break

    frame_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    if p0 is not None and len(p0) > 0:
        # Calculate optical flow
        p1, status, err = cv2.calcOpticalFlowPyrLK(
            prev_gray, frame_gray, p0, None, **lk_params
        )

        # Select valid tracked points (status == 1)
        if p1 is not None:
            good_new = p1[status == 1]
            good_old = p0[status == 1]

            # Draw trajectory tracks
            for i, (new, old) in enumerate(zip(good_new, good_old)):
                a, b = new.ravel().astype(int)
                c, d = old.ravel().astype(int)
                col = colors[i % len(colors)].tolist()
                mask_canvas = cv2.line(mask_canvas, (a, b), (c, d), col, 2)
                frame = cv2.circle(frame, (a, b), 4, col, -1)

            p0 = good_new.reshape(-1, 1, 2)

    # Re-detect if points have dropped below threshold
    if p0 is None or len(p0) < 30:
        # Re-detect new features to replenish tracker
        new_pts = cv2.goodFeaturesToTrack(frame_gray, mask=None, **feature_params)
        if new_pts is not None:
            p0 = new_pts
            mask_canvas = np.zeros_like(frame)  # Reset faded canvas

    output = cv2.add(frame, mask_canvas)
    cv2.imshow('KLT Point Feature Tracker', output)

    prev_gray = frame_gray.copy()
    if cv2.waitKey(20) & 0xFF == 27:
        break

cap.release()
cv2.destroyAllWindows()
STEP 6 · TIME AS SPACE

Spatio-Temporal Analysis & Motion History Images

Instead of treating a video as individual disconnected photos, imagine stacking every frame on top of each other like a deck of cards. This creates a 3D block of space-time data: $I(x, y, t)$.

The 3D Spatio-Temporal Volume

If you slice this 3D data block horizontally along the $y$-axis, you get an X-T slice (Horizontal position vs Time):

Reading an X-T Slice:
  • Vertical Stripes: The pixel at $x$ remains the same color over time → Static background object.
  • Tilted Diagonal Lines: The position $x$ changes steadily as time $t$ progresses → Moving object!
  • Slope of the line ($\Delta x / \Delta t$): Equals the exact velocity of the object! Steep lines = slow motion; shallow lines = high speed.

Motion Energy vs Motion History Images (Bobick & Davis)

Motion Energy Image (MEI)

A binary snapshot indicating where motion occurred over a time window $\tau$:

Eτ(x, y, t) = ∪i=0..τ-1 D(x, y, t - i)

Shows the complete spatial footprint of an action (e.g., sitting down vs standing up look like a vertical blob).

Motion History Image (MHI)

A grayscale image where pixel intensity encodes how recently motion happened:

H(x, y, t) = τ  if motion at (x,y)
            = max(0, H(x, y, t-1) - 1)  else

Bright pixels = motion happened right now. Dim pixels = motion happened seconds ago.

ANALOGY: FOOTPRINTS IN THE SNOW

A fresh footprint in freshly fallen snow is crisp and deep (high value $\tau$). Older footprints from 10 minutes ago have slowly accumulated drifting snow and are faint. By looking at the brightness gradient of the footprints, you can instantly see which direction the person walked!

Extracting Motion Direction from MHI Gradients

By computing spatial gradients $(\partial H / \partial x, \partial H / \partial y)$ across the MHI, we can extract the precise flow orientation of the action without running expensive optical flow on every frame!

Python Practical: Building a Motion History Image (MHI)

import cv2
import numpy as np

cap = cv2.VideoCapture(0)

ret, frame = cap.read()
h, w = frame.shape[:2]

# Initialize MHI canvas (float32 array)
mhi = np.zeros((h, w), dtype=np.float32)
prev_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

MHI_DURATION = 30  # Number of frames motion persists (decay lifespan)

while cap.isOpened():
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # Frame difference to find active motion
    diff = cv2.absdiff(prev_gray, gray)
    _, motion_mask = cv2.threshold(diff, 30, 1, cv2.THRESH_BINARY)

    # 1. Decrement all existing values by 1 (decay over time)
    mhi[mhi > 0] -= 1

    # 2. Reset pixels with active motion to full duration
    mhi[motion_mask == 1] = MHI_DURATION

    # Normalize MHI to 0..255 for display
    mhi_display = np.uint8((mhi / MHI_DURATION) * 255)

    # Apply false-color heatmap (JET) so recency looks like thermal glow
    mhi_colored = cv2.applyColorMap(mhi_display, cv2.COLORMAP_JET)
    mhi_colored[mhi_display == 0] = 0  # Keep static background black

    cv2.imshow('Live Feed', frame)
    cv2.imshow('Motion History Image (Recency Heatmap)', mhi_colored)

    prev_gray = gray
    if cv2.waitKey(20) & 0xFF == 27:
        break

cap.release()
cv2.destroyAllWindows()
STEP 7 · 3D MOTION

Dynamic Stereo & Scene Flow

Standard stereo cameras give 3D depth $(X, Y, Z)$ at a single instant. Optical flow gives 2D velocities $(u, v)$ across time. Dynamic Stereo marries both into Scene Flow: the complete 3D velocity vector field in metric meters per second.

The Convergence of Stereo and Time

A dynamic stereo rig consists of two calibrated cameras (Left and Right) recording video simultaneously:

  • Spatial Disparity ($d$): Between Left and Right frames at time $t$. Using baseline $B$ and focal length $f$, depth is:
    Z = (f · B) / d
  • Temporal Optical Flow ($u, v$): Between Left frame at time $t$ and Left frame at time $t + 1$.
  • Scene Flow ($V_X, V_Y, V_Z$): Combining the 3D position $(X_t, Y_t, Z_t)$ and $(X_{t+1}, Y_{t+1}, Z_{t+1})$ yields the physical 3D velocity vector of the real world.

Autonomous Vehicle Case Study

Imagine a self-driving car equipped with a stereo camera driving down a busy city avenue:

Measurement Standard Optical Flow Dynamic Stereo (Scene Flow)
Crossing Pedestrian Shows 2D vector of 15 pixels/frame leftward. Cannot tell if child is 3 meters away or adult is 30 meters away! Calculates position $X=2.4\text{m}, Z=8.1\text{m}$ and velocity $V_X = -1.2\text{ m/s}$. Emergency braking triggered accurately.
Ego-Motion Every static building has massive optical flow because the car is moving. Confusing to interpret. Identifies that static buildings have $V_{\text{world}} = 0$ while car has $V_{\text{car}} = 12\text{ m/s}$. Separates camera motion from moving objects.

The 4-Way Correspondence Constraint

Left Frame (t) ←— Disparity d(t) —→ Right Frame (t)
↓ Temporal Flow ↓ Temporal Flow
Left Frame (t+1) ←— Disparity d(t+1) —→ Right Frame (t+1)

Because all four images must agree, scene flow algorithms use this closed loop to reject false depth matches and occlusions with remarkable precision.

STEP 8 · GLOBAL MOTION

Motion Parameter Estimation & RANSAC

When a handheld camera or drone moves, how do we estimate the camera's global motion while ignoring independent moving objects (like cars or people walking in front)?

Parametric Motion Models

Affine Motion (6 Degrees of Freedom)

Handles translation $(t_x, t_y)$, rotation $\theta$, anisotropic scale, and shear. Preserves parallel lines:

[ x' ] = [ a11   a12 ] [ x ] + [ tx ]
[ y' ] = [ a21   a22 ] [ y ] + [ ty ]

Ideal for video stabilization when camera rotation and zoom are moderate.

Planar Homography (8 Parameters)

The exact projective transformation between two views of a flat plane (or pure camera rotation about its center):

p' ∼ H · p   (where H is a 3x3 matrix)

Used for panoramic image stitching and aerial mapping.

Why Least Squares Fails: The Outlier Catastrophe

Suppose our tracker finds 100 feature vectors between frames. 80 points belong to background buildings (camera panning right), while 20 points belong to a bus driving left.

Least Squares Disaster: Standard least squares minimizes $\sum (y_i - \hat{y}_i)^2$. Because errors are squared, those 20 bus points exert enormous leverage, corrupting the solution completely!

The RANSAC Algorithm (Random Sample Consensus)

Fischler and Bolles (1981) introduced RANSAC to fit mathematical models in the presence of massive outlier contamination:

  1. Hypothesize: Randomly pick the minimum number of points required to fit the model (e.g., 3 point pairs for Affine, or 4 for Homography).
  2. Model: Compute transformation candidate $H_{\text{cand}}$ using only this minimal subset.
  3. Test & Score: Project all $N$ points using $H_{\text{cand}}$. Count how many points have error $\|p'_i - H_{\text{cand}} p_i\| < \epsilon$ (inliers).
  4. Iterate: Repeat steps 1–3 for $K$ iterations. Keep the model with the largest consensus inlier set.
  5. Refine: Re-estimate the final transformation matrix using all verified inliers via Least Squares.

Python Practical: Video Stabilization via RANSAC Affine Estimation

import cv2
import numpy as np

def estimate_camera_motion(prev_gray, curr_gray):
    """
    Estimates global background affine motion while ignoring
    independently moving objects using RANSAC.
    """
    # 1. Detect good features in previous frame
    prev_pts = cv2.goodFeaturesToTrack(
        prev_gray, maxCorners=300, qualityLevel=0.01, minDistance=15
    )
    if prev_pts is None:
        return np.eye(2, 3)

    # 2. Track points into current frame
    curr_pts, status, _ = cv2.calcOpticalFlowPyrLK(
        prev_gray, curr_gray, prev_pts, None
    )

    valid_prev = prev_pts[status == 1]
    valid_curr = curr_pts[status == 1]

    if len(valid_prev) < 10:
        return np.eye(2, 3)

    # 3. Fit 2D Rigid/Affine motion using RANSAC
    #    cv2.RANSAC filters out moving pedestrians/vehicles as outliers!
    M, inliers = cv2.estimateAffinePartial2D(
        valid_prev, valid_curr, method=cv2.RANSAC, ransacReprojThreshold=3.0
    )

    return M if M is not None else np.eye(2, 3)

# Example usage on simulated shake:
# dx, dy = M[0, 2], M[1, 2]  # Translation
# da = np.arctan2(M[1, 0], M[0, 0])  # Rotation angle
print("RANSAC motion estimator compiled successfully!")

Deep-Dive Concept Checks

Why does the aperture problem disappear at corner points?
At a flat edge, the image gradient exists in only one direction, leaving motion along the edge unconstrained. At a corner, image gradients point in at least two orthogonal directions ($\lambda_1 > 0$ and $\lambda_2 > 0$), making the structure tensor $A^T A$ full rank and invertible.
How does an image pyramid allow Lucas-Kanade to track fast-moving objects?
Lucas-Kanade uses a 1st-order Taylor series approximation which breaks if displacements exceed a few pixels. By downsampling the image into a pyramid (e.g. 1/8 scale), a 40-pixel displacement shrinks to 5 pixels, which LK solves easily before refining progressively down to the native resolution.
What is the difference between Scene Flow and Optical Flow?
Optical Flow is 2D and measures apparent pixel velocities $(dx/dt, dy/dt)$ on the flat sensor. Scene Flow is 3D and measures real-world physical velocities $(dX/dt, dY/dt, dZ/dt)$ in meters per second in 3D Euclidean space.
