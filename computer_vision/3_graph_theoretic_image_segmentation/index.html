Step 1 · A different representation

What if an image were a network?

Graph-theoretic segmentation represents visual pieces as nodes and their relationships as edges. Strongly related nodes stay together; weak connections are candidates for a cut.

Node

A pixel or region

One item that may receive a segment label.

Edge

A relationship

A connection between neighboring nodes.

Weight

Similarity

A number derived from color, texture, or boundary strength.

Why use a graph? K-means asks whether features are close in feature space. A graph can additionally insist that regions be spatial neighbors and explicitly represent their boundary.

Learning outcomes

  • Build the vocabulary of nodes, edges, weights, and cuts.
  • Explain why superpixels reduce a pixel graph.
  • Construct a region-adjacency graph (RAG).
  • Interpret the normalized-cut objective and its parameters.
Step 2 · Pixels become nodes

Neighbors exchange evidence

Connect each pixel to its four or eight immediate neighbors. Similar colors get strong edges; a sharp visual boundary gets a weak edge.

Choosing an edge weight

Similarity weight

w(i,j) = exp(−||cᵢ−cⱼ||² / σ). Similar neighboring colors create large weights.

Boundary weight

A strong image gradient can become a high cutting cost or a low similarity, depending on the graph definition.

Scale matters: if every pixel connects to every other pixel, memory and eigensolver cost grow quickly. Real workflows often reduce the graph first.
Step 3 · Make the graph smaller

Superpixels become region nodes

SLIC groups nearby, similarly colored pixels into compact initial regions. A region-adjacency graph connects only superpixels that touch.

Start with RGB

The original image contains hundreds of thousands of pixels.

Run SLIC

Produce a few hundred compact, connected superpixels.

Build the RAG

One node per superpixel; edges only where regions meet.

Assign weights

Compare mean colors across each neighboring pair.

What the parameters mean

n_segments

The requested starting granularity. More superpixels retain detail but create a larger graph.

compactness

The trade-off between color similarity and spatially regular superpixel shapes.

sigma

How quickly graph similarity falls as mean colors differ.

Connectivity

Which touching patterns are allowed to form graph edges.

Step 4 · Partition the graph

Normalized cut balances separation and coherence

A useful cut should remove weak connections between groups without isolating tiny nodes merely because they have few edges.

Cut cost

Separate dissimilar groups

Add the weights of edges crossing from group A to group B. Lower cross-group similarity is easier to cut.

Association

Keep coherent groups

Normalize by each group’s connection to the whole graph so tiny fragments are not automatically preferred.

Normalized-cut idea: minimize the fraction of each group’s total association that must be broken. The algorithm recursively makes two-way cuts until no beneficial split remains.
Current scikit-image workflow
from skimage import color, data, graph, segmentation

image = data.coffee()
superpixels = segmentation.slic(
    image, compactness=30, n_segments=400, start_label=1)
rag = graph.rag_mean_color(image, superpixels, mode="similarity")
segments = graph.cut_normalized(superpixels, rag)
result = color.label2rgb(segments, image, kind="avg", bg_label=0)

Reference: scikit-image Normalized Cut example.

Step 6 · Check & review

Trace the complete data flow

Image → superpixels → region-adjacency graph → weighted cut → output labels.

Why build a graph from superpixels instead of all pixels?

Superpixels compress many nearby pixels into a much smaller region graph.

What does a weak similarity edge suggest?

Weak similarity is evidence that cutting between those neighbors may be inexpensive.
