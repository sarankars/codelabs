Why point features?

Tracking every pixel is expensive and ambiguous (the aperture problem). Instead, we track a small set of distinctive points — corners, blobs, or keypoints — that are easy to find again in the next frame.

STEP 2 · FOUNDATION

What Is Motion in a Video?

A video is a sequence of 2D images captured at regular time intervals. Motion appears when the intensity pattern at a pixel location changes across frames.

Frame difference — the simplest motion signal

The most basic way to see motion is to subtract two consecutive frames:

D(x, y) = I(x, y, t+1) − I(x, y, t)

Where I(x,y,t) is the intensity of pixel (x,y) at time t. Large differences indicate motion.

Static scene

If nothing moves, D ≈ 0 everywhere. Only sensor noise remains.

Moving object

D is large along the boundary of the moving object and zero in static regions.

The Aperture Problem

Problem: Aperture Problem

A plain edge (uniform strip of colour) moving perpendicular to itself gives a strong signal. But the same edge moving parallel to itself gives zero difference — motion is invisible! Only distinctive points like corners let us resolve motion direction uniquely.

Horizontal edge moving left-right:  D = 0  (invisible motion)
Corner point moving left-right:     D != 0 (detectable motion)

Why is a long, uniform edge difficult to track?

STEP 3 · FEATURES

What Makes a Good Feature Point?

Not every pixel is worth tracking. A good feature point must be detectable, localizable, and re-detectable after motion.

Three types of local structure

Flat region

All directions look the same. Shifting the window in any direction gives the same intensity pattern. Cannot be localized.

[ ] [ ] [ ]
Edge

One direction gives a change; the other is uniform. Partially localizable.

Corner

Shifting in any direction gives a different intensity pattern. Fully localizable in 2D.

Blob / Keypoint

A compact region distinct from its surroundings at a particular scale. Also fully localizable and scale-aware.

KEY INSIGHT

Good tracking features are usually corners or blobs because they are constrained in all directions and can therefore be re-found accurately after the camera or object moves.

STEP 4 · DETECTION

Harris Corner Detector

The Harris detector (Harris & Stephens, 1988) measures how intensity changes when a small analysis window is shifted in every direction. Corners produce large changes in all directions.

The structure tensor M

For each pixel (x,y), compute the image gradients Ix (horizontal) and Iy (vertical), then build M over a small window:

M = Σwindow [ Ix²   IxIy ]
                    [ IxIy   Iy² ]

What the eigenvalues tell us

λ₁λ₂Structure type
≈ 0≈ 0Flat region — no gradient in any direction
Large≈ 0Edge — gradient only in one direction
LargeLargeCorner — gradient in all directions

The Harris response score R

R = det(M) − k · trace(M)²
where det(M) = λ₁λ₂ and trace(M) = λ₁ + λ₂
k is typically 0.04 – 0.06
R ≫ 0

Corner — both eigenvalues are large.

R ≪ 0

Edge — one eigenvalue is large, the other small.

R ≈ 0

Flat — both eigenvalues are small.

Non-maximum suppression

After computing R for every pixel, keep only local maxima above a threshold as final corner detections.

Harris is rotation-invariant

The eigenvalues of M do not change when the image is rotated. Harris corners are found at the same physical location even after the camera rotates.

LIMITATION

Harris is not scale-invariant. A corner detected at one resolution may not be detected if the image is zoomed in or out significantly.

STEP 5 · PRACTICAL

Harris Corner Detection in Python

Use OpenCV's cornerHarris to find corners in an image, threshold the response, and mark the detected corners in red.

Step-by-step walkthrough

  1. Read and convert to grayscale. Harris works on a single intensity channel.
  2. Compute the Harris response R for every pixel using cv2.cornerHarris().
  3. Dilate the response to make corners slightly larger and easier to see.
  4. Threshold R — keep pixels where R > threshold × max(R).
  5. Mark corners on the original image in red.
import cv2
import numpy as np
import matplotlib.pyplot as plt

# 1. Load image
img  = cv2.imread('image.jpg')
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
gray = np.float32(gray)           # Harris requires float32

# 2. Compute Harris response R
#    blockSize : neighbourhood size for M computation
#    ksize     : Sobel kernel size for gradients
#    k         : Harris free parameter
R = cv2.cornerHarris(gray, blockSize=2, ksize=3, k=0.04)

# 3. Dilate response (optional - helps visualise)
R_dilated = cv2.dilate(R, None)

# 4. Threshold and mark corners in red
output    = img.copy()
threshold = 0.01 * R_dilated.max()        # 1% of maximum R
output[R_dilated > threshold] = [0, 0, 255]

# 5. Display
plt.figure(figsize=(12, 5))
plt.subplot(1, 2, 1)
plt.imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))
plt.title('Original Image')
plt.axis('off')
plt.subplot(1, 2, 2)
plt.imshow(cv2.cvtColor(output, cv2.COLOR_BGR2RGB))
plt.title('Harris Corners (red)')
plt.axis('off')
plt.tight_layout()
plt.show()

blockSizeNeighbourhood window size for M2 or 3

kHarris sensitivity parameter0.04 – 0.06
thresholdFraction of max R above which a pixel is a corner0.01 – 0.05

STEP 6 · DETECTION

Shi-Tomasi: “Good Features to Track”

Shi and Tomasi (1994) proposed using the minimum eigenvalue of M directly as the corner score — a stricter and more reliable criterion for tracking.

Score = min(λ₁, λ₂)

A pixel is a corner if its minimum eigenvalue exceeds a threshold. Both eigenvalues must be large — meaning the patch is constrained in all directions.

Harris R

Uses det − k·trace². Sensitive to the choice of k. Can sometimes misclassify edges.

Shi-Tomasi score

Uses min(λ₁, λ₂). No free parameter. Proven optimal for tracking.

OpenCV: goodFeaturesToTrack

import cv2
import numpy as np
import matplotlib.pyplot as plt

img    = cv2.imread('image.jpg')
gray   = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# Detect up to 200 strongest corners
# qualityLevel : fraction of best corner score to accept (0-1)
# minDistance  : minimum pixel distance between two corners
corners = cv2.goodFeaturesToTrack(
    gray,
    maxCorners   = 200,
    qualityLevel = 0.01,
    minDistance  = 10
)

# corners shape: (N, 1, 2)  -  N points, each [x, y]
corners = np.int32(corners)

output = img.copy()
for corner in corners:
    x, y = corner.ravel()
    cv2.circle(output, (x, y), 5, (0, 255, 0), -1)

plt.figure(figsize=(12, 5))
plt.subplot(1, 2, 1)
plt.imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))
plt.title('Original')
plt.axis('off')
plt.subplot(1, 2, 2)
plt.imshow(cv2.cvtColor(output, cv2.COLOR_BGR2RGB))
plt.title('Shi-Tomasi Corners (green)')
plt.axis('off')
plt.tight_layout()
plt.show()

print(f"Detected {len(corners)} corners")

STEP 7 · DETECTION

SIFT — Scale-Invariant Feature Transform

SIFT (Lowe, 2004) finds blob-like keypoints that are invariant to both scale and rotation, making it far more robust than Harris for matching features across large viewpoint changes.

How SIFT detects keypoints

Build a Gaussian scale-space pyramid
↓
Compute Difference of Gaussians (DoG) between adjacent levels
↓
Find local extrema in (x, y, scale) space
↓
Reject low-contrast points and edge responses
↓
Assign dominant orientation (rotation invariance)
↓
Keypoint: (x, y, scale, orientation)
Gaussian blur at scale σ

L(x,y,σ) = G(σ) * I(x,y)
Progressively blurs the image to suppress fine detail.

Difference of Gaussians (DoG)

DoG = L(x,y,kσ) − L(x,y,σ)
Approximates the Laplacian of Gaussian — a blob detector across scales.

Python + OpenCV: detect SIFT keypoints

import cv2

print(f"Number of SIFT keypoints: {len(keypoints)}")

STEP 8 · TRACKING

Optical Flow — Theory

Optical flow is the apparent motion of brightness patterns in an image sequence. It assigns a velocity vector (u, v) to pixels, describing how far they moved between two frames.

The Brightness Constancy Assumption

The core assumption of optical flow: a pixel's intensity stays the same as it moves.

I(x, y, t) = I(x + u, y + v, t + 1)

Applying a first-order Taylor expansion gives the optical flow constraint equation:

Ix · u + Iy · v + It = 0
TermMeaning
Ix, IySpatial image gradients (∂I/∂x, ∂I/∂y)
ItTemporal gradient (∂I/∂t) — frame difference
u, vHorizontal and vertical flow (unknowns to solve for)
Aperture problem again!

One equation, two unknowns (u, v). The system is underdetermined for a single pixel. Additional constraints are needed: a smoothness prior (dense flow) or a local patch constraint (Lucas-Kanade).

Two families of optical flow methods

Dense optical flow

Computes a flow vector for every pixel. Rich, but computationally heavier. Example: Farnebäck method.

Sparse optical flow

Computes flow only for a set of pre-selected feature points. Much faster. Example: Lucas-Kanade / KLT tracker.

STEP 9 · TRACKING

Lucas-Kanade & the KLT Tracker

The Lucas-Kanade method (1981) solves the aperture problem by assuming all pixels in a small window around a feature point share the same flow vector.

The window constraint

For a window of n pixels, one equation per pixel:

Ix1*u + Iy1*v = -It1
Ix2*u + Iy2*v = -It2
   ...
Ixn*u + Iyn*v = -Itn

In matrix form: A · [u, v]¹ = b

[u, v]¹ = (A¹A)−¹ A¹ b

Notice: A¹A is exactly the Harris structure tensor M! The system is well-conditioned only when M has two large eigenvalues — i.e. the feature is a corner.

Why corners are the best features to track

The KLT solution is reliable only when both eigenvalues of M are large — precisely the Harris corner condition. Edges and flat regions give poorly-conditioned M matrices and unreliable flow estimates.

Pyramidal KLT for large motion

Large motions break the small-displacement assumption. The solution: build an image pyramid.

Image at full resolution (level 0)
↓ downsample ×2
Image at half resolution (level 1)
↓ downsample ×2
Image at quarter resolution (level 2)
↓
Estimate coarse flow at top level
↓ propagate and refine downward
Final sub-pixel accurate flow at level 0
OPENCV

cv2.calcOpticalFlowPyrLK implements pyramidal Lucas-Kanade. The parameter maxLevel controls the number of pyramid levels.

STEP 10 · PRACTICAL

Sparse KLT Tracking in Python

Track Shi-Tomasi corners across video frames using cv2.calcOpticalFlowPyrLK and draw motion trails for each tracked point.

Step-by-step algorithm

  1. Read the first frame and convert to grayscale. Detect Shi-Tomasi corners as initial tracking points.
  2. For each subsequent frame, call calcOpticalFlowPyrLK to predict where each corner moved.
  3. Check the status array — discard points that the tracker lost (status = 0).
  4. Draw motion trails by recording the history of each point's position.
  5. Update the previous frame and previous points for the next iteration.
import cv2
import numpy as np

# Parameters for Shi-Tomasi feature detection
FEATURE_PARAMS = dict(
    maxCorners   = 200,
    qualityLevel = 0.01,
    minDistance  = 10,
    blockSize    = 7
)

# Parameters for Lucas-Kanade optical flow
LK_PARAMS = dict(
    winSize  = (21, 21),    # search window around each point
    maxLevel = 3,           # pyramid levels (0 = no pyramid)
    criteria = (cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 30, 0.01)
)

COLOURS = np.random.randint(0, 255, (200, 3))

# Open video (use 0 for webcam)
cap = cv2.VideoCapture('video.mp4')

ret, old_frame = cap.read()
old_gray       = cv2.cvtColor(old_frame, cv2.COLOR_BGR2GRAY)

# Detect initial corners in the first frame
p0 = cv2.goodFeaturesToTrack(old_gray, mask=None, **FEATURE_PARAMS)

# Blank canvas for drawing trails
trail_canvas = np.zeros_like(old_frame)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    frame_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # Track points with pyramidal Lucas-Kanade
    # p1     : predicted new positions
    # status : 1 if tracked successfully, 0 if lost
    p1, status, error = cv2.calcOpticalFlowPyrLK(
        old_gray, frame_gray, p0, None, **LK_PARAMS
    )

    if p1 is None or status is None:
        p0       = cv2.goodFeaturesToTrack(frame_gray, mask=None, **FEATURE_PARAMS)
        old_gray = frame_gray.copy()
        continue

    good_new = p1[status == 1]   # new positions of good points
    good_old = p0[status == 1]   # old positions of good points

    # Draw motion trails
    for i, (new, old) in enumerate(zip(good_new, good_old)):
        a, b   = new.ravel().astype(int)
        c, d   = old.ravel().astype(int)
        colour = COLOURS[i % len(COLOURS)].tolist()
        trail_canvas = cv2.line(trail_canvas, (a, b), (c, d), colour, 2)
        frame        = cv2.circle(frame, (a, b), 5, colour, -1)

    # Composite trails over current frame
    output = cv2.add(frame, trail_canvas)
    cv2.imshow('KLT Tracker', output)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

    # Update for next iteration
    old_gray = frame_gray.copy()
    p0       = good_new.reshape(-1, 1, 2)

cap.release()
cv2.destroyAllWindows()

Key parameters explained

ParameterMeaning
winSizeSearch window around each point. Larger = handles bigger motion.
maxLevelPyramid levels. 0 = no pyramid. 3–4 = handles large fast motion.
criteriaIteration stop condition: max iterations or convergence threshold.
statusOutput: 1 = point tracked successfully, 0 = point lost.

STEP 11 · PRACTICAL

Dense Optical Flow — Farnebäck Method

Dense optical flow computes a motion vector for every pixel. OpenCV's calcOpticalFlowFarneback uses polynomial expansion to estimate a smooth flow field across the entire image.

How it works

Approximate local intensity with a polynomial near each pixel
↓
Estimate displacement that minimises the difference in polynomial coefficients
↓
Apply Gaussian regularisation for a smooth, consistent flow field
↓
Output: two-channel array (u, v) — one vector per pixel

Visualising flow with HSV colour mapping

Encode direction as hue and magnitude as brightness.

import cv2
import numpy as np

cap = cv2.VideoCapture('video.mp4')

ret, old_frame = cap.read()
old_gray = cv2.cvtColor(old_frame, cv2.COLOR_BGR2GRAY)

# Pre-allocate HSV canvas
hsv       = np.zeros_like(old_frame)
hsv[...,1] = 255   # full saturation

while True:
    ret, frame = cap.read()
    if not ret:
        break

    frame_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # Compute dense optical flow
    flow = cv2.calcOpticalFlowFarneback(
        old_gray, frame_gray, None,
        pyr_scale  = 0.5,   # pyramid scale between levels
        levels     = 3,     # pyramid levels
        winsize    = 15,    # smoothing window size
        iterations = 3,     # iterations at each level
        poly_n     = 5,     # pixel neighbourhood for polynomial
        poly_sigma = 1.2,   # Gaussian sigma for polynomial
        flags      = 0
    )
    # flow shape: (height, width, 2)
    # flow[..., 0] = u (horizontal velocity)
    # flow[..., 1] = v (vertical velocity)

    # Convert (u,v) to polar (magnitude, angle)
    magnitude, angle = cv2.cartToPolar(flow[..., 0], flow[..., 1])

    # Encode direction as Hue (0-180 for OpenCV HSV)
    hsv[..., 0] = angle * 180 / np.pi / 2
    # Encode magnitude as Value, normalised
    hsv[..., 2] = cv2.normalize(magnitude, None, 0, 255, cv2.NORM_MINMAX)

    # Convert HSV to BGR for display
    flow_rgb = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)
    combined = np.hstack([frame, flow_rgb])
    cv2.imshow('Dense Optical Flow', combined)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

    old_gray = frame_gray.copy()

cap.release()
cv2.destroyAllWindows()
INTERPRET

In the HSV visualisation: colour tells you which direction pixels are moving, and brightness tells you how fast they are moving.

Sparse (KLT)

Fast. Tracks ~50–200 interest points. Ideal for real-time object tracking and SLAM.

Dense (Farnebäck)

Slower. Gives a motion vector for every pixel. Ideal for action recognition and scene flow analysis.

STEP 12 · ROBUSTNESS

Handling Point Loss: Re-detection Strategy

As tracking progresses, points are lost due to occlusion, fast motion, or leaving the frame. A robust tracker periodically re-detects new features to maintain tracking density.

Why points get lost

Occlusion

A tracked point passes behind another object and its appearance changes completely.

Out of frame

The tracked object exits the image boundary.

Large motion blur

Fast movement blurs the patch beyond recognition.

Illumination change

Sudden lighting shifts break the brightness constancy assumption.

Re-detection when points fall below a threshold

import cv2
import numpy as np

FEATURE_PARAMS = dict(maxCorners=200, qualityLevel=0.01,
                      minDistance=10, blockSize=7)
LK_PARAMS      = dict(winSize=(21, 21), maxLevel=3,
                      criteria=(cv2.TERM_CRITERIA_EPS |
                                cv2.TERM_CRITERIA_COUNT, 30, 0.01))
MIN_FEATURES   = 50   # re-detect when fewer than this many points remain

cap          = cv2.VideoCapture('video.mp4')
ret, frame   = cap.read()
old_gray     = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
p0           = cv2.goodFeaturesToTrack(old_gray, mask=None, **FEATURE_PARAMS)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    frame_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    if p0 is not None and len(p0) > 0:
        p1, status, _ = cv2.calcOpticalFlowPyrLK(
            old_gray, frame_gray, p0, None, **LK_PARAMS)
        if p1 is not None and status is not None:
            good_new = p1[status == 1]
            good_old = p0[status == 1]
        else:
            good_new = np.empty((0, 2))
    else:
        good_new = np.empty((0, 2))

    for pt in good_new:
        x, y = pt.ravel().astype(int)
        cv2.circle(frame, (x, y), 4, (0, 255, 0), -1)

    # Re-detect if too few points remain
    if len(good_new) < MIN_FEATURES:
        print(f"Re-detecting: only {len(good_new)} points left")
        p0 = cv2.goodFeaturesToTrack(frame_gray, mask=None, **FEATURE_PARAMS)
    else:
        p0 = good_new.reshape(-1, 1, 2)

    cv2.putText(frame, f"Points: {len(good_new)}", (10, 30),
                cv2.FONT_HERSHEY_SIMPLEX, 0.8, (255, 255, 0), 2)
    cv2.imshow('Robust KLT', frame)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

    old_gray = frame_gray.copy()

cap.release()
cv2.destroyAllWindows()
Best practice:

Set MIN_FEATURES to about 25% of your target feature count. This ensures tracking never degrades too far before recovering with fresh features.

STEP 13 · MATCHING

SIFT Feature Matching Between Frames

When KLT loses a point, SIFT descriptors can match features between a reference frame and the current frame, enabling re-identification across large changes in viewpoint or scale.

Matching pipeline

Detect SIFT keypoints and 128-D descriptors in frame A
↓
Detect SIFT keypoints and descriptors in frame B
↓
Match descriptors using FLANN nearest-neighbour search
↓
Apply Lowe's ratio test to discard ambiguous matches
↓
Optional: compute homography with RANSAC to remove outliers
import cv2
import matplotlib.pyplot as plt

img1 = cv2.imread('frame_001.jpg', cv2.IMREAD_GRAYSCALE)
img2 = cv2.imread('frame_020.jpg', cv2.IMREAD_GRAYSCALE)

# 1. Detect and compute SIFT descriptors
sift = cv2.SIFT_create(nfeatures=1000)
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

# 2. Match using FLANN (fast approximate nearest neighbour)
FLANN_INDEX_KDTREE = 1
index_params  = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)
flann         = cv2.FlannBasedMatcher(index_params, search_params)
matches       = flann.knnMatch(des1, des2, k=2)  # 2 nearest neighbours

# 3. Lowe's ratio test
good_matches = []
for m, n in matches:
    if m.distance < 0.75 * n.distance:   # best match << second best
        good_matches.append(m)

print(f"Total: {len(matches)},  Good: {len(good_matches)}")

# 4. Draw matches
result = cv2.drawMatches(
    img1, kp1, img2, kp2, good_matches[:60], None,
    matchColor=(0, 255, 0),
    singlePointColor=(255, 0, 0),
    flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS
)

plt.figure(figsize=(16, 6))
plt.imshow(result, cmap='gray')
plt.title(f'SIFT Matches: {len(good_matches)} good after ratio test')
plt.axis('off')
plt.tight_layout()
plt.show()

Lowe's ratio test explained

Why ratio test?

For each descriptor in image A, FLANN finds the two closest descriptors in image B. If the best match distance is much less than the second best (ratio < 0.75), the match is unambiguous and accepted. Otherwise it's discarded as a false match.

Accept if: d(best) / d(second_best) < 0.75

    """

                          minDistance=10, blockSize=7)

                          criteria=(cv2.TERM_CRITERIA_EPS |
                                    cv2.TERM_CRITERIA_COUNT, 30, 0.01))
    COLOURS = np.random.randint(0, 255, (max_corners, 3))

        print("ERROR: Cannot read first frame"); return

    old_gray     = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    p0           = cv2.goodFeaturesToTrack(old_gray, mask=None, **FEATURE_PARAMS)
    trail_canvas = np.zeros_like(frame)
    frame_count  = 0

    while True:
        ret, frame = cap.read()
        if not ret:
            break

        frame_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        frame_count += 1
        good_new = np.empty((0, 2))
        good_old = np.empty((0, 2))

        if p0 is not None and len(p0) > 0:
            p1, status, _ = cv2.calcOpticalFlowPyrLK(
                old_gray, frame_gray, p0, None, **LK_PARAMS)
            if p1 is not None and status is not None:
                good_new = p1[status == 1]
                good_old = p0[status == 1]

        for i, (new, old) in enumerate(zip(good_new, good_old)):
            a, b = new.ravel().astype(int)
            c, d = old.ravel().astype(int)
            col  = COLOURS[i % len(COLOURS)].tolist()
            trail_canvas = cv2.line(trail_canvas, (a, b), (c, d), col, 2)
            frame        = cv2.circle(frame, (a, b), 4, col, -1)

        output = cv2.add(frame, trail_canvas)

        if len(good_new) < min_features:
            p0           = cv2.goodFeaturesToTrack(frame_gray, mask=None, **FEATURE_PARAMS)
            trail_canvas = np.zeros_like(frame)  # reset trails after re-detection
        else:
            p0 = good_new.reshape(-1, 1, 2)

        cv2.putText(output, f"Frame: {frame_count}", (10, 30),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.7, (200, 200, 200), 2)
        cv2.putText(output, f"Points: {len(good_new)}", (10, 60),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.7, (0, 255, 0), 2)

        cv2.imshow('Full Tracking Pipeline', output)
        if cv2.waitKey(30) & 0xFF == ord('q'):
            break

        old_gray = frame_gray.copy()

    cap.release()
    cv2.destroyAllWindows()
    print(f"Processed {frame_count} frames.")

STEP 15 · APPLICATIONS

Real-World Applications

Point feature tracking is a fundamental building block in many important computer vision systems.

📹 Video Stabilisation

Track features across frames to estimate global camera motion (homography). Warp frames to compensate, producing smooth video from shaky footage.

🤖 SLAM

Robot tracks features to estimate its own camera pose (position + orientation) while simultaneously building a 3D map of the environment.

🎬 Augmented Reality

Track a planar marker's feature points to estimate the homography, then overlay 3D graphics in correct perspective on every frame.

🚗 Autonomous Driving

Track features to compute ego-motion and detect independently moving objects (pedestrians, other vehicles).

🎯 Sports Analysis

Track players and ball across broadcast video frames to extract trajectory statistics and tactical patterns.

🩹 Medical Imaging

Track tissue motion in cardiac MRI or ultrasound to measure heart deformation and detect anomalies.

When does KLT fail?
KLT fails when motion is too large for the search window (even with pyramids), when the brightness constancy assumption breaks (strong illumination change), or when a feature gets occluded. Use SIFT-based matching or re-detection to recover.
What is the aperture problem and how do we solve it?
The aperture problem means that for a local window, motion along an edge direction is invisible — only the perpendicular component is measurable. Corners solve this by providing a gradient constraint in all directions. Lucas-Kanade exploits a window of pixels to get enough equations to solve for both u and v uniquely.
Why does pyramid KLT handle fast motion?
At the top of the pyramid, the image is small and even large real-world displacements appear small. The tracker estimates a coarse flow at the top, then refines it level by level down to full resolution, accumulating the total flow. This extends the effective search range without requiring a prohibitively large window.
SIFT vs. KLT for tracking?
KLT is faster and works frame-to-frame, but cannot handle large viewpoint changes. SIFT is slower but robust to scale, rotation, and large viewpoint changes. In practice, use KLT for frame-to-frame tracking and SIFT when re-identification after loss is needed.
STEP 17 · REVISION

Revision & Practice

Review all key concepts before moving on to deeper topics in motion analysis.

What is the brightness constancy assumption?
A pixel's intensity stays the same as it moves between frames: I(x,y,t) = I(x+u, y+v, t+1). This gives the optical flow constraint equation Ix·u + Iy·v + It = 0.
What is the aperture problem?
The optical flow constraint has two unknowns (u, v) but only one equation per pixel. Motion along an edge is undetectable — only the perpendicular component can be estimated.
Why are corners the best features to track?
The structure tensor M has two large eigenvalues at a corner, making the Lucas-Kanade system well-conditioned with a unique, accurate flow estimate. Edges and flat regions give degenerate M matrices.
What does Harris response R > 0 mean?
Both eigenvalues of M are large → the pixel is a corner. R << 0 means edge; R ≈ 0 means flat region.
How does Shi-Tomasi improve on Harris?
Shi-Tomasi uses min(λ₁, λ₂) directly as the score, with no free parameter k. This is provably optimal for tracking.
What does the SIFT 128-D descriptor capture?
A histogram of gradient orientations computed over a 16×16 neighbourhood. It is invariant to rotation and moderately invariant to illumination changes.
What is Lowe's ratio test?
Accept a SIFT match only if d(best) / d(second_best) < 0.75. This removes ambiguous matches where two descriptors are nearly equally close.
What does status=1 from calcOpticalFlowPyrLK mean?
The tracker successfully found that point in the new frame. status=0 means the point was lost.
Dense vs sparse optical flow — when to use each?
Sparse (KLT): real-time tracking, robotics, low compute. Dense (Farnebäck): action recognition, full scene analysis, more compute needed.
