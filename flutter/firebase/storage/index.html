STEP 1 · FOUNDATIONS

Why Firebase Cloud Storage?

Learn why apps need dedicated file storage, how it compares to Cloud Firestore, and the golden architecture for handling user media in Flutter.

By the end of this codelab: You will master Firebase Cloud Storage in Flutter! You will pick photos from camera/gallery, upload raw bytes and files, track live progress percentages with reactive indicators, fetch secure download URLs, connect storage files with Firestore documents, delete files cleanly, and enforce strict backend Security Rules.

The Big Question: Why Not Put Photos in Firestore?

In the previous codelabs, you learned how to store user profiles and tasks in Cloud Firestore. When beginners want to add profile photos or post attachments, their first instinct is often to encode the photo as a Base64 text string and save it into a Firestore document. Why is that a bad idea?

📄 Cloud Firestore (Text & Data)

Best for lightweight, structured text (names, prices, timestamps). Each Firestore document has a hard maximum size limit of 1 MB. A single phone camera photo is often 4 MB to 12 MB, which will immediately crash your Firestore write!

🗂️ Firebase Cloud Storage (Binary Files)

Built specifically for large binary blobs: images, videos, audio notes, PDFs, and ZIP archives. Powered by Google Cloud Storage, it can effortlessly store files up to 5 Terabytes each with automatic global CDN caching!

The Golden 2-Step Architecture

Every professional mobile application (Instagram, WhatsApp, Uber, Twitter) uses this exact division of labor:

📱 User picks Photo (3 MB) │ ├─► STEP 1: Upload raw photo to Firebase Storage │ URL returned: "https://firebasestorage.googleapis.com/.../photo.jpg" │ └─► STEP 2: Save the small HTTPS URL + caption into Cloud Firestore! { "userId": "usr_9981", "caption": "Sunset at the beach 🌅", "imageUrl": "https://firebasestorage.googleapis.com/...", "uploadedAt": 1728500000 }
Simple Analogy: Think of Firebase Storage as a giant secure warehouse or Google Drive where large physical boxes are kept. Think of Firestore as the library index card that records what is in the box and holds the secret key (the Download URL) pointing to its shelf!

STEP 3 · FILE PATHS

Storage References & Paths

Understand how files are addressed in Firebase Storage using hierarchical references.

What is a Reference?

In Firebase Cloud Storage, you interact with files through an object called a Reference (Reference). A reference is a lightweight pointer to a location in your cloud bucket. It does not download or upload anything by itself; it simply points to a destination path.

root ref (/) │ ├── "avatars" (folder) │ └── "user_123.jpg" <--- Reference pointing to this file! │ └── "posts" (folder) └── "2026" └── "vacation.png"

How to Create References in Dart

Get the root storage instance using FirebaseStorage.instance.ref(), then use .child() to navigate folders:

import 'package:firebase_storage/firebase_storage.dart';

// 1. Get the root bucket reference
final storageRef = FirebaseStorage.instance.ref();

// 2. Point to a folder called 'avatars'
final avatarsRef = storageRef.child('avatars');

// 3. Point to a specific file inside 'avatars'
final userAvatarRef = avatarsRef.child('user_abc.jpg');

// Or build the complete path in a single child call:
final directRef = FirebaseStorage.instance.ref().child('avatars/user_abc.jpg');

Useful Reference Properties

Property / MethodExample OutputWhat it tells you
ref.name "user_abc.jpg" The filename at the end of the path.
ref.fullPath "avatars/user_abc.jpg" The complete cloud path from bucket root.
ref.bucket "my-app-codelab.firebasestorage.app" The Google Cloud Storage bucket name.
ref.parent Reference to "avatars" Points to the folder one level up.
Pro-Tip for Clean Structure: Always prefix user files with their unique User ID (UID):
final userRef = FirebaseStorage.instance.ref().child('users/$uid/avatar.jpg');
This makes writing Security Rules simple and prevents users from overwriting each other's uploads!

STEP 4 · USER INPUT

Picking Images with ImagePicker

Allow users to select an image from the Photo Gallery or take a photo with the Camera in Flutter.

Understanding XFile (The Cross-Platform Hero)

When using the image_picker package, picked files are returned as an XFile object. Why is this important?

  • On mobile (Android & iOS), a file exists at a local file system path like /data/user/0/.../image.jpg.
  • On Flutter Web, browsers have no direct filesystem access! Files exist as raw in-memory blobs.
  • XFile works everywhere! It provides xfile.path on mobile AND xfile.readAsBytes() which works seamlessly on Web, Mobile, and Desktop!

Image Picker Helper Method

Here is a clean Dart method to pick an image from the gallery or camera:

import 'package:image_picker/image_picker.dart';

class MediaService {
  final ImagePicker _picker = ImagePicker();

  // Pick an image from device gallery
  Future<XFile?> pickFromGallery() async {
    final XFile? image = await _picker.pickImage(
      source: ImageSource.gallery,
      maxWidth: 1024,  // Good practice: resize large camera images
      maxHeight: 1024,
      imageQuality: 85, // Compresses to 85% to save bandwidth & storage costs
    );
    return image;
  }

  // Snap a new picture with the device camera
  Future<XFile?> snapFromCamera() async {
    final XFile? photo = await _picker.pickImage(
      source: ImageSource.camera,
      maxWidth: 1024,
      maxHeight: 1024,
      imageQuality: 85,
    );
    return photo;
  }
}

Previewing the Picked Image in UI

Once picked, you can preview the photo to the user before they hit "Upload". Using readAsBytes() lets you preview on both mobile and web effortlessly:

import 'dart:typed_data';

STEP 5 · CORE OPERATION

Uploading to Cloud Storage

Upload local files, raw bytes, or strings to Firebase Cloud Storage with proper metadata.

The Three Upload Methods

Firebase Storage provides three different methods depending on what format your data is in:

MethodParametersBest Used For
putData() Uint8List bytes, [SettableMetadata] Recommended! Works identically across Mobile, Web, and Desktop. Works directly with XFile.readAsBytes().
putFile() File file, [SettableMetadata] Mobile/Desktop only (requires dart:io). Will crash if run on Flutter Web.
putString() String data, {PutStringFormat} Text files, Base64 strings, or raw data URLs.

Writing the Upload Function

Here is the standard, production-ready upload function using putData(). Always provide a SettableMetadata with the correct contentType (e.g. image/jpeg or image/png) so the browser knows how to render the image instead of downloading it as a raw binary file!

import 'dart:typed_data';
import 'package:firebase_storage/firebase_storage.dart';
import 'package:image_picker/image_picker.dart';

Future<String> uploadImageToStorage({
  required XFile xfile,
  required String folderName,
}) async {
  // 1. Read bytes from XFile (cross-platform safe)
  final Uint8List fileBytes = await xfile.readAsBytes();

  // 2. Generate a unique filename using timestamp
  final String fileName = '${DateTime.now().millisecondsSinceEpoch}_${xfile.name}';

  // 3. Create reference to the storage destination
  final Reference storageRef = FirebaseStorage.instance
      .ref()
      .child('$folderName/$fileName');

  // 4. Specify metadata (mime-type)
  final SettableMetadata metadata = SettableMetadata(
    contentType: xfile.mimeType ?? 'image/jpeg',
    customMetadata: {
      'pickedBy': 'flutter_app',
    },
  );

  // 5. Start the upload task
  final UploadTask uploadTask = storageRef.putData(fileBytes, metadata);

  // 6. Wait for upload to complete
  final TaskSnapshot snapshot = await uploadTask;

  // 7. Retrieve and return the public HTTPS download URL
  final String downloadUrl = await snapshot.ref.getDownloadURL();
  return downloadUrl;
}
Common Mistake: Omitting contentType: 'image/jpeg'! If you upload raw bytes without metadata, Firebase defaults to application/octet-stream. When a user opens the download URL in a web browser, the browser will force-download the file instead of displaying it inline!
STEP 6 · USER EXPERIENCE

Live Upload Progress & Pause/Resume

Show responsive progress bars, byte transfer counters, and control uploads with pause, resume, and cancel.

Why Show Progress?

When users upload 5 MB images over mobile data or slow 3G connections, uploads can take several seconds. Without feedback, users think the app is frozen and tap buttons repeatedly. UploadTask provides a real-time reactive Stream of TaskSnapshot events!

The Upload Lifecycle States

TaskState.running

File is actively transmitting bytes to Google Cloud servers.

TaskState.paused

Upload is suspended by user action or network interruption.

TaskState.success

All bytes received and verified. Download URL is now ready!

TaskState.canceled

User cancelled the upload or app was closed.

Listening to Progress Events

Calculate progress by dividing bytesTransferred by totalBytes:

final UploadTask task = storageRef.putData(fileBytes, metadata);

// Listen to live stream updates
task.snapshotEvents.listen((TaskSnapshot snapshot) {
  switch (snapshot.state) {
    case TaskState.running:
      final double progress = snapshot.bytesTransferred / snapshot.totalBytes;
      final int percent = (progress * 100).toInt();
      debugPrint('Uploading: $percent% (${snapshot.bytesTransferred} / ${snapshot.totalBytes} bytes)');
      break;
    case TaskState.paused:
      debugPrint('Upload paused.');
      break;
    case TaskState.success:
      debugPrint('Upload finished successfully! 🎉');
      break;
    case TaskState.canceled:
      debugPrint('Upload was canceled.');
      break;
    case TaskState.error:
      debugPrint('Upload failed with error.');
      break;
  }
});

Controlling Tasks (Pause, Resume, Cancel)

// Pause an active upload
task.pause();

// Resume a paused upload
task.resume();

// Cancel and discard partial upload
task.cancel();

Building a Reactive Progress UI Widget

class UploadProgressBar extends StatelessWidget {
  final UploadTask task;

  const UploadProgressBar({super.key, required this.task});

  @override
  Widget build(BuildContext context) {
    return StreamBuilder<TaskSnapshot>(
      stream: task.snapshotEvents,
      builder: (context, snapshot) {
        if (!snapshot.hasData) return const SizedBox.shrink();

        final data = snapshot.data!;
        final double ratio = data.totalBytes > 0 
            ? data.bytesTransferred / data.totalBytes 
            : 0;
        final int percentage = (ratio * 100).clamp(0, 100).toInt();

        return Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            LinearProgressIndicator(
              value: ratio,
              minHeight: 8,
              backgroundColor: Colors.grey.shade300,
              valueColor: const AlwaysStoppedAnimation(Color(0xFF2856D8)),
            ),
            const SizedBox(height: 6),
            Row(
              mainAxisAlignment: MainAxisAlignment.spaceBetween,
              children: [
                Text(
                  '$percentage% uploaded',
                  style: const TextStyle(fontWeight: FontWeight.bold, fontSize: 13),
                ),
                Text(
                  '${(data.bytesTransferred / 1024).toStringAsFixed(0)} KB / ${(data.totalBytes / 1024).toStringAsFixed(0)} KB',
                  style: const TextStyle(fontSize: 12, color: Colors.black54),
                ),
              ],
            ),
          ],
        );
      },
    );
  }
}
STEP 7 · MEDIA DISPLAY

Getting Download URLs & Displaying Media

Generate secure tokenized download URLs and display network images cleanly in Flutter widgets.

What is a Download URL?

Once a file finishes uploading to Firebase Cloud Storage, you call await ref.getDownloadURL(). This generates a permanent, secure HTTPS link that looks like this:

https://firebasestorage.googleapis.com/v0/b/project.firebasestorage.app/o/avatars%2Fuser.jpg?alt=media&token=9a8b7c6d-1234-5678-90ab
How the token works: Anyone with this link can view or download the file without needing Firebase SDKs or API keys! If you ever need to revoke access to the link, you can revoke or regenerate the download token inside the Firebase Console.

Displaying the Image in Flutter

Use Flutter's built-in Image.network() widget. Always provide a loadingBuilder and errorBuilder to handle slow connections or bad URLs gracefully:

Widget buildStorageImage(String downloadUrl) {
  return ClipRRect(
    borderRadius: BorderRadius.circular(16),
    child: Image.network(
      downloadUrl,
      width: double.infinity,
      height: 240,
      fit: BoxFit.cover,
      loadingBuilder: (context, child, loadingProgress) {
        if (loadingProgress == null) return child;
        final double? progress = loadingProgress.expectedTotalBytes != null
            ? loadingProgress.cumulativeBytesLoaded / loadingProgress.expectedTotalBytes!
            : null;
        return Container(
          height: 240,
          color: Colors.grey.shade100,
          child: Center(
            child: CircularProgressIndicator(value: progress),
          ),
        );
      },
      errorBuilder: (context, error, stackTrace) {
        return Container(
          height: 240,
          color: Colors.red.shade50,
          child: const Center(
            child: Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                Icon(Icons.broken_image, size: 48, color: Colors.red),
                SizedBox(height: 8),
                Text('Could not load image', style: TextStyle(color: Colors.red)),
              ],
            ),
          ),
        );
      },
    ),
  );
}
STEP 8 · ARCHITECTURE

Linking Storage with Firestore

Connect Cloud Storage files with Cloud Firestore database documents to build real-world feeds, profiles, and galleries.

The Complete End-to-End Workflow

Now let's connect the knowledge from our Firestore codelab with Storage! When creating a social post, product listing, or profile avatar:

  1. Pick: User chooses a photo using ImagePicker.
  2. Upload: Stream bytes to FirebaseStorage.
  3. URL: Retrieve the resulting downloadURL.
  4. Firestore Write: Add a new document to Firestore posts collection storing the title, the download URL, the storage path (for deletion later!), and a server timestamp.

Full Dart Implementation

import 'dart:typed_data';
import 'package:cloud_firestore/cloud_firestore.dart';
import 'package:firebase_storage/firebase_storage.dart';
import 'package:image_picker/image_picker.dart';

class PostRepository {
  final FirebaseFirestore _firestore = FirebaseFirestore.instance;
  final FirebaseStorage _storage = FirebaseStorage.instance;

  Future<void> createPost({
    required XFile imageFile,
    required String caption,
    required String userId,
  }) async {
    // Step 1: Read raw bytes
    final Uint8List bytes = await imageFile.readAsBytes();

    // Step 2: Create a unique path in Storage
    final String timestamp = DateTime.now().millisecondsSinceEpoch.toString();
    final String storagePath = 'user_posts/$userId/$timestamp.jpg';
    final Reference ref = _storage.ref().child(storagePath);

    // Step 3: Upload bytes to Storage with metadata
    final metadata = SettableMetadata(contentType: 'image/jpeg');
    final uploadTask = ref.putData(bytes, metadata);
    final snapshot = await uploadTask;

    // Step 4: Get download URL
    final String downloadUrl = await snapshot.ref.getDownloadURL();

    // Step 5: Save record to Firestore collection
    await _firestore.collection('posts').add({
      'userId': userId,
      'caption': caption,
      'imageUrl': downloadUrl,
      'storagePath': storagePath, // Save path so we can delete the file later!
      'createdAt': FieldValue.serverTimestamp(),
    });
  }
}
Key Insight: Always save the storagePath inside the Firestore document! Later, when a user taps "Delete Post", you won't need to guess where the file lives in Storage—you simply call FirebaseStorage.instance.ref(storagePath).delete()!
STEP 9 · READ OPERATIONS

Downloading & Reading Files

Download files directly into memory as bytes or save them to the device filesystem.

Two Ways to Download

While Image.network(url) is great for displaying pictures on screen, sometimes your app needs to process raw file bytes (like parsing a PDF, applying image filters, or saving a file for offline access).

1. Download to Memory (getData)

Fetches the file directly into a Uint8List buffer in RAM. Always specify a safe maximum size (e.g. 10 MB) to prevent Out-Of-Memory (OOM) crashes on low-end devices!

2. Download to Disk (writeToFile)

Saves the file directly into local storage (like device cache or documents folder). Great for background downloads of large PDFs or videos.

Example 1: Download File into Memory

import 'dart:typed_data';
import 'package:firebase_storage/firebase_storage.dart';

Future<Uint8List?> downloadFileBytes(String storagePath) async {
  final ref = FirebaseStorage.instance.ref().child(storagePath);

  try {
    // Set max size limit (e.g. 5 MegaBytes = 5 * 1024 * 1024)
    const int maxSizeBytes = 5 * 1024 * 1024;
    final Uint8List? data = await ref.getData(maxSizeBytes);
    return data;
  } on FirebaseException catch (e) {
    debugPrint('Download failed: ${e.code} - ${e.message}');
    return null;
  }
}

Example 2: Download Directly to Device Storage

import 'dart:io';
import 'package:firebase_storage/firebase_storage.dart';

Future<File> downloadToFile({
  required String storagePath,
  required String localFilePath,
}) async {
  final ref = FirebaseStorage.instance.ref().child(storagePath);
  final File localFile = File(localFilePath);

  // Download directly to local storage file
  final DownloadTask downloadTask = ref.writeToFile(localFile);
  await downloadTask;
  return localFile;
}
STEP 10 · FOLDER EXPLORATION

Listing & Browsing Files

Browse folders, list bucket contents, and paginate through cloud files like a file explorer.

Listing Methods: listAll() vs list()

Just like exploring files in Finder or File Explorer, Firebase Storage allows you to inspect what files and subdirectories exist under any reference:

MethodBehaviorBest For
ref.listAll() Fetches ALL items and subfolders in one single call. Small folders (e.g. a user's uploaded gallery of 10-20 images).
ref.list(ListOptions) Fetches a paginated page of items with a limit and next page token. Large buckets with hundreds or thousands of files to prevent app slowdown.

Inspecting ListResult

When you call listAll(), you receive a ListResult containing two collections:

  • result.items: A list of Reference objects pointing to files in that folder.
  • result.prefixes: A list of Reference objects pointing to sub-folders!
import 'package:firebase_storage/firebase_storage.dart';

Future<List<String>> fetchAllUserImageUrls(String userId) async {
  final folderRef = FirebaseStorage.instance.ref().child('user_posts/$userId');

  // 1. Fetch all items in the folder
  final ListResult result = await folderRef.listAll();

  // 2. Map every file reference to its download URL
  final List<String> urls = [];
  for (final Reference fileRef in result.items) {
    final String url = await fileRef.getDownloadURL();
    urls.add(url);
  }

  return urls;
}

Paginated Listing with ListOptions

Future<void> fetchPageOfFiles({String? nextPageToken}) async {
  final folderRef = FirebaseStorage.instance.ref().child('public_photos');

  // Request up to 10 files at a time
  final ListResult page = await folderRef.list(ListOptions(
    maxResults: 10,
    pageToken: nextPageToken,
  ));

  for (var file in page.items) {
    debugPrint('File found: ${file.name}');
  }

  // Save page.nextPageToken to load the next 10 items when user scrolls!
  if (page.nextPageToken != null) {
    debugPrint('Next token: ${page.nextPageToken}');
  }
}
STEP 11 · ATTRIBUTES

Working with File Metadata

Read file sizes, creation dates, content types, and store custom developer key-value pairs.

What is File Metadata?

Every file in Firebase Storage has metadata attached to it. Firebase provides two metadata objects:

  • FullMetadata: Read-only properties generated by Google Cloud (byte size, upload time, MD5 hash).
  • SettableMetadata: Writable attributes that you can set and update (content-type, cache-control, custom tags).

Inspecting FullMetadata

Future<void> printFileDetails(Reference fileRef) async {
  final FullMetadata meta = await fileRef.getMetadata();

  debugPrint('File Name: ${meta.name}');
  debugPrint('Size in Bytes: ${meta.size}');
  debugPrint('Size in KB: ${(meta.size! / 1024).toStringAsFixed(1)} KB');
  debugPrint('Content-Type: ${meta.contentType}');
  debugPrint('Uploaded At: ${meta.timeCreated}');
  debugPrint('Updated At: ${meta.updated}');

  // Custom key-value tags attached by developer
  debugPrint('Custom Tags: ${meta.customMetadata}');
}

Updating Metadata on an Existing File

You can update attributes without re-uploading the file bytes using updateMetadata():

Future<void> tagFileAsVerified(Reference fileRef) async {
  final SettableMetadata newMetadata = SettableMetadata(
    cacheControl: 'public, max-age=3600', // Cache on client for 1 hour
    customMetadata: {
      'status': 'verified',
      'moderatedBy': 'admin_team',
    },
  );

  final FullMetadata updated = await fileRef.updateMetadata(newMetadata);
  debugPrint('Updated metadata status: ${updated.customMetadata?['status']}');
}
STEP 12 · CLEANUP

Deleting Files Safely

Prevent storage bloat and orphaned files by deleting cloud media when user posts are removed.

Deleting by Storage Reference

To delete a file from Storage, simply call .delete() on its reference:

Future<void> deleteStorageFile(String storagePath) async {
  try {
    final ref = FirebaseStorage.instance.ref().child(storagePath);
    await ref.delete();
    debugPrint('File $storagePath deleted successfully!');
  } on FirebaseException catch (e) {
    if (e.code == 'object-not-found') {
      debugPrint('File was already deleted or never existed.');
    } else {
      debugPrint('Error deleting file: ${e.code} - ${e.message}');
    }
  }
}

Deleting Directly from a Download URL

What if your code only has the https://firebasestorage.googleapis.com/... download URL and you don't know the exact path? You can obtain the reference directly using refFromURL()!

Future<void> deleteFileByUrl(String downloadUrl) async {
  try {
    // Automatically extracts the path and bucket from the HTTPS URL!
    final Reference ref = FirebaseStorage.instance.refFromURL(downloadUrl);
    await ref.delete();
    debugPrint('File deleted successfully via URL!');
  } on FirebaseException catch (e) {
    debugPrint('Delete failed: ${e.message}');
  }
}

Coordinated Delete: Storage + Firestore

Always delete the storage asset when deleting the Firestore document. If you only delete the Firestore document, the photo remains forever in Storage, continuing to charge you storage fees for files no one can ever find (an "orphaned file")!

Future<void> deletePostAndPhoto({
  required String postId,
  required String storagePath,
}) async {
  // 1. Delete binary photo in Cloud Storage
  try {
    await FirebaseStorage.instance.ref().child(storagePath).delete();
  } catch (e) {
    debugPrint('Notice: Storage file missing or could not delete: $e');
  }

  // 2. Delete index record in Cloud Firestore
  await FirebaseFirestore.instance.collection('posts').doc(postId).delete();
}

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  runApp(const SnapVaultApp());
}

class SnapVaultApp extends StatelessWidget {
  const SnapVaultApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'SnapVault - Firebase Storage',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: const Color(0xFF2856D8)),
        useMaterial3: true,
      ),
      home: const SnapVaultHomeScreen(),
    );

}

class SnapVaultHomeScreen extends StatefulWidget {
  const SnapVaultHomeScreen({super.key});

  @override
  State<SnapVaultHomeScreen> createState() => _SnapVaultHomeScreenState();
}

class _SnapVaultHomeScreenState extends State<SnapVaultHomeScreen> {
  final ImagePicker _picker = ImagePicker();
  final TextEditingController _captionController = TextEditingController();

  XFile? _selectedFile;
  Uint8List? _previewBytes;
  UploadTask? _activeUploadTask;
  double _uploadProgress = 0.0;
  bool _isUploading = false;

  // 1. Pick Image
  Future<void> _pickImage(ImageSource source) async {
    final XFile? file = await _picker.pickImage(
      source: source,
      maxWidth: 1200,
      imageQuality: 85,
    );

    if (file != null) {
      final bytes = await file.readAsBytes();
      setState(() {
        _selectedFile = file;
        _previewBytes = bytes;
      });
    }
  }

  // 2. Upload to Storage & Write to Firestore
  Future<void> _uploadAndPost() async {
    if (_selectedFile == null || _previewBytes == null) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Please select a photo first!')),
      );
      return;
    }

    final String caption = _captionController.text.trim();
    if (caption.isEmpty) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Please enter a caption!')),
      );
      return;
    }

    setState(() {
      _isUploading = true;
      _uploadProgress = 0.0;
    });

    try {
      final String timestamp = DateTime.now().millisecondsSinceEpoch.toString();
      final String storagePath = 'snapvault_photos/$timestamp.jpg';
      final Reference ref = FirebaseStorage.instance.ref().child(storagePath);

      final metadata = SettableMetadata(
        contentType: 'image/jpeg',
        customMetadata: {'caption': caption},
      );

      // Start upload task
      final UploadTask task = ref.putData(_previewBytes!, metadata);
      setState(() { _activeUploadTask = task; });

      // Track progress
      task.snapshotEvents.listen((TaskSnapshot snapshot) {
        if (snapshot.totalBytes > 0) {
          setState(() {
            _uploadProgress = snapshot.bytesTransferred / snapshot.totalBytes;
          });
        }
      });

      // Await completion
      final TaskSnapshot completedSnapshot = await task;
      final String downloadUrl = await completedSnapshot.ref.getDownloadURL();

      // Save to Firestore
      await FirebaseFirestore.instance.collection('snaps').add({
        'caption': caption,
        'imageUrl': downloadUrl,
        'storagePath': storagePath,
        'createdAt': FieldValue.serverTimestamp(),
      });

      // Reset Form
      setState(() {
        _selectedFile = null;
        _previewBytes = null;
        _captionController.clear();
        _activeUploadTask = null;
        _isUploading = false;
        _uploadProgress = 0.0;
      });

      if (mounted) {
        ScaffoldMessenger.of(context).showSnackBar(
          const SnackBar(content: Text('Photo uploaded to SnapVault! 🎉')),
        );
      }
    } catch (e) {
      setState(() { _isUploading = false; });
      if (mounted) {
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text('Upload failed: $e')),
        );
      }
    }
  }

  // 3. Delete Photo from Storage and Firestore
  Future<void> _deleteSnap(String docId, String storagePath) async {
    try {
      // Delete binary file in Storage
      await FirebaseStorage.instance.ref().child(storagePath).delete();
    } catch (_) {
      // Proceed even if already gone
    }

    // Delete Firestore document
    await FirebaseFirestore.instance.collection('snaps').doc(docId).delete();

    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Photo deleted!')),
      );
    }
  }

  @override
  void dispose() {
    _captionController.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('SnapVault', style: TextStyle(fontWeight: FontWeight.bold)),
        backgroundColor: const Color(0xFF2856D8),
        foregroundColor: Colors.white,
      ),
      body: SingleChildScrollView(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            // UPLOAD CARD
            Card(
              elevation: 3,
              shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(16)),
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  children: [
                    if (_previewBytes != null)
                      ClipRRect(
                        borderRadius: BorderRadius.circular(12),
                        child: Image.memory(
                          _previewBytes!,
                          height: 180,
                          width: double.infinity,
                          fit: BoxFit.cover,
                        ),
                      )
                    else
                      Container(
                        height: 140,
                        width: double.infinity,
                        decoration: BoxDecoration(
                          color: Colors.grey.shade100,
                          borderRadius: BorderRadius.circular(12),
                          border: Border.all(color: Colors.grey.shade300),
                        ),
                        child: const Center(
                          child: Icon(Icons.add_photo_alternate_outlined, size: 50, color: Colors.grey),
                        ),
                      ),
                    const SizedBox(height: 12),
                    Row(
                      mainAxisAlignment: MainAxisAlignment.center,
                      children: [
                        OutlinedButton.icon(
                          onPressed: _isUploading ? null : () => _pickImage(ImageSource.gallery),
                          icon: const Icon(Icons.photo_library),
                          label: const Text('Gallery'),
                        ),
                        const SizedBox(width: 12),
                        OutlinedButton.icon(
                          onPressed: _isUploading ? null : () => _pickImage(ImageSource.camera),
                          icon: const Icon(Icons.camera_alt),
                          label: const Text('Camera'),
                        ),
                      ],
                    ),
                    const SizedBox(height: 12),
                    TextField(
                      controller: _captionController,
                      decoration: const InputDecoration(
                        labelText: 'Write a caption...',
                        border: OutlineInputBorder(),
                      ),
                    ),
                    const SizedBox(height: 12),
                    if (_isUploading) ...[
                      LinearProgressIndicator(value: _uploadProgress),
                      const SizedBox(height: 6),
                      Text(
                        'Uploading: ${(_uploadProgress * 100).toInt()}%',
                        style: const TextStyle(fontWeight: FontWeight.bold),
                      ),
                      const SizedBox(height: 8),
                    ],
                    ElevatedButton.icon(
                      onPressed: _isUploading ? null : _uploadAndPost,
                      style: ElevatedButton.styleFrom(
                        backgroundColor: const Color(0xFF2856D8),
                        foregroundColor: Colors.white,
                        minimumSize: const Size(double.infinity, 46),
                      ),
                      icon: const Icon(Icons.cloud_upload),
                      label: const Text('Upload to SnapVault', style: TextStyle(fontWeight: FontWeight.bold)),
                    ),
                  ],
                ),
              ),
            ),
            const SizedBox(height: 24),

            // LIVE FEED HEADER
            const Text(
              'Recent Cloud Snaps',
              style: TextStyle(fontSize: 20, fontWeight: FontWeight.bold),
            ),
            const SizedBox(height: 12),

            // LIVE FIRESTORE FEED
            StreamBuilder<QuerySnapshot>(
              stream: FirebaseFirestore.instance
                  .collection('snaps')
                  .orderBy('createdAt', descending: true)
                  .snapshots(),
              builder: (context, snapshot) {
                if (snapshot.hasError) {
                  return Center(child: Text('Error: ${snapshot.error}'));
                }
                if (snapshot.connectionState == ConnectionState.waiting) {
                  return const Center(child: CircularProgressIndicator());
                }

                final docs = snapshot.data?.docs ?? [];
                if (docs.isEmpty) {
                  return const Padding(
                    padding: EdgeInsets.all(32),
                    child: Center(
                      child: Text('No photos uploaded yet! Snap one above.'),
                    ),
                  );
                }

                return ListView.builder(
                  shrinkWrap: true,
                  physics: const NeverScrollableScrollPhysics(),
                  itemCount: docs.length,
                  itemBuilder: (context, index) {
                    final data = docs[index].data() as Map<String, dynamic>;
                    final String docId = docs[index].id;
                    final String imageUrl = data['imageUrl'] ?? '';
                    final String caption = data['caption'] ?? '';
                    final String storagePath = data['storagePath'] ?? '';

                    return Card(
                      margin: const EdgeInsets.only(bottom: 16),
                      clipBehavior: Clip.antiAlias,
                      shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(16)),
                      child: Column(
                        crossAxisAlignment: CrossAxisAlignment.start,
                        children: [
                          Image.network(
                            imageUrl,
                            height: 220,
                            width: double.infinity,
                            fit: BoxFit.cover,
                            loadingBuilder: (context, child, progress) {
                              if (progress == null) return child;
                              return Container(
                                height: 220,
                                color: Colors.grey.shade100,
                                child: const Center(child: CircularProgressIndicator()),
                              );
                            },
                          ),
                          Padding(
                            padding: const EdgeInsets.all(12),
                            child: Row(
                              children: [
                                Expanded(
                                  child: Text(
                                    caption,
                                    style: const TextStyle(fontSize: 15, fontWeight: FontWeight.w600),
                                  ),
                                ),
                                IconButton(
                                  icon: const Icon(Icons.delete_outline, color: Colors.red),
                                  onPressed: () => _deleteSnap(docId, storagePath),
                                ),
                              ],
                            ),
                          ),
                        ],
                      ),
                    );
                  },
                );
              },
            ),
          ],
        ),
      ),
    );
  }
}
STEP 14 · SECURITY

Firebase Storage Security Rules

Protect cloud assets from unauthorized uploads, enforce size quotas, and restrict file MIME types.

Why Security Rules are Critical

Unlike traditional servers where backend PHP or Node.js code handles uploads, Flutter connects directly from the client device to Google Cloud Storage. If your rules allow anyone to write, a malicious attacker could upload gigabytes of junk files and run up your billing!

Storage Rules Syntax vs Firestore Rules

Storage rules start with service firebase.storage instead of service cloud.firestore:

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    // Your path rules go here!
  }
}

Rule Example 1: User-Isolated Avatar Folders

Only allow authenticated users to read and write to their own dedicated folder (users/{userId}/...):

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{userId}/{allPaths=**} {
      // Anyone logged in can view avatars
      allow read: if request.auth != null;
      
      // Only the folder owner can upload or delete their photos!
      allow write: if request.auth != null && request.auth.uid == userId;
    }
  }
}

Rule Example 2: Validating Size and File Types

You can inspect the incoming file using request.resource before accepting it:

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /snapvault_photos/{fileName} {
      // Anyone can read public photos
      allow read: if true;

      // Allow write ONLY if:
      // 1. User is signed in
      // 2. File size is under 5 MegaBytes (5 * 1024 * 1024 bytes)
      // 3. File is an image (image/jpeg, image/png, image/webp)
      allow write: if request.auth != null
                   && request.resource.size < 5 * 1024 * 1024
                   && request.resource.contentType.matches('image/.*');
    }
  }
}

Security Rules Best Practices

  1. Never leave rules as allow read, write: if true; in production.
  2. Always check request.resource.size to prevent users from uploading massive 1 GB files that blow up your quota.
  3. Check request.resource.contentType.matches('image/.*') so malicious users cannot upload executable .exe or script files to your bucket.
STEP 15 · DEBUGGING

Troubleshooting & Common Pitfalls

Diagnose and resolve common Firebase Storage runtime exceptions and platform issues.

Error SymptomRoot CauseImmediate Fix
[storage/unauthorized] User does not have permission Firebase Security Rules rejected the request (e.g. user is not signed in or size limit was exceeded). Check Firebase Console > Storage > Rules. Verify request.auth != null matches your login state.
[storage/object-not-found] No object exists at desired reference Attempting to fetch getDownloadURL() on a path that does not exist or before upload finished. Ensure you await task completely before requesting the download URL, and double check your reference path.
Unsupported operation: Platform._operatingSystem on Web Using File(path) from dart:io inside Flutter Web code. Use xfile.readAsBytes() and putData(bytes) which works identically on Web and Mobile!
App crashes when opening Gallery or Camera Missing permissions in AndroidManifest.xml or iOS Info.plist. Add READ_MEDIA_IMAGES to Android manifest and NSPhotoLibraryUsageDescription to iOS Info.plist.
CORS error on Flutter Web (XMLHttpRequest error) Browser blocked cross-origin requests to Google Cloud Storage bucket. Deploy a CORS JSON configuration to your Firebase Storage bucket via Google Cloud CLI: gcloud storage buckets update gs://<bucket-name> --cors-file=cors.json.

Revision & Final Checklist

Review key takeaways, test your complete understanding, and celebrate your mastery of Firebase Storage!

Key Concept Flashcards

What is the difference between Firestore and Firebase Storage?
Firestore is a NoSQL document database for structured JSON-like text under 1 MB. Firebase Storage is an object store for large binary files (photos, videos, audio, documents) up to 5 TB.
Why should you always pass SettableMetadata with contentType?
Without specifying `contentType: 'image/jpeg'`, Firebase defaults to `application/octet-stream`. Browsers will download the file as a raw attachment instead of displaying it inline in `Image.network()`.
Why save the storagePath inside the Firestore document?
When a user deletes a post, you need the original storage path to delete the binary photo from Firebase Storage. Otherwise, the file becomes an orphaned asset continuing to incur storage costs!
How do you calculate upload progress?
Listen to `UploadTask.snapshotEvents` and divide `snapshot.bytesTransferred` by `snapshot.totalBytes` to get a 0.0 to 1.0 progress ratio.
