What is Firebase?

Firebase is Google's comprehensive app development platform (Backend-as-a-Service / BaaS). Instead of provisioning and maintaining your own custom backend servers, API endpoints, authentication flows, and scaling infrastructure, Firebase provides managed cloud services ready to integrate into your client apps:

Backend-as-a-Service (BaaS)

Provides managed cloud databases (Cloud Firestore, Realtime Database), cloud storage for user media, serverless compute (Cloud Functions), and authentication out-of-the-box.

App Health & Analytics

Delivers real-time crash reporting (Crashlytics), performance monitoring, Google Analytics, and device attestation security (Firebase App Check).

Why FlutterFire CLI?

Say goodbye to manual JSON/plist downloads, gradle file hacking, and separate platform setup ceremonies.

Old Manual Way (Fragile & Error-Prone):
Download google-services.json → Put in android/app/
Download GoogleService-Info.plist → Add to Xcode manually
Copy JS config snippet → Paste in web/index.html
Edit 4+ build.gradle files → Pray sync passes

Modern FlutterFire CLI Way (Automated & Repeatable):
Run `flutterfire configure`
↓
Auto-creates & registers Android, iOS, & Web apps
↓
Generates `lib/firebase_options.dart`
↓
Call `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`
Why the CLI matters

Flutter targets multiple platforms from a single codebase. Managing credentials individually across Android, iOS, Web, macOS, and Windows causes drift, accidental credential loss, and build breakages.

Type-safe Dart options

FlutterFire generates a single Dart file with FirebaseOptions for every selected platform, automatically selected at runtime via TargetPlatform and kIsWeb.

STEP 7 · AUTOMATION

Run flutterfire configure

The cornerstone command that connects your Flutter code to your cloud backend.

From the root of your Flutter project, run:

flutterfire configure
Interactive Prompts:

The CLI will guide you through an interactive menu:

  1. Select a Firebase project: Use arrow keys to pick the project you created in Step 5.
  2. Which platforms should your configuration support? Spacebar to select (Android, iOS, Web, macOS, Windows), then press Enter.
What flutterfire configure does behind the scenes:
1. Inspects your Flutter app's bundle identifier / package name.
2. Communicates with Firebase API to register an Android app, iOS app, and Web app.
3. Generates the necessary Firebase credentials.
4. Automatically adds google-services classpath to Android Gradle scripts.
5. Generates `lib/firebase_options.dart` with platform-specific options.
NON-INTERACTIVE AUTOMATION

For scripts or CI/CD pipelines, you can run non-interactively by specifying flags:

flutterfire configure \
  --project=my-flutter-app-9481a \
  --platforms=android,ios,web \
  --yes
STEP 8 · CODE WALKTHROUGH

Explore firebase_options.dart

Inspect the auto-generated file that makes multi-platform Firebase initialization possible in pure Dart.

Open lib/firebase_options.dart. You will see code structured like this:

// File generated by FlutterFire CLI.
// Do not manually modify unless you know what you are doing.
import 'package:firebase_core/firebase_core.dart' show FirebaseOptions;
import 'package:flutter/foundation.dart'
    show defaultTargetPlatform, kIsWeb, TargetPlatform;

class DefaultFirebaseOptions {
  static FirebaseOptions get currentPlatform {
    if (kIsWeb) {
      return web;
    }
    switch (defaultTargetPlatform) {
      case TargetPlatform.android:
        return android;
      case TargetPlatform.iOS:
        return ios;
      case TargetPlatform.macOS:
        return macos;
      case TargetPlatform.windows:
        return windows;
      case TargetPlatform.linux:
        throw UnsupportedError(
          'DefaultFirebaseOptions have not been configured for linux - '
          'you can reconfigure this by running the FlutterFire CLI again.',
        );
      default:
        throw UnsupportedError(
          'DefaultFirebaseOptions are not supported for this platform.',
        );
    }
  }

STEP 9 · INITIALIZATION

Initialize Firebase in main.dart

Bootstrap Firebase asynchronously before rendering any Flutter UI widgets.

Update lib/main.dart with the proper initialization lifecycle:

import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart';

Future<void> main() async {
  // 1. Guarantee engine-framework communication channels are ready
  WidgetsFlutterBinding.ensureInitialized();

  // 2. Initialize Firebase with platform-appropriate credentials
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );

  // 3. Launch application widget tree
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Firebase CLI Demo',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: const Color(0xFF2856D8)),
        useMaterial3: true,
      ),
      home: const Scaffold(
        body: Center(
          child: Text('Firebase Connected! 🎉'),
        ),
      ),
    );
  }
}
Why WidgetsFlutterBinding.ensureInitialized() is mandatory:

Firebase.initializeApp() invokes native binary platform channels (Java/Kotlin on Android, Objective-C/Swift on iOS, JavaScript on Web). If you invoke platform channels before runApp() without calling WidgetsFlutterBinding.ensureInitialized(), Flutter throws a runtime binding error.

Why must `WidgetsFlutterBinding.ensureInitialized()` be called before `Firebase.initializeApp()`?

STEP 10 · PLATFORM SPECIFICS

Android Setup & Requirements

Configure Gradle settings, minimum SDK versions, and signing certificates for Android.

Most modern Firebase plugins (like Auth and Firestore) require at least Android API 21 (or 23 for certain ML plugins). Ensure your android/app/build.gradle has the correct minSdkVersion:

// android/app/build.gradle
android {
    namespace "com.example.firebase_cli_starter"
    compileSdk flutter.compileSdkVersion
    ndkVersion flutter.ndkVersion

    defaultConfig {
        applicationId "com.example.firebase_cli_starter"
        // Set minSdkVersion to 21 or higher
        minSdkVersion 21
        targetSdkVersion flutter.targetSdkVersion
        versionCode flutterVersionCode.toInteger()
        versionName flutterVersionName
        multiDexEnabled true
    }
}
GRADLE PLUGINS

FlutterFire CLI automatically adds the Google Services Gradle plugin. Verify that android/build.gradle and android/app/build.gradle include it:

// android/build.gradle (Project level)
plugins {
    id 'com.google.gms.google-services' version '4.4.1' apply false
}

// android/app/build.gradle (App level)
plugins {
    id 'com.android.application'
    id 'kotlin-android'
    id 'dev.flutter.flutter-gradle-plugin'
    id 'com.google.gms.google-services' // <-- Applied here
}
Signing Certificates (SHA-1 / SHA-256):

If you plan to use Firebase Phone Auth or Google Sign-In on Android, you must register your debug SHA certificate. Generate it via:

cd android && ./gradlew signingReport

Copy the debug SHA1 string and paste it into Project Settings → Android App → Add fingerprint in the Firebase Console.

STEP 13 · VERIFY

Verify Firebase Connection

Verify that Firebase is properly configured and initialized with a simple, minimal test in main.dart.

To confirm that your Flutter application is properly connected to your Firebase project, update lib/main.dart with this simple verification widget:

import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    // Read the project ID from the initialized Firebase instance
    final projectId = Firebase.app().options.projectId;

    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(
          title: const Text('Firebase Verification'),
          backgroundColor: const Color(0xFF2856D8),
          foregroundColor: Colors.white,
        ),
        body: Center(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              const Icon(Icons.check_circle_outline, color: Colors.green, size: 72),
              const SizedBox(height: 16),
              const Text(
                'Firebase Connected!',
                style: TextStyle(fontSize: 22, fontWeight: FontWeight.bold),
              ),
              const SizedBox(height: 8),
              Text(
                'Connected Project ID: $projectId',
                style: const TextStyle(fontSize: 16, color: Colors.black87),
              ),
            ],
          ),
        ),
      ),
    );
  }
}

STEP 15 · SECURITY

Security Fundamentals

Understand how Firebase secures client applications and protects credentials.

Critical Security Mindset:

Client-side code (including Flutter mobile & web apps) cannot keep secrets. Anyone can inspect compiled binary files or web bundles. Therefore, Firebase relies on Server-Side Security Rules and App Check on Google's servers to authorize or deny requests.

Server-Side Security Rules

When you add databases (like Cloud Firestore) or Cloud Storage in subsequent codelabs, you will secure them by writing server-enforced security rules directly in the Firebase Console.

Firebase App Check

Protect your backend resources from abuse, bots, and unauthorized clients using device attestation providers (Play Integrity on Android, DeviceCheck on iOS, reCAPTCHA v3 on Web).

Security Best Practices Checklist

  1. Never store Firebase Admin Service Account private keys inside a Flutter app.
  2. Always define strict Security Rules in the console before shipping to production.
  3. Enable Firebase App Check to block unauthorized non-app requests.
  4. Add SHA-1 fingerprints for release signing keys before releasing on Google Play.
STEP 16 · FINAL REVISION

Firebase CLI Setup Revision

Review key takeaways and test your complete understanding.

Why use FlutterFire CLI instead of manual setup?
FlutterFire CLI registers apps across platforms simultaneously, updates native build files automatically, and generates type-safe Dart options (`DefaultFirebaseOptions.currentPlatform`) to prevent platform configuration drift.
What is DefaultFirebaseOptions.currentPlatform?
A static getter that inspects `kIsWeb` and `defaultTargetPlatform` at runtime and returns the matching `FirebaseOptions` instance (Android, iOS, Web, macOS, or Windows).
Why call WidgetsFlutterBinding.ensureInitialized()?
Because `Firebase.initializeApp()` communicates with native platform channels before `runApp()` starts the widget engine; the binding must be ready first.
How do you update configuration if you add iOS later?
Run `flutterfire configure` again in the project root, choose the same project, and include iOS in the platform selection.
