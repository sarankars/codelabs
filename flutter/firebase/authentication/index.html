STEP 1 · INTRODUCTION

What is Firebase Authentication?

Understand why authentication matters, how Firebase Auth works, and what you will build in this codelab.

By the end of this codelab: You will add Firebase Authentication to a Flutter app supporting three sign-in methods — Email & Password, Google Sign-In, and Phone Number OTP — with a reactive auth state listener, sign-out flow, and proper error handling.

Why Does Your App Need Authentication?

Authentication answers one critical question: “Who is this user?” Without it, every user is anonymous — you cannot personalise data, protect private content, or restrict actions. With Firebase Auth you get a verified, unique uid for every user that persists across sessions and devices.

🔒Identity

Every signed-in user receives a stable uid — the source of truth for linking Firestore documents, Storage files, and backend data.

🛡️Security Rules

Firestore and Storage security rules read request.auth.uid to allow or deny requests at the server level — never trusting the client.

🌎Cross-Platform

The same Firebase user account works on Android, iOS, and Web from a single Dart codebase using FlutterFire.

How Firebase Authentication Works

User opens app ↓ App checks FirebaseAuth.instance.authStateChanges() ↓ (stream emits User? — null = not signed in) ├── null → Show Login Screen └── User → Show Home Screen ↓ User chooses a sign-in method ↓ Firebase verifies identity (Google, SMS, password, etc.) ↓ Firebase issues an ID Token (JWT) ↓ FirebaseAuth.instance.currentUser is populated ↓ authStateChanges() emits User → app navigates to home

Sign-In Methods Covered

📧 Email / Password

Classic username-password flow. Users register with an email and choose a password. Firebase handles hashing, storage, and reset emails.

📷 Google Sign-In

One-tap OAuth flow using the user’s existing Google account. No password required — Firebase receives a Google ID token and exchanges it for a Firebase credential.

📱 Phone Number

Firebase sends a one-time OTP via SMS. The user enters the code to verify ownership of a real phone number — popular in markets with low email adoption.

What is firebase_auth?

The firebase_auth Flutter plugin is the official FlutterFire package that wraps the Firebase Auth SDK for Android, iOS, and Web. It provides:

  • FirebaseAuth.instance — singleton entry point
  • authStateChanges() — reactive stream of the current User?
  • createUserWithEmailAndPassword(), signInWithEmailAndPassword()
  • signInWithCredential() — accepts Google, Apple, Phone credentials
  • signOut() — clears the local session token
📋 Prerequisites:

This codelab assumes you have completed the Firebase CLI Setup codelab — your Flutter project has firebase_core installed, firebase_options.dart generated, and Firebase initialized in main.dart.

STEP 4 · APP ARCHITECTURE

Listen to Auth State Changes

The foundation of any auth-aware app is a reactive stream that tells your UI when the user signs in or out — without polling or manually managing state.

The authStateChanges() Stream

FirebaseAuth.instance.authStateChanges() returns a Stream<User?>. It emits:

  • null — when no user is signed in (show login screen)
  • A User object — when a user is signed in (show home screen)
  • Fires automatically on app start, sign-in, sign-out, and token refresh

Project File Structure

lib/ ├── main.dart ← Firebase init + root router ├── auth_gate.dart ← Listens to authStateChanges() ├── home_screen.dart ← Shown when signed in ├── login_screen.dart ← Shown when signed out ├── email_auth_screen.dart ← Email/Password form └── phone_auth_screen.dart ← Phone OTP form

auth_gate.dart — The Auth Router

This widget uses a StreamBuilder to reactively switch between the login and home screens. This is the most important pattern in auth-aware Flutter apps.

// lib/auth_gate.dart
import 'package:firebase_auth/firebase_auth.dart';
import 'package:flutter/material.dart';
import 'home_screen.dart';
import 'login_screen.dart';

class AuthGate extends StatelessWidget {
  const AuthGate({super.key});

  @override
  Widget build(BuildContext context) {
    return StreamBuilder<User?>(
      // Listens to sign-in / sign-out events in real time
      stream: FirebaseAuth.instance.authStateChanges(),
      builder: (context, snapshot) {
        // While Firebase is resolving the initial auth state
        if (snapshot.connectionState == ConnectionState.waiting) {
          return const Scaffold(
            body: Center(child: CircularProgressIndicator()),
          );
        }

        // snapshot.data is null  = no user signed in
        if (snapshot.data == null) {
          return const LoginScreen();
        }

        // snapshot.data is a User = user is signed in
        return const HomeScreen();
      },
    );
  }
}

Update main.dart

Make AuthGate the root of the app so it guards every route from the first frame:

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart';
import 'auth_gate.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Firebase Auth Demo',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(
          seedColor: const Color(0xFF2856D8),
        ),
        useMaterial3: true,
      ),
      home: const AuthGate(), // AuthGate replaces the default home widget
    );
  }
}
✅ Why this pattern is powerful:

You never need to call Navigator.push for auth transitions. When the user signs in, Firebase updates the stream, StreamBuilder rebuilds automatically, and HomeScreen appears. When they sign out, LoginScreen appears. Zero manual navigation logic.

STEP 5 · SIGN-IN METHOD

Email & Password Authentication

Implement user registration and login using classic email and password credentials managed entirely by Firebase.

How Email / Password Auth Works

User enters email + password ↓ createUserWithEmailAndPassword() for new accounts OR signInWithEmailAndPassword() for existing accounts ↓ Firebase validates credentials on its servers ↓ Returns UserCredential (containing User) ↓ authStateChanges() stream emits the User ↓ AuthGate navigates to HomeScreen automatically

Key API Methods

MethodWhen to UseReturns
createUserWithEmailAndPassword(email, password)New user registrationFuture<UserCredential>
signInWithEmailAndPassword(email, password)Returning user loginFuture<UserCredential>
sendPasswordResetEmail(email)User forgot passwordFuture<void>
signOut()Log the user outFuture<void>

Build email_auth_screen.dart

// lib/email_auth_screen.dart
import 'package:firebase_auth/firebase_auth.dart';
import 'package:flutter/material.dart';

class EmailAuthScreen extends StatefulWidget {
  const EmailAuthScreen({super.key});

  @override
  State<EmailAuthScreen> createState() => _EmailAuthScreenState();
}

class _EmailAuthScreenState extends State<EmailAuthScreen> {
  final _formKey     = GlobalKey<FormState>();
  final _emailCtrl   = TextEditingController();
  final _passwordCtrl = TextEditingController();

  bool    _isLogin = true;
  bool    _loading = false;
  String? _errorMessage;

  @override
  void dispose() {
    _emailCtrl.dispose();
    _passwordCtrl.dispose();
    super.dispose();
  }

  Future<void> _submit() async {
    if (!_formKey.currentState!.validate()) return;
    setState(() { _loading = true; _errorMessage = null; });

    try {
      if (_isLogin) {
        await FirebaseAuth.instance.signInWithEmailAndPassword(
          email: _emailCtrl.text.trim(),
          password: _passwordCtrl.text.trim(),
        );
      } else {
        await FirebaseAuth.instance.createUserWithEmailAndPassword(
          email: _emailCtrl.text.trim(),
          password: _passwordCtrl.text.trim(),
        );
      }
      // AuthGate handles navigation automatically
      if (mounted) Navigator.pop(context);
    } on FirebaseAuthException catch (e) {
      setState(() { _errorMessage = _friendlyError(e.code); });
    } finally {
      if (mounted) setState(() { _loading = false; });
    }
  }

  String _friendlyError(String code) {
    return switch (code) {
      'email-already-in-use' => 'An account with this email already exists.',
      'invalid-email'        => 'Please enter a valid email address.',
      'weak-password'        => 'Password must be at least 6 characters.',
      'user-not-found'       => 'No account found with this email.',
      'wrong-password'       => 'Incorrect password. Please try again.',
      'too-many-requests'    => 'Too many attempts. Please wait a moment.',
      _                      => 'Authentication failed ($code).',
    };
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text(_isLogin ? 'Sign In' : 'Create Account'),
        backgroundColor: const Color(0xFF2856D8),
        foregroundColor: Colors.white,
      ),
      body: Center(
        child: SingleChildScrollView(
          padding: const EdgeInsets.all(24),
          child: Form(
            key: _formKey,
            child: Column(
              mainAxisSize: MainAxisSize.min,
              crossAxisAlignment: CrossAxisAlignment.stretch,
              children: [
                TextFormField(
                  controller: _emailCtrl,
                  decoration: const InputDecoration(
                    labelText: 'Email',
                    prefixIcon: Icon(Icons.email_outlined),
                    border: OutlineInputBorder(),
                  ),
                  keyboardType: TextInputType.emailAddress,
                  validator: (v) => (v == null || !v.contains('@'))
                      ? 'Enter a valid email' : null,
                ),
                const SizedBox(height: 16),
                TextFormField(
                  controller: _passwordCtrl,
                  decoration: const InputDecoration(
                    labelText: 'Password',
                    prefixIcon: Icon(Icons.lock_outline),
                    border: OutlineInputBorder(),
                  ),
                  obscureText: true,
                  validator: (v) => (v == null || v.length < 6)
                      ? 'Minimum 6 characters' : null,
                ),
                const SizedBox(height: 24),
                if (_errorMessage != null) ...[
                  Container(
                    padding: const EdgeInsets.all(12),
                    decoration: BoxDecoration(
                      color: Colors.red.shade50,
                      border: Border.all(color: Colors.red.shade300),
                      borderRadius: BorderRadius.circular(4),
                    ),
                    child: Text(_errorMessage!,
                      style: TextStyle(color: Colors.red.shade800)),
                  ),
                  const SizedBox(height: 16),
                ],
                FilledButton(
                  onPressed: _loading ? null : _submit,
                  child: _loading
                      ? const SizedBox(height: 20, width: 20,
                          child: CircularProgressIndicator(
                            color: Colors.white, strokeWidth: 2))
                      : Text(_isLogin ? 'Sign In' : 'Create Account'),
                ),
                const SizedBox(height: 12),
                TextButton(
                  onPressed: () {
                    setState(() { _isLogin = !_isLogin; _errorMessage = null; });
                  },
                  child: Text(_isLogin
                      ? "Don't have an account? Register"
                      : 'Already have an account? Sign In'),
                ),
              ],
            ),
          ),
        ),
      ),
    );
  }
}

Understanding FirebaseAuthException

Every Firebase Auth failure throws a FirebaseAuthException with a machine-readable code string. Always catch this exception and convert the code into a user-friendly message — never show raw error codes to users.

Common Error Codes:
  • email-already-in-use — email is taken during registration
  • invalid-email — malformed email string
  • weak-password — password under 6 characters
  • user-not-found — no account for that email
  • wrong-password — password mismatch
  • too-many-requests — account temporarily locked after repeated failures

STEP 8 · SIGN-IN METHOD

Google Sign-In

Add one-tap Google OAuth authentication — the fastest and most user-friendly sign-in method for Flutter apps targeting Android and iOS.

The Google Sign-In Flow Explained

User taps "Continue with Google" ↓ GoogleSignIn().signIn() → Shows native Google account picker ↓ User selects account → GoogleSignInAccount returned ↓ .authentication → returns idToken + accessToken ↓ GoogleAuthProvider.credential(idToken, accessToken) ↓ FirebaseAuth.instance.signInWithCredential(credential) ↓ Firebase verifies the Google ID token with Google's servers ↓ Returns UserCredential → authStateChanges() emits User ↓ AuthGate navigates to HomeScreen automatically

Create google_sign_in_service.dart

// lib/google_sign_in_service.dart
import 'package:firebase_auth/firebase_auth.dart';
import 'package:google_sign_in/google_sign_in.dart';

class GoogleSignInService {
  /// Initiates Google Sign-In and returns a [UserCredential].
  /// Throws [Exception] if the user cancels or sign-in fails.
  static Future<UserCredential> signIn() async {
    // Step 1: Open the Google account picker
    final GoogleSignInAccount? googleUser = await GoogleSignIn().signIn();

    if (googleUser == null) {
      throw Exception('Sign-in cancelled by user.');
    }

    // Step 2: Obtain Google auth tokens
    final GoogleSignInAuthentication googleAuth =
        await googleUser.authentication;

    // Step 3: Create a Firebase credential from the Google tokens
    final AuthCredential credential = GoogleAuthProvider.credential(
      idToken: googleAuth.idToken,
      accessToken: googleAuth.accessToken,
    );

    // Step 4: Sign into Firebase with the Google credential
    return FirebaseAuth.instance.signInWithCredential(credential);
  }

  /// Signs out of both Google and Firebase.
  static Future<void> signOut() async {
    await GoogleSignIn().signOut();
    await FirebaseAuth.instance.signOut();
  }
}
Why call GoogleSignIn().signOut() too?

If you only call FirebaseAuth.instance.signOut(), the Google Sign-In library still remembers the previously selected account. Next time the user taps "Continue with Google", it auto-selects the same account without showing the picker. Calling GoogleSignIn().signOut() ensures the account picker always appears on the next sign-in.

Web Support for Google Sign-In

On Flutter Web, the native account picker is not available. Use signInWithPopup instead:

// Unified cross-platform Google Sign-In
import 'package:flutter/foundation.dart' show kIsWeb;
import 'package:firebase_auth/firebase_auth.dart';

Future<UserCredential> signInWithGoogle() async {
  if (kIsWeb) {
    return FirebaseAuth.instance.signInWithPopup(GoogleAuthProvider());
  } else {
    return GoogleSignInService.signIn(); // native flow
  }
}

Phone Number Authentication

Implement SMS-based OTP verification — Firebase sends a one-time code to the user’s phone number, which they enter to prove ownership.

How Phone Auth Works

User enters phone number (e.g. +91 98765 43210) ↓ verifyPhoneNumber() called ↓ Firebase sends SMS with 6-digit OTP ↓ Callbacks fire: ├── verificationCompleted() → instant auto-verify (Android only) ├── verificationFailed() → error (invalid number, quota) ├── codeSent() → OTP sent → show OTP input field └── codeAutoRetrievalTimeout() → auto-retrieval timed out ↓ User enters OTP code ↓ PhoneAuthProvider.credential(verificationId, smsCode) ↓ FirebaseAuth.instance.signInWithCredential(credential) ↓ authStateChanges() emits User → AuthGate shows HomeScreen
Phone Number Format (E.164):

Always use E.164 format: +[country code][number]. Examples: +919876543210 (India), +16505551234 (USA), +447911123456 (UK). Include the country code and omit all spaces, dashes, and parentheses.

Build phone_auth_screen.dart

// lib/phone_auth_screen.dart
import 'package:firebase_auth/firebase_auth.dart';
import 'package:flutter/material.dart';

class PhoneAuthScreen extends StatefulWidget {
  const PhoneAuthScreen({super.key});

  @override
  State<PhoneAuthScreen> createState() => _PhoneAuthScreenState();
}

class _PhoneAuthScreenState extends State<PhoneAuthScreen> {
  final _phoneCtrl = TextEditingController();
  final _otpCtrl   = TextEditingController();

  String? _verificationId;
  bool    _codeSent = false;
  bool    _loading  = false;
  String? _error;

  @override
  void dispose() {
    _phoneCtrl.dispose();
    _otpCtrl.dispose();
    super.dispose();
  }

  // Step 1: Send OTP
  Future<void> _sendOtp() async {
    final phone = _phoneCtrl.text.trim();
    if (phone.isEmpty) {
      setState(() => _error = 'Enter a phone number in E.164 format.');
      return;
    }
    setState(() { _loading = true; _error = null; });

    await FirebaseAuth.instance.verifyPhoneNumber(
      phoneNumber: phone,

      // Android: auto-verifies if Google Play Services reads the SMS
      verificationCompleted: (PhoneAuthCredential credential) async {
        await FirebaseAuth.instance.signInWithCredential(credential);
        if (mounted) Navigator.pop(context);
      },

      // Called if verification fails
      verificationFailed: (FirebaseAuthException e) {
        if (mounted) setState(() {
          _loading = false;
          _error = e.message ?? 'Verification failed (${e.code}).';
        });
      },

      // Called when Firebase has dispatched the SMS
      codeSent: (String verificationId, int? resendToken) {
        if (mounted) setState(() {
          _verificationId = verificationId;
          _codeSent = true;
          _loading  = false;
        });
      },

      // Called after auto-retrieval window expires
      codeAutoRetrievalTimeout: (String verificationId) {
        if (mounted) setState(() { _verificationId = verificationId; });
      },

      timeout: const Duration(seconds: 60),
    );
  }

  // Step 2: Verify OTP
  Future<void> _verifyOtp() async {
    final smsCode = _otpCtrl.text.trim();
    if (smsCode.length != 6) {
      setState(() => _error = 'Enter the 6-digit OTP code.');
      return;
    }
    if (_verificationId == null) return;
    setState(() { _loading = true; _error = null; });

    try {
      final credential = PhoneAuthProvider.credential(
        verificationId: _verificationId!,
        smsCode: smsCode,
      );
      await FirebaseAuth.instance.signInWithCredential(credential);
      if (mounted) Navigator.pop(context);
    } on FirebaseAuthException catch (e) {
      setState(() {
        _loading = false;
        _error = e.code == 'invalid-verification-code'
            ? 'Incorrect OTP. Please check and try again.'
            : 'Verification failed (${e.code}).';
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Phone Sign-In'),
        backgroundColor: const Color(0xFF2856D8),
        foregroundColor: Colors.white,
      ),
      body: Center(
        child: SingleChildScrollView(
          padding: const EdgeInsets.all(24),
          child: Column(
            mainAxisSize: MainAxisSize.min,
            crossAxisAlignment: CrossAxisAlignment.stretch,
            children: [
              const Icon(Icons.phone_iphone_rounded,
                size: 64, color: Color(0xFF2856D8)),
              const SizedBox(height: 20),

              if (!_codeSent) ...[
                const Text('Enter your phone number',
                  style: TextStyle(fontSize: 20, fontWeight: FontWeight.bold),
                  textAlign: TextAlign.center),
                const SizedBox(height: 8),
                const Text('Include country code, e.g. +91 9876543210',
                  style: TextStyle(color: Colors.grey),
                  textAlign: TextAlign.center),
                const SizedBox(height: 20),
                TextFormField(
                  controller: _phoneCtrl,
                  decoration: const InputDecoration(
                    labelText: 'Phone Number',
                    hintText: '+91 9876543210',
                    prefixIcon: Icon(Icons.phone_outlined),
                    border: OutlineInputBorder(),
                  ),
                  keyboardType: TextInputType.phone,
                ),
                const SizedBox(height: 20),
                FilledButton(
                  onPressed: _loading ? null : _sendOtp,
                  child: _loading
                      ? const SizedBox(height: 20, width: 20,
                          child: CircularProgressIndicator(
                            color: Colors.white, strokeWidth: 2))
                      : const Text('Send OTP'),
                ),
              ] else ...[
                Text('Code sent to ${_phoneCtrl.text}',
                  style: const TextStyle(fontSize: 18,
                    fontWeight: FontWeight.bold),
                  textAlign: TextAlign.center),
                const SizedBox(height: 8),
                const Text('Enter the 6-digit code from your SMS',
                  style: TextStyle(color: Colors.grey),
                  textAlign: TextAlign.center),
                const SizedBox(height: 20),
                TextFormField(
                  controller: _otpCtrl,
                  decoration: const InputDecoration(
                    labelText: '6-Digit OTP',
                    prefixIcon: Icon(Icons.lock_outlined),
                    border: OutlineInputBorder(),
                  ),
                  keyboardType: TextInputType.number,
                  maxLength: 6,
                  textAlign: TextAlign.center,
                  style: const TextStyle(fontSize: 24, letterSpacing: 12,
                    fontWeight: FontWeight.bold),
                ),
                const SizedBox(height: 16),
                FilledButton(
                  onPressed: _loading ? null : _verifyOtp,
                  child: _loading
                      ? const SizedBox(height: 20, width: 20,
                          child: CircularProgressIndicator(
                            color: Colors.white, strokeWidth: 2))
                      : const Text('Verify OTP'),
                ),
                const SizedBox(height: 12),
                TextButton(
                  onPressed: () => setState(() {
                    _codeSent = false;
                    _otpCtrl.clear();
                    _error = null;
                  }),
                  child: const Text('← Change phone number'),
                ),
              ],

              if (_error != null) ...[
                const SizedBox(height: 16),
                Container(
                  padding: const EdgeInsets.all(12),
                  decoration: BoxDecoration(
                    color: Colors.red.shade50,
                    border: Border.all(color: Colors.red.shade300),
                    borderRadius: BorderRadius.circular(4),
                  ),
                  child: Text(_error!,
                    style: TextStyle(color: Colors.red.shade800)),
                ),
              ],
            ],
          ),
        ),
      ),
    );
  }
}

Auth Security Best Practices

Use Auth UID in Firestore Security Rules

// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Users can only read and write their own document
    match /users/{userId} {
      allow read, write: if request.auth != null
                        && request.auth.uid == userId;
    }

    // Only authenticated users can read posts
    match /posts/{postId} {
      allow read: if request.auth != null;
      // Only the post author can write/update/delete
      allow write: if request.auth != null
                  && request.auth.uid == resource.data.authorUid;
    }
  }
}
🚫 Never Trust the Client

Never rely on client-side auth checks alone. Always enforce rules server-side in Firestore Rules — a malicious client can bypass any client-side check.

✅ Verify Emails

Call user.sendEmailVerification() after registration and check user.emailVerified before allowing access to sensitive features.

Google Sign-In and Apple Sign-In are more secure than email/password — they eliminate password reuse, brute-force, and phishing risks.

Quick-Answer Flashcards

What is authStateChanges() and why is it the preferred way to track auth?
It is a Stream<User?> from FirebaseAuth.instance. It automatically emits the current user whenever auth state changes — on app start, sign-in, sign-out, and token refresh. Using a StreamBuilder on it means you never need manual navigation calls for auth transitions.
What is an AuthCredential and when do you create one?
An AuthCredential is a platform-independent token bundle that Firebase Auth uses to sign in. You create one for federated providers: GoogleAuthProvider.credential(idToken, accessToken) for Google Sign-In, and PhoneAuthProvider.credential(verificationId, smsCode) for phone OTP. Then pass it to signInWithCredential(credential).
Explain the Phone Auth codeSent callback.
It fires when Firebase has successfully dispatched an SMS. It receives a verificationId (server-side session token) and an optional resendToken. Store the verificationId and show the OTP input field. Later combine it with the user-entered code via PhoneAuthProvider.credential() and call signInWithCredential().
Why is SHA-1 required for Google Sign-In on Android?
Google’s OAuth system verifies the app making a Google Sign-In request is the genuine app — not a fake copy. It checks the SHA-1 fingerprint of the APK signing certificate against registered fingerprints in your Firebase project. Without a matching SHA-1, Google rejects the request with ApiException: 10.
What is the difference between currentUser and authStateChanges()?
FirebaseAuth.instance.currentUser is a synchronous getter returning the cached User? — fine for one-time reads. authStateChanges() is a reactive stream that fires whenever auth state changes. For UI that needs to update on sign-in/sign-out events, always prefer the stream.
