STEP 1 · INTRODUCTION

Data Persistence in Flutter

Learn how to keep app data even after the app is closed and opened again.

Suggested time: 40 minutes
By the end: Understand temporary vs persistent data, use shared_preferences, save/read/update/delete values, store a list, encode simple structured data as JSON, and know when SQLite is a better choice.
User changes data
↓
Flutter saves it locally
↓
App closes
↓
App opens again
↓
Saved data is loaded
Simple idea:

Persistence means data survives longer than the current widget or app session.

STEP 2 · CONCEPT

What Is Data Persistence?

Normal variables disappear when the app process is stopped. Persistent data is stored somewhere outside those temporary variables.

Temporary state

A counter stored only in a Dart variable. Restart the app and it normally returns to its initial value.

Persistent state

A username, theme preference, onboarding flag, or saved record stored on the device.

Think of it like this:

A variable is a whiteboard. Persistent storage is a notebook.

STEP 3 · CHOOSING STORAGE

Which Storage Should We Use?

Different kinds of data need different storage tools.

Storage Good for Example
shared_preferences Small key-value values Dark mode, username, login preference
Files Text, JSON, exported content Notes file, cached JSON
SQLite Many structured records and queries Students, expenses, products
Today:

We start with shared_preferences because it is the easiest way to understand persistence.

STEP 4 · SETUP

Create the Flutter Project

Create a normal Flutter app and add the persistence package.

flutter create persistence_demo
cd persistence_demo
flutter pub add shared_preferences

Import the package

import 'package:shared_preferences/shared_preferences.dart';
Key idea:

shared_preferences stores values using a key and a value.

STEP 5 · KEY-VALUE

Understand Keys and Values

Every saved value is stored under a name called a key.

"username" → "Pratham"
"age" → 22
"darkMode" → true
"score" → 95.5
await prefs.setString('username', 'Pratham');
await prefs.setInt('age', 22);
await prefs.setBool('darkMode', true);
await prefs.setDouble('score', 95.5);
Important:

Use the same key when reading the value later.

STEP 6 · SAVE

Save Data

First get the preferences object, then call a setter.

Future<void> saveName() async {
  final prefs = await SharedPreferences.getInstance();

  await prefs.setString(
    'student_name',
    'Aman',
  );
}
getInstance()

Gives us access to the app's preference storage.

setString()

Saves a String value under a key.

Read the line:

Save the value Aman under the key student_name.

STEP 7 · READ

Read Saved Data

Use a getter that matches the type you saved.

Future<void> loadName() async {
  final prefs = await SharedPreferences.getInstance();

  final name = prefs.getString('student_name');

  print(name);
}

Handle a missing value

final name =
    prefs.getString('student_name') ?? 'Guest';
Why ???

If the key does not exist, the getter can return null. The fallback gives us a safe default value.

STEP 8 · PRACTICAL

Save and Load a Username

Now connect persistence to a real Flutter screen.

import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: HomePage(),
    );
  }
}

class HomePage extends StatefulWidget {
  const HomePage({super.key});

  @override
  State<HomePage> createState() => _HomePageState();
}

class _HomePageState extends State<HomePage> {
  final nameController = TextEditingController();
  String savedName = 'No name saved';

  Future<void> saveName() async {
    final prefs = await SharedPreferences.getInstance();

    await prefs.setString(
      'student_name',
      nameController.text,
    );

    setState(() {
      savedName = nameController.text;
    });
  }

  Future<void> loadName() async {
    final prefs = await SharedPreferences.getInstance();

    setState(() {
      savedName =
          prefs.getString('student_name') ??
          'No name saved';
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Persistence Demo'),
      ),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [
            TextField(
              controller: nameController,
              decoration: const InputDecoration(
                labelText: 'Student Name',
                border: OutlineInputBorder(),
              ),
            ),
            const SizedBox(height: 16),
            ElevatedButton(
              onPressed: saveName,
              child: const Text('Save'),
            ),
            ElevatedButton(
              onPressed: loadName,
              child: const Text('Load'),
            ),
            const SizedBox(height: 24),
            Text(
              'Saved Name: $savedName',
            ),
          ],
        ),
      ),
    );
  }
}
Type name → Save → shared_preferences
Close/reopen app → Load → same saved value
STEP 9 · INITSTATE

Load Data Automatically

Usually users should not have to press a Load button every time the screen opens.

@override
void initState() {
  super.initState();
  loadName();
}
Flow:

Widget is created → initState() runs once → saved value is loaded → setState() updates the UI.

REMEMBER

Do not make initState() itself async. Call an async method from it instead.

STEP 10 · UPDATE

Update Existing Data

There is no special update method. Save another value using the same key.

await prefs.setString(
  'student_name',
  'Riya',
);
student_name → Aman
↓ setString with same key
student_name → Riya
Simple rule:

Same key + new value = old value is replaced.

STEP 11 · DELETE

Remove Saved Data

Delete one value using its key.

final prefs =
    await SharedPreferences.getInstance();

await prefs.remove('student_name');

Clear all preferences

await prefs.clear();
Be careful:

clear() removes all values managed by the preferences store for the app. Use it only when that is really what you want.

STEP 13 · COUNTER

Persistent Counter

This example makes the difference between normal state and persistent state very clear.

class _CounterPageState extends State<CounterPage> {
  int count = 0;

  @override
  void initState() {
    super.initState();
    loadCount();
  }

  Future<void> loadCount() async {
    final prefs =
        await SharedPreferences.getInstance();

    setState(() {
      count = prefs.getInt('count') ?? 0;
    });
  }

  Future<void> increment() async {
    final prefs =
        await SharedPreferences.getInstance();

    setState(() {
      count++;
    });

    await prefs.setInt('count', count);
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Text(
          '$count',
          style: const TextStyle(fontSize: 40),
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: increment,
        child: const Icon(Icons.add),
      ),
    );
  }
}

Class experiment

Run the app, tap the counter several times, completely close the app, and open it again. Ask students why the number is still there.

STEP 14 · LISTS

Save a List of Strings

A simple list of names can be stored directly if every item is a String.

Future<void> saveStudents() async {
  final prefs =
      await SharedPreferences.getInstance();

  await prefs.setStringList(
    'students',
    ['Aman', 'Riya', 'John'],
  );
}

Future<void> loadStudents() async {
  final prefs =
      await SharedPreferences.getInstance();

  final students =
      prefs.getStringList('students') ?? [];

  print(students);
}
Limitation:

List<String> works directly, but a List<Student> does not.

STEP 15 · JSON IDEA

What About a Student Object?

For a small demonstration, convert an object into JSON text, save the text, then decode it later.

import 'dart:convert';

final student = {
  'name': 'Aman',
  'age': 20,
};

final jsonText = jsonEncode(student);

await prefs.setString(
  'student',
  jsonText,
);

Read it again

final jsonText =
    prefs.getString('student');

if (jsonText != null) {
  final student = jsonDecode(jsonText);

  print(student['name']);
  print(student['age']);
}
Teaching note:

This shows the idea of serialization. For many objects, relationships, searching, filtering, and updates, use a real database rather than turning your whole app into preference strings.

STEP 16 · MODEL

Convert a Dart Model to JSON

A model can provide methods that convert between Dart objects and maps.

class Student {
  final String name;
  final int age;

  Student({
    required this.name,
    required this.age,
  });

  Map<String, dynamic> toJson() {
    return {
      'name': name,
      'age': age,
    };
  }

  factory Student.fromJson(
    Map<String, dynamic> json,
  ) {
    return Student(
      name: json['name'],
      age: json['age'],
    );
  }
}
Student object → toJson() → Map → jsonEncode() → String → storage

storage → String → jsonDecode() → Map → fromJson() → Student object
STEP 17 · COMPLETE APP

Mini Persistent Notes App

Save a list of notes locally and restore them when the app opens.

import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: NotesPage(),
    );
  }
}

class NotesPage extends StatefulWidget {
  const NotesPage({super.key});

  @override
  State<NotesPage> createState() => _NotesPageState();
}

class _NotesPageState extends State<NotesPage> {
  final controller = TextEditingController();
  List<String> notes = [];

  @override
  void initState() {
    super.initState();
    loadNotes();
  }

  Future<void> loadNotes() async {
    final prefs =
        await SharedPreferences.getInstance();

    setState(() {
      notes =
          prefs.getStringList('notes') ?? [];
    });
  }

  Future<void> saveNotes() async {
    final prefs =
        await SharedPreferences.getInstance();

    await prefs.setStringList(
      'notes',
      notes,
    );
  }

  Future<void> addNote() async {
    final text = controller.text.trim();

    if (text.isEmpty) return;

    setState(() {
      notes.add(text);
      controller.clear();
    });

    await saveNotes();
  }

  Future<void> deleteNote(int index) async {
    setState(() {
      notes.removeAt(index);
    });

    await saveNotes();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Persistent Notes'),
      ),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [
            TextField(
              controller: controller,
              decoration: const InputDecoration(
                labelText: 'Enter note',
                border: OutlineInputBorder(),
              ),
            ),
            const SizedBox(height: 12),
            ElevatedButton(
              onPressed: addNote,
              child: const Text('Add Note'),
            ),
            const SizedBox(height: 12),
            Expanded(
              child: ListView.builder(
                itemCount: notes.length,
                itemBuilder: (context, index) {
                  return ListTile(
                    title: Text(notes[index]),
                    trailing: IconButton(
                      icon: const Icon(Icons.delete),
                      onPressed: () {
                        deleteNote(index);
                      },
                    ),
                  );
                },
              ),
            ),
          ],
        ),
      ),
    );
  }
}
Add/delete note → update List → save List<String>
Restart app → initState() → load saved list → rebuild UI
STEP 18 · LIMITATIONS

When Should We Use a Database?

Preferences are convenient, but they are not a replacement for a database.

Use preferences

Theme, onboarding completed, selected language, small settings, tiny lists.

Use SQLite/database

Hundreds of expenses, students with many fields, filtering, searching, sorting, relations, reports.

Also:

Do not treat ordinary preferences as secure storage for passwords, tokens, or other sensitive secrets.

Rule of thumb:

Small setting? Key-value storage. Many structured records? Database.

STEP 19 · REVISION

Quick Revision and Viva Questions

Review the core persistence ideas.

1. What is data persistence?
Keeping data so it can still be available after the current app session or widget state ends.
2. What is shared_preferences?
A Flutter plugin for storing small key-value data locally.
3. What is a key?
A unique String name used to identify a stored value.
4. How do we save a String?
Use setString(key, value).
5. How do we read a String?
Use getString(key).
6. How do we update a value?
Save a new value using the same key.
7. How do we delete one value?
Use remove(key).
8. Which list type can be stored directly?
List<String>.
9. Why might we use JSON?
To serialize a small structured object into a String representation.
10. When is SQLite more suitable?
When the app has many structured records or needs efficient searching, filtering, updating, and querying.
