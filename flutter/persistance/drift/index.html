STEP 2 · WHY DATABASES?

Why Not Use SharedPreferences?

Preferences are great for small settings. A database is better when the app has many structured records.

Need SharedPreferences SQLite
Dark mode setting ✅ Good Possible but unnecessary
One username ✅ Good Possible but unnecessary
500 students ❌ Awkward ✅ Good
Search students ❌ Manual ✅ Query
Sort by age ❌ Manual ✅ Query
Update one record ❌ Awkward ✅ Good
Rule:

Small settings → preferences. Structured collections and queries → database.

STEP 3 · DRIFT

What Does Drift Do?

Drift sits between your Flutter code and SQLite.

SQLite

The actual relational database engine that stores rows and tables.

Drift

A Dart database library that generates strongly typed database code.

build_runner

Runs Drift's generator and creates the Dart code your database class needs.

Students table
↓ Drift generator
Generated Student data class
↓
Dart insert / select / update / delete

STEP 5 · TABLE

Define a Students Table

In Drift, we describe our SQLite table using a Dart class.

Create lib/database/app_database.dart.

import 'package:drift/drift.dart';
import 'package:drift_flutter/drift_flutter.dart';

part 'app_database.g.dart';

class Students extends Table {
  IntColumn get id => integer().autoIncrement()();

  TextColumn get name => text()();

  IntColumn get age => integer()();

  TextColumn get course => text()();
}
Students

The table definition.

part ...g.dart

Connects this file to code generated by Drift.

Notice:

You describe columns in Dart. Drift later generates strongly typed classes for them.

STEP 9 · GENERATED TYPES

What Did Drift Generate?

The generator turns the table definition into convenient Dart types.

Student

Represents a complete row read from the students table.

StudentsCompanion

Used when inserting or updating values, especially when some fields such as auto IDs are omitted.

Student(
  id: 1,
  name: 'Aman',
  age: 20,
  course: 'CSE',
)
StudentsCompanion.insert(
  name: 'Aman',
  age: 20,
  course: 'CSE',
)
Difference:

A Student usually represents an existing row. A StudentsCompanion is convenient when writing rows.

STEP 10 · CREATE

Insert a Student

CRUD begins with Create.

Add this method inside AppDatabase.

Future<int> addStudent({
  required String name,
  required int age,
  required String course,
}) {
  return into(students).insert(
    StudentsCompanion.insert(
      name: name,
      age: age,
      course: course,
    ),
  );
}

STEP 11 · READ

Read All Students

Use select() to query a table.

Future<List<Student>> getAllStudents() {
  return select(students).get();
}
select(students)

Creates a query for the students table.

get()

Executes the query once and returns a Future containing the rows.

Use it

final students =
    await database.getAllStudents();

for (final student in students) {
  print(student.name);
}
STEP 12 · WHERE

Find a Student by ID

A WHERE condition filters rows.

Future<Student?> getStudentById(int studentId) {
  return (
    select(students)
      ..where(
        (student) =>
            student.id.equals(studentId),
      )
  ).getSingleOrNull();
}
SELECT students
↓
WHERE id = studentId
↓
one Student or null
Why nullable?

The requested ID might not exist, so the result type is Student?.

STEP 13 · UPDATE

Update a Student

Drift can update the row represented by a generated data class.

Future<bool> updateStudent(
  Student student,
) {
  return update(students).replace(student);
}

Create an updated copy

final updatedStudent =
    student.copyWith(
      name: 'Riya Sharma',
      age: 21,
    );

await database.updateStudent(
  updatedStudent,
);
Why copyWith()?

Generated row classes are immutable. Instead of changing fields directly, create a new copy with selected fields replaced.

STEP 14 · DELETE

Delete a Student

Delete one row using its generated object.

Future<int> deleteStudent(
  Student student,
) {
  return delete(students).delete(student);
}

Or delete using an ID

Future<int> deleteStudentById(int id) {
  return (
    delete(students)
      ..where(
        (student) =>
            student.id.equals(id),
      )
  ).go();
}
Careful:

Always use a WHERE clause when you intend to delete only selected rows.

STEP 15 · STREAMS

Let the UI Update Automatically

One of Drift's nicest Flutter features is watching a query as a Stream.

Stream<List<Student>> watchAllStudents() {
  return select(students).watch();
}
Method Behavior
get() Run the query once.
watch() Keep listening and emit new results when relevant database rows change.
Insert / Update / Delete
↓
Database changes
↓
watch() emits new list
↓
StreamBuilder rebuilds UI
STEP 16 · LIVE UI

Show Students with StreamBuilder

The screen can listen directly to the database stream.

StreamBuilder<List<Student>>(
  stream: database.watchAllStudents(),
  builder: (context, snapshot) {
    if (!snapshot.hasData) {
      return const Center(
        child: CircularProgressIndicator(),
      );
    }

    final students = snapshot.data!;

    if (students.isEmpty) {
      return const Center(
        child: Text('No students yet'),
      );
    }

    return ListView.builder(
      itemCount: students.length,
      itemBuilder: (context, index) {
        final student = students[index];

        return ListTile(
          title: Text(student.name),
          subtitle: Text(
            '${student.course} • Age ${student.age}',
          ),
        );
      },
    );
  },
)
Result:

You do not manually reload the list after each insert or delete. The watched query emits updated results.

STEP 17 · ORDER BY

Sort Query Results

SQLite databases can sort data before it reaches the UI.

Future<List<Student>> getStudentsByName() {
  return (
    select(students)
      ..orderBy([
        (student) =>
            OrderingTerm.asc(student.name),
      ])
  ).get();
}

Age descending

Future<List<Student>> getStudentsByAge() {
  return (
    select(students)
      ..orderBy([
        (student) =>
            OrderingTerm.desc(student.age),
      ])
  ).get();
}
Better design:

Ask the database to sort when possible instead of loading everything and sorting large datasets in Dart.

STEP 20 · SCHEMA

What Is schemaVersion?

Database structure changes over time. Drift uses a schema version to help manage those changes.

@override
int get schemaVersion => 1;

Later you may change the table

class Students extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get name => text()();
  IntColumn get age => integer()();
  TextColumn get course => text()();

  // New column added later
  TextColumn get email =>
      text().nullable()();
}
Do not simply ignore this in production:

After releasing an app, changing an existing database schema requires a proper migration so users keep their old data.

For this beginner codelab:

We stay at schema version 1 and focus first on CRUD and queries.

STEP 21 · DATABASE FILE

Complete AppDatabase

Put the database concepts together in one file.

import 'package:drift/drift.dart';
import 'package:drift_flutter/drift_flutter.dart';

part 'app_database.g.dart';

class Students extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get name => text()();
  IntColumn get age => integer()();
  TextColumn get course => text()();
}

@DriftDatabase(
  tables: [Students],
)
class AppDatabase extends _$AppDatabase {
  AppDatabase()
      : super(
          driftDatabase(
            name: 'college_database',
          ),
        );

  @override
  int get schemaVersion => 1;

  Future<int> addStudent({
    required String name,
    required int age,
    required String course,
  }) {
    return into(students).insert(
      StudentsCompanion.insert(
        name: name,
        age: age,
        course: course,
      ),
    );
  }

  Future<List<Student>> getAllStudents() {
    return select(students).get();
  }

  Stream<List<Student>> watchAllStudents() {
    return (
      select(students)
        ..orderBy([
          (student) =>
              OrderingTerm.asc(student.name),
        ])
    ).watch();
  }

  Future<Student?> getStudentById(int id) {
    return (
      select(students)
        ..where(
          (student) =>
              student.id.equals(id),
        )
    ).getSingleOrNull();
  }

  Future<bool> updateStudent(
    Student student,
  ) {
    return update(students).replace(student);
  }

  Future<int> deleteStudent(
    Student student,
  ) {
    return delete(students).delete(student);
  }

  Future<List<Student>> searchStudents(
    String query,
  ) {
    return (
      select(students)
        ..where(
          (student) =>
              student.name.contains(query),
        )
    ).get();
  }
}
After saving this file:

Run the build runner command again so generated types stay synchronized with your table definitions.

STEP 22 · COMPLETE APP

Student Management App

Now use the database from Flutter and let a StreamBuilder keep the list synchronized.

import 'package:flutter/material.dart';
import 'database/app_database.dart';

void main() {
  final database = AppDatabase();

  runApp(
    MyApp(database: database),
  );
}

class MyApp extends StatelessWidget {
  final AppDatabase database;

  const MyApp({
    super.key,
    required this.database,
  });

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: StudentsPage(
        database: database,
      ),
    );
  }
}

class StudentsPage extends StatefulWidget {
  final AppDatabase database;

  const StudentsPage({
    super.key,
    required this.database,
  });

  @override
  State<StudentsPage> createState() =>
      _StudentsPageState();
}

class _StudentsPageState
    extends State<StudentsPage> {
  final nameController =
      TextEditingController();

  final ageController =
      TextEditingController();

  final courseController =
      TextEditingController();

  Future<void> addStudent() async {
    final name =
        nameController.text.trim();

    final age =
        int.tryParse(ageController.text);

    final course =
        courseController.text.trim();

    if (name.isEmpty ||
        age == null ||
        course.isEmpty) {
      return;
    }

    await widget.database.addStudent(
      name: name,
      age: age,
      course: course,
    );

    nameController.clear();
    ageController.clear();
    courseController.clear();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text(
          'Drift Student Database',
        ),
      ),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: Column(
              children: [
                TextField(
                  controller: nameController,
                  decoration:
                      const InputDecoration(
                    labelText: 'Name',
                  ),
                ),
                TextField(
                  controller: ageController,
                  keyboardType:
                      TextInputType.number,
                  decoration:
                      const InputDecoration(
                    labelText: 'Age',
                  ),
                ),
                TextField(
                  controller:
                      courseController,
                  decoration:
                      const InputDecoration(
                    labelText: 'Course',
                  ),
                ),
                const SizedBox(height: 12),
                ElevatedButton(
                  onPressed: addStudent,
                  child:
                      const Text('Add Student'),
                ),
              ],
            ),
          ),
          Expanded(
            child: StreamBuilder<List<Student>>(
              stream: widget.database
                  .watchAllStudents(),
              builder: (context, snapshot) {
                if (!snapshot.hasData) {
                  return const Center(
                    child:
                        CircularProgressIndicator(),
                  );
                }

                final students =
                    snapshot.data!;

                if (students.isEmpty) {
                  return const Center(
                    child: Text(
                      'No students yet',
                    ),
                  );
                }

                return ListView.builder(
                  itemCount: students.length,
                  itemBuilder:
                      (context, index) {
                    final student =
                        students[index];

                    return ListTile(
                      title:
                          Text(student.name),
                      subtitle: Text(
                        '${student.course} • Age ${student.age}',
                      ),
                      leading: CircleAvatar(
                        child: Text(
                          '${student.id}',
                        ),
                      ),
                      trailing: IconButton(
                        icon: const Icon(
                          Icons.delete,
                        ),
                        onPressed: () {
                          widget.database
                              .deleteStudent(
                                student,
                              );
                        },
                      ),
                    );
                  },
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}
Form → addStudent()
↓
Drift INSERT
↓
SQLite changes
↓
watchAllStudents() emits
↓
StreamBuilder updates automatically

STEP 24 · REVISION

Quick Revision and Viva Questions

Review the complete SQLite + Drift flow.

1. What is SQLite?
A lightweight relational database stored locally with the application.
2. What is Drift?
A Dart database library that provides a type-safe API and generated code for working with databases such as SQLite.
3. Why do we use build_runner?
To run Drift's code generator and create classes based on our table and database definitions.
4. What does a Table class represent?
The schema of a database table and its columns.
5. What is StudentsCompanion?
A generated helper type used to provide values for inserts and updates.
6. What is the difference between get() and watch()?
get() executes once. watch() returns a Stream that emits again when relevant database data changes.
7. How do we insert a row?
Use into(table).insert(...).
8. How do we filter rows?
Use a query with a where() expression.
9. Why use SQLite instead of SharedPreferences?
SQLite is designed for larger structured datasets and database queries such as filtering, sorting, and updating records.
10. What is schemaVersion?
A version number representing the current database schema, used when managing schema changes and migrations.
