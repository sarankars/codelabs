STEP 1 · GOAL

Student CRUD with Drift + Provider + go_router

Build a small Student Management app and use it to understand database persistence, ChangeNotifier state management, Provider, and declarative navigation.

Suggested time: 10 minutes
By the end: Create, read, update, and delete students in Drift; keep screen state inside a ChangeNotifier; expose it with Provider; and navigate between list, add, and edit screens using go_router.

Main rule:

The screen should not directly write SQL or call Drift queries. The screen talks to the provider, and the provider talks to the database.

STEP 2 · ARCHITECTURE

Understand the App Flow

Before writing code, separate the responsibilities of each layer.

PartResponsibilityExample
DriftStore and retrieve persistent recordsInsert a student, fetch all students
ChangeNotifierHold UI state and notify listeners when it changesKeep the current student list
ProviderMake the notifier available to widgetscontext.watch<StudentProvider>()
go_routerDecide which screen should be shown for a URL/path/students/5/edit
Keep this distinction clear:

Provider is how widgets access the state object. ChangeNotifier is the object that actually stores state and sends notifications.

STEP 5 · DRIFT TABLE

Create the Students Table

The table class describes the columns Drift should create in SQLite.

// lib/models/students.dart
import 'package:drift/drift.dart';

class Students extends Table {
  IntColumn get id => integer().autoIncrement()();

  TextColumn get name => text()();

  IntColumn get age => integer()();

  TextColumn get course => text()();
}

STEP 6 · DATABASE

Configure Drift and Generate Code

Register the table in one Drift database class.

// lib/database/app_database.dart
import 'package:drift/drift.dart';
import 'package:drift_flutter/drift_flutter.dart';
import 'package:drift_student_app/models/students.dart';

part 'app_database.g.dart';

@DriftDatabase(tables: [Students])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(
    driftDatabase(name: 'college_database'),
  );

  @override
  int get schemaVersion => 1;
}

Generate the Drift code

dart run build_runner build
Generated file:

You need app_database.g.dart. You do not need a separate students.g.dart for this setup.

STEP 7 · DATABASE CRUD

Put CRUD Methods in AppDatabase

Now give the database a small API that the provider can call.

// Add inside AppDatabase

Future<int> addStudent(StudentsCompanion student) {
  return into(students).insert(student);
}

Future<List<Student>> getAllStudents() {
  return select(students).get();
}

Future<bool> updateStudent(Student student) {
  return update(students).replace(student);
}

Future<int> deleteStudent(int id) {
  return (delete(students)
        ..where((student) => student.id.equals(id)))
      .go();
}
CRUDMethodResult
CreateaddStudent()Inserts a new row
ReadgetAllStudents()Returns List<Student>
UpdateupdateStudent()Replaces the row having the same primary key
DeletedeleteStudent(id)Deletes the matching id
STEP 8 · STATE

Create the State Layer

The database stores data, but widgets still need a state object that tells them when to rebuild.

class StudentProvider extends ChangeNotifier {
  // state lives here

  void somethingChanged() {
    notifyListeners();
  }
}
StudentProvider changes its data
↓
notifyListeners()
↓
widgets using watch/Consumer are notified
↓
those widgets rebuild
Important:

notifyListeners() does not navigate and it does not write to SQLite. It only tells listeners that this notifier's state changed.

STEP 9 · PROVIDER

Store Students Inside StudentProvider

Inject the database through the constructor and keep the current list in private state.

// lib/providers/student_provider.dart
import 'package:flutter/material.dart';
import 'package:drift_student_app/database/app_database.dart';

class StudentProvider extends ChangeNotifier {
  final AppDatabase database;

  StudentProvider(this.database);

  List<Student> _students = [];
  bool _isLoading = false;

  List<Student> get students => _students;
  bool get isLoading => _isLoading;

  Future<void> loadStudents() async {
    _isLoading = true;
    notifyListeners();

    _students = await database.getAllStudents();

    _isLoading = false;
    notifyListeners();
  }
}
Why private fields?

The UI can read students, but it should not directly replace _students. Changes should go through provider methods.

STEP 10 · CREATE

Add a Student

The provider converts form values into the Drift companion required for an insert.

Future<void> addStudent({
  required String name,
  required int age,
  required String course,
}) async {
  await database.addStudent(
    StudentsCompanion.insert(
      name: name,
      age: age,
      course: course,
    ),
  );

  await loadStudents();
}

↓

↓
StudentsCompanion.insert(...)
↓

↓

↓

Why a Companion?

For an insert, Drift's companion lets the database handle generated/default values such as the auto-incrementing id.

STEP 11 · UPDATE / DELETE

Complete the Provider CRUD Methods

Update needs the existing id; delete only needs the id.

Future<void> updateExistingStudent({
  required int id,
  required String name,
  required int age,
  required String course,
}) async {
  await database.updateStudent(
    Student(
      id: id,
      name: name,
      age: age,
      course: course,
    ),
  );

  await loadStudents();
}

Future<void> deleteStudent(int id) async {
  await database.deleteStudent(id);
  await loadStudents();
}

Student? findById(int id) {
  for (final student in _students) {
    if (student.id == id) return student;
  }
  return null;
}
Common mistake:

If you update without preserving the original id, Drift will not know which existing row you mean.

STEP 12 · PROVIDER API

Understand read(), watch(), and Consumer

Use listening only where a widget actually needs to rebuild.

// Rebuild this widget when StudentProvider changes
final provider = context.watch<StudentProvider>();

// Get the provider once; do not rebuild because of this line
final provider = context.read<StudentProvider>();

// Another listening style
Consumer<StudentProvider>(
  builder: (context, provider, child) {
    return Text('${provider.students.length}');
  },
);
APIUse it when...
watchThe widget displays provider state and should rebuild when it changes.
readA callback only wants to call a provider method, such as Save or Delete.
ConsumerYou want to make the listening/rebuild area visually explicit.
STEP 13 · ROUTING

Create the App Router

We need routes for the list, creating a new student, and editing an existing student.

// lib/router/app_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';
import 'package:drift_student_app/screens/student_form_page.dart';
import 'package:drift_student_app/screens/student_list_page.dart';

final GoRouter appRouter = GoRouter(
  initialLocation: '/students',
  routes: [
    GoRoute(
      path: '/students',
      builder: (context, state) => const StudentListPage(),
    ),
    GoRoute(
      path: '/students/add',
      builder: (context, state) => const StudentFormPage(),
    ),
    GoRoute(
      path: '/students/:id/edit',
      builder: (context, state) {
        final id = int.parse(state.pathParameters['id']!);
        return StudentFormPage(studentId: id);
      },
    ),
  ],
);
/students → list
/students/add → create form
/students/7/edit → edit student whose id is 7
Path parameter:

:id is dynamic. go_router puts the actual value into state.pathParameters.

STEP 14 · MAIN

Wire Database, Provider, and Router Together

Create one database, create one StudentProvider above MaterialApp.router, and load the initial data.

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import 'package:drift_student_app/database/app_database.dart';
import 'package:drift_student_app/providers/student_provider.dart';
import 'package:drift_student_app/router/app_router.dart';

void main() {
  final database = AppDatabase();

  runApp(
    ChangeNotifierProvider(
      create: (_) => StudentProvider(database)..loadStudents(),
      child: const MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      title: 'Student CRUD',
      routerConfig: appRouter,
    );
  }
}
Why above MaterialApp.router?

Every routed page appears below this provider, so list/add/edit screens can all access the same StudentProvider.

STEP 15 · READ UI

Show All Students

The list screen watches the provider because it must rebuild after CRUD operations.

// lib/screens/student_list_page.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';
import 'package:provider/provider.dart';
import 'package:drift_student_app/providers/student_provider.dart';

class StudentListPage extends StatelessWidget {
  const StudentListPage({super.key});

  @override
  Widget build(BuildContext context) {
    final provider = context.watch<StudentProvider>();

    return Scaffold(
      appBar: AppBar(
        title: const Text('Students'),
      ),
      body: provider.isLoading
          ? const Center(child: CircularProgressIndicator())
          : provider.students.isEmpty
              ? const Center(child: Text('No students yet'))
              : ListView.builder(
                  itemCount: provider.students.length,
                  itemBuilder: (context, index) {
                    final student = provider.students[index];

                    return ListTile(
                      title: Text(student.name),
                      subtitle: Text(
                        '${student.age} years • ${student.course}',
                      ),
                      onTap: () {
                        context.push('/students/${student.id}/edit');
                      },
                      trailing: IconButton(
                        icon: const Icon(Icons.delete),
                        onPressed: () {
                          context
                              .read<StudentProvider>()
                              .deleteStudent(student.id);
                        },
                      ),
                    );
                  },
                ),
      floatingActionButton: FloatingActionButton(
        onPressed: () => context.push('/students/add'),
        child: const Icon(Icons.add),
      ),
    );
  }
}
Notice both APIs:

The page uses watch to display the list, but the delete button uses read because its callback only triggers an action.

STEP 16 · FORM UI

Use One Screen for Add and Edit

If studentId is null, the form creates. If an id exists, it loads that student and updates it.

// lib/screens/student_form_page.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';
import 'package:provider/provider.dart';
import 'package:drift_student_app/providers/student_provider.dart';

class StudentFormPage extends StatefulWidget {
  final int? studentId;

  const StudentFormPage({
    super.key,
    this.studentId,
  });

  @override
  State<StudentFormPage> createState() => _StudentFormPageState();
}

class _StudentFormPageState extends State<StudentFormPage> {
  final formKey = GlobalKey<FormState>();
  final nameController = TextEditingController();
  final ageController = TextEditingController();
  final courseController = TextEditingController();

  bool get isEditing => widget.studentId != null;

  @override
  void initState() {
    super.initState();

    if (isEditing) {
      final provider = context.read<StudentProvider>();
      final student = provider.findById(widget.studentId!);

      if (student != null) {
        nameController.text = student.name;
        ageController.text = student.age.toString();
        courseController.text = student.course;
      }
    }
  }

  @override
  void dispose() {
    nameController.dispose();
    ageController.dispose();
    courseController.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text(isEditing ? 'Edit Student' : 'Add Student'),
      ),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Form(
          key: formKey,
          child: Column(
            children: [
              TextFormField(
                controller: nameController,
                decoration: const InputDecoration(labelText: 'Name'),
                validator: (value) => value == null || value.trim().isEmpty
                    ? 'Enter a name'
                    : null,
              ),
              TextFormField(
                controller: ageController,
                keyboardType: TextInputType.number,
                decoration: const InputDecoration(labelText: 'Age'),
                validator: (value) => int.tryParse(value ?? '') == null
                    ? 'Enter a valid age'
                    : null,
              ),
              TextFormField(
                controller: courseController,
                decoration: const InputDecoration(labelText: 'Course'),
                validator: (value) => value == null || value.trim().isEmpty
                    ? 'Enter a course'
                    : null,
              ),
              const SizedBox(height: 20),
              ElevatedButton(
                onPressed: saveStudent,
                child: Text(isEditing ? 'Update' : 'Save'),
              ),
            ],
          ),
        ),
      ),
    );
  }

  Future<void> saveStudent() async {
    if (!formKey.currentState!.validate()) return;

    final provider = context.read<StudentProvider>();
    final name = nameController.text.trim();
    final age = int.parse(ageController.text);
    final course = courseController.text.trim();

    if (isEditing) {
      await provider.updateExistingStudent(
        id: widget.studentId!,
        name: name,
        age: age,
        course: course,
      );
    } else {
      await provider.addStudent(
        name: name,
        age: age,
        course: course,
      );
    }

    if (mounted) context.pop();
  }
}
Why mounted?

The database call is asynchronous. Before using context after await, make sure this State is still mounted.

STEP 17 · FLOW

Trace the Create Flow

Follow one button press through every layer.

1. User taps +
↓
2. go_router pushes /students/add
↓
3. User fills form and taps Save
↓
4. context.read<StudentProvider>().addStudent(...)
↓
5. Provider creates StudentsCompanion.insert(...)
↓
6. AppDatabase inserts into SQLite
↓
7. Provider calls loadStudents()
↓
8. Provider calls notifyListeners()
↓
9. StudentListPage was using watch(), so it rebuilds
↓
10. context.pop() returns to the updated list

Class question

If we remove notifyListeners(), would the database still contain the new row? Yes. The persistence layer can succeed while the current UI remains stale until something else rebuilds it.

STEP 18 · FLOW

Trace Update and Delete

CRUD becomes much easier once students can narrate the direction of data.

Update

Tap student → /students/:id/edit → form finds student → controllers are pre-filled → Update → provider → database.replace → reload list → notify → pop

Delete

Tap delete → provider.deleteStudent(id) → database delete WHERE id = ... → reload list → notifyListeners() → ListView rebuilds
Separation test:

If you see delete(students) inside a widget, your UI knows too much about persistence. Move that work into the database/provider layers.

STEP 19 · DEBUGGING

Common Mistakes to Watch For

Most beginner problems happen at the boundary between generation, Provider scope, and navigation.

Undefined class _$AppDatabase
Check part 'app_database.g.dart';, then run dart run build_runner build.
ProviderNotFoundException
Make sure ChangeNotifierProvider is above MaterialApp.router so every routed screen can reach it.
Database changed but UI did not
Reload/update the provider state and call notifyListeners(). Also make sure the displaying widget uses watch or Consumer.
Edit page is empty
Verify the route id parses correctly and findById() can find the student in the already-loaded provider list.
build_runner conflict
During practice, try dart run build_runner build --delete-conflicting-outputs if stale generated outputs are blocking generation.
STEP 20 · REVISION

Revision, Viva, and Practice Challenge

Finish by making students explain the architecture, not just copy the code.

1. What does Drift do?
It manages persistent relational data and gives us type-safe Dart APIs around the database.
2. What does ChangeNotifier do?
It holds state and can notify listeners when that state changes.
3. What does Provider do here?
It exposes StudentProvider to descendant widgets and provides APIs such as read and watch.
4. read vs watch?
read accesses without listening; watch listens and rebuilds the widget when the provider notifies.
5. Why use StudentsCompanion.insert for create?
It represents insert values while allowing generated/default columns such as an auto-increment id to be omitted.
6. Why does update need the id?
The primary key identifies which existing database row should be replaced.
7. What is :id in /students/:id/edit?
A dynamic go_router path parameter.
8. Why is Provider above MaterialApp.router?
So every page created by the router is below the same provider scope.
