STEP 1 · THE BIG PICTURE

Make the UI respond to the user

A Flutter interface becomes interactive when user actions trigger callbacks, callbacks run logic, state changes, and Flutter rebuilds the affected UI.

By the end: You can handle button taps, gestures, text changes, local state, selection controls, controllers, and reusable child-widget callbacks.

STEP 2 · CALLBACKS

Pass a function, don't call it immediately

Flutter widgets expose callback properties. You give the widget a function, and Flutter calls that function later when the event happens.

void sayHello() {
  print('Hello!');
}

ElevatedButton(
  onPressed: sayHello,
  child: const Text('Say Hello'),
);
onPressed: sayHello passes the function itself.
Pass the function

onPressed: sayHello

Flutter stores the callback and runs it after the user taps.

Do not call it here

onPressed: sayHello()

This executes immediately while building and does not provide the callback Flutter expects.

Anonymous callbacks

ElevatedButton(
  onPressed: () {
    print('Button tapped');
  },
  child: const Text('Tap Me'),
);
Two common callback shapes

() { ... } receives no value. (value) { ... } receives data from the event—for example, the latest text or a Checkbox value.

STEP 4 · LOCAL STATE

A changed variable is not enough

When values on the screen can change during the lifetime of a widget, local mutable state belongs in a StatefulWidget. Calling setState() tells Flutter to rebuild using the new state.

StatelessWidget

Great when the widget renders from inputs and does not own changing local values.

StatefulWidget

Use when this widget owns values that change while the user interacts with it.

class CounterPage extends StatefulWidget {
  const CounterPage({super.key});

  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
  int count = 0;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Text('$count'),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          setState(() {
            count++;
          });
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
setState() does not magically change the value. Your Dart code changes the value; setState() schedules the rebuild.

STEP 5 · UI FROM STATE

Let state decide what the user sees

State can control text, icons, colors, visibility, enabled/disabled behavior, and entire branches of the widget tree.

bool liked = false;

IconButton(
  onPressed: () {
    setState(() {
      liked = !liked;
    });
  },
  icon: Icon(
    liked
        ? Icons.favorite
        : Icons.favorite_border,
  ),
);

Conditional expressions

Text(
  isLoggedIn
      ? 'Welcome back!'
      : 'Please sign in',
)

if (showDetails)
  const Text('Extra details appear here'),

In Flutter, you usually describe what the UI should look like for the current state. When state changes, Flutter builds that description again.

STEP 6 · CUSTOM TAP SURFACES

Make more than buttons tappable

GestureDetector lets any child widget respond to gestures. InkWell is useful for tappable Material surfaces that should show ripple feedback.

GestureDetector(
  onTap: () {
    print('Card tapped');
  },
  onDoubleTap: () {
    print('Card double-tapped');
  },
  onLongPress: () {
    print('Card long-pressed');
  },
  child: Container(
    padding: const EdgeInsets.all(24),
    color: Colors.blue,
    child: const Text('Tap this card'),
  ),
)
GestureDetector

Flexible gesture recognition. Useful when the child is not specifically a Material control.

InkWell

Great for Material surfaces when you want visible ink/ripple feedback on tap.

InkWell(
  onTap: () {
    print('Course opened');
  },
  child: const Padding(
    padding: EdgeInsets.all(16),
    child: Text('Open Course'),
  ),
)

STEP 7 · TEXT INPUT

React while the user types

TextField.onChanged provides the latest text each time the field changes. This is a callback that carries a value.

String name = '';

TextField(
  onChanged: (value) {
    setState(() {
      name = value;
    });
  },
),

Text('Hello $name'),
COMPARE

STEP 8 · CONTROL THE FIELD

Read and control text programmatically

A TextEditingController is useful when you want to read the field on demand, set its text, clear it, or observe it through a controller object.

class _ProfilePageState extends State<ProfilePage> {
  final nameController = TextEditingController();

  @override
  void dispose() {
    nameController.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          controller: nameController,
        ),
        ElevatedButton(
          onPressed: () {
            print(nameController.text);
          },
          child: const Text('Submit'),
        ),
      ],
    );
  }
}
Controllers should be disposed when the owning State object is permanently removed.
ApproachBest mental model
onChangedReact whenever the user changes the text.

Controller examples

Use controller.text to read the current text and controller.clear() to clear the field.

STEP 9 · CONTROLLED VALUES

Value in, change callback out

Selection controls make Flutter's state pattern very visible: the widget receives its current value, reports a new value through onChanged, and your state stores that new value.

bool agreed = false;

Checkbox(
  value: agreed,
  onChanged: (value) {
    setState(() {
      agreed = value ?? false;
    });
  },
)
bool notificationsEnabled = true;

Switch(
  value: notificationsEnabled,
  onChanged: (value) {
    setState(() {
      notificationsEnabled = value;
    });
  },
)

STEP 10 · REUSABLE INTERACTION

Data goes down, events come up

A reusable child widget can receive data through constructor parameters and notify its parent through a callback. This keeps state ownership clear and prepares students for larger Flutter architectures.

Parent

Owns liked state.

Passes isLiked down.

Provides an onTap callback.

data →← event
Child

Displays the current value.

Does not need to own the parent's state.

Calls the callback when tapped.

class LikeButton extends StatelessWidget {
  const LikeButton({
    super.key,
    required this.isLiked,
    required this.onTap,
  });

  final bool isLiked;
  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) {
    return IconButton(
      onPressed: onTap,
      icon: Icon(
        isLiked
            ? Icons.favorite
            : Icons.favorite_border,
      ),
    );
  }
}
LikeButton(
  isLiked: liked,
  onTap: () {
    setState(() {
      liked = !liked;
    });
  },
)
