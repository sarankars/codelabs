App Themes & Dark Mode
STEP 1 · DESIGN ONCE

Stop styling every widget by hand

A theme is the application-wide design contract for colors, typography, component appearance, and light/dark behavior. Reusable widgets read from that contract instead of carrying scattered style values.

By the end: You can build Material 3 light and dark themes with ThemeData, ColorScheme, TextTheme, component themes, custom fonts, and ThemeMode—then use them cleanly inside reusable widgets.
Consistency

A shared ThemeData keeps screens and components visually aligned.

Maintainability

Change one theme definition instead of editing dozens of widgets.

Dark mode

The same widgets adapt by reading semantic colors from the active theme.

MENTAL MODEL

Think of a theme as design data flowing down the widget tree. Material widgets automatically use it, and your reusable widgets can access it with Theme.of(context).

STEP 2 · THEME DATA

Start with a complete ThemeData

ThemeData is Flutter's configuration object for a Material app. Material 3 is the default in current Flutter, and most visual behavior is driven by colorScheme and textTheme.

final lightTheme = ThemeData(
  colorScheme: ColorScheme.fromSeed(
    seedColor: const Color(0xFF6750A4),
    brightness: Brightness.light,
  ),
  textTheme: const TextTheme(
    headlineMedium: TextStyle(
      fontSize: 30,
      fontWeight: FontWeight.w700,
    ),
    bodyLarge: TextStyle(fontSize: 16),
  ),
);
Material 3 is enabled by default in modern Flutter. The useMaterial3 flag is mainly relevant when explicitly opting out of Material 3.
Two important inputs

ColorScheme gives the app semantic color roles. TextTheme defines the typography hierarchy. Component themes then refine specific widget families such as buttons or cards.

STEP 3 · SEMANTIC COLORS

Use roles, not random colors

ColorScheme names colors by responsibility: primary actions, surfaces, text-on-surface, error states, and more. This lets the same widget adapt correctly across light and dark themes.

Good

Use colorScheme.primary, surface, onSurface, error, and other semantic roles.

Avoid

Hard-coding Colors.black and Colors.white inside reusable widgets unless that exact color is intentionally part of the design.

STEP 4 · TYPOGRAPHY SYSTEM

Give text styles a hierarchy

Instead of inventing font sizes per screen, define typography roles once and consume them through Theme.of(context).textTheme.

displaySmall · Hero headings
headlineMedium · Screen titles
titleLarge · Card titles
bodyLarge · Primary body text
bodyMedium · Supporting text
final baseTextTheme = ThemeData.light().textTheme;

final appTextTheme = baseTextTheme.copyWith(
  headlineMedium: baseTextTheme.headlineMedium?.copyWith(
    fontWeight: FontWeight.w700,
    letterSpacing: -0.5,
  ),
  titleLarge: baseTextTheme.titleLarge?.copyWith(
    fontWeight: FontWeight.w600,
  ),
);
REUSABLE WIDGET

Inside a component, prefer Theme.of(context).textTheme.titleLarge rather than creating another TextStyle(fontSize: ...). That keeps typography consistent and makes future redesigns easier.

STEP 6 · CUSTOM FONTS

Make the font part of the theme

A custom font should be configured once and then flow through the app. Keep font files in the project, declare them in pubspec.yaml, and apply the family through the theme.

pubspec.yaml

flutter:
  fonts:
    - family: Inter
      fonts:
        - asset: assets/fonts/Inter-Regular.ttf
        - asset: assets/fonts/Inter-SemiBold.ttf
          weight: 600
        - asset: assets/fonts/Inter-Bold.ttf
          weight: 700

ThemeData

final theme = ThemeData(
  fontFamily: 'Inter',
  colorScheme: scheme,
);
IMPORTANT

The family name used in ThemeData(fontFamily: ...) must match the family declared in pubspec.yaml. After changing assets or pubspec.yaml, restart the app if hot reload does not pick up the change.

STEP 8 · MATERIALAPP

Let ThemeMode choose the active theme

MaterialApp accepts theme, darkTheme, and themeMode. ThemeMode.system follows the device preference; light and dark force a specific mode.

STEP 9 · CONSUME THE THEME

Reusable widgets should ask the theme

A good reusable widget owns structure and behavior, but delegates application styling to the theme wherever possible.

class CourseCard extends StatelessWidget {
  const CourseCard({
    super.key,
    required this.title,
    required this.onPressed,
  });

  final String title;
  final VoidCallback onPressed;

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);

    return Card(
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Row(
          children: [
            Expanded(
              child: Text(
                title,
                style: theme.textTheme.titleLarge,
              ),
            ),
            FilledButton(
              onPressed: onPressed,
              child: const Text('Open'),
            ),
          ],
        ),
      ),
    );
  }
}
The card does not specify its background color, button style, or exact title font. The active theme already defines those rules.
Use Theme.of

Read colorScheme and textTheme when your custom widget needs semantic values.

Trust component themes

Let Material components inherit configured defaults instead of restyling every instance.

Keep exceptions local

Override a style only when that specific component intentionally differs from the system.

STEP 10 · PUT IT TOGETHER

Create one maintainable theme system

Now combine the pieces into a small theme module and wire it into the app. The design system becomes reusable just like your widgets.

import 'package:flutter/material.dart';

class AppTheme {
  static const seed = Color(0xFF6750A4);

  static ThemeData light() => _build(Brightness.light);
  static ThemeData dark() => _build(Brightness.dark);

  static ThemeData _build(Brightness brightness) {
    final scheme = ColorScheme.fromSeed(
      seedColor: seed,
      brightness: brightness,
    );

    return ThemeData(
      colorScheme: scheme,
      fontFamily: 'Inter',
      textTheme: const TextTheme(
        headlineMedium: TextStyle(fontWeight: FontWeight.w700),
        titleLarge: TextStyle(fontWeight: FontWeight.w600),
      ),
      filledButtonTheme: FilledButtonThemeData(
        style: FilledButton.styleFrom(
          padding: const EdgeInsets.symmetric(
            horizontal: 20,
            vertical: 14,
          ),
        ),
      ),
      inputDecorationTheme: InputDecorationTheme(
        filled: true,
        border: OutlineInputBorder(
          borderRadius: BorderRadius.circular(12),
        ),
      ),
    );
  }
}
Show the MaterialApp wiring 
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: AppTheme.light(),
      darkTheme: AppTheme.dark(),
      themeMode: ThemeMode.system,
      home: const HomeScreen(),
    );
  }
}
