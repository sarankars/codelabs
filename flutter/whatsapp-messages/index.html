STEP 3 · APP SHELL

Create MyApp & Scaffold

Use a stateful widget so the Faker object belongs to the screen state instead of being recreated as a local variable on every build.

class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  final Faker faker = Faker();

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(),
    );
  }
}
MaterialApp

Creates the Material application environment and sets the first screen with home.

Scaffold

Provides the familiar visual screen structure: app bar, body, drawers, buttons, and more.

StatefulWidget

Splits immutable widget configuration from mutable screen state.

Faker field

Makes one generator available to the state object.

STEP 5 · SCROLLING CONCEPT

What Is SingleChildScrollView?

SingleChildScrollView is a box that gives one child the ability to move through a viewport when that child is larger than the available space.

Single child

It accepts one child. To scroll several widgets together, wrap them in one Column or Row.

Default direction

It scrolls vertically unless scrollDirection: Axis.horizontal is supplied.

Eager layout

The complete child is built and laid out—even content far beyond the visible screen.

Best fit

A normally small screen made of different sections that may overflow on compact devices.

Make one Column scroll

body: SingleChildScrollView(
  child: Column(
    children: const [
      ListTile(title: Text('Message 1')),
      ListTile(title: Text('Message 2')),
      ListTile(title: Text('Message 3')),
    ],
  ),
),
Scaffold body (finite viewport)
└── SingleChildScrollView (scroll owner)
    └── Column (the one child)
        ├── Message row
        ├── Message row
        └── Message row
DO NOT ADD EXPANDED

A vertical scroll view gives its child unbounded height in the scrolling direction. An Expanded inside that Column cannot calculate a finite share of the remaining height.

STEP 6 · REPEAT ROWS

Generate 100 Message Entries

A collection for inside children inserts one widget for every loop iteration.

body: SingleChildScrollView(
  child: Column(
    children: [
      for (int i = 0; i < 100; i++)
        ListTile(
          title: Text('Person ${i + 1}'),
          subtitle: const Text('Message preview'),
        ),
    ],
  ),
),

How the collection for works

PartMeaning
int i = 0Start with index zero.
i < 100Continue while the index is below 100.
i++Increase the index after each row.
ListTile(...)Insert one tile into the children list per iteration.
Performance observation: Before the first frame can display, Flutter creates all 100 ListTile widgets because they are part of the Column's complete child list. This is the limitation we will solve with lazy building.
STEP 7 · MESSAGE DESIGN

Add Avatars, Names & Previews

ListTile already understands the leading–title–subtitle pattern needed by a messages inbox.

ListTile(
  onTap: () {},
  leading: CircleAvatar(
    backgroundImage: NetworkImage(
      faker.image.loremPicsum(
        random: 0,
        seed: faker.randomGenerator.string(100),
      ),
    ),
  ),
  title: Text(
    faker.person.name(),
    style: const TextStyle(
      fontWeight: FontWeight.bold,
    ),
  ),
  subtitle: Text(
    faker.lorem.sentence(),
    maxLines: 1,
    overflow: TextOverflow.ellipsis,
  ),
),
Widget or callResponsibility
CircleAvatarCrops the network image into a circular profile image.
NetworkImageLoads an image from the URL returned by Faker.
faker.person.name()Produces a placeholder contact name.
faker.lorem.sentence()Produces placeholder message text.
maxLines: 1Keeps each preview on one line.
TextOverflow.ellipsisShows an ellipsis when the preview does not fit.
NETWORK NOTE

The avatars depend on Lorem Picsum and require network access. Add an error fallback in a production prototype, and never depend on placeholder image services for real user profiles.

Rebuild behavior: Because Faker is called while the widget tree is built, a rebuild can generate different people and messages. That mirrors the supplied exercise, but stable demo records should be generated once and stored in state.
STEP 8 · COMPLETE VERSION

Add Dividers & Run the Screen

Wrap each tile and divider in an inner Column, then run the completed SingleChildScrollView version.

import 'package:faker/faker.dart';
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  final Faker faker = Faker();

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(
          leading: const Icon(Icons.menu),
          titleSpacing: 0,
          title: const Text('Messenger'),
          centerTitle: false,
        ),
        body: SingleChildScrollView(
          child: Column(
            children: [
              for (int i = 0; i < 100; i++)
                Column(
                  children: [
                    ListTile(
                      onTap: () {},
                      leading: CircleAvatar(
                        backgroundImage: NetworkImage(
                          faker.image.loremPicsum(
                            random: 0,
                            seed: faker.randomGenerator.string(100),
                          ),
                        ),
                      ),
                      title: Text(
                        faker.person.name(),
                        style: const TextStyle(
                          fontWeight: FontWeight.bold,
                        ),
                      ),
                      subtitle: Text(
                        faker.lorem.sentence(),
                        maxLines: 1,
                        overflow: TextOverflow.ellipsis,
                      ),
                    ),
                    const Divider(height: 0),
                  ],
                ),
            ],
          ),
        ),
      ),
    );
  }
}

Verify the result

  1. The app bar stays at the top while the body scrolls.
  2. Each row displays a circular image, bold name, and one-line preview.
  3. A divider separates adjacent conversations.
  4. The final row remains reachable by scrolling.

Small improvements

  1. Replace the leading Icon with an IconButton.
  2. Add trailing: const Text('10:30') to each tile.
  3. Change the message count from 100 to 10 and compare startup behavior.
  4. Use your theme to give the app bar a recognizable color.
STEP 9 · CHOOSE THE RIGHT LIST

ListView, Lazy Lists & When to Use Them

This screen is a long, repeated sequence, so a lazy ListView is a better final implementation than SingleChildScrollView + Column.

ApproachBuild behaviorUse it when
SingleChildScrollView + ColumnBuilds the complete Column and every message row.A small page has different sections that should scroll together and normally fits.
ListView(children: ...)Also receives an explicit, eagerly created list of widgets.The list is short and the children are already known.
ListView.builderCalls itemBuilder for rows as they are needed near the viewport.A long, data-driven sequence without special separators.
ListView.separatedLazily builds both rows and the separators between them.A long, finite list like this inbox where every row needs a divider.
Terminology: “Lazy list” is a behavior, not the name of another Flutter widget. ListView.builder and ListView.separated are lazy constructors of ListView.

Recommended replacement: ListView.separated

Replace the complete SingleChildScrollView body with this code:

body: ListView.separated(
  itemCount: 100,
  itemBuilder: (context, index) {
    return ListTile(
      onTap: () {},
      leading: CircleAvatar(
        backgroundImage: NetworkImage(
          faker.image.loremPicsum(
            random: index,
            seed: 'contact-$index',
          ),
        ),
      ),
      title: Text(
        faker.person.name(),
        style: const TextStyle(fontWeight: FontWeight.bold),
      ),
      subtitle: Text(
        faker.lorem.sentence(),
        maxLines: 1,
        overflow: TextOverflow.ellipsis,
      ),
    );
  },
  separatorBuilder: (context, index) =>
      const Divider(height: 0),
),
ONE MORE PRODUCTION STEP

Generate or load the message data once outside itemBuilder, then make the builder read the record at index. Otherwise a row can receive a new random name when Flutter rebuilds it.

If no divider is needed

body: ListView.builder(
  itemCount: messages.length,
  itemBuilder: (context, index) {
    final message = messages[index];
    return MessageTile(message: message);
  },
),

Decision rule

Different sections, limited content?

Start with SingleChildScrollView + Column.

Repeated data that may grow?

Start with ListView.builder or ListView.separated.
