STEP 1 · WHY ROUTING?

Navigation Gets Bigger as Apps Grow

For a tiny app, Navigator is enough. In a larger app, it is useful to keep routes organized in one routing configuration.

By the end: Configure GoRouter, define GoRoutes, use MaterialApp.router, navigate with go() and push(), pass URL parameters, and create nested routes.
Navigator

You manually push and pop routes.

go_router

You describe routes using URL-like paths and let the router build the correct screen.

/ → Home
/profile → Profile
/students/101 → Student 101
/products?category=mobile → Filtered products

Create the Project and Add go_router

STEP 4 · DEFINE ROUTES

Create a GoRouter

GoRouter stores your app's route configuration.

final router = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) {
        return const HomePage();
      },
    ),
    GoRoute(
      path: '/profile',
      builder: (context, state) {
        return const ProfilePage();
      },
    ),
  ],
);
Part Meaning
GoRouter Main routing configuration.
GoRoute Defines one route.
path The URL-like path.
builder Returns the screen for that path.
STEP 5 · CONNECT THE ROUTER

Use MaterialApp.router

Connect your GoRouter to Flutter using routerConfig.

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      routerConfig: router,
    );
  }
}
Key line:

routerConfig: router connects the app to your route configuration.

STEP 6 · GO TO A ROUTE

Navigate with context.go()

Use go() when you want the app to move to a destination path.

ElevatedButton(
  onPressed: () {
    context.go('/profile');
  },
  child: const Text('Open Profile'),
)
context.go('/');
Easy meaning:

context.go('/profile') means “make /profile the current destination.”

STEP 7 · PUSH ON TOP

Navigate with context.push()

push() puts another destination on top of the current navigation history.

context.push('/profile');
TOP → ProfilePage
HomePage
context.pop();
Memory trick:

push() puts a page on top. pop() removes the top page.

STEP 8 · KNOW THE DIFFERENCE

context.go() vs context.push()

Both navigate, but they express different intentions.

Method Simple meaning Good use
go() Go to this destination. Main sections and URL-style navigation.
push() Put this destination on top. Details pages where Back should return.
pop() Remove the top page. Return from a pushed page.
STEP 9 · RETURN DATA BACK

Get a Result Back from Another Screen

When you open a page with context.push(), you can wait for that page to return a value.

Goal: Open another screen, choose a value there, return it with context.pop(result), and receive it back on the Home screen.
HomePage
↓ context.push<String>('/color')
ColorPage
↓ user selects Blue
context.pop('Blue')
↓
HomePage receives "Blue"

1. Create the route

GoRoute(
  path: '/color',
  builder: (context, state) {
    return const ColorPage();
  },
),

2. Wait for the result on HomePage

final result =
    await context.push<String>('/color');

if (result != null) {
  print('Selected color: $result');
}
Important:

context.push() returns a Future. That Future completes when the pushed page is popped.

3. Return a value from ColorPage

class ColorPage extends StatelessWidget {
  const ColorPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Choose Color'),
      ),
      body: Column(
        children: [

          ListTile(
            title: const Text('Blue'),
            onTap: () {
              context.pop('Blue');
            },
          ),

          ListTile(
            title: const Text('Green'),
            onTap: () {
              context.pop('Green');
            },
          ),
        ],
      ),
    );
  }
}

4. Update the Home screen

class HomePage extends StatefulWidget {
  const HomePage({super.key});

  @override
  State<HomePage> createState() {
    return _HomePageState();
  }
}

class _HomePageState extends State<HomePage> {

  String selectedColor = 'None';

  Future<void> chooseColor() async {

    final result =
        await context.push<String>('/color');

    if (result == null) {
      return;
    }

    setState(() {
      selectedColor = result;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Home'),
      ),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [

            Text(
              'Selected: $selectedColor',
            ),

            ElevatedButton(
              onPressed: chooseColor,
              child: const Text(
                'Choose Color',
              ),
            ),
          ],
        ),
      ),
    );
  }
}
Easy memory trick:

push() sends you forward. pop(result) sends you back with data.

await context.push<String>('/color')
↓
context.pop('Blue')
↓
result == 'Blue'
↓
setState()
↓
Home screen updates

STEP 10 · REPLACE THE TOP PAGE

Use context.pushReplacement()

pushReplacement() removes the current top page and replaces it with a new route.

Login Page
↓ pushReplacement('/home')
Home Page
↓
Login is no longer underneath 
ElevatedButton(
  onPressed: () {
    context.pushReplacement('/home');
  },
  child: const Text('Login'),
)
When is this useful?

A common example is after login. Once the user reaches Home, you normally do not want the Back button to return to the Login page.

Method What happens?
push() Adds the new page on top.
pushReplacement() Removes the current top page and puts the new page there.

STEP 11 · DATA IN THE PATH

Pass a Path Parameter

Use a path parameter when the value identifies what you are opening.

/students/101
↓
101 = student ID
GoRoute(
  path: '/students/:id',
  builder: (context, state) {
    final id = state.pathParameters['id']!;

    return StudentPage(
      studentId: id,
    );
  },
)
context.go('/students/101');
Remember:

:id declares the parameter. state.pathParameters['id'] reads it.

STEP 12 · OPTIONAL URL DATA

Pass a Query Parameter

Query parameters appear after ? and are useful for filters, searches, and optional settings.

/products?category=mobile
↓
path = /products
query = category=mobile
GoRoute(
  path: '/products',
  builder: (context, state) {
    final category =
        state.uri.queryParameters['category'];

    return ProductsPage(
      category: category,
    );
  },
)
context.go('/products?category=mobile');
Type Example Read with
Path /students/101 state.pathParameters['id']
Query /products?category=mobile state.uri.queryParameters['category']
STEP 13 · ROUTES INSIDE ROUTES

Create Nested Routes

Put related child routes inside the parent's routes list.

/students
└── /students/:id
    └── Student details
GoRoute(
  path: '/students',
  builder: (context, state) {
    return const StudentsPage();
  },
  routes: [
    GoRoute(
      path: ':id',
      builder: (context, state) {
        final id =
            state.pathParameters['id']!;

        return StudentPage(
          studentId: id,
        );
      },
    ),
  ],
)
Notice:

The child path is only :id. go_router combines it with the parent /students.

STEP 14 · NESTED NAVIGATION

Keep a Bottom Bar While Screens Change

Nested navigation means part of the app keeps its own Navigator. A common example is a BottomNavigationBar that stays visible while its child screen changes.

Simple idea: Use ShellRoute when you want a common layout around several routes.
App
↓
ShellRoute
├── Home
└── Profile
↓
BottomNavigationBar stays visible
Important difference:

A normal nested GoRoute groups related URL paths. A ShellRoute creates another Navigator and keeps a shared shell around its child routes.

1. Create the ShellRoute

final router = GoRouter(
  initialLocation: '/home',
  routes: [

    ShellRoute(
      builder: (context, state, child) {
        return MainPage(
          child: child,
        );
      },
      routes: [

        GoRoute(
          path: '/home',
          builder: (context, state) {
            return const HomePage();
          },
        ),

        GoRoute(
          path: '/profile',
          builder: (context, state) {
            return const ProfilePage();
          },
        ),
      ],
    ),
  ],
);
What is child?

child is the screen matched by the route. We place that child inside our common page layout.

2. Create the common layout

class MainPage extends StatelessWidget {

  final Widget child;

  const MainPage({
    super.key,
    required this.child,
  });

  @override
  Widget build(BuildContext context) {

    return Scaffold(

      body: child,

      bottomNavigationBar:
          BottomNavigationBar(

        currentIndex:
            GoRouterState.of(context)
                    .uri
                    .path == '/profile'
                ? 1
                : 0,

        onTap: (index) {

          if (index == 0) {
            context.go('/home');
          }

          if (index == 1) {
            context.go('/profile');
          }
        },

        items: const [

          BottomNavigationBarItem(
            icon: Icon(Icons.home),
            label: 'Home',
          ),

          BottomNavigationBarItem(
            icon: Icon(Icons.person),
            label: 'Profile',
          ),
        ],
      ),
    );
  }
}
Tap Home
↓
context.go('/home')
↓
ShellRoute keeps MainPage
↓
child becomes HomePage

3. What stays on the screen?

Changes

The child page changes between HomePage and ProfilePage.

Stays

The BottomNavigationBar stays because it belongs to MainPage.

EXAM / INTERVIEW POINT

ShellRoute creates a nested Navigator for its matching child routes and is useful for layouts such as persistent bottom navigation.

What about separate history for every tab?

For more advanced apps where each bottom-navigation tab must remember its own navigation stack, go_router provides StatefulShellRoute. You only need to remember that concept for now.

STEP 15 · PUT IT TOGETHER

Complete go_router Example

One small app using routes, go, push, path parameters, query parameters, and nesting.

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

void main() {
  runApp(const MyApp());
}

final router = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) {
        return const HomePage();
      },
    ),
    GoRoute(
      path: '/profile',
      builder: (context, state) {
        return const ProfilePage();
      },
    ),
    GoRoute(
      path: '/products',
      builder: (context, state) {
        final category =
            state.uri.queryParameters['category'];

        return ProductsPage(
          category: category,
        );
      },
    ),
    GoRoute(
      path: '/students',
      builder: (context, state) {
        return const StudentsPage();
      },
      routes: [
        GoRoute(
          path: ':id',
          builder: (context, state) {
            final id =
                state.pathParameters['id']!;

            return StudentPage(
              studentId: id,
            );
          },
        ),
      ],
    ),
  ],
);

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      routerConfig: router,
    );
  }
}

class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Home')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            ElevatedButton(
              onPressed: () {
                context.go('/profile');
              },
              child: const Text('Go to Profile'),
            ),
            ElevatedButton(
              onPressed: () {
                context.push('/students/101');
              },
              child: const Text('Open Student 101'),
            ),
            ElevatedButton(
              onPressed: () {
                context.go('/products?category=mobile');
              },
              child: const Text('Mobile Products'),
            ),
          ],
        ),
      ),
    );
  }
}

class ProfilePage extends StatelessWidget {
  const ProfilePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Profile')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            context.go('/');
          },
          child: const Text('Go Home'),
        ),
      ),
    );
  }
}

class StudentsPage extends StatelessWidget {
  const StudentsPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Students')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            context.push('/students/101');
          },
          child: const Text('Open Student 101'),
        ),
      ),
    );
  }
}

class StudentPage extends StatelessWidget {
  final String studentId;

  const StudentPage({
    super.key,
    required this.studentId,
  });

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Student Details'),
      ),
      body: Center(
        child: Text('Student ID: $studentId'),
      ),
    );
  }
}

class ProductsPage extends StatelessWidget {
  final String? category;

  const ProductsPage({
    super.key,
    this.category,
  });

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Products')),
      body: Center(
        child: Text(
          'Category: ${category ?? 'All'}',
        ),
      ),
    );
  }
}

You describe which screen belongs to each location, and the router builds navigation from that configuration.

1. What is go_router?
A Flutter package for declarative, URL-based routing.
2. What is GoRouter?
The main object that stores the route configuration.

It defines a path and the widget for that path.

It connects the Flutter app to the router configuration.

It goes to a destination path and makes the stack match that destination.

It removes the current top page and replaces it with a new route.

state.pathParameters['name']
10. How do you read a query parameter?
state.uri.queryParameters['name']
11. What is a nested route?
A child GoRoute inside a parent's routes list.
10. Why declarative routing?
It keeps routes structured and makes larger navigation easier to organize.
