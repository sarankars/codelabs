STEP 1 · WHY STATE LISTENERS?

Why Do We Need Notifiers?

setState() is great for local UI state. Notifiers help when we want an object to announce that its data has changed.

By the end: Understand Listenable, ValueNotifier, ValueListenableBuilder, ChangeNotifier, notifyListeners(), ListenableBuilder, manual listeners, disposal, list state, and how all of this leads naturally to Provider.
setState()

The widget tells Flutter that its own local state changed.

Notifier

A separate object tells its listeners that some state changed.

Data changes
↓
Notifier informs listeners
↓
Listening UI reacts
Main idea:

A notifier says, “Something inside me changed. Anyone listening should react now.”

STEP 4 · SIMPLE STATE

Meet ValueNotifier

ValueNotifier is the easiest notifier to learn because it stores one value.

final counter = ValueNotifier<int>(0);
Part Meaning
ValueNotifier The notifier object.
<int> The type of value stored.
0 The initial value.

Read the value

print(counter.value);

Change the value

counter.value = 10;

counter.value++;
Important:

Changing .value automatically notifies ValueNotifier's listeners.

STEP 5 · LISTEN IN THE UI

Listen with ValueListenableBuilder

ValueListenableBuilder rebuilds its builder whenever the notifier's value changes.

ValueListenableBuilder<int>(
  valueListenable: counter,
  builder: (context, value, child) {
    return Text(
      '$value',
      style: const TextStyle(fontSize: 40),
    );
  },
)
Part Meaning
valueListenable The ValueNotifier we want to observe.
value The latest value inside the notifier.

STEP 6 · PRACTICAL 1

Build a Counter Without setState()

Use ValueNotifier and ValueListenableBuilder together in a complete page.

import 'package:flutter/material.dart';

class CounterPage extends StatefulWidget {
  const CounterPage({super.key});

  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {

  final ValueNotifier<int> counter =
      ValueNotifier<int>(0);

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('ValueNotifier Counter'),
      ),
      body: Center(
        child: ValueListenableBuilder<int>(
          valueListenable: counter,
          builder: (context, value, child) {
            return Text(
              '$value',
              style: const TextStyle(fontSize: 50),
            );
          },
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          counter.value++;
        },
        child: const Icon(Icons.add),
      ),
    );
  }

  @override
  void dispose() {
    counter.dispose();
    super.dispose();
  }
}
Notice:

There is no setState(). Changing counter.value is enough.

Try it yourself

  1. Add a decrement button.
  2. Add a reset button.
  3. Print the value whenever it changes.
STEP 7 · PRACTICAL 2

Use ValueNotifier with Boolean State

The stored type does not have to be int. ValueNotifier works with any value type.

final ValueNotifier<bool> isDark =
    ValueNotifier<bool>(false);

Toggle the value

isDark.value = !isDark.value;

Listen using a Switch

ValueListenableBuilder<bool>(
  valueListenable: isDark,
  builder: (context, value, child) {
    return Switch(
      value: value,
      onChanged: (newValue) {
        isDark.value = newValue;
      },
    );
  },
)
Good examples

Password visibility, checkbox state, dark mode, loading state.

Another common example

A selected tab index stored in ValueNotifier<int>.

STEP 9 · COMPLEX STATE

Create Your Own ChangeNotifier

ChangeNotifier lets us create one class that owns related state and the methods that change it.

import 'package:flutter/foundation.dart';

class CounterNotifier extends ChangeNotifier {

  int _count = 0;

  int get count => _count;

  void increment() {
    _count++;
    notifyListeners();
  }

  void decrement() {
    _count--;
    notifyListeners();
  }
}
Private state

_count cannot be directly changed from outside the class.

Getter

count lets the UI read the current value safely.

Most important line:

notifyListeners() tells every listener that the notifier's state has changed.

STEP 10 · THE CORE METHOD

Understand notifyListeners() Properly

Changing a field inside ChangeNotifier does not automatically update listeners. You must notify them.

void increment() {
  _count++;
  notifyListeners();
}
increment()
↓
_count changes
↓
notifyListeners()
↓
listeners are informed
If you call it

Listening UI gets a chance to rebuild.

If you forget it

The data changes internally, but listening UI may continue showing the old value.

STEP 11 · LISTEN TO CHANGENOTIFIER

Rebuild UI with ListenableBuilder

ChangeNotifier is a Listenable, so Flutter's ListenableBuilder can react to it.

final CounterNotifier counterNotifier =
    CounterNotifier();
ListenableBuilder(
  listenable: counterNotifier,
  builder: (context, child) {
    return Text(
      '${counterNotifier.count}',
      style: const TextStyle(fontSize: 50),
    );
  },
)

Change the state

ElevatedButton(
  onPressed: () {
    counterNotifier.increment();
  },
  child: const Text('Increase'),
)
Very important:

ChangeNotifier works without Provider. Provider is a separate package that helps us share and access the notifier later.

STEP 12 · ADDLISTENER

Listen Without Rebuilding UI

Sometimes we want to run code on a state change without building a widget.

counterNotifier.addListener(() {
  print('Counter changed');
  print(counterNotifier.count);
});

Use a named listener if you want to remove it later

void onCounterChanged() {
  print(counterNotifier.count);
}

counterNotifier.addListener(
  onCounterChanged,
);

// Later
counterNotifier.removeListener(
  onCounterChanged,
);
Use manual listeners for:

Logging, debugging, side effects, or reacting to controller changes. For normal UI updates, builder widgets are usually cleaner.

STEP 13 · CLEANUP

Dispose Objects You Own

Notifier-style objects may keep listeners and resources. Clean them up when the owning widget is removed.

@override
void dispose() {
  counterNotifier.dispose();
  super.dispose();
}
Notifier

counterNotifier.dispose()

Text controller

controller.dispose()

Focus

focusNode.dispose()

Animation

animationController.dispose()

GOOD HABIT

If your widget creates an object, owns its lifetime, and that object exposes dispose(), dispose it.

STEP 14 · PRACTICAL 3

Manage a Student List with ChangeNotifier

Now use ChangeNotifier for realistic state: a list that can add and remove students.

1. Create StudentNotifier

import 'package:flutter/foundation.dart';

class StudentNotifier extends ChangeNotifier {

  final List<String> _students = [];

  List<String> get students => _students;

  void addStudent(String name) {
    _students.add(name);
    notifyListeners();
  }

  void removeStudent(String name) {
    _students.remove(name);
    notifyListeners();
  }
}

2. Create the page

class StudentsPage extends StatefulWidget {
  const StudentsPage({super.key});

  @override
  State<StudentsPage> createState() {
    return _StudentsPageState();
  }
}

class _StudentsPageState extends State<StudentsPage> {

  final StudentNotifier studentNotifier =
      StudentNotifier();

  final TextEditingController nameController =
      TextEditingController();

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Students'),
      ),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [

            TextField(
              controller: nameController,
              decoration: const InputDecoration(
                labelText: 'Student Name',
                border: OutlineInputBorder(),
              ),
            ),

            const SizedBox(height: 12),

            ElevatedButton(
              onPressed: () {
                final name =
                    nameController.text.trim();

                if (name.isEmpty) {
                  return;
                }

                studentNotifier.addStudent(name);
                nameController.clear();
              },
              child: const Text('Add Student'),
            ),

            const SizedBox(height: 20),

            Expanded(
              child: ListenableBuilder(
                listenable: studentNotifier,
                builder: (context, child) {

                  return ListView.builder(
                    itemCount:
                        studentNotifier.students.length,
                    itemBuilder: (context, index) {

                      final student =
                          studentNotifier.students[index];

                      return ListTile(
                        title: Text(student),
                        trailing: IconButton(
                          icon:
                              const Icon(Icons.delete),
                          onPressed: () {
                            studentNotifier
                                .removeStudent(student);
                          },
                        ),
                      );
                    },
                  );
                },
              ),
            ),
          ],
        ),
      ),
    );
  }

  @override
  void dispose() {
    studentNotifier.dispose();
    nameController.dispose();
    super.dispose();
  }
}
UI responsibility

TextField, buttons, ListView, displaying current data.

Notifier responsibility

Owning the list, adding/removing items, notifying listeners.

TextEditingController and FocusNode are familiar examples of objects that can notify listeners.

TextEditingController

final controller =

focusNode.addListener(() {
  print(focusNode.hasFocus);
});
Big realization:

The notifier/listener pattern is not something unusual added by Provider. Flutter already uses this pattern throughout the framework.

STEP 16 · CHOOSE THE RIGHT TOOL

ValueNotifier vs ChangeNotifier

Use the simplest notifier that fits the state you are managing.

Feature ValueNotifier ChangeNotifier
Best for One simple value Related state + methods
Examples Counter, bool, selected index Cart, students, login, profile
Update Change .value Change fields and call notifyListeners()
Common builder ValueListenableBuilder ListenableBuilder
Easy rule:

One simple value? Start with ValueNotifier. A feature with multiple values and operations? Use ChangeNotifier.

What about setState()?
setState() is still excellent for local widget state. Not every boolean or counter needs a separate notifier.
STEP 17 · NEXT TOPIC

Why Provider Comes Next

Our notifier works, but sharing the same notifier across many screens manually becomes repetitive.

DashboardPage
├── HomePage
├── StudentsPage
├── ProfilePage
└── SettingsPage

Imagine all four screens need the same student state.

StudentsPage(
  studentNotifier: studentNotifier,
)

Then pass it to another screen:

StudentDetailsPage(
  studentNotifier: studentNotifier,
)
Problem:

Passing the same object through many constructors becomes repetitive. This is often called prop drilling.

Provider will solve the sharing problem

ChangeNotifier
+
Provider
↓
Easy access across the widget tree
ChangeNotifierProvider(
  create: (context) => StudentNotifier(),
  child: const MyApp(),
)
Remember this distinction:

ChangeNotifier manages the state. Provider helps make that state available to widgets.

Quick revision

1. What is a notifier?
An object that can inform listeners when its state changes.
2. What is ValueNotifier?
A notifier designed to hold one value.
3. How do we read ValueNotifier state?
Using its .value property.
4. Which widget commonly listens to ValueNotifier?
ValueListenableBuilder.
5. What is ChangeNotifier?
A class that lets us create a custom state object and notify registered listeners.
6. Why call notifyListeners()?
To inform listeners that the ChangeNotifier's state changed.
7. Which widget can listen to ChangeNotifier directly?
ListenableBuilder.
8. What does addListener() do?
Registers a callback that runs when the notifier reports a change.
9. Why dispose a notifier?
To clean up listeners/resources when the owner no longer needs it.
10. Why teach Provider next?
Provider makes it easier to create, share, and access notifier state across the widget tree.
