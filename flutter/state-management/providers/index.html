STEP 1 · INTRODUCTION

State Management with Provider

Learn how to keep shared Flutter state in one place and let many widgets read or update it.

Suggested time: 10 minutes
By the end: Use ChangeNotifier, ChangeNotifierProvider, context.watch(), context.read(), Consumer, MultiProvider, provider scope, shared state across routes, student management, and loading states.

Provider

Simple idea:

Provider helps many widgets use the same state without passing it through every constructor.

STEP 2 · THE PROBLEM

Why Do We Need Shared State?

Sometimes many widgets need the same data.

Local state

Used by one widget only.

Shared state

Used by many widgets or screens, such as students, cart, theme, or logged-in user.

Use Provider when:

More than one widget needs to read or change the same data.

STEP 3 · SETUP

Add the Provider Package

flutter create provider_demo
cd provider_demo
flutter pub add provider

Import it

import 'package:provider/provider.dart';
STEP 4 · CREATE STATE

Create a ChangeNotifier

A ChangeNotifier stores state and can tell the UI when that state changes.

class CounterProvider extends ChangeNotifier {
  int count = 0;

  void increment() {
    count++;
    notifyListeners();
  }
}
count

This is the state.

notifyListeners()

Tells listening widgets that state changed.

Core flow:

Change value → notifyListeners() → listening widgets rebuild.

STEP 5 · CHANGENOTIFIERPROVIDER

Make the State Available

ChangeNotifierProvider creates the notifier and makes it available below it.

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => CounterProvider(),
      child: const MyApp(),
    ),
  );
}
Scope:

Only widgets below this provider can access it.

STEP 6 · WATCH STATE

Read and React with context.watch()

watch() reads the provider and rebuilds the widget when the provider changes.

final counter =
    context.watch<CounterProvider>();

return Text(
  'Count: ${counter.count}',
);
Meaning:

“Give me this provider and rebuild me when it changes.”

STEP 7 · CALL METHODS

Use context.read() for Actions

read() gets the provider without listening for rebuilds.

ElevatedButton(
  onPressed: () {
    context
        .read<CounterProvider>()
        .increment();
  },
  child: const Text('Increment'),
)
Method Use
watch() Read and rebuild when state changes.
read() Read once, usually to call a method.
STEP 8 · CONSUMER

Use Consumer

Consumer is another way to listen to a provider.

Consumer<CounterProvider>(
  builder: (context, counter, child) {
    return Text(
      'Count: ${counter.count}',
    );
  },
)
Use Consumer when:

Only a small part of the UI needs to rebuild.

STEP 9 · COUNTER APP

Complete Provider Counter

Put ChangeNotifier, Provider, watch, and read together.

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => CounterProvider(),
      child: const MyApp(),
    ),
  );
}

class CounterProvider extends ChangeNotifier {
  int count = 0;

  void increment() {
    count++;
    notifyListeners();
  }
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      home: HomePage(),
    );
  }
}

class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    final counter =
        context.watch<CounterProvider>();

    return Scaffold(
      appBar: AppBar(
        title: const Text('Provider Demo'),
      ),
      body: Center(
        child: Text(
          'Count: ${counter.count}',
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          context
              .read<CounterProvider>()
              .increment();
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
Tap button → read().increment() → count changes → notifyListeners() → watch() rebuilds UI
STEP 10 · PRACTICAL STATE

Build a StudentProvider

Now store a shared list instead of one number.

class StudentProvider extends ChangeNotifier {
  final List<String> students = [
    'Aman',
    'Riya',
  ];

  void addStudent(String name) {
    students.add(name);
    notifyListeners();
  }

  void deleteStudent(int index) {
    students.removeAt(index);
    notifyListeners();
  }
}
STEP 11 · STUDENT UI

Add and Delete Students

The screen watches the list and calls provider methods for actions.

class StudentsPage extends StatelessWidget {
  const StudentsPage({super.key});

  @override
  Widget build(BuildContext context) {
    final provider =
        context.watch<StudentProvider>();

    return Scaffold(
      appBar: AppBar(
        title: const Text('Students'),
      ),
      body: ListView.builder(
        itemCount: provider.students.length,
        itemBuilder: (context, index) {
          final student =
              provider.students[index];

          return ListTile(
            title: Text(student),
            trailing: IconButton(
              icon: const Icon(Icons.delete),
              onPressed: () {
                context
                    .read<StudentProvider>()
                    .deleteStudent(index);
              },
            ),
          );
        },
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          context
              .read<StudentProvider>()
              .addStudent('John');
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
STEP 12 · MULTIPROVIDER

Use More Than One Provider

Large apps usually have several pieces of shared state.

MultiProvider(
  providers: [
    ChangeNotifierProvider(
      create: (context) => CounterProvider(),
    ),
    ChangeNotifierProvider(
      create: (context) => StudentProvider(),
    ),
  ],
  child: const MyApp(),
)
MultiProvider:

It simply organizes multiple providers neatly.

STEP 13 · SCOPE

Understand Provider Scope

A provider is available only to widgets below it in the widget tree.

ChangeNotifierProvider<StudentProvider>
↓
MaterialApp
↓
HomePage
↓
StudentsPage
Below it:

Can access the provider.

Above it:

Cannot access the provider.

STEP 14 · SHARE ACROSS ROUTES

Share State Across Screens

Put the provider above MaterialApp so multiple routes can use the same instance.

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => StudentProvider(),
      child: const MyApp(),
    ),
  );
}
StudentProvider
↓

└── StudentsPage
Result:

Both routes see the same student list.

STEP 15 · LOADING

Manage Loading State

Providers can also store UI state such as whether data is loading.

class StudentProvider extends ChangeNotifier {
  bool isLoading = false;
  final List<String> students = [];

  Future<void> loadStudents() async {
    isLoading = true;
    notifyListeners();

    await Future.delayed(
      const Duration(seconds: 2),
    );

    students.addAll([
      'Aman',
      'Riya',
      'John',
    ]);

    isLoading = false;
    notifyListeners();
  }
}

Show the loading UI

final provider =
    context.watch<StudentProvider>();

if (provider.isLoading) {
  return const Center(
    child: CircularProgressIndicator(),
  );
}
isLoading = true → notifyListeners() → spinner → load data → isLoading = false → notifyListeners() → list
STEP 16 · COMPLETE APP

Student Management with Provider

Combine shared state, loading, add, delete, watch, and read.

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => StudentProvider(),
      child: const MyApp(),
    ),
  );
}

class StudentProvider extends ChangeNotifier {
  final List<String> students = [];
  bool isLoading = false;

  Future<void> loadStudents() async {
    isLoading = true;
    notifyListeners();

    await Future.delayed(
      const Duration(seconds: 2),
    );

    students.clear();
    students.addAll(['Aman', 'Riya', 'John']);

    isLoading = false;
    notifyListeners();
  }

  void addStudent(String name) {
    students.add(name);
    notifyListeners();
  }

  void deleteStudent(int index) {
    students.removeAt(index);
    notifyListeners();
  }
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: StudentsPage(),
    );
  }
}

class StudentsPage extends StatelessWidget {
  const StudentsPage({super.key});

  @override
  Widget build(BuildContext context) {
    final provider =
        context.watch<StudentProvider>();

    return Scaffold(
      appBar: AppBar(
        title: const Text('Student Management'),
      ),
      body: provider.isLoading
          ? const Center(
              child: CircularProgressIndicator(),
            )
          : ListView.builder(
              itemCount: provider.students.length,
              itemBuilder: (context, index) {
                return ListTile(
                  title: Text(
                    provider.students[index],
                  ),
                  trailing: IconButton(
                    icon: const Icon(Icons.delete),
                    onPressed: () {
                      context
                          .read<StudentProvider>()
                          .deleteStudent(index);
                    },
                  ),
                );
              },
            ),
      floatingActionButton: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          FloatingActionButton(
            heroTag: 'load',
            onPressed: () {
              context
                  .read<StudentProvider>()
                  .loadStudents();
            },
            child: const Icon(Icons.download),
          ),
          const SizedBox(height: 12),
          FloatingActionButton(
            heroTag: 'add',
            onPressed: () {
              context
                  .read<StudentProvider>()
                  .addStudent('New Student');
            },
            child: const Icon(Icons.add),
          ),
        ],
      ),
    );
  }
}
STEP 17 · REVISION

Quick Revision and Viva Questions

Review the key Provider ideas.

1. What is Provider?
A package used to expose shared state to widgets in the widget tree.
2. What is ChangeNotifier?
A class that stores state and can notify listening widgets.
3. Why call notifyListeners()?
To tell listening widgets that state changed.
4. What does context.watch() do?
Reads a provider and rebuilds when it changes.
5. What does context.read() do?
Reads a provider without listening, usually to call a method.
6. What is Consumer?
A widget that listens to a provider and rebuilds its builder.
7. What is MultiProvider?
A clean way to provide multiple providers.
8. What is provider scope?
A provider is available only to widgets below it.
9. Can state be shared across routes?
Yes. Put the provider above the routes, such as above MaterialApp.
