STEP 2 · TWO DIRECTIONS

Row Goes Across. Column Goes Down.

Row arranges children horizontally. Column arranges children vertically. Both accept a children list and use the same flex layout rules.

CHILD VS CHILDREN

A single-child widget such as Padding uses child. A multi-child widget such as Row, Column, Wrap, or Stack uses children.

STEP 4 · COMPOSITION

Nest Rows and Columns to Build Real UI

Most screens are not one enormous row or column. Build small visual groups, then place those groups inside other layouts.

Row: profile header
├── CircleAvatar
├── SizedBox: horizontal gap
└── Column: profile text
    ├── Text: name
    └── Text: role
const Row(
  crossAxisAlignment: CrossAxisAlignment.center,
  children: [
    CircleAvatar(
      radius: 28,
      child: Text('MS'),
    ),
    SizedBox(width: 12),
    Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        Text(
          'Maya Singh',
          style: TextStyle(fontWeight: FontWeight.bold),
        ),
        SizedBox(height: 4),
        Text('Flutter learner'),
      ],
    ),
  ],
)

Keep nesting understandable

Group by meaning

Think “profile text column,” not “another random column.”

Name complex pieces

Move meaningful sections into variables, helper methods, and later reusable widgets.

Use start and end

Let inherited text direction decide which physical side is the start.

Choose higher-level widgets

A ListTile may express a standard leading-title-trailing row more clearly.

Reading strategy: Start with the outer layout, name each group, and then move inward. Do not try to understand every nested property at once.

STEP 5 · SHARE AVAILABLE ROOM

Expanded Fills. Flexible May Use Less.

Flex children divide the unused main-axis space in a Row, Column, or Flex. The flex value controls each child's share.

Change the flex ratio

1
1
1

Equal flex values divide the available width equally.

WidgetBehaviorTypical use
ExpandedUses a tight fit and fills its allocated share.Text or panels that must take remaining space.
FlexibleUses a loose fit by default and may be smaller than its share.Content that can shrink without being forced to fill.
SpacerAn empty flexible region.Push children apart without a visible box.

Protect long text in a Row

Row(
  children: [
    const CircleAvatar(child: Text('MS')),
    const SizedBox(width: 12),
    Expanded(
      child: Text(
        'A long course title that must fit the remaining width',
        maxLines: 1,
        overflow: TextOverflow.ellipsis,
      ),
    ),
    const Icon(Icons.chevron_right),
  ],
)

Use Spacer for intentional empty flex space

const Row(
  children: [
    Text('Draft'),
    Spacer(),
    Icon(Icons.cloud_done),
    SizedBox(width: 8),
    Text('Saved'),
  ],
)
PARENT RULE

Expanded, Flexible, and Spacer must be descendants of a flex layout such as Row, Column, or Flex.

STEP 6 · DEBUG FLEX LAYOUTS

Fix Overflow by Fixing Constraints

A yellow-and-black stripe means a render object could not fit its child. Do not hide the stripe; determine which child needs a useful width or which layout should flow differently.

Common Row overflow

Problem
Row(
  children: [
    const Icon(Icons.school),
    Text(veryLongTitle),
    const Icon(Icons.chevron_right),
  ],
)
Fix
Row(
  children: [
    const Icon(Icons.school),

        veryLongTitle,
        overflow: TextOverflow.ellipsis,
      ),
    ),
    const Icon(Icons.chevron_right),
  ],
)

Common unbounded flex error

A flex child cannot calculate “the remaining space” on an unbounded main axis. This often happens when an Expanded is placed in a vertical Column that is itself inside a vertical scroll view.

Ask these questions:
  1. Which axis is overflowing?
  2. Does the parent provide a finite maximum on that axis?
  3. Should a child shrink with Expanded or Flexible?
  4. Should items flow with Wrap?
  5. Is the content actually a list that belongs in the scrolling codelab?
DO NOT USE shrinkWrap AS A REFLEX

Changing a scrollable's shrinkWrap setting can affect performance and does not repair an unrelated flex constraint. Identify the actual parent-child constraint first.

STEP 8 · INTENTIONAL OVERLAP

Stack Layers. Positioned Pins.

Stack paints children on top of one another. Later children appear above earlier children. Use Positioned when a child should attach to selected edges.

ToolUse
Stack.alignmentDefault alignment for non-positioned children.
PositionedPin a child using top, right, bottom, left, width, or height.

PositionedDirectionalUse logical start and end edges.

CONSTRAINT RULE

A positioned child must still satisfy the size implied by its chosen edges. Avoid specifying conflicting values such as left, right, and width together.

STEP 9 · CHOOSE A CLEARER TOOL

Know the Useful Alternatives

Row, Column, Wrap, and Stack are flexible primitives. A more specialized widget can sometimes express the design with less code.

ListTile

A standard leading, title, subtitle, and trailing arrangement. Prefer it over rebuilding the same row repeatedly.

IndexedStack

Shows one child by index while keeping the other children in the tree and preserving their state.

Table

Aligns a small set of values into shared columns. It is not a replacement for a large scrolling data grid.

OverflowBar

Arranges action buttons in a row and moves them vertically when they do not fit.

Flex

The general form of Row and Column when the direction must be selected programmatically.

ButtonBar replacement

Prefer OverflowBar for adaptable groups of actions in current Flutter code.

IndexedStack

IndexedStack(
  index: selectedIndex,
  children: const [
    CourseOverview(),
    CourseLessons(),
    CourseProgress(),
  ],
)

Table

const Table(
  columnWidths: {
    0: IntrinsicColumnWidth(),
    1: FlexColumnWidth(),
  },
  children: [
    TableRow(children: [Text('Duration'), Text('30 days')]),
    TableRow(children: [Text('Level'), Text('Intermediate')]),
  ],
)
Keep Table small: IntrinsicColumnWidth measures content and can be expensive when repeated many times. Use it for compact information, not hundreds of rows.

STEP 10 · GUIDED BUILD

Build a Course Overview Card

Combine linear layout, flex space, wrapping content, and an overlapping status indicator in one practical component.

Card
└── Padding
    └── Column
        ├── Row: Stack avatar + Expanded text + progress
        ├── Divider
        ├── Wrap: topic chips
        └── Row: two Expanded buttons
class CourseOverviewCard extends StatelessWidget {
  const CourseOverviewCard({super.key});

  @override
  Widget build(BuildContext context) {
    return Card(
      child: Padding(
        padding: const EdgeInsets.all(20),
        child: Column(
          mainAxisSize: MainAxisSize.min,
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Row(
              children: [
                Stack(
                  clipBehavior: Clip.none,
                  children: [
                    const CircleAvatar(
                      radius: 30,
                      child: Text('FS'),
                    ),
                    Positioned(
                      top: -2,
                      right: -2,
                      child: Container(
                        width: 18,
                        height: 18,
                        decoration: BoxDecoration(
                          color: Colors.green,
                          shape: BoxShape.circle,
                          border: Border.all(
                            color: Colors.white,
                            width: 2,
                          ),
                        ),
                      ),
                    ),
                  ],
                ),
                const SizedBox(width: 14),
                const Expanded(
                  child: Column(
                    mainAxisSize: MainAxisSize.min,
                    crossAxisAlignment: CrossAxisAlignment.start,
                    children: [
                      Text(
                        'Flutter UI Foundations',
                        maxLines: 1,
                        overflow: TextOverflow.ellipsis,
                        style: TextStyle(fontWeight: FontWeight.bold),
                      ),
                      SizedBox(height: 4),
                      Text('Week 2 · 4 lessons'),
                    ],
                  ),
                ),
                const SizedBox(width: 12),
                const Text(
                  '72%',
                  style: TextStyle(fontWeight: FontWeight.bold),
                ),
              ],
            ),
            const Divider(height: 32),
            const Wrap(
              spacing: 8,
              runSpacing: 8,
              children: [
                Chip(label: Text('Layouts')),
                Chip(label: Text('Flex')),
                Chip(label: Text('Wrap')),
                Chip(label: Text('Stack')),
              ],
            ),
            const SizedBox(height: 20),
            Row(
              children: [
                Expanded(
                  child: OutlinedButton(
                    onPressed: () {},
                    child: const Text('Review'),
                  ),
                ),
                const SizedBox(width: 12),
                Expanded(
                  child: FilledButton(
                    onPressed: () {},
                    child: const Text('Continue'),
                  ),
                ),
              ],
            ),
          ],
        ),
      ),
    );
  }
}
Read it outside in: The column creates vertical sections. Each row solves one horizontal section. Expanded protects flexible content, Wrap lets chips flow, and Stack owns the deliberate overlap.

Run these layout experiments

  1. Change the title to a much longer value and confirm it does not overflow.
  2. Give the Continue button flex: 2.
  3. Add three more chips and narrow the window.
  4. Move the status dot to the bottom-right.
  5. Set the outer column's crossAxisAlignment to center and explain every visual change.
