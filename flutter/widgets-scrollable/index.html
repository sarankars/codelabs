STEP 1 · START HERE

Choose the Right Scrollable

Scrolling is not something you add after a layout overflows. It is a layout decision based on the shape, size, and behavior of your content.

By the end: You can build efficient vertical, horizontal, and grid-based scrolling interfaces; control their position; and fix the most common constraint errors.

Start from the content

ContentGood starting widget
A small screen made of different sectionsSingleChildScrollView with one Column
A short, known sequenceListView
A long or data-driven sequenceListView.builder or ListView.separated
Items arranged in rows and columnsGridView or GridView.builder
A list and grid sharing one advanced scroll effectCustomScrollView with slivers—a later topic

ListView: users move through a continuous vertical sequence.

Viewport + content + position

Viewport

The visible window through which the user sees the content.

Scroll extent

The full distance through which the content can move.

Offset

The current distance from the beginning of the scrollable.

Axis

The direction of movement: vertical or horizontal.

CORE IDEA

A Column lays out children but does not scroll. A ListView both lays out and scrolls its children.

STEP 2 · ONE CHILD

SingleChildScrollView

Use SingleChildScrollView when one normally small composition must remain reachable on a short screen, in landscape, or when the keyboard appears.

PropertyPurposeTypical value
childThe one widget that scrolls.A Column
scrollDirectionSelects the scrolling axis.Axis.vertical
paddingAdds space around the content.EdgeInsets.all(16)
physicsChanges how the scrollable responds to gestures.Usually the platform default
controllerReads or changes the scroll position.A ScrollController
Scaffold(
  appBar: AppBar(title: const Text('Course details')),
  body: SingleChildScrollView(
    padding: const EdgeInsets.all(16),
    child: Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        const CourseBanner(),
        const SizedBox(height: 16),
        Text(
          'What you will learn',
          style: Theme.of(context).textTheme.headlineSmall,
        ),
        const SizedBox(height: 8),
        const CourseOutline(),
        const SizedBox(height: 24),
        const EnrollButton(),
      ],
    ),
  ),
)
EFFICIENCY

This widget builds its complete child. If the page contains many repeated items or is expected to be much taller than the viewport, prefer a lazy list.

Do not use Expanded in an unbounded axis

A vertical scroll view gives its child unlimited height in the scroll direction. An Expanded inside that child cannot calculate a finite share of “remaining height.”

Avoid

SingleChildScrollView → Column → Expanded

Prefer

Let the Column size its children, or redesign the screen around a bounded ListView.

STEP 3 · LINEAR CONTENT

ListView & ListView.separated

ListView arranges children one after another in the scroll direction. Choose its constructor based on how the items are produced.

A small, fixed list

ListView(
  padding: const EdgeInsets.all(16),
  children: const [
    ListTile(
      leading: Icon(Icons.play_circle_outline),
      title: Text('Introduction'),
    ),
    ListTile(
      leading: Icon(Icons.widgets_outlined),
      title: Text('Widgets'),
    ),
    ListTile(
      leading: Icon(Icons.view_agenda_outlined),
      title: Text('Layouts'),
    ),
  ],
)

Add separators without manual indexes

final lessons = ['Introduction', 'Widgets', 'Layouts'];

ListView.separated(
  padding: const EdgeInsets.all(16),
  itemCount: lessons.length,
  itemBuilder: (context, index) {
    return ListTile(
      leading: CircleAvatar(child: Text('${index + 1}')),
      title: Text(lessons[index]),
    );
  },
  separatorBuilder: (context, index) => const Divider(),
)
ConstructorBest use
ListView(children: ...)A small number of widgets already known in the code.
ListView.separatedA finite data-driven list that needs consistent gaps or dividers.
ListView.builderA long data-driven list without a separate separator builder.
Safe-area note: A primary vertical ListView may apply padding from MediaQuery at its scrollable edges. Set an explicit padding, including EdgeInsets.zero, when you need to control it.
STEP 4 · LAZY BUILDING

ListView.builder

The builder constructor creates items on demand. It is the everyday choice for lists produced from application data.

final courses = List.generate(
  100,
  (index) => 'Flutter lesson ${index + 1}',
);

ListView.builder(
  padding: const EdgeInsets.all(16),
  itemCount: courses.length,
  itemBuilder: (context, index) {
    final course = courses[index];

    return Card(
      child: ListTile(
        leading: const Icon(Icons.school_outlined),
        title: Text(course),
        subtitle: Text('Lesson ${index + 1} of ${courses.length}'),
      ),
    );
  },
)
PropertyWhy it matters
itemCountGives the scroll view a known item count and prevents indexes beyond the collection.
itemBuilderBuilds the widget requested for an index.
itemExtentSets one fixed size in the scroll direction and can make layout more efficient.
prototypeItemMeasures a representative widget when every item has the same extent.
IMPORTANT

Provide itemCount when the list is finite. It improves scroll metrics and keeps the builder from requesting invalid indexes.

What happens to items away from the viewport?

Lazy lists create visible children as needed. Children far outside the viewport can be destroyed and rebuilt later, so durable application state should live in your data model rather than only inside a list row.

STEP 5 · SIDEWAYS & PAGES

Horizontal Lists & PageView

Use a horizontal list when several items may share the viewport. Use PageView when each item should behave like a distinct page.

Show several items in a horizontal rail

SizedBox(
  height: 180,
  child: ListView.separated(
    padding: const EdgeInsets.symmetric(horizontal: 16),
    scrollDirection: Axis.horizontal,
    itemCount: courses.length,
    separatorBuilder: (context, index) =>
        const SizedBox(width: 12),
    itemBuilder: (context, index) {
      return SizedBox(
        width: 240,
        child: CourseCard(course: courses[index]),
      );
    },
  ),
)
CONSTRAINTS

A horizontal list placed in a vertical layout needs a bounded height. Here, SizedBox(height: 180) defines the viewport height, while each card defines its width.

Make the direction obvious

  • Show part of the next item when the design allows it.
  • Keep card widths consistent so the movement is predictable.
  • Add a heading such as “Popular courses” before the rail.
  • Do not hide essential actions in a carousel when users may not discover them.

Move one full page at a time

PageView.builder(
  itemCount: onboardingPages.length,
  onPageChanged: (index) {
    setState(() => currentPage = index);
  },
  itemBuilder: (context, index) {
    return OnboardingPage(
      page: onboardingPages[index],
    );
  },
)
ChooseWhenTypical examples
Horizontal ListViewSeveral cards can be visible and users browse a continuous rail.Featured courses, categories, stories
PageViewOne page owns the viewport and movement should snap between pages.Onboarding, full-screen gallery, tab-like pages
STATE

Use onPageChanged to update dots, labels, or buttons. If you create a PageController in a state object, dispose it just like a ScrollController.

STEP 6 · TWO DIMENSIONS

GridView

GridView is a scrollable two-dimensional arrangement. The grid delegate controls column count, width, spacing, and tile shape.

A fixed number of columns

GridView.count(
  padding: const EdgeInsets.all(16),
  crossAxisCount: 2,
  crossAxisSpacing: 12,
  mainAxisSpacing: 12,
  childAspectRatio: 1.2,
  children: const [
    CourseCard(title: 'Dart'),
    CourseCard(title: 'Widgets'),
    CourseCard(title: 'Layouts'),
    CourseCard(title: 'Navigation'),
  ],
)

A lazy, width-aware grid

GridView.builder(
  padding: const EdgeInsets.all(16),
  itemCount: courses.length,
  gridDelegate: const SliverGridDelegateWithMaxCrossAxisExtent(
    maxCrossAxisExtent: 240,
    crossAxisSpacing: 12,
    mainAxisSpacing: 12,
    childAspectRatio: 1.2,
  ),
  itemBuilder: (context, index) {
    return CourseCard(course: courses[index]);
  },
)
DelegateChoose it when
SliverGridDelegateWithFixedCrossAxisCountThe design requires an exact column count.
SliverGridDelegateWithMaxCrossAxisExtentColumns should adapt while each tile stays below a maximum width.
ONE SCROLL OWNER

A GridView already scrolls. If a page needs a header, list, and grid to move together, learn CustomScrollView and slivers instead of nesting multiple full-size scroll views.

STEP 7 · CONTROL & FEEDBACK

Controllers, Physics & Scrollbars

Most scrollables work without configuration. Add control only when the product behavior needs it.

Move to a known position

class CourseListState extends State<CourseList> {
  final _scrollController = ScrollController();

  @override
  void dispose() {
    _scrollController.dispose();
    super.dispose();
  }

  void _backToTop() {
    _scrollController.animateTo(
      0,
      duration: const Duration(milliseconds: 400),
      curve: Curves.easeOut,
    );
  }

  @override
  Widget build(BuildContext context) {
    return ListView.builder(
      controller: _scrollController,
      itemCount: courses.length,
      itemBuilder: (context, index) =>
          CourseTile(course: courses[index]),
    );
  }
}
LIFECYCLE

Create a long-lived ScrollController in state when you need to reuse it, and dispose it when that state is removed.

Common scroll behavior tools

ToolPurpose
ScrollbarAdds a visible position indicator, especially helpful on desktop and web.
RefreshIndicatorRuns an asynchronous refresh action after a downward overscroll gesture.
AlwaysScrollableScrollPhysicsAllows the scrollable to accept scrolling even when its content does not exceed the viewport; useful with pull-to-refresh.
NeverScrollableScrollPhysicsPrevents user-driven scrolling when another widget owns the gesture.
RefreshIndicator(
  onRefresh: loadCourses,
  child: ListView.builder(
    physics: const AlwaysScrollableScrollPhysics(),
    itemCount: courses.length,
    itemBuilder: (context, index) =>
        CourseTile(course: courses[index]),
  ),
)
Platform behavior: The default physics already adapts to the platform. Do not replace it only to make every platform feel identical.
STEP 8 · DEBUG & BUILD

Fix Common Errors

Most scrolling bugs come from choosing the wrong scroll owner or giving a scrollable an unbounded size on its cross axis.

ProblemCauseUseful fix
“Vertical viewport was given unbounded height”A vertical scrollable is inside a Column without a height.Wrap the scrollable with Expanded or give it a bounded height.
Expanded fails inside a vertical scroll viewThe scroll direction provides no finite remaining height.Remove the flex child or redesign around one bounded scrollable.
The page feels slowA long list uses SingleChildScrollView + Column.Use a lazy builder.
Nested scrolling feels stuckTwo same-axis scrollables compete for gestures.Choose one scroll owner; use slivers for mixed content.
shrinkWrap: true is used everywhereThe inner scrollable is being measured from all its children.Prefer proper constraints or one parent scrollable; reserve shrink-wrap for small, bounded cases.
