Easy definition:

STEP 5 · REST

Understand REST by Looking at Products

REST is a common architectural style for web APIs. From the client side, the important idea is that data is exposed as resources and standard HTTP methods are used to interact with those resources.

Resource

A thing exposed by the API. Here, our main resource is products.

Representation

The server sends a representation of a product, usually as JSON.

GET /products → get products
GET /products/1 → get product 1
POST /products/add → simulate adding a product
PATCH /products/1 → simulate updating product 1
DELETE /products/1 → simulate deleting product 1
REST is not a Flutter feature.

Flutter is simply one client. A website, native Android app, iOS app, or another server could call the same endpoints.

An HTTP request contains the information the server needs to understand what the client wants.

Host: dummyjson.com

STEP 8 · HTTP RESPONSE

What Does the Server Send Back?

The server processes the request and returns a response containing a status, headers and usually some data.

HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "title": "Essence Mascara Lash Princess",
  "category": "beauty",
  "price": 9.99,
  "rating": 4.94
}
Status code

Tells the app whether the request succeeded or failed.

Response body

Contains the returned data, commonly as JSON.

STEP 9 · HTTP METHODS

Different Methods Express Different Actions

The HTTP method tells the API what type of operation the client wants to perform.

MethodTypical meaningDummyJSON example
GETRead dataGET /products
POSTCreate/submit dataPOST /products/add
PUTUpdate/replace dataPUT /products/1
PATCHPartially update dataPATCH /products/1
DELETERemove dataDELETE /products/1
Memory trick:

GET = read, POST = create, PUT/PATCH = update, DELETE = remove.

STEP 12 · PUT AND PATCH

Understand Product Updates

PUTOften used for a full replacement/update.
PATCHOften used to update only selected fields.

STEP 14 · STATUS CODES

How Does the App Know What Happened?

HTTP status codes summarize the result of a request.

Range / CodeMeaningExample
200SuccessA product was returned.
201CreatedA create request succeeded.
400Bad requestThe request is invalid.
401UnauthorizedAuthentication is required or invalid.
404Not foundThe requested resource does not exist.
500Server errorThe server failed while processing the request.
Useful practice:

DummyJSON also exposes HTTP test routes, such as https://dummyjson.com/http/404, which can be useful later for practicing error handling.

STEP 15 · HEADERS AND BODY

Extra Information Around the Data

Headers carry metadata. The request body carries the main data we want to send.

POST /products/add
Content-Type: application/json

{
  "title": "Flutter Hoodie",
  "price": 1299
}
Header

Content-Type: application/json tells the server that the body contains JSON.

Body

The JSON object contains the product data being sent.

Later:

Authentication APIs may also use an Authorization header, commonly with a bearer token.

STEP 19 · COMMON MISTAKES

Avoid These Networking Confusions

Keep the responsibilities of the client, API, request and response separate.

Mistake: API = server

The API is the interface exposed by the server.

Mistake: JSON = Dart Map

JSON is text. Flutter later decodes it into Dart values.

Mistake: every API has the same shape

Always read the API documentation before parsing its response.

Mistake: POST means permanent here

DummyJSON's write operations are simulations for testing and learning.

Most important habit:

Before writing Flutter code, open the API documentation and understand the endpoint, method, parameters, headers and response JSON.

1. What is the client in our example?

2. What is the server?
The remote system at dummyjson.com that receives our HTTP requests and sends responses.
3. What is an API?
A defined interface that allows one software system to communicate with another.
4. What is REST?
A common architectural style for web APIs that exposes resources and uses HTTP concepts to interact with them.
5. What is our base URL?
https://dummyjson.com
6. What does GET /products do?
Requests the products collection.
7. How do we request one product?
Use a URL such as GET /products/1.
8. How can we search products?
Use a query such as /products/search?q=phone.
9. What do limit and skip help with?
Pagination—requesting a smaller section of a larger collection.
10. What is a status code?
A numeric result such as 200 or 404 that summarizes the outcome of an HTTP request.
11. What is Content-Type?
A header that describes the format of the request or response body, such as application/json.
12. What is JSON?
A text format commonly used by REST APIs to exchange structured data.
13. Are DummyJSON POST/PATCH/DELETE changes permanent?
No. They are simulated operations intended for testing and prototyping.
