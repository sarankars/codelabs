STEP 4 · REUSE THE MODEL

Use the Product Model from the Previous Codelab

We will use a small model containing only the fields needed for this CRUD exercise.

class Product {
  final int? id;
  final String title;
  final double price;

  const Product({
    this.id,
    required this.title,
    required this.price,
  });

  factory Product.fromJson(Map<String, dynamic> json) {
    return Product(
      id: json['id'] as int?,
      title: json['title'] as String? ?? '',
      price: (json['price'] as num?)?.toDouble() ?? 0,
    );
  }

  Map<String, dynamic> toJson() {
    return {
      'title': title,
      'price': price,
    };
  }
}
Why is id nullable?

Before a new product is sent to the server, it may not have an ID yet. The server response supplies one.

STEP 6 · READ MANY

Fetch the Product List with GET

Start with the READ part of CRUD.

static Future<List<Product>> getProducts() async {
  final uri = Uri.parse('$baseUrl?limit=10');
  final response = await http.get(uri);

  if (response.statusCode != 200) {
    throw Exception('Failed to load products');
  }

  final data = jsonDecode(response.body)
      as Map<String, dynamic>;

  final list = data['products'] as List<dynamic>;

  return list
      .map((json) => Product.fromJson(
            json as Map<String, dynamic>,
          ))
      .toList();
}

STEP 8 · CREATE

Create a Product with POST

POST sends new data to the server. DummyJSON uses /products/add for this operation.

static Future<Product> createProduct(
  Product product,
) async {
  final uri = Uri.parse('$baseUrl/add');

  final response = await http.post(
    uri,
    headers: {
      'Content-Type': 'application/json',
    },
    body: jsonEncode(product.toJson()),
  );

  if (response.statusCode != 200 &&
      response.statusCode != 201) {
    throw Exception('Failed to create product');
  }

  return Product.fromJson(
    jsonDecode(response.body) as Map<String, dynamic>,
  );
}

STEP 10 · UPDATE

Update a Product with PATCH

Use the product ID in the path and send only the fields you want to change.

static Future<Product> updateProduct(
  Product product,
) async {
  if (product.id == null) {
    throw Exception('Product ID is required');
  }

  final uri = Uri.parse('$baseUrl/${product.id}');

  final response = await http.patch(
    uri,
    headers: {
      'Content-Type': 'application/json',
    },
    body: jsonEncode(product.toJson()),
  );

  if (response.statusCode != 200) {
    throw Exception('Failed to update product');
  }

  return Product.fromJson(
    jsonDecode(response.body) as Map<String, dynamic>,
  );
}
PATCH vs PUT:

PATCH is commonly used for partial changes. PUT is commonly used when replacing a full representation. DummyJSON accepts either for product updates.

STEP 11 · DELETE

Delete a Product by ID

DELETE normally identifies the target resource using its ID in the URL.

static Future<void> deleteProduct(int id) async {
  final uri = Uri.parse('$baseUrl/$id');
  final response = await http.delete(uri);

  if (response.statusCode != 200) {
    throw Exception('Failed to delete product');
  }
}
DummyJSON behavior:

The response reports the product as deleted, but the public server does not permanently remove it.

STEP 13 · FORM → POST

Create a Product from Form Values

Validate the form, convert text into a Product object, then call the API.

Future<void> createProduct() async {
  if (!formKey.currentState!.validate()) {
    return;
  }

  final product = Product(
    title: titleController.text.trim(),
    price: double.parse(priceController.text),
  );

  try {
    final created =
        await ProductApi.createProduct(product);

    if (!mounted) return;
    Navigator.pop(context, created);
  } catch (e) {
    if (!mounted) return;
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(content: Text(e.toString())),
    );
  }
}

STEP 18 · REMOVE FROM UI

Delete Remotely, Then Remove Locally

Only remove the product from the visible list after the DELETE request succeeds.

Future<void> removeProduct(Product product) async {
  try {
    await ProductApi.deleteProduct(product.id!);

    setState(() {
      products.removeWhere(
        (item) => item.id == product.id,
      );
    });
  } catch (e) {
    if (!mounted) return;

    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(content: Text(e.toString())),
    );
  }
}

STEP 20 · PUT THE SERVICE TOGETHER

Complete ProductApi

This service now contains every CRUD operation used by the application.

class ProductApi {
  static const baseUrl =
      'https://dummyjson.com/products';

  static Future<List<Product>> getProducts() async {
    final response = await http.get(
      Uri.parse('$baseUrl?limit=10'),
    );

    if (response.statusCode != 200) {
      throw Exception('Failed to load products');
    }

    final data = jsonDecode(response.body)
        as Map<String, dynamic>;

    return (data['products'] as List<dynamic>)
        .map((json) => Product.fromJson(
              json as Map<String, dynamic>,
            ))
        .toList();
  }

  static Future<Product> createProduct(
    Product product,
  ) async {
    final response = await http.post(
      Uri.parse('$baseUrl/add'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode(product.toJson()),
    );

    if (response.statusCode != 200 &&
        response.statusCode != 201) {
      throw Exception('Create failed');
    }

    return Product.fromJson(
      jsonDecode(response.body),
    );
  }

  static Future<Product> updateProduct(
    Product product,
  ) async {
    final response = await http.patch(
      Uri.parse('$baseUrl/${product.id}'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode(product.toJson()),
    );

    if (response.statusCode != 200) {
      throw Exception('Update failed');
    }

    return Product.fromJson(
      jsonDecode(response.body),
    );
  }

  static Future<void> deleteProduct(int id) async {
    final response = await http.delete(
      Uri.parse('$baseUrl/$id'),
    );

    if (response.statusCode != 200) {
      throw Exception('Delete failed');
    }
  }
}
STEP 21 · NEVER ASSUME SUCCESS

Handle Success and Failure Responses

An HTTP request completing does not automatically mean the operation succeeded.

SituationWhat to do
Expected success codeDecode response and update UI.
Unexpected status codeThrow or return an application error.
No internet / timeoutCatch the exception and show retry/error UI.
Invalid form inputStop before making the request.
Important:

try/catch handles thrown failures. Checking statusCode handles valid HTTP responses that still represent failure.

STEP 24 · QUICK REVISION

REST CRUD Revision

These are the ideas you should be able to explain before moving to Provider integration.

1. Which method reads resources?
GET.
2. Which method creates a resource?
POST.
3. Which method can partially update a resource?
PATCH.
4. Which method removes a resource?
DELETE.
5. Why send Content-Type: application/json?
It tells the server that the request body contains JSON.
6. Why call jsonEncode()?
The HTTP request body needs JSON text, while the model's toJson() produces a Dart map.
7. Where is the ID used for update/delete?
Usually in the URL path, for example /products/7.
8. Why check statusCode?
Because receiving an HTTP response does not guarantee that the operation succeeded.
9. Why update the local list after a successful mutation?
So the interface immediately reflects the result returned by the API.
10. Why does DummyJSON need special explanation after writes?
Its POST/PATCH/DELETE endpoints simulate the operation and return realistic responses, but they do not permanently change the public dataset.
