STEP 3 · INSTALL HTTP

Add the http Package

Dart's http package gives us simple functions for making HTTP requests.

flutter pub add http
import 'package:http/http.dart' as http;
Why as http?

It gives the package a clear prefix. We can write http.get(), http.post(), and so on, making it obvious that the function belongs to the HTTP package.

Why are we adding the http package?

STEP 4 · CREATE THE URL

Turn the API Address into a Uri

http.get() expects a Uri, not just an ordinary String.

final url = Uri.parse(
  'https://dummyjson.com/products?limit=10',
);
PartMeaning
Uri.parse(...)Parses a URL string into a Uri object Dart can work with.
/productsThe products resource.
?limit=10A query parameter asking for 10 products.
Remember:

String is text. Uri is Dart's structured representation of a URI/URL.

STEP 5 · HTTP GET

Send the Request with http.get()

A GET request asks the server to return data.

final response = await http.get(url);
http.get(url)
↓
GET /products?limit=10
↓
DummyJSON
↓
http.Response
Why await?

The network request takes time. http.get() returns a Future<http.Response>, so we await the response instead of blocking the UI thread.

Why does http.get() work asynchronously?

STEP 6 · FIRST FUNCTION

Put the Request Inside an async Function

Let's make the smallest useful function and inspect what comes back.

Future<void> fetchProducts() async {
  final url = Uri.parse(
    'https://dummyjson.com/products?limit=10',
  );

  final response = await http.get(url);

  print(response.statusCode);
  print(response.body);
}
Two things to inspect first:

response.statusCode tells us how the request went. response.body contains the response body as text.

STEP 7 · STATUS CODE

Did the Request Succeed?

The server uses an HTTP status code to tell the client the result of the request.

if (response.statusCode == 200) {
  print('Request successful');
} else {
  print('Request failed');
}
StatusSimple meaning
200The GET request succeeded.
404The requested resource was not found.
500The server encountered an error.
GOOD HABIT

Do not assume that receiving a response means the request was successful. Always inspect the status code.

STEP 8 · RESPONSE BODY

response.body Is Still a String

The API sends JSON, but the HTTP package initially gives the body to us as text.

print(response.body);

Important:

Even though it looks like a Dart map, response.body is a String. We need to decode the JSON before accessing fields like products.

STEP 9 · JSON DECODING

Convert JSON Text into Dart Data

Use jsonDecode() from dart:convert.

import 'dart:convert';
final data = jsonDecode(response.body);
response.body

↓ jsonDecode()

↓

For this response:

The top-level JSON value is an object, so after decoding it behaves like a Dart map containing keys such as products, total, skip, and limit.

STEP 10 · READ THE DATA

Extract products from the Decoded JSON

The API wraps the product array inside a products field.

final data = jsonDecode(response.body);
final products = data['products'];

print(products.length);
print(products[0]['title']);
print(products[0]['price']);
For now, we are using dynamic JSON.

STEP 11 · HTTP FAILURES

Throw an Error When the Server Says No

If the status code is not what we expect, do not continue parsing the response as successful data.

Future<List<dynamic>> fetchProducts() async {
  final url = Uri.parse(
    'https://dummyjson.com/products?limit=10',
  );

  final response = await http.get(url);

  if (response.statusCode != 200) {
    throw Exception(
      'Failed to load products: ${response.statusCode}',
    );
  }

  final data = jsonDecode(response.body);
  return data['products'];
}
Why throw?

Throwing an exception moves the program into its error path. The UI can then show an error message instead of pretending the data loaded correctly.

STEP 12 · EXCEPTIONS

The Request Itself Can Fail

Sometimes there is no usable HTTP response at all—for example, because the device has no connection or the request cannot reach the server.

try {
  final products = await fetchProducts();
  print(products);
} catch (error) {
  print('Something went wrong: $error');
}
HTTP failure

The server responds, but the status code indicates failure.

Request exception

The request may fail before a useful response is received.

One UI idea:

Both kinds of failure can lead to the same visible Error state, while you can still log or inspect the technical reason separately.

STEP 13 · UI STATES

STEP 14 · START THE REQUEST

Fetch Products When the Screen Opens

A StatefulWidget can start the request from initState().

@override
void initState() {
  super.initState();
  loadProducts();
}
Why not await directly in initState()?

initState() itself is not marked async. Instead, call an async method such as loadProducts() from it.

STEP 15 · UPDATE STATE

Move from Loading to Success or Error

The request changes the state of the screen, so update the fields and rebuild the UI with setState().

Future<void> loadProducts() async {
  setState(() {
    isLoading = true;
    errorMessage = null;
  });

  try {
    final result = await fetchProducts();

    setState(() {
      products = result;
      isLoading = false;
    });
  } catch (error) {
    setState(() {
      errorMessage = error.toString();
      isLoading = false;
    });
  }
}

↓

STEP 16 · CONDITIONAL UI

Show the Correct State

The build() method can return different widgets depending on the current state.

if (isLoading) {
  return const Center(
    child: CircularProgressIndicator(),
  );
}

if (errorMessage != null) {
  return Center(
    child: Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text(errorMessage!),
        const SizedBox(height: 12),
        ElevatedButton(
          onPressed: loadProducts,
          child: const Text('Retry'),
        ),
      ],
    ),
  );
}
Retry matters:

Network failures can be temporary. A retry button lets the user run the same request again without restarting the app.

STEP 17 · SUCCESS UI

Render the Remote Products in a ListView

Once loading is finished and there is no error, we can safely show the downloaded products.

return ListView.separated(
  padding: const EdgeInsets.all(16),
  itemCount: products.length,
  separatorBuilder: (context, index) {
    return const Divider();
  },
  itemBuilder: (context, index) {
    final product = products[index];

    return ListTile(
      title: Text(product['title']),
      subtitle: Text(product['category']),
      trailing: Text('\$${product['price']}'),

You now have remote UI.

The values shown by the widgets did not come from hard-coded Dart data or a local database. They came from a server over HTTP.

STEP 18 · PUT IT TOGETHER

Complete Products API Example

This version combines the request, status-code check, JSON decoding, exception handling, and all three UI states.

import 'dart:convert';

import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorSchemeSeed: Colors.blue,
      ),
      home: const ProductsPage(),
    );
  }
}

class ProductsPage extends StatefulWidget {
  const ProductsPage({super.key});

  @override
  State<ProductsPage> createState() {
    return _ProductsPageState();
  }
}

class _ProductsPageState extends State<ProductsPage> {
  bool isLoading = true;
  String? errorMessage;
  List<dynamic> products = [];

  @override
  void initState() {
    super.initState();
    loadProducts();
  }

  Future<List<dynamic>> fetchProducts() async {
    final url = Uri.parse(
      'https://dummyjson.com/products?limit=10',
    );

    final response = await http.get(url);

    if (response.statusCode != 200) {
      throw Exception(
        'Failed to load products: ${response.statusCode}',
      );
    }

    final data = jsonDecode(response.body);
    return data['products'];
  }

  Future<void> loadProducts() async {
    setState(() {
      isLoading = true;
      errorMessage = null;
    });

    try {
      final result = await fetchProducts();

      if (!mounted) return;

      setState(() {
        products = result;
        isLoading = false;
      });
    } catch (error) {
      if (!mounted) return;

      setState(() {
        errorMessage = error.toString();
        isLoading = false;
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Products'),
      ),
      body: buildBody(),
    );
  }

  Widget buildBody() {
    if (isLoading) {
      return const Center(
        child: CircularProgressIndicator(),
      );
    }

    if (errorMessage != null) {
      return Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            const Text('Could not load products'),
            const SizedBox(height: 8),
            Text(errorMessage!),
            const SizedBox(height: 12),
            ElevatedButton(
              onPressed: loadProducts,
              child: const Text('Retry'),
            ),
          ],
        ),
      );
    }

    return ListView.separated(
      padding: const EdgeInsets.all(16),
      itemCount: products.length,
      separatorBuilder: (context, index) {
        return const Divider();
      },
      itemBuilder: (context, index) {
        final product = products[index];

        return ListTile(
          title: Text(product['title']),
          subtitle: Text(product['category']),
          trailing: Text('\$${product['price']}'),
        );
      },
    );
  }
}

Try these changes

  1. Change limit=10 to limit=5.
  2. Display the product's rating below its category.
  3. Temporarily change the URL to an invalid endpoint and observe the error UI.
  4. Add RefreshIndicator around the list and call loadProducts() when the user pulls to refresh.

STEP 20 · DEBUG SMARTER

Common First-API Mistakes

Most beginner networking bugs come from a small set of misunderstandings.

MistakeWhy it failsFix
Passing a String directly to http.get()The method expects a Uri.Use Uri.parse(...).
Using response.body['products']body is a String.Run jsonDecode(response.body) first.
Ignoring statusCodeError responses may be treated like successful data.Check the expected success status before parsing.
No loading stateThe screen can appear empty while the request runs.Track isLoading.
No try/catchA request exception is not represented in the UI.Catch it and show an error state.
Calling setState after disposalThe async request may finish after the widget leaves the tree.Check mounted before updating state after awaits.
Platform note:

If a request works on one platform but not another, also check the platform's networking configuration and browser CORS rules. The Dart code can be correct while a platform policy blocks the request.

STEP 21 · QUICK REVISION

Fetching REST API Data Revision

Use these questions for class revision, viva practice, or a quick knowledge check.

1. Why do we use the http package?
To send HTTP requests and receive HTTP responses from Dart and Flutter applications.
2. What does Uri.parse() do?
It converts a URI/URL string into a Uri object that networking APIs can use.
3. What does http.get() return?
A Future<http.Response>.
4. Why do we use await?
Because the network request completes asynchronously in the future.
5. What is response.statusCode?
The HTTP status code returned by the server, such as 200.
6. What is response.body?
The response body as a String.
7. Why is jsonDecode() needed?
It converts JSON text into Dart data structures such as maps and lists.
8. Where are the products in the DummyJSON response?
Inside the decoded value at data['products'].
9. Why check the status code before using the data?
Because the server may return an error response instead of the successful resource we expect.
10. Why use try/catch around networking?
Because network operations can fail, and the app should turn those failures into a controlled error state.
11. What three states should a basic remote-data screen represent?
Loading, success, and error.
12. Why check mounted after await?
The widget might have been removed from the tree while the asynchronous request was running.
