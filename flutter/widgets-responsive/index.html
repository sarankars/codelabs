STEP 2 · MEASURE THE WINDOW

Read Window Information with MediaQuery

MediaQuery provides the app window size and environment information such as system padding, keyboard insets, and text scaling.

Widget build(BuildContext context) {
  final size = MediaQuery.sizeOf(context);
  final safePadding = MediaQuery.paddingOf(context);
  final keyboardInsets = MediaQuery.viewInsetsOf(context);
  final textScaler = MediaQuery.textScalerOf(context);

  return Text(
    '${size.width} × ${size.height}',
    textScaler: textScaler,
  );
}
QueryUse it for
MediaQuery.sizeOf(context)The size of the current app window in logical pixels.
paddingOf(context)System areas that are fully obscured, such as notches and status bars.
viewInsetsOf(context)Areas completely covered by system UI, commonly the on-screen keyboard.
textScalerOf(context)The user's current text scaling preference.
orientationOf(context)The window's current portrait or landscape orientation.
Prefer focused queries: If you only need the size, use MediaQuery.sizeOf instead of reading the complete MediaQueryData. The widget then depends only on the property it uses.

STEP 3 · MEASURE LOCALLY

Use LayoutBuilder for Parent Constraints

LayoutBuilder runs at layout time and gives you the constraints passed to that exact location in the widget tree.

LayoutBuilder(
  builder: (context, constraints) {
    final isWide = constraints.maxWidth >= 560;

    if (isWide) {
      return Row(
        children: const [
          Expanded(child: CourseDetails()),
          SizedBox(width: 16),
          Expanded(child: ProgressChart()),
        ],
      );
    }

      children: [
        CourseDetails(),

      ],
    );
  },

ChooseWhen
MediaQuery.sizeOfThe decision belongs to the whole app window or full screen.
LayoutBuilderA reusable component should respond to the space its parent gives it.

STEP 4 · BRANCH DELIBERATELY

Create Practical, Content-Based Breakpoints

A breakpoint is the width at which the current composition stops working well and another composition becomes clearer.

CompactMediumExpanded
enum WindowClass { compact, medium, expanded }

WindowClass windowClassFor(double width) {
  if (width < 600) return WindowClass.compact;
  if (width < 1024) return WindowClass.medium;
  return WindowClass.expanded;
}
Example rangePossible composition
Compact: below 600One column, bottom navigation, full-width actions.
Medium: 600–1023Two columns or a compact navigation rail.
Expanded: 1024 and abovePersistent rail, multi-column content, capped reading width.
NOT UNIVERSAL CONSTANTS

These numbers are useful starting points, not a law. Resize your real content, include large text, and place the breakpoint where the design needs to change.

Avoid dozens of width checks. Classify the width once, then pass the chosen window class or shared layout values to the parts that need them.

STEP 5 · LET CONTENT REFLOW

Use Flexible Layouts Before Branching

Not every size change needs a completely different widget tree. Many layouts can adapt naturally with flexible sizing, wrapping, and sensible limits.

Expanded and Flexible

Share remaining space without hard-coded widths.

Wrap

Move chips, buttons, or tags onto another run.

ConstrainedBox

Cap widths so reading lines and forms do not stretch endlessly.

FractionallySizedBox

Size a child as a fraction of the available space.

AspectRatio

Preserve a deliberate shape while dimensions change.

FittedBox

Scale bounded visual content when scaling is actually appropriate.

Keep readable content centered

Center(
  child: ConstrainedBox(
    constraints: const BoxConstraints(maxWidth: 720),
    child: ListView(
      padding: const EdgeInsets.all(24),
      children: const [
        CourseHeader(),
        SizedBox(height: 24),
        LessonContent(),
      ],
    ),
  ),
)
LARGE-SCREEN HABIT

Use extra space to improve composition, not merely to stretch every element. Long paragraphs, forms, and primary actions usually benefit from a maximum width.

STEP 6 · WIDTH AND HEIGHT

Respond to Orientation When Shape Matters

OrientationBuilder compares the available width and height. Use it when the relationship between those dimensions changes the composition.

Lesson outline

OrientationBuilder(
  builder: (context, orientation) {
    final landscape = orientation == Orientation.landscape;

    return Flex(
      direction: landscape ? Axis.horizontal : Axis.vertical,
      children: const [
        Expanded(child: LessonVideo()),
        Expanded(child: LessonOutline()),
      ],
    );
  },
)
DO NOT ASSUME

Landscape does not automatically mean “large,” and portrait does not mean “phone.” A narrow split-screen region may still need the compact composition.

STEP 7 · CHANGE THE COMPOSITION

Adapt Navigation to Available Width

Compact layouts commonly use bottom navigation. Wider layouts can keep destinations visible in a navigation rail without taking space from the bottom.

Widget build(BuildContext context) {
  final wide = MediaQuery.sizeOf(context).width >= 600;

  return Scaffold(
    bottomNavigationBar: wide
        ? null
        : NavigationBar(
            selectedIndex: selectedIndex,
            onDestinationSelected: onDestinationSelected,
            destinations: const [
              NavigationDestination(
                icon: Icon(Icons.home_outlined),
                label: 'Home',
              ),
              NavigationDestination(
                icon: Icon(Icons.school_outlined),
                label: 'Learn',
              ),
            ],
          ),
    body: Row(
      children: [
        if (wide)
          NavigationRail(
            selectedIndex: selectedIndex,
            onDestinationSelected: onDestinationSelected,
            destinations: const [
              NavigationRailDestination(
                icon: Icon(Icons.home_outlined),
                label: Text('Home'),
              ),
              NavigationRailDestination(
                icon: Icon(Icons.school_outlined),
                label: Text('Learn'),
              ),
            ],
          ),
        Expanded(child: pages[selectedIndex]),
      ],
    ),
  );
}
Share the model: Both navigation presentations should read and update the same selected index and the same destination definitions. Width changes should not reset the current destination.

STEP 8 · SCALE COLLECTIONS

Build Grids That Choose Their Column Count

For collections, define the useful tile width and spacing. Let the grid determine how many columns fit instead of maintaining many manual column counts.

GridView.builder(
  padding: const EdgeInsets.all(24),
  itemCount: courses.length,
  gridDelegate: const SliverGridDelegateWithMaxCrossAxisExtent(
    maxCrossAxisExtent: 320,
    crossAxisSpacing: 16,
    mainAxisSpacing: 16,
    childAspectRatio: 1.35,
  ),
  itemBuilder: (context, index) {
    return CourseCard(course: courses[index]);
  },
)
DelegateUse when
SliverGridDelegateWithFixedCrossAxisCountThe design requires an exact number of columns at the current window class.
SliverGridDelegateWithMaxCrossAxisExtentTiles should stay below a useful maximum width and the column count may adapt naturally.

Keep parent and scroll constraints clear

  • A grid already scrolls; avoid nesting it casually inside another same-axis scroll view.
  • Inside a Column, wrap the primary grid with Expanded.
  • For a header and grid moving together, use one scroll owner such as slivers.
  • Test zero items, one item, long titles, and many items at every width class.

STEP 9 · MORE THAN WIDTH

Make Responsive UI Resilient

A layout is not robust until it handles large text, safe areas, keyboards, different input methods, and content that does not match your sample data.

TestWhat can failUseful response
Large text scalingLabels clip or fixed-height cards overflow.Allow wrapping, avoid unnecessary fixed heights, and test accessibility sizes.
On-screen keyboardFields and submit actions become hidden.Use scrolling and account for viewInsetsOf when needed.
Notches and system UIContent becomes obscured near an edge.Use SafeArea or appropriate system padding.
Mouse and keyboardHover, focus, and shortcuts are missing.Keep visible focus, useful tooltips, and reachable actions.
Long or translated textRows overflow and buttons become unreadable.Use flexible children and allow labels to wrap.
Very wide windowReading lines stretch and hierarchy disappears.Cap content width or introduce another useful pane.
SafeArea(
  child: LayoutBuilder(
    builder: (context, constraints) {
      return SingleChildScrollView(
        padding: EdgeInsets.only(
          left: 24,
          top: 24,
          right: 24,
          bottom: MediaQuery.viewInsetsOf(context).bottom + 24,
        ),
        child: ConstrainedBox(
          constraints: const BoxConstraints(maxWidth: 640),
          child: const CourseForm(),
        ),
      );
    },
  ),
)

Responsive testing matrix

  1. Resize continuously from 320 to 1440 logical pixels.
  2. Test portrait and landscape without locking orientation.
  3. Increase the system text size.
  4. Open the keyboard on the last form field.
  5. Use long names and translated labels.
  6. Navigate with keyboard focus on desktop or web.

STEP 10 · GUIDED BUILD

Build a Responsive Course Dashboard

Combine window classes, adaptive navigation, a capped content region, and an automatically resizing course grid.

Scaffold
├── compact: NavigationBar
└── Row
    ├── medium/expanded: NavigationRail
    └── Expanded
        └── Center → ConstrainedBox
            └── GridView.builder
class ResponsiveCourseDashboard extends StatelessWidget {
  const ResponsiveCourseDashboard({
    super.key,
    required this.courses,
    required this.selectedIndex,
    required this.onDestinationSelected,
  });

  final List<Course> courses;
  final int selectedIndex;
  final ValueChanged<int> onDestinationSelected;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        final windowClass = windowClassFor(constraints.maxWidth);
        final compact = windowClass == WindowClass.compact;

        return Scaffold(
          bottomNavigationBar: compact
              ? NavigationBar(
                  selectedIndex: selectedIndex,
                  onDestinationSelected: onDestinationSelected,
                  destinations: const [
                    NavigationDestination(
                      icon: Icon(Icons.home_outlined),
                      label: 'Home',
                    ),
                    NavigationDestination(
                      icon: Icon(Icons.school_outlined),
                      label: 'Courses',
                    ),
                  ],
                )
              : null,
          body: SafeArea(
            child: Row(
              children: [
                if (!compact)
                  NavigationRail(
                    selectedIndex: selectedIndex,
                    extended: windowClass == WindowClass.expanded,
                    onDestinationSelected: onDestinationSelected,
                    destinations: const [
                      NavigationRailDestination(
                        icon: Icon(Icons.home_outlined),
                        label: Text('Home'),
                      ),
                      NavigationRailDestination(
                        icon: Icon(Icons.school_outlined),
                        label: Text('Courses'),
                      ),
                    ],
                  ),
                Expanded(
                  child: Center(
                    child: ConstrainedBox(
                      constraints: const BoxConstraints(maxWidth: 1200),
                      child: GridView.builder(
                        padding: const EdgeInsets.all(24),
                        itemCount: courses.length,
                        gridDelegate: const
                            SliverGridDelegateWithMaxCrossAxisExtent(
                          maxCrossAxisExtent: 320,
                          crossAxisSpacing: 16,
                          mainAxisSpacing: 16,
                          childAspectRatio: 1.3,
                        ),
                        itemBuilder: (context, index) {
                          return CourseCard(course: courses[index]);
                        },
                      ),
                    ),
                  ),
                ),
              ],
            ),
          ),
        );
      },
    );
  }
}
Read the decisions: LayoutBuilder classifies the available width. Compact uses bottom navigation. Wider layouts show a rail. The grid chooses its own column count, while ConstrainedBox stops the dashboard from becoming excessively wide.

Improve the dashboard

  1. Add an empty state that remains centered at every width.
  2. Show a details pane only in the expanded window class.
  3. Keep the selected course when resizing.
  4. Test course titles at large text scale.
  5. Replace the example thresholds with values discovered from your real content.
STEP 11 · APPLY THE IDEAS

Make One Existing Screen Responsive

Choose a screen you already built. Improve its composition without creating separate “phone” and “tablet” applications.

Requirements

  1. Use MediaQuery.sizeOf or LayoutBuilder for a clear reason.
  2. Define compact, medium, and expanded behavior from content needs.
  3. Use flexible layout widgets before adding extra branches.
  4. Adapt at least one major component, such as navigation or a list-detail view.
  5. Cap the width of reading or form content on large windows.
  6. Handle large text, long labels, keyboard insets, and safe areas.
  7. Resize continuously rather than checking only three fixed screenshots.

Completion checklist

  • I distinguish app-window size from physical device labels.
  • I know when to use MediaQuery and LayoutBuilder.
  • I can define and explain content-based breakpoints.
  • I use flexible sizing, wrapping, and maximum widths.
  • I can adapt navigation without losing selection state.
  • I can build a width-aware grid.
  • I do not confuse orientation with device size.
  • I test large text, keyboard insets, long content, and wide windows.
